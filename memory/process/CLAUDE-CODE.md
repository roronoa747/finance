# Интеграция фреймворка с примитивами Claude Code

Фреймворк работает на файлах и дисциплине — этот листок переводит правила из
«написано в гайде» в «технически обеспечено средствами Claude Code». Всё ниже —
опциональные усилители; конвейер работает и без них.

## Slash-команды ролей (готовы, `.claude/commands/`)

По команде на роль конвейера — вместо копирования промптов из SESSION.md:

| Команда | Роль | Когда |
|---|---|---|
| `/brief <слаг> [бриф]` | составитель, интервью | новая инициатива |
| `/backlog <слаг>` | составитель, бэклог | после подтверждённого резюме |
| `/worker <слаг> <N>` | исполнитель блока | старт блока |
| `/critic <слаг> <N>` | критик | после Handoff |
| `/accept <слаг> <N>` | приёмка | после итогов критика |
| `/dir-review <слаг> <N> <каталог>` | ревью каталога | только L, после «принято» |
| `/cleanup <слаг> <N>` | клинап | только L, после всех ревью |

Каждая сессия — в новом окне/`/clear` (инвариант «одна сессия — одна роль»).
Общая часть промптов живёт в командах; блок-специфика (цель, факты, среда) — по-
прежнему в SESSION.md, команды её читают. Модель под роль — `MODELS.md` (владелец
выбирает модель сессии сам; уровень назван в description команды).

## Hooks — верификация как механика (включить при старте проекта)

PostToolUse-хук в `.claude/settings.json` проекта автоматически гоняет билд после
каждой правки кода — «зелёные тесты» перестают зависеть от честности сессии.
Пример под Go (пути поправить под фактический layout при старте проекта):

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{
          "type": "command",
          "command": "f=$(jq -r '.tool_input.file_path // empty'); case \"$f\" in *.go) cd backend && go build ./... 2>&1 | tail -5 ;; esac"
        }]
      }
    ]
  }
}
```

Не включать до появления кода (хук по несуществующим путям — шум). Полный тест-
прогон в хук не класть (медленно на каждый Edit) — билд/vet в хук, тесты — в CI
и в верификации сессии.

## Plan mode — гейт составителя

`/brief` и исследовательские сессии запускать в plan mode (Shift+Tab): агент
читает и предлагает, писать не может до одобрения. Технически обеспечивает
анти-паттерн «бэклог авансом» из BRIEF-GUIDE.

## Permissions — роль как ограничение инструментов

В `.claude/settings.json` можно сузить права; практично для приёмки («не чинит
сама»): запуск сессии приёмки с `--permission-mode` plan / deny-правилами на
Edit|Write для каталогов кода. Держать просто: если мешает — дисциплины протокола
достаточно.

## Секрет-скан: gitleaks (опциональное усиление pre-commit)

Наш `memory/process/hooks/pre-commit` — самодостаточный (без зависимостей). Если в
системе установлен gitleaks, добавь в конец хука перед `exit $fail`:

```sh
if command -v gitleaks >/dev/null 2>&1; then
  gitleaks protect --staged --no-banner --redact || fail=1
fi
```

(Команду сверить с установленной версией gitleaks — CLI менялся между мажорами.)

## Headless — мост к автоматизации

`claude -p "<промпт>"` запускает сессию без интерактива — для cron/CI: например,
еженощный «прогони тесты всех репо, сверь memory/STATE.md с фактом, короткий отчёт».
Заводить только когда появится реальная потребность (инвариант: абстракции «на
будущее» не заводим).

## CI — обязательный, вне Claude Code

Шаблоны GitHub Actions — `templates/ci-go.yml`, `templates/ci-web.yml`. Правило —
в BACKLOG-GUIDE «Верификация»: CI заводится первым бэклогом проекта; красный CI =
блок не готов, что бы ни писал Handoff.
