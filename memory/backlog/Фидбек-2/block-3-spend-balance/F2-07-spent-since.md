# F2-07 — Траты тают баланс (фронт, finance.ts, стор операций)

Блок 3 · MVP · Репо/каталог: `frontend/` · Зависит от: F2-06 · Роли: участник (его телефон пишет итог), viewer (видит)

## Контекст (что уже есть)

- Решения — Р-6 (что тает: все траты после сверки — ручные, Apple Pay, выписка; отмеченная платежом и дубль двух
  источников — один раз; приходы плюсом; перевод себе со счёта — минусом; зарплата — только по «Пришла»), Р-8 (итог
  каждого человека — своей записью документа семьи, операции партнёра не видны).
- Сейчас `accountBalance(a, payments, ctx)` (`lib/finance.ts:1633`) = база сверки + зарплаты − отметки платежей + обмены,
  всё после `amountSetAt` (`afterAnchor` :1594). Стор: `balanceCtx()` / `withBalance` (stores/finance.ts:286-294); тот же
  `ctx` — в `shiftedBase` (:1738 finance.ts; `shiftAccountAmount` стора :1404) и в `updateAccount` (сравнение «не
  изменилось»). Новый вклад в остаток — только через `BalanceCtx`, иначе сдвиг и сверка разъедутся с экраном.
- Операции (§6 бэклога): `ops.all` — свои с правками (ручные, `source: 'tap'|'push'`, выписка; дубли телефон↔выписка стор
  снимает сам); `isSpend` / `spendOf` (учитывает `refund`; `internal` — не трата); `totalMarks(ops).marked` — строки,
  отмеченные платежом или зарплатой и ждущие «это платёж по …?». `Operation.date` — `YYYY-MM-DD`, `at?` — время (есть у
  трат с телефона); `amount` — целые тенге, минус — списание; валютная покупка с `amount` 0 ждёт курса.
- Образец записи итогов в документ семьи — `writeTotals` (stores/operations.ts:437): своя запись по id, ноль пишется явно,
  тот же итог второй раз не пишется (`sameTotal`), запись — `finance.mutateHouseholdDoc`. Где вызывается `writeTotals` —
  там же пересчитывать и этот итог (плюс смена якоря сверки и хозяина счёта).
- Слияние (`lib/merge.ts`): незнакомый список объектов с `id` старый код сливает по id — новый список безопасен для
  телефонов на прошлой сборке.

## Задача

1. `types/finance.ts`: в документе семьи список `accountSpent?: AccountSpent[]`, `AccountSpent = Tracked & { id:
   '<accountId>:<by>', accountId, by: PersonId, since: string | null /* amountSetAt, от которого считали */, amount: number
   /* нетто: траты − приходы, целые тенге, может быть < 0 */ }`.
2. `lib/finance.ts`: `spentSince(ops, marked, anchor)` → нетто своих операций после сверки: `+ spendOf` у трат, `−` приходы
   (`amount > 0`, включая перевод себе на счёт), `+` перевод себе со счёта (`internal`, `amount < 0`); строки из `marked` —
   никогда (отмеченный платёж уже списан отметкой, выписочная зарплата — «Пришла»). «После сверки»: есть `at` — `at >
   anchor`; только `date` — день позже дня сверки (тот же день — уже в сверенной сумме). Без якоря — все операции.
   Валютная покупка без пересчёта (`amount` 0) — 0.
3. `accountBalance`: `ctx.spent?: AccountSpent[]` — минус `amount` записей этого счёта, у которых `since` совпадает с
   нынешним `amountSetAt` (`?? null`) и `by` — среди хозяев (`spendOwners`, F2-06); устаревшие (`since` другой) не
   действуют — после сверки баланс = введённой сумме, пока телефон хозяина не пересчитал. Стор кладёт `accountSpent` в
   `balanceCtx()`.
4. Стор операций: телефон участника, если он хозяин счёта для трат (`spendAccountOf`), пишет свою запись `AccountSpent`
   (`spentSince(all, marked, amountSetAt)`) — при пересчёте итогов, при смене якоря сверки этого счёта и хозяина; тот же
   итог второй раз не пишет. Перестал быть хозяином — своя запись обнуляется (не удаляется — надгробие закрыло бы id).
   Viewer и демо без своих операций — не пишут.

## Тесты

- Юнит `spentSince`: ручная, Apple Pay и выписочная траты; возврат (`refund`) уменьшает; приход плюсом; перевод себе туда
  и обратно; отмеченная платежом и строка, ждущая «это платёж по …?», — 0; зарплата из выписки, отмеченная «Пришла», — 0;
  граница сверки (`at` до/после, `date` в день сверки / на следующий); без якоря — все; валютная без курса — 0; деньги
  целые.
- Юнит `accountBalance`: `spent` действующий / устаревший `since` / чужой счёт / человек не хозяин; `shiftedBase` с `spent`
  сохраняет видимый остаток (сдвиг на дельту не теряет трат); сверка обнуляет вклад трат.
- Стор операций (юнит): хозяин — запись по id `<счёт>:<я>`; та же сумма — без записи; перестал быть хозяином — `amount: 0`;
  viewer — ничего.
- e2e `e2e/f2-block3-spend-balance.test.ts` (два телефона, `phone` из `e2e/support/family.ts`): карта «оба», траты на
  обоих телефонах → у каждого баланс = база − траты обоих; трата, отмеченная платежом, — один раз; сверка → баланс =
  введённой сумме, следующая трата снова тает.

## Критерии приёмки

- Ручная трата / Apple Pay / выписка уменьшают баланс счёта для трат один раз; партнёр видит тот же баланс, не видя
  операций; сверка остатка начинает счёт заново.
- Все числа — `lib/finance.ts`; целые тенге. Build, весь vitest; Go не тронут.

## Вне скоупа

- Показ («Счета», «Неделя») — F2-08; несколько валют; привязка операции к конкретному счёту (у человека один счёт для трат);
  изменения «Месяца» и итогов разделов.
