# AP-03 — Ручка касания: сумма, валюта, банк, дубли (бэкенд)

Блок 1 · MVP · Каталог: `backend/` · Зависит от: AP-02 · Роли: внешний клиент (ключ member)

## Контекст (что уже есть)

- Триггер «Транзакция» iOS 17+ отдаёт строки: `Merchant`, `Amount` (строка с символом валюты в формате локали:
  «$6.22», для тенге формат не подтверждён — сверка на утреннем смоуке), `Card` (название карты в Wallet: «Kaspi Gold»…),
  `Name`; даты и кода валюты нет — момент приёма = момент оплаты (команда «Запускать сразу»). Баги Apple: срабатывание
  на отклонённую оплату, иногда пустой продавец и сумма 0, повторное срабатывание.
- Решения: Р-7, Р-15 (сервер только разбирает строку: код + минорные единицы; тенге — `amount`, тиыны отбрасываются;
  USD/EUR/RUB/CNY — `amount = 0` + `fx_*`; прочее → не записывать), Р-9 (тот же источник, та же сумма ≤ 2 мин — одна
  операция), Р-11 (только операция; без номеров — 6+ цифр вырезаются), Р-13 (≤ 200 операций с телефона в сутки по
  Алматы → 429), Р-14 (id — 16 случайных hex, дата — день по Алматы, вид `purchase`, банк по карте, `category_id` null,
  `source = 'tap'`, `occurred_at = now`).
- Контракт — §6 индекса «Контракт ручек телефона». Мидлварь ключа и пакет `internal/applepay` — AP-02; колонки — AP-01.
  Гвард текста: `longDigits` (`handlers/statements.go:50`), лимит 200 знаков, без NUL (`validateOperation` :180-195).
  Алматы — `time.FixedZone("Asia/Almaty", 5*60*60)`.

## Задача

1. `applepay.ParseAmount(s string) (currency string, minor int64, ok bool)` — чистая функция:
   - валюта по символу или коду в любом месте строки: `₸`, `KZT`, `тг`/`тенге` → KZT; `$`/`USD`; `€`/`EUR`; `₽`/`RUB`/
     `руб`; `¥`/`CNY`/`元` → CNY; любой другой символ/код (`£`, `₺`, `AED`, …) или нет ни одного — `ok = false`
     (не угадывать: строка без символа — не тенге по умолчанию; **исключение не делать** — сверка на смоуке);
   - число: группы через пробел, NBSP (U+00A0), узкий NBSP (U+202F), апостроф, точку или запятую; дробная часть — точка
     или запятая + ровно 1–2 цифры в конце; «1,234» / «1.234» (3 цифры) — тысячи; знак минус/плюс и скобки — не трата →
     `ok = false`;
   - результат в минорных единицах (×100), ноль → `ok = false`.
2. `applepay.BankOfCard(card string) string`: без учёта регистра `kaspi`/`каспи` → `kaspi`; `freedom`/`supercard`/
   `фридом` → `freedom`; `halyk`/`халык`/`народный` → `halyk`; иначе `card`.
3. `applepay.CleanMerchant(s)`: управляющие символы и NUL прочь, 6+ цифр подряд прочь, пробелы схлопнуты, ≤ 200 знаков
   (по рунам); пусто → «Apple Pay» (такая трата попадёт в «Без раздела», выписка заменит её по сумме — Р-16 п. 2).
4. Репозиторий (в `statement_repo.go` или `phonekey_repo.go` — по месту): `InsertPhoneOperation(ctx, userID,
   householdID, op)`, `FindRecentPhoneOperation(ctx, userID, source, currency, amountOrMinor, since time.Time)`,
   `CountPhoneOperationsSince(ctx, userID, since)` — по индексу AP-01.
5. Хендлер `POST /api/wallet/tap` (вне JWT-группы, мидлварь ключа AP-02), тело `{merchant?, amount?, card?, name?,
   at?, raw?}` — все строки необязательны (Р-13а: **команда владельца уже шлёт всю транзакцию текстом в одном поле
   `merchant`**, формат текста неизвестен) ≤ 4 КБ, лишние поля игнорируются (без `DisallowUnknownFields`), `now`
   инжектируется:
   - `amount` пуст → денежный токен ищется в `merchant`, `raw`, `name` (`applepay.FindAmount(text) (currency, minor,
     rest, ok)` — первый токен «число + символ/код валюты» или «символ/код + число»; `rest` — текст без токена); продавец
     — `rest` без названия карты, если оно узнаётся (`BankOfCard`), затем `CleanMerchant`; банк — по `card`, иначе по
     тексту;
   - сумма так и не разобрана и ключ принадлежит пользователю из `ADMIN_EMAILS` → тело (≤ 2 КБ, обрезка) пишется в
     `app.wallet_debug` (перезапись; строки старше 24 ч удаляются при каждой записи) и показывается в `/admin` одной
     строкой «Последнее нераспознанное касание» с временем (только своё — админ видит своё); у всех остальных тело не
     хранится нигде;
   - сумма не разобрана → 200 `{"status":"skipped","reason":"amount"|"currency"}`;
   - за сутки (Алматы) ≥ 200 операций с телефона → 429 `{"error":"limit"}`;
   - та же валюта и сумма с `source = 'tap'` за последние 2 мин → 200 `{"status":"duplicate"}`;
   - иначе запись (тенге: `amount = -(minor / 100)` — целое деление; валюта: `amount = 0`, `fx_currency`, `fx_amount =
     minor`) → 200 `{"status":"saved"}`. Ответ не содержит операции.
   - Деление на 100 — единственная арифметика сервера над суммой (разбор строки, как разбор выписки); курса здесь нет.

## Тесты

- Р-13а: тело `{"merchant": "<вся транзакция текстом>"}` — `FindAmount` вынимает сумму из вариантов «MAGNUM 5 000 ₸
  Kaspi Gold», «5 000 ₸ · MAGNUM», «Kaspi Gold\nMAGNUM\n5 000,00 ₸» → saved, продавец «MAGNUM»; текст без суммы →
  skipped; у админа тело в `wallet_debug` (перезапись, ≤ 2 КБ), у не-админа — таблица пуста; запись старше 24 ч
  удаляется.
- `ParseAmount` таблицей (≥ 25 строк): «1 234,50 ₸», «₸1 234», «1 234 ₸» с NBSP и U+202F, «KZT 5 000», «5000 тг»,
  «$6.22», «US$6.22» (→ USD), «€5,00», «5,00 EUR», «₽1 200», «¥88», «1,234.56 $», «1.234,56 €», «£3», «6.22» (без
  валюты), «-$5», «$0.00», «», «abc», «₸ 12 345 678,9» (одна цифра дроби).
- `BankOfCard`, `CleanMerchant` (номер карты «**** 1234» остаётся, «1234567» вырезается, пустое → «Apple Pay»).
- Хендлер (моки, фиксированное `now`): saved тенге — сумма отрицательная целая, дата по Алматы (20:00 UTC → следующий
  день), `category_id` null, `source` tap; валюта — `amount` 0 и `fx_*`; повтор через 90 с → duplicate, через 3 мин →
  saved; 201-я за сутки → 429; без ключа → 401; viewer → 403; тело 5 КБ → 413; ни один `log.` не пишет тело (проверка
  перехватом `log.SetOutput`).
- PG: запись строкой с `source = 'tap'` проходит CHECK-и `000002` (продавец с 6+ цифрами не доходит до базы).

## Критерии приёмки

- `go build ./... && go vet ./... && go test ./...` + PG — зелёные.
- Стенд: `curl -X POST localhost:8141/api/wallet/tap -H "Authorization: Bearer <ключ стенда>" -H
  "Content-Type: application/json" -d '{"merchant":"Magnum","amount":"1 234,50 ₸","card":"Kaspi Gold"}'` → saved; тот же
  через минуту → duplicate; `GET /api/operations` с JWT того же человека — операция с `source: "tap"`, `amount: -1234`.

## Вне скоупа

- Раздел, курс, итоги — телефон (AP-04). Склейка с пушем — Блок 2 (AP-10). Определение отклонённой оплаты — нельзя
  (фантом убирает выписка, Р-16 п. 3).
