# AP-05 — Выписка заменяет траты с телефона (фронт)

Блок 1 · MVP · Каталог: `frontend/src/` · Зависит от: AP-04 · Роли: member

## Контекст (что уже есть)

- Р-2 «выписка — истина», уточнено **Р-16** (порядок сопоставления для каждой операции выписки):
  1. операция с телефона того же знака, сумма равна (у пересчитанной из валюты — в пределах 3 %), дата ±1 день, тот же
     продавец по `normalizeMerchant`;
  2. нет — **единственная** операция с телефона того же знака, суммы (как в п. 1) и дат ±1 день у того же банка или у
     банка `card`;
  3. операции с телефона банка выписки с датой в `[from, to − 1 день]` без пары — фантом, тоже убираются.
  Каждая операция с телефона — не больше чем в одной паре; ближайшая по дате побеждает.
- `stores/operations.ts`: `draftOps` :257-266, `commitUpload` :300-306 (`fresh.every(o => o.id in ops)` — «уже были»),
  `shown` / `shownTotals` :316-330 (выписка, ждущая тост «Отменить», — **должна показывать картину уже без заменённых**),
  `send` :447-494 (свои операции, итоги, очередь), `writeTotals` :355-382. Файлы черновика — `draft.files[i].parsed`
  (`bank`, `from`, `to`, `operations`). Похожая чистая функция пар — `pairInternalTransfers` (`lib/statements/model.ts`
  :233-255), `dayNumber` :224, допуски — `lib/statements/matching.ts` (`within` :49 — не экспортирована; процент — через
  `lib/finance.ts`, правило 6).
- Надгробие уходит на сервер тем же батчем: `toWire({...op})` + `deleted: true` (AP-01: необратимо).

## Задача

1. Чистая функция `replacedByStatement(statementOps, phoneOps, files: {bank, from, to}[]): Set<string>` (id операций с
   телефона) — в `lib/statements/` (новый файл `phone.ts` или в `matching.ts`); допуск 3 % — константа
   `PHONE_FX_TOLERANCE`, проверка суммы — функцией из `lib/finance.ts` (новая `withinShare(actual, expected, share)` или
   существующая, если найдётся). Операции выписки без телефонных — пустое множество.
2. `send`: заменённые → убрать из `ops`, надгробия в `pending` (одной задачей), периоды заменённых — в `writeTotals`.
   `shown` / `shownTotals` во время тоста — без заменённых (иначе двойной счёт на 6 секунд). «Отменить» — ничего не
   убрано.
3. Демо: операций с телефона нет — путь не срабатывает (без особых веток).

## Тесты

- `replacedByStatement` таблицей: п. 1 — «MAGNUM ALMATY KZ» в выписке ↔ «Magnum» с телефона, та же сумма, +1 день;
  п. 1 с валютой — 2989 ↔ 3030 (≤ 3 %) да, 3200 нет; п. 2 — разные названия, единственный кандидат того же банка; два
  кандидата — не заменять по п. 2; банк `card` — заменяется по п. 2; п. 3 — фантом внутри периода убран, в последний
  день периода — остаётся, другого банка — остаётся; приход и расход одной суммы не пара; одна телефонная — максимум
  одна пара.
- Стор: загрузка выписки с совпадающей операцией → в `all` одна (выписочная), в `pending` — надгробие, итог недели не
  удвоен; во время тоста `shownTotals` уже без дубля; «Отменить» — телефонная на месте.
- Регрессия: выписка без операций с телефона — поведение `send` прежнее (существующие тесты стора зелёные).

## Критерии приёмки

- `npm run build && npx vitest run` — зелёные.
- Стенд: касание `curl`-ом «Magnum 5 000 ₸» → «Неделя» 5 000; загрузить выписку-фикстуру того же банка с этой покупкой
  (`lib/statements/fixtures` или настоящая из `memory/secrets/statements`, не в git) → «Неделя» по-прежнему 5 000 за эту
  покупку, на втором устройстве того же человека (второй профиль браузера) телефонная исчезла после `pull`.

## Вне скоупа

- Замена «наоборот» (пуш после выписки) — нет: выписка грузится позже трат. Отметки платежей по заменённым — не
  переносятся (их ставит выписка). Пуши — Блок 2 (та же функция, без изменений).
