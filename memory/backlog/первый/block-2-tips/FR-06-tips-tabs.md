## Задача

1. На каждую из четырёх вкладок — **один** `Tip` у главного предмета (Р-7), id вида `tab-dreams`, `tab-week`,
   `tab-month`, `tab-money`. Текст — 1–2 короткие строки «что это и куда нажать», без механики («выписка», «PDF»);
   черновики — исполнитель, финальные слова — владелец на `/ux` (Р-9). Viewer — свой текст без призыва к действию
   (Р-7), тот же id.
2. Пустые состояния: если главного предмета на вкладке нет (нет мечты, нет недели) — подсказки нет, она ждёт
   появления предмета (пустой экран сам — первый шаг, правило 12).
3. Показываются всем один раз (Р-7): нынешним семьям, партнёру, viewer, в демо — ничего не проверяют, кроме «видел».
4. Не мешать главным действиям: пузырь не закрывает главную кнопку экрана и сам предмет; одновременно со своим тостом
   (`Toast`) или листом — не показывается (FR-05 п. 3).

## Тесты

- DOM-тесты вкладок (рядом с существующими `Dreams.*`, `Money.*`, `MonthPlan`/`Month`, `Week`): подсказка видна при
  пустом «видел», после «Понятно» — нет; viewer — свой текст; пустое состояние — нет подсказки.

## Критерии приёмки

- Каждая вкладка при первом заходе — один пузырь у главного предмета; после «Понятно» не возвращается (перезагрузка,
  смена вкладок); демо и viewer — тоже.
- Пузырь не закрывает главную кнопку на 390 и 375 px, обе темы.
- `npm run build && npx vitest run` зелёные; стенд — нынешняя семья (документ с данными), новая семья после первого
  запуска, viewer, демо.

## Вне скоупа

- Подсказки на второстепенных экранах (экран цели, листы, настройки); тур; новые события (Р-10).
