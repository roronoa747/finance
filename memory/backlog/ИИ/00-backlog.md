## 1. Цель

Включённым владельцем семьям ИИ (Claude) помогает дойти до мечты: разбирает месяц (что хорошо, где риск, 2–3 шага),
предлагает разделы незнакомым продавцам после выписки и делает желание из скриншота товара. Данные уходят минимальные, с
одним понятным согласием; семья без флага ИИ не видит. Успех — критерии готовности брифа: у семьи владельца ИИ включён из
админки; разбор настоящего месяца по делу, все числа текста совпадают с экраном, партнёр видит тот же разбор; на настоящей
выписке у продавцов «Без раздела» — предложения, принятие одним нажатием; скриншот → желание с фото и ценой; в админке —
запросы и ≈ $; согласие спрошено один раз. Режим процесса — **L** для Блоков 1–2, **M с `/ux`** для Блоков 3–4 (§5).

## 2. Зафиксированные решения

- **Р-1. Три функции в MVP:** разбор месяца, незнакомые продавцы, желание из скриншота. Не-скоуп: чат и свободные вопросы
  («Можно купить?»), автоприменение предложений, подписка и оплата, ИИ у семей без флага. *(интервью р. 1)*
- **Р-2. Провайдер — Claude (Anthropic API), платный тариф** (данные API не идут на обучение). Вызов только из Go, ключ —
  env `ANTHROPIC_API_KEY` (значение — `memory/secrets/anthropic.md`, в доки — только имя). Модель — env по функции (Р-13).
  **Без ключа ИИ выключен везде** (ручки → 503, `/auth/me` → `ai: false`), прод без ключа валиден. Доступность API из
  `icn1` и лимит времени функции Vercel проверяются в первой задаче (AI-01) по документации, **не по памяти**; недоступно —
  стоп и вопрос владельцу. *(интервью р. 1; env, модели, проверка — дефолт)*
- **Р-3. Разбору месяца уходит сводка + траты по разделам:** цифры месяца, посчитанные `finance.ts` (доход, платежи,
  остаток, долги со ставками, цели с прогрессом и сроками), итоги трат по разделам; имена → «участник 1/2»; **без заметок,
  без операций и продавцов, без личного документа**. Модель денег не считает; число в ответе, которого нет во входе, —
  брак ответа (проверка в Go: одна повторная попытка, снова брак — ошибка, непроверенное не показываем). *(интервью р. 1;
  запрет счёта и проверка — дефолт по Р-25 RP)*
- **Р-4. Разбор месяца — небольшой кнопкой на «Месяце» у остатка** (рядом с «Хватит?», правило 12) → лист: что хорошо,
  где риск, 2–3 шага со ссылками на экраны; тон «мы», без упрёков и сравнения участников. Ответ сохраняется в **общий
  документ** — партнёр видит тот же текст; «Обновить» — не чаще раза в день. *(интервью р. 2; содержание и тон — дефолт по
  Р-25/Р-27 RP)*
- **Р-5. Незнакомые продавцы — ИИ сам предлагает:** после загрузки выписки в пачке «Без раздела» у каждого продавца стоит
  предложение раздела; человек принимает одним нажатием или меняет; **автоматически ничего не применяется**. Уходят только
  названия продавцов и названия разделов (без сумм, дат, ФИО; название с 6+ цифрами не уходит). Принятое — то же правило
  «продавец → раздел» в личном документе, что и ручной ответ. *(интервью р. 3; состав запроса — дефолт по B2C-31)*
- **Р-6. Желание из скриншота:** «+» → «Желание» → тихая кнопка «Из скриншота» → картинка из фото уходит в Claude через Go
  (**на сервере не хранится**) → предзаполнены название, цена и фото товара (вырез по рамке, которую вернула модель; не
  вышло — весь скриншот) → человек проверяет и сохраняет. *(интервью р. 2; вырез и хранение — дефолт)*
- **Р-7. ИИ включается семье в админке:** список семей (почты участников, включён ли ИИ, запросов и ≈ $ за месяц) с
  переключателем; флаг — в базе (миграция). Участники семьи с флагом — все функции; **viewer видит сохранённый разбор,
  кнопок ИИ нет** (сервер — 403). *(интервью р. 2; viewer — дефолт)*

  пачки продавцов + скриншоты), счётчик на сервере, месяц — по Алматы (`Asia/Almaty`); кончился — спокойное «ИИ вернётся

- **Р-9. Согласие — один раз на человека:** при первом использовании лист «что уходит» (цифры месяца без имён, названия
  продавцов, скриншот), куда (Anthropic), «не обучается на ваших данных» → «Включить» / «Не надо»; выключить — в
  настройках; у разбора — ссылка «что ушло». Согласие хранится в **личном документе** (общее для устройств человека).
  «Не надо» — функция не вызывается, приложение работает как без ИИ. *(интервью р. 3; хранение — дефолт)*
- **Р-10. Без флага — ИИ не видно совсем; демо — пример:** в демо «Разобрать» показывает заранее написанный разбор
  демо-семьи без запроса; предложений продавцов и скриншота в демо нет. *(интервью р. 3; демо только для разбора — дефолт)*

  при каком условии (флаг семьи + согласие человека), без обучения. *(дефолт)*

Решения составителя (дефолты, при составлении бэклога 2026-10-15; источник фактов о моделях — справка Claude API,
кэш 2026-10-06; AI-01 сверяет с живой документацией):

- **Р-13. Модели и клиент.** Официальный Go SDK `github.com/anthropics/anthropic-sdk-go` (не голый HTTP — SDK даёт типы,
  ошибки по статусам и `option.WithBaseURL` для `httptest`). Модель — env по функции с дефолтом:
  `AI_MODEL_REVIEW` = `claude-opus-5-5` (разбор), `AI_MODEL_SELLERS` = `claude-haiku-5-5` (продавцы, лёгкая),
  `AI_MODEL_WISH` = `claude-opus-5-5` (скриншот, зрение). Ответ — структурный JSON по схеме (structured outputs), без
  свободного текста вне схемы. Ретраи SDK — не больше 1, таймаут запроса — меньше лимита функции (AI-01).
- **Р-14. Что считается запросом.** Одно нажатие = один запрос лимита (разбор, одна пачка продавцов на загрузку выписки,
  один скриншот); повтор проверки чисел внутри разбора — тот же запрос. Ошибка модели / таймаут / брак ответа — **не
  списываются**. Расход ≈ $ = токены `usage` × цена модели (таблица цен — константы в Go рядом с клиентом; неизвестная
  модель — расход 0 и «≈ —» в админке), хранится **целым числом микродолларов**.
- **Р-15. Ничего лишнего на сервере.** Ни ключ, ни тело запроса, ни ответ модели, ни картинка не пишутся в логи и в базу;
  в базе — только флаг семьи и счётчики (запросы, токены, микродоллары) по семье и месяцу. Сервер ничего не добавляет к
  присланному (ни id семьи, ни почты) — тесты фиксируют состав исходящего тела.
