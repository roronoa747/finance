## Задача

1. Отбор для запроса `aiSellerNames(groups)` (чистая функция в `lib/statements/`): только группы с `match.merchant`
   (не `counterparty`); без 6+ цифр; без «ИП + 1–3 слова без цифр» (фамилия человека — модель не угадает, B2C-08); не
   больше 50 по сумме убывания; дубли — один раз.
2. Когда спрашивать: при открытии `UnknownBatch`, если `stores/ai.available`, есть сеть и есть отобранные названия без
   предложения → `ensureConsent()` → один запрос `apiClient.aiSellers(names, categories)`. Предложения кэшируются на
   устройстве (ключ `lib/storage` в `LOCAL_KEYS` `stores/finance.ts:147` — выход стирает; по нормализованному `match`,
   срок — 60 дней), повторное открытие пачки не шлёт
   запрос для уже спрошенных. Ошибки — тихо: строка «Подсказки не пришли» в шапке пачки, ручной выбор как был;
   `ai_limit` — «ИИ вернётся 1-го».
3. Строка продавца с предложением: под подписью — чип раздела (цвет раздела из токена/`hue`) и справа ✓ «Принять»
   (`soft sm`, одна кнопка) → `recategorizeAll([match], {categoryId})`; строка уходит из пачки как при ручном ответе.
   Изменить — как сейчас (отметить → чипы снизу). `null` → без предложения. Шапка: «ИИ предлагает · N» (точка на
   разделе, не блок). Массового «Принять все» нет (Р-5: каждое — одним нажатием у своего продавца).
4. Тексты финальные — `/ux`.

## Тесты

- `aiSellerNames`: `counterparty`-группы, «ИП Абенова», «KASPI 1234567» — не попадают; «Magnum Cash&Carry»,
  «ИП Сулейменов Аптека Плюс» — попадают; ≤ 50; порядок по сумме.
- DOM `UnknownBatch` (фейковый клиент со счётчиком): без `ai` — запроса нет, вид как раньше; первое открытие —
  согласие → один запрос с ровно отобранными названиями и разделами; повторное открытие — 0 запросов; «Принять» →
  `recategorizeAll` с `{categoryId}` (то же правило, что ручной ответ — сравнить с записью через чипы); `null` — без
  чипа; 429 — «ИИ вернётся 1-го», ручной выбор работает; «Не надо» —
  запросов нет.
