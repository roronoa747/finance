**2026-10-15.** Дифф: `e1f4aeb..3b70f34` (AI-01 … AI-06, правки критика), каталог `backend/` + корневые `go.mod`,
`go.sum`, `vercel.json` — 26 файлов, +1965/−28 (из них `go.sum` ×2 — 262). На своей машине: `cd backend && go build
./... && go vet ./... && go test ./...` — ✅ все пакеты; размер `cmd/server` (linux/amd64) до и после блока — сборкой
`main@e1f4aeb` во временном worktree.

**Резюме:** блокеров нет. Целевые пункты промпта сошлись (таймауты, ретраи, ошибки без содержимого, SQL списка, миграция),
кроме **отката миграции** — он записан без строки `schema_migrations`, и повторный выкат кода после отката сломал бы
админку (клинап, правка трёх строк доков до деплоя). Вторая находка — **расход неудачных вызовов не попадает в «≈ $»**:
Anthropic их выставляет в счёт, а клиент отдаёт пустой `Usage`; решается до первой ручки ИИ (хвост → Блок 2, AI-08).

## Проверено независимо (не по Handoff-у)

- **Таймауты против лимита функции:** дедлайн вызова 45 с (`ai.go:24`, один контекст на весь вызов с ретраем) < `WriteTimeout`
  60 с (`cmd/server/main.go`) = `maxDuration` 60 (`vercel.json`). Остальные внешние клиенты со своими 3–5 с (`fx`, `googleauth`,
  `linkpreview`, `db`) — поднятый до 60 с потолок функции им не мешает.
- **Ретраи SDK:** `WithMaxRetries(1)` + middleware `x-should-retry: false` на 429 (`ai.go:148-154`) — 429 не ждёт `retry-after`
  внутри дедлайна; тесты `TestCallRetriesOnce`, `TestCall429IsNotRetried`.
- **Ошибки без содержимого:** `classify` (`ai.go:158-173`) оставляет только статус; SDK-сообщение (URL + тело ответа) не
  выходит из пакета; логи хендлеров — `%v` от ошибок репозитория, без тел запросов.
- **SQL списка семей** (`ai_repo.go:46-67`): `LEFT JOIN ai_usage` по месяцу (чужой месяц не протекает — PG-тест), почты —
  `array_agg … ORDER BY m.slot` с `COALESCE '{}'` для семьи без участников, порядок «ИИ сверху, затем новые». Мок
  повторяет порядок (+ тай-брейк по id, которого в SQL нет — для мока безвредно).
- **Миграция 000007:** только добавляет (Р-19), `IF NOT EXISTS`, `ON DELETE CASCADE` (PG-тест каскада). Раннер
  `internal/db/migrate.go:61-90` ведёт учёт по имени файла в `app.schema_migrations` — отсюда Н-1.
- **Деньги — целые:** `CostMicros` в целых микродолларах (центы/MTok × токены / 100 — формула сверена), `BIGINT` в базе.
- **Конвенции:** `decodeStrictJSONBody` — теперь единственный строгий разбор тела в `handlers` (других
  `DisallowUnknownFields` нет); `adminOnly` — один на `Metrics` и три ручки ИИ; `AIFlags` — узкий интерфейс как
  `GoogleVerifier`; мок рядом с SQL — как `MockEventRepo`. Дублей с прошлыми блоками, кроме Н-3, не нашёл.
- **Вес функции:** `cmd/server` 14,1 → 21,3 МБ (+7,2 МБ, +52 %) — SDK и его зависимости (otel, jsonschema, yaml) — Н-5.

## Находки

### Н-1 · средняя · Записанный откат миграции неполон: после него повторный выкат не накатит 000007

`backend/migrations/000007_ai.sql:5`, `backend/README.md:137-138`, `SESSION.md:119-120` (план отката клинапа). Откат —
`DROP TABLE app.ai_usage; ALTER TABLE app.households DROP COLUMN ai_enabled;`, но строка `000007_ai.sql` остаётся в
`app.schema_migrations`. Раннер (`internal/db/migrate.go:61-67`) пропускает файл по имени → при повторном выкате кода ИИ
`cmd/migrate` скажет «всё применено», а `GET /api/admin/families` и `PUT …/ai` ответят 500 (нет колонки `ai_enabled`);
`/auth/me` выживет (`aiOn` логирует и отвечает `false`), поэтому поломку легко не заметить. Проверил чтением раннера.

**Рекомендация.** Во всех трёх местах дописать третью команду: `DELETE FROM app.schema_migrations WHERE version =
'000007_ai.sql';`. Правка комментария в ещё не применённой на проде миграции безопасна — раннер не сверяет содержимое.

**Вердикт: клинап** — до деплоя: клинап как раз зачитывает этот откат владельцу в вопросе о деплое.

### Н-2 · средняя · Токены отказа, обрезки и брака модели оплачены, но в расход «≈ $» не пишутся

`backend/internal/ai/ai.go:126-142` (+ комментарий `:93`). На `stop_reason` `refusal` / `max_tokens` и на ответ вне схемы
Anthropic уже выставил счёт за вход и вывод, а `Call` возвращает `Usage{}` — вызывающий не может записать расход. Р-14
говорит «ошибка… не списывается» про **лимит** семьи; расход же — «токены `usage` × цена». Сейчас ручек ИИ нет (только
`ai-check`, который не пишет ничего по ТЗ), но первая ручка Блока 2 (AI-08: 502 `ai_failed` без записи) закрепит
недосчёт. Обрезка по `max_tokens` на Opus дорогая: весь потолок вывода × $20/MTok за попытку, и в админке её не видно.

**Рекомендация.** `Call` возвращает `Usage` и при ошибке, когда API ответил (refusal, max_tokens, вне схемы); ручки Блока 2
на такой ошибке зовут `AddUsage(…, requests = 0, in, out, cost)` — интерфейс уже принимает `requests` отдельно, лимит не
трогается. Сетевые ошибки и таймауты — без `Usage` (токены неизвестны).

**Вердикт: хвост §4** — меняет контракт клиента, на который опирается AI-08, и толкование Р-14 (решение владельца).
Предложение судьбы: Блок 2, в AI-08 (до первой записи расхода).
