## 1. Цель

У многих бизнес и личные траты на одной карте: выписку бизнес-карты грузить не хотят. Им нужно вписывать семейные
траты руками — быстро, из «+», и чтобы такая трата жила как любая другая: «Неделя», разделы, «Месяц», итог раздела
партнёру, разбор ИИ. Успех: «+» → «Трата» → сумма и раздел → «Сохранить» (≤ 3 нажатий после «+», ввод суммы не
считаем), трата видна в разделе недели; свою ручную трату можно поправить и удалить. **Режим S** — две задачи, без блоков.

## 2. Зафиксированные решения

- **Р-1 Форма** (владелец 2026-10-20): в листе «+» пункт **«Трата»**. Поля: **сумма** и **раздел** — обязательны
  (разделы — те же разделы трат семьи, чипами), **дата** — по умолчанию сегодня, **заметка** «что / где» —
  необязательно. Одна главная кнопка «Сохранить» (`--brand`), на всё ≤ 3 нажатий после «+».
- **Р-2 Обычная личная операция** (владелец 2026-10-20): ручная трата — как строка выписки или Apple Pay: «Неделя»,
  разделы, «Месяц», итоги для партнёра (`writeTotals` → `SpendTotal`), разбор ИИ; партнёр видит только итог раздела,
  не строку. Ручную можно **поправить и удалить**; у выписки поведение не меняется.
- **Р-3 Без «бизнес»-пометок** (владелец 2026-10-20): никаких пометок и исключений «это бизнес» — «лучше разделять
  просто».
- Деньги — целые тенге (валюта не нужна), суммы считает `lib/finance.ts` / `lib/statements/model.ts`; ввод суммы —
  `NumField`, как в остальных полях чисел. Правило 12 CLAUDE.md.

## Handoff MAN-01, MAN-02 (исполнитель, 2026-10-20)

**Что сделано.**
- **MAN-01** — лист «+»: первым пунктом **«Трата»** («сумма и раздел») → `/week?spend=1` → лист `week/HandSpendSheet`:
  «Сколько, ₸» (`NumField`, курсор сразу в поле), «Раздел» — чипы разделов трат семьи (первые 6 + «Ещё N ▾»; разделов в
  документе нет — словарь по умолчанию), «Что или где» (необязательно), «Когда» (сегодня; позже сегодня — нельзя), одна
  главная **«Сохранить»** (`--brand`). Без суммы / раздела — строка «что не так» у поля (`useFormCheck`, Р-114).
  Сохранили — лист закрыт, адрес снят, на экране неделя этой траты. Стор `saveHand`: операция в копию, итоги недели и
  месяца (`writeTotals` → `SpendTotal`; при смене даты — и старого периода) в общий документ, на сервер — тем же
  `POST /api/operations/batch`, что строки выписки; разделов в документе нет — засеваются, как при первой выписке.
- **MAN-02** — правка и удаление: в листе раздела «Недели» ручная строка — кнопка с карандашом у суммы
  (`data-hand-op`), строки выписки — как были, только чтение. Нажатие → тот же лист «Трата» с заполненными полями;
  «Сохранить» — тот же id (итоги старого и нового раздела/даты переписаны); «Удалить трату» → подтверждение →
  `removeHand`: из копии и итогов, на сервер — надгробие (`deleted`), второй телефон убирает её при `pull`.
- **Go** — `knownBanks` батча операций + `hand` (`handlers/statements.go`); загрузка выписки банка `hand` — по-прежнему
  400. Тесты ручки: батч `hand` — 200, загрузка `hand` — 400.

**Как устроено (решения исполнителя).**
1. **Без миграции БД.** Ручная трата — строка `app.operations` с `bank = 'hand'` (колонка — свободный текст 1…32,
   CHECK только на длину); `source` не трогаем — у батча он всегда `'statement'` по умолчанию колонки (CHECK
   `source IN ('statement','tap','push')` из 000008 менять не пришлось). Клиент узнаёт ручную по банку (`isHand`), не
   по `source`: признак переживает синк на второй телефон без новой колонки. **Владельцу перед деплоем ничего
   запускать не нужно.**
2. **Выписка ручную не заменяет и не дублирует замену.** Замена касается только операций с телефона (`o.source` —
   `tap`/`push`) того же банка или `card` (`replacedByStatement`); у ручной нет `source` и банк `hand` не равен банку
   ни одной выписки → ни пары, ни «фантома». Серверная склейка Apple Pay ищет `source = 'tap'/'push'` — ручную не
   видит. Тест: строка выписки с той же суммой, днём и продавцом ручную не убирает.
3. **Раздел ручной — решение человека.** `categorize` возвращает её раздел как есть: ни правило семьи («Magnum →
   Подарки»), ни словарь, ни правило платежа его не меняют при пересчётах (`recategorize`, `forgetRule`,
   `settleReleased`). `matchCandidates` её пропускает — вопроса «Похоже, это платёж по Аренде?» по своей записи нет.
4. **Подпись строки** (`merchant`) — заметка, пусто — имя раздела: сервер не берёт покупку без продавца. Заметка — через
   `sanitize` (длинные цифры и полные ФИО уходят, Р-23): строку с номером карты сервер отверг бы 400, и очередь встала бы.
5. **Деньги** — `parseMoney` (целые тенге), минус и дробь из формы не проходят (`-Math.abs(Math.round)`); итоги —
   `spendTotals` / `writeTotals`, как у выписки.
6. **Р-3** — никаких «бизнес»-пометок нет.

**Правило 12 по экрану.**
- «+»: главное — «Трата», первым пунктом (самое частое действие дня; выписка — раз в неделю). Путь: «Трата» →
  набрать сумму → чип раздела → «Сохранить» = **3 нажатия после «+»** (набор цифр не считаем; на Android клавиатура
  открывается сама, iOS — касание поля, хвост Х-3).
- Лист «Трата»: одно главное действие — «Сохранить» (`--brand`) у формы; «Удалить трату» — тихо внизу (`DangerZone`)
  только при правке. Ушло в «Ещё N ▾» — 12 редких разделов (иначе 18 чипов сталкивали «Сохранить» за край экрана 390).
  Подсказок (`Hint`) нет — подписи полей 1–3 слова. Ничего не скрыто сверх «Ещё».
- Лист раздела «Недели»: действие «поправить» — у своего предмета, карандаш (`--ink-3`) у суммы ручной строки.
- «Неделя»: новых цифр нет — трата входит в сумму недели и строку раздела.

**Отклонения / локальные решения.**
1. Лист живёт на «Неделе» (`/week?spend=1`), а не в оболочке: после «Сохранить» человек сразу видит трату в разделе.
2. Правка — из листа раздела «Недели» (единственный список своих операций в `main`); лента «Траты недели» (`wk-feed`)
   ещё не в `main` — хвост Х-2.
3. Партнёр видит только итог раздела (`spendTotals` общего документа); операции личные (`GET /api/operations`
   партнёра — свои, 0 строк) — как у выписки.
