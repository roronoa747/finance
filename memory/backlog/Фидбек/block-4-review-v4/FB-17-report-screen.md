## Задача

1. **Отчёт v4** (`review.v === 4` или нет разбора у участника без ИИ): «Работа ИИ» (свои операции, `work`; без ИИ — не
   показывается) → **первая карточка — мысль модели** (`lead`: заголовок, текст, крупная цифра факта; без ИИ / брак — нет)
   → карточка `next` → остальные `reviewCards` по порядку → «Куда ушло» v4. Карточка кода: заголовок, одна крупная цифра
   (₸ в месяц или %), одна строка, **одна кнопка** с призывом (Р-24) — небольшая у предмета, брендовая в карточке (одно
   действие на экран); сделано — ✓ у цифры (лист закрыт с изменением: разовая отмечена, платёж заведён, план поставлен…).
   Карточки считаются **при открытии** (свежие, FB-15), не из сохранённого разбора.
2. **Кнопки → существующие листы поверх отчёта** (два нажатия до действия): `op` → `OpSheet`; `cat` → лист раздела
   месяца (`?cat=`; «Переводы людям» / «Наличные» — свои операции → `OpSheet`); `unknown` → **новый лист «Не разобрано»**
   на «Месяце» по образцу «Разовых» (`useQuerySheet('unknown')` + `SectionOpsList`, свои операции `UNKNOWN_CATEGORY`
   месяца) — и тихая строка «Не разобрано» становится нажимаемой в тот же лист; `pay` → `AddPaymentSheet`; `image` →
   `ImageMoveSheet`; `do` → `DoSheet`; `plan` → «Изменить план» раздела с суммой «обычно»; `obligation` → лист платежа.
   Закрыли лист — снова отчёт на той же карточке (адрес `?review=1&card=n` не теряется — грабли FB-22: «Назад» по
   истории).
3. **«Куда ушло» v4 (Р-25):** одна полоса из четырёх частей (продавцы · люди · наличные · платежи; цвета — токены,
   у каждой пары для тёмной темы) с подписями долей; ниже — разделы продавцов (`WhereBars`, `whereRows(…, by)`); выходные
   — маленькой картинкой (7 дней недели, сб–вс выделены) и одной долей. Строки модели `where` у v4 нет.
4. **Входы на «Месяце»:** пилюля разбора — участнику всегда (текущий месяц): с ИИ — «✦ Разбор» как было, без ИИ / «Не
   надо» — «Разбор» (только карточки кода, без запроса); viewer — нет у v4 (старые v1–v3 месяца — как было). Точка — новый
   свой разбор или новая карточка «Не разобрано». ✦ у предмета — `markFor` v4 (FB-16).
5. **Демо (Р-27):** `DEMO_REVIEW` → v4 (первая карточка-пример и `next`), карточки кода демо считаются из демо-операций;
   пометка «Пример», без «Обновить».
6. `DESIGN.md` (раздел отчёта разбора) — карточка v4, полоса «Куда ушло», лист «Не разобрано»; Handoff по правилу 12
   (главное действие каждого экрана и у какого предмета, что ушло в подсказку, что скрыто).

## Тесты

- `AiReport.dom.test.ts`: v4 с ИИ — порядок «Работа ИИ» → мысль → `next` → остальные → «Куда ушло»; без ИИ — без мысли и
  «Работы ИИ»; брак (нет разбора) — карточки кода есть; каждая кнопка открывает свой лист (по виду таблицы Р-24); v3 и
  v1/v2 разборы показываются как раньше (регрессия).
- `MonthPlan.dom.test.ts`: пилюля «Разбор» у участника без ИИ, нет у viewer; строка «Не разобрано» → лист с операциями →
  `OpSheet`.
- Демо: отчёт v4 открывается без сети, карточки с кнопками.

## Критерии приёмки

- Chrome 390 и 375, обе темы: отчёт листается, каждая кнопка — лист и обратно в отчёт, ✓ после действия; нет горизонтальной
  прокрутки; одна крупная цифра на карточке; цвета только из токенов.
- `cd frontend && npm run build && npx vitest run` — зелёные.
