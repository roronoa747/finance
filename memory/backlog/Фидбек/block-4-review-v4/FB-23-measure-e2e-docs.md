## Задача

1. **Живой замер:** факты v4 с настоящих выписок владельца (3 месяца, как FB-14) → ручка v4 на **Opus 5.5, Sonnet 5,
   Haiku 5.5** (по 3 разбора, effort как в ручке) → таблица в Handoff: брак (из N), токены вход/выход, $ и ₸ за разбор,
   ₸ в месяц на пару (×3 разбора × 2), качество мысли одной строкой на модель (без имён и сумм семьи). Лимит замера — $1.
   Рекомендация модели — одной строкой; **решение — владелец** (оркестратор спрашивает до деплоя; модель — env
   `AI_MODEL_REVIEW` на Vercel, код дефолта не трогать без решения).
2. **e2e `fb-block4-review-v4.test.ts`** (два телефона одной семьи, `fakeServer`): (а) у каждого свой отчёт — мои карточки
   по моим операциям, разбор партнёра мне не виден, повод партнёра мой не закрывает; (б) семья без ИИ — «Разбор» с
   карточками кода, запроса нет; (в) кнопки: «Разобрать» людей → лист раздела → `OpSheet` «Кому → что» → карточка ✓;
   «Отметить разовой» → разовая → карточка исчезает при новом открытии, «обычно» не тронуто; «В платежи» → платёж заведён;
   (г) имя человека из перевода не уходит в тело `aiReview`; (д) Х-8 — метка мечты без имени чужого раздела; (е) viewer —
   отчёта v4 нет.
3. **Доки:** `Privacy.vue` / лист согласия — если текст «что уходит» перечисляет советы v3 — поправить на v4 (без поднятия
   версии согласия, FB-16); `frontend/README.md` (разбор v4 — где карточки, где модель); §6 бэклога — строка «После 4б».

## Критерии приёмки

- Таблица замера в Handoff с ценой ₸ за разбор по трём моделям и браком; рекомендация названа; ни имён, ни сумм семьи.
- e2e зелёные; `cd frontend && npm run build && npx vitest run`, `cd backend && go build ./... && go vet ./... && go test ./...`.

## Вне скоупа

- Включение модели на проде и деплой — клинап через оркестратора после «да» владельца (вопрос перечисляет модель и цену).
- Новые виды карточек по итогам замера — хвост, не правка.
