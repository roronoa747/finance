# FB-22 — Ошибка: «Назад» гоняет по кругу «Цифры» ↔ «Настройки» (фронт)

Блок 4 · часть 4в (M без `/ux`, деплоится раньше остального блока) · Каталог: `frontend/src/components/AppShell.vue`
(`goBack`), `frontend/src/router/index.ts`, `frontend/e2e/` · Зависит от: — · Роли: владелец-админ (ссылка «Цифры» видна
только `authStore.admin`)

## Контекст (что уже есть)

- Владелец, 2026-10-22: «иногда зацикленность — „Цифры“ и „Настройки“, невозможно прервать цикл повторений этих двух
  меню, пока не обновишь страницу». «Цифры» — экран `/admin` (`views/Admin.vue`, заголовок шапки — `AppShell.vue:126`);
  вход — строка внизу «Настроек» (`views/Settings.vue:167`, `RouterLink to="/admin"`).
- Своих переходов у `Admin.vue` нет. Уходят с обоих экранов кнопкой «Назад» шапки — `goBack()` (`AppShell.vue:102`):
  есть `history.state.back` → `router.back()`, иначе `router.push` к корню (`/admin` и `/settings/me` → `/settings`,
  остальные → `/`).
- **Гипотеза оркестратора (проверить, не принимать на веру):** если у записи `/admin` нет `back` (экран открыт первым в
  вкладке, после `replace`, холодный запуск PWA на последнем адресе и т. п.), «Назад» делает `push('/settings')` — у новой
  записи `/settings` `back = '/admin'`; «Назад» на «Настройках» → `router.back()` → снова `/admin` без `back` →
  `push('/settings')` → круг. `push` вместо возврата добавляет записи и обрезает «вперёд», поэтому выйти нельзя, пока
  перезагрузка не сбросит историю. Возможен и другой путь — найти по воспроизведению.

## Задача

1. Воспроизвести в браузере (стенд, Chrome 390; админ — `ADMIN_EMAILS` стенда) и записать в Handoff точные шаги, при
   которых «Назад» не выводит из пары «Цифры» ↔ «Настройки». Если гипотеза не подтвердилась — найти настоящую причину.
2. Починить минимально, без новой абстракции навигации: «Назад» с любого экрана за конечное число нажатий приводит к корню
   вкладки («Настройки» → «Мечты»), и ни один экран не возвращает на тот, с которого на него пришли «Назад»-ом.
   Ожидаемое направление: «Назад», уходящий к родителю без истории, — `replace`, а не `push`, либо «Назад» на
   «Настройках» не ведёт «назад по истории» на дочерний экран (`/admin`, `/settings/me`). Решает исполнитель по причине.
3. Проверить ту же пару «Свой кружок» (`/settings/me`) ↔ «Настройки» — у неё та же ветка `goBack`.

## Тесты

- DOM/юнит на `goBack`: `/admin` без `back` → «Назад» → «Настройки» → «Назад» → «Мечты» (не `/admin`); то же для
  `/settings/me`; обычный путь «Мечты → Настройки → Цифры → Назад → Назад» — как был.
- e2e `fb-block4-back-loop.test.ts` по воспроизведённым шагам.
- Мутант: вернуть прежний `goBack` — тест красный.

## Критерии приёмки

- Шаги владельца из Handoff на стенде: из «Цифр» и «Свой кружок» «Назад» выводит на «Мечты» без перезагрузки страницы;
  обычная навигация «Назад» по остальным экранам не изменилась (весь e2e зелёный).
- `cd frontend && npm run build && npx vitest run` зелёные.
