## Задача

1. На выписках владельца (локально, скриптом в scratchpad или временным тестом вне git) посчитать, что код **уже** находит
   (все виды v3) и чего не находит, но видно глазами: кандидаты инсайтов — не меньше 8, например: «куда растеклось» по
   неделям/дням недели; пики (день, когда ушло больше всего и на что); перевод людям как доля трат; доля наличных; «что
   выросло 2 месяца подряд»; «план не менялся N месяцев при другом факте»; «подписки без использования»? (нет данных —
   отметить); «импульсные» покупки (крупная покупка в выходной в разделе без плана); «первые дни после зарплаты»; сравнение
   с «обычно» по неделям; «мечта: сколько месяцев при текущем темпе»; «если убрать X — на сколько раньше» (есть).
2. Для каждого кандидата: считает код или нужна модель; какое **действие с призывом** (одна кнопка: «Сделать» со сдвигом
   плана / «Поставить план» / «Отметить разовой» / «В платежи» / «Открыть») — не «посмотреть»; где показывать (отчёт,
   строка раздела, «Неделя»); частота; цена за нажатие в ₸ при модели (2–3 модели) и 0 ₸ для кода.
3. Собрать ≤ 5 вариантов состава разбора v4 (от «только код, без модели» до «модель выбирает и формулирует»), у каждого —
   макет карточки 390 px с вымышленными названиями и округлёнными долями, цена за разбор и в месяц на семью, риск брака.
   Отдельный вопрос артефакта: отчёт ИИ при партнёрском виде (Р-18) — семейный как есть / свой у каждого / семейный без
   названий продавцов партнёра.
4. Рекомендация составителя-исследователя одной строкой; артефакт — Artifact (приватный), ссылка в Handoff; **данные
   семьи в артефакт не класть** (Р-20).
5. Решение владельца оркестратор записывает в `memory/decisions/fb-review-v4.md`; затем `/backlog Фидбек` «дозаполнить
   Блок 4» (§5) заполняет FB-15…FB-17.
