  1. **FB-09: сумма формы — не той подписки, у которой нажали.** У продавца владельца три подписки разной цены каждый
     месяц (один продавец, `groupKey` один). `recurringOf` берёт `detectRecurring` по всей группе — одна медиана всех строк:
     нажатие «В платежи» у самой дорогой строки открывает форму с суммой средней подписки; «Добавить» отмечает месяц
     дорогой строкой (`amount` отметки ≠ сумме платежа), а следующие выписки по правилу продавца будут отмечать другую
     подписку. Критерий «лист открыт с суммой … этого списания» не выполнен на данных владельца (это и есть его сценарий

     синка у всех — старые «Разовые», строка раздела без снятой траты. Стенд: снял на первом телефоне — после
     переоткрытия у него, второго телефона и партнёра «Разовые» прежние, на сервере `oneOff` при `oneOff: null` в правке.
     Там же: итог ручной разовой «Подарки» на сервере стал `amount 0, ops 0, oneOff N` (нулевая запись со второго телефона

     `oneOff: 0` явно (и в нулевой записи), `sameTotal`/`oneOffOf` считают 0 = нет. Тест — (а2).

     после любой отметки, обнулившей `unmarked`, — вероятно, и на проде), но ломает критерий FB-09 «строка не трата».
