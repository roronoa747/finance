## Задача

1. Вынести построение записи из `shiftAccountAmount` `:1436-1439` в локальную функцию стора (например
   `newAccountShift(accountId, amount, meta, t): AccountShift` — `id`, `by` — слот телефона, `date: meta.date ?? todayIso()`,
   `goalId` при наличии). `shiftAccountAmount` использует её; поведение без `meta` — прежнее (без записи).
2. `applyPrepayment`, **семейный счёт**: внутри того же `mutateHouseholdDoc` `:1832-1833`, рядом со сдвигом `acc.amount + took`,
   — `doc.accountShifts = [...(doc.accountShifts ?? []), newAccountShift(acc.id, took, { kind: 'goal-out', goalId }, t)]`.
   Одна запись на фактический сдвиг счёта (`amount = took`, сумма одного перевода «с депозита»); `goalId` — только если
   `takes.length === 1`, иначе без `goalId`. Документ по-прежнему меняется одной мутацией.
3. `applyPrepayment`, **личный счёт** `:1835`: `shiftAccountAmount(record.accountId, took, { kind: 'goal-out', goalId })` — те же
   правила `goalId`. `took = 0` → как раньше (ни сдвига, ни записи). Сигнатура `applyPrepayment`, `settlePlan`, `removePrepayment`,
   типы — без изменений (новых `kind` не вводить).
4. UI не меняется. В Handoff — цифры сценария стенда (без данных семьи).

## Тесты

- `stores/finance.test.ts`, describe «клинап: вложить уже накопленное» (`:1844`): после `applyPlanStep` с `lump` —
  `store.accountShifts` содержит ровно одну запись `{ accountId: 'card', amount: 150_000, kind: 'goal-out', by: 'a' }` без
  `goalId` (две цели) с сегодняшней датой; план с одной целью на паузе → `goalId` этой цели; `lump: 0` / `PrepaySheet`-путь без
  `planId` → записей нет; личный счёт (`privateDoc.accounts`) → запись в `privateDoc.accountShifts`, в семейном — нет; запись и
  движения целей — в одной мутации (один `rev`/вызов `mutateHouseholdDoc` — через spy, как в соседних тестах, если есть
  образец; иначе — проверить, что после мутации и запись, и движения уже на месте без второй).
- e2e `e2e/fg-block3-tails.test.ts` (сценарий через экраны, `fakeServer` + `phone`): семья A, карта для трат 2 000 000, кредит с
  процентами, цели с накопленным; план «Сначала долги» с `lump` (через `choosePlan`, как в `pv-block3`, или через «Копить или
  гасить?» → «Вложить уже накопленное» → выбрать) → зарплата пришла → распределение с шагом долга (`writePlan`) → «На карте» =
  2 000 000 − шаг + `took`; выписка карты: строка −шаг (досрочка банку) и приход +`took` «с депозита» в пределах 5 дней → «На карте»
  **не меняется** от строки `+took` (до правки — выше на `took`); вторая такая же строка прихода → доход (вычитается из
  «потрачено», как обычный приход); партнёр B видит ту же цифру. Один сценарий — карта одного хозяина (`spendBy` a), шаг вносит B
  со своего телефона → приход в выписке A считается один раз.
- Мутанты (откат копией файла, в Handoff): (1) семейный путь без записи → юнит + e2e красные; (2) личный путь без `meta` → юнит
  красный; (3) запись с `kind: 'goal-in'` / `amount: -took` → e2e красный (знак не совпал — пары нет); (4) запись по каждой цели
  вместо одной → юнит красный.

## Критерии приёмки

- Стенд (семья из двух на моках, Chrome 390, обе темы — регрессия «На карте» / «Капитал»): план с «Вложить уже накопленное» →
  зарплата → шаг долга → на сервере `householdDoc.accountShifts` запись `goal-out` +`took`, `by` — слот телефона, сегодняшний день;

  Личный счёт: запись в `privateDoc`. Viewer: план не выбирает, записей не пишет (как раньше). Экраны не изменились.
- `cd frontend && npm run build && npx vitest run` зелёные (весь набор, включая e2e Блоков 2 и `f2-block3-*`); бэкенд не
  тронут (иначе `go build ./... && go test ./...`).

## Вне скоупа

- `removePrepayment` — запись `goal-out` не хоронит: деньги с целей на карте остались, перевод в выписке придёт — пара нужна.
- Миграция прошлых досрочек из целей (до блока) — нет; они сверятся ближайшей сверкой карты (как взносы до Блока 2).
- Новый `kind` в `AccountShift`, `planId` в записи, показ записей на экранах, сверка личных счетов — нет.
- Прочие осознанные ограничения Блока 2 (общая карта «оба»: записал один, перевод в выписке другого; запись на фактическую
  дельту при обрезке у нуля) — не трогаем.
