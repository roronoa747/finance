# FG-18 — Досрочка со счёта ↔ строка выписки: «−шаг банку» не вычитается из «На карте» второй раз (фронт)

Блок 3 · MVP · Репо/каталог: `frontend/src` · Зависит от: FG-17 (в ветке) · Роли: участник (свои операции), viewer (нет)

Хвост **FG-Х5** (исполнитель Блока 3, 2026-10-26; подтверждён критиком; судьба — владелец 2026-10-26, «добавить в Блок 3,
выкатить вместе»): досрочка со счёта (`Payment` `kind: 'prepay'` с `accountId`) **уже уменьшила остаток** (`accountBalance`),
а строка «−сумма» того же перевода в выписке **вычитается ещё раз** (`spentSince`): «На карте» ниже правды на сумму досрочки
до ручной сверки. Отметки `markedOps` досрочку не знают (в них — платежи по графику и живые `opId`), пары сдвигов `shiftedOps`
(FG-15) — только записи `AccountShift`. Путь частый: шаг плана «Сначала долги» каждый месяц (`writePlan`) и «Внёс досрочно»
(`PrepaySheet`). С FG-17 в месяц старта плана с «вложить накопленное» карта после выписки ниже на **весь шаг** (стенд
исполнителя: 1 900 000 → 1 650 000 при строках −250 000 и +150 000). Тот же класс, что F2-Х1 / FG-15 / FG-17; режим блока
**M** (Р-4: счёт денег); данных и миграций нет (Р-10); экраны не меняются.

## Контекст (что уже есть)

  живые платежи этого счёта после якоря (`countedPayments` `:1570-1584` — досрочки все живые, без «одна на месяц»;
  `afterAnchor(p, a.amountSetAt)` `:1604` — `p.at >= anchor`) и потраченное хозяев `spentOn` → записи `AccountSpent`. Потраченное
  пишет `writeAccountSpent(marked)` `stores/operations.ts:476-504`: `spentSince(all, counted, since)` (`lib/finance.ts:1654-1665`:
  строки после дня якоря, кроме `counted`; списание не-`internal` — `spendOf` `model.ts:411`, `internal` — `-amount`, приход —
  минусом). `counted = marked ∪ shiftedOps(all, shifts, sole ? null : by, marked)` `:490-492`: `shifts` — живые `AccountShift` этого
  счёта (`finance.accountShifts`), `sole` — `spendOwners(acc).length === 1` (карта одного хозяина → сдвиги любого телефона, «оба» —
  только свои `by`). `marked = totalMarks(list).marked` `:642-644` = `markedOps` — **тот же набор идёт в итоги разделов**
  (`SpendTotal.unmarked`), в него пару класть нельзя (решение FG-15).
- **Пара сдвигов** — `shiftedOps(ops, shifts: AccountShift[], me: PersonId | null, skip)` `lib/statements/matching.ts:202-220`:
  живые сдвиги `me` (или любые при `null`) по дате; каждому — ближайшая свободная строка той же суммы **со знаком** (тенге — ровно;

  берутся; вид строки не важен. От сдвига используются только `id`, `amount`, `date` (ISO-день), `by`, `deletedAt`. `todayIso`
  уже импортирован `:5` (`todayIso(new Date(x.at))` — образец `exchangeOfOperation` `:255`).
- **Досрочка** — `stores/finance.ts` `applyPrepayment(creditId, by, { amount, mode, accountId?, planId?, period? })` `:1791-1852`:

  `opId?` `:574` (у досрочки `opId` не бывает).

## Задача

1. `lib/statements/matching.ts`: пара «досрочка ↔ строка выписки» **тем же механизмом, что сдвиги** — не вторая функция
   сопоставления. Параметр `shifts` у `shiftedOps` расширить до структурного типа (например
   `type ShiftLike = Pick<AccountShift, 'id' | 'amount' | 'date' | 'by' | 'deletedAt'>`), поведение для `AccountShift` — прежнее.
   Добавить чистую функцию (например `prepaidShifts(payments: Payment[], accountId: string): ShiftLike[]`): живые платежи
   `kind === 'prepay'` с `p.accountId === accountId` и `p.amount > 0` → `{ id: p.id, amount: -p.amount, date: todayIso(new Date(p.at)),
   by: p.by }`. Досрочка с `accountId: null` («не списывать») или с другого счёта — не пара (остаток она не двигала / двигала другой
   счёт). JSDoc — одна строка: кто и зачем (FG-18, FG-Х5), образец — комментарий `shiftedOps` `:193-201`.
2. `stores/operations.ts` `writeAccountSpent` `:490-492`: `shiftedOps(all.value, [...shifts, ...prepaidShifts(finance.payments, acc.id)],
   sole ? null : by, marked)` — тот же `me` (карта одного хозяина — досрочка любого телефона: партнёр внёс с моей карты, строка в моей
   выписке; «оба» — только свои `by`), то же окно `DAY_WINDOW`, одна строка — одной досрочке, строки `marked` не берутся. **Только
   здесь**: `totalMarks().marked` и итоги разделов не меняются (строка «−шаг» остаётся списанием своего раздела — как покупка мечты
   в FG-15). Наблюдатель `:1089-1092` (`writeTotals`, без `prepay`) не трогать.
3. `stores/operations.ts` наблюдатель счёта для трат `:1150-1155`: в подпись добавить id живых досрочек этого счёта
   (`finance.payments`, `kind === 'prepay'`, `accountId === a.id`, без `deletedAt`) рядом с id сдвигов — новая или снятая досрочка
   пересчитывает потраченное (выписка загружена раньше, чем отмечена досрочка; «Снять» досрочку → строка снова списание).
4. `lib/finance.ts` ничего не считает по-новому (`spentSince`, `accountBalance` как есть). `stores/finance.ts`, типы, UI — без
   изменений; новых полей у `Payment` / `AccountShift` не вводить. Handoff: цифры стенда (без данных семьи) — до/после выписки с
   обеими строками, что видит партнёр.

## Критерии приёмки

- Стенд (семья из двух на моках `8303`/`5303`, Chrome 390, обе темы): план с «Вложить уже накопленное» → «Отложил» шаг → «На карте» и
  строка карты в «Капитале» = одно число; выписка со строками −шаг и +took → число **не изменилось**; у партнёра — то же; строка
  −шаг осталась в «Месяц → Траты» своего раздела. «Внёс досрочно» из листа кредита → выписка со строкой −сумма → «На карте» не
  изменилась; «Снять» досрочку → строка снова списание, «На карте» **та же** (остаток вернулся, строку банка вычла трата — по банку
  деньги ушли); без строки в выписке «Снять» → карта выше на сумму. Viewer не пишет (как раньше). Экраны не изменились.
  *(критик, 2026-10-26: было «"Снять" → карта выше на сумму, строка — списание» — при загруженной строке одно исключает другое; верен
  e2e п. 2 «Тестов», «карта выше» при строке — это поведение без наблюдателя п. 3, мутант 5)*
- `cd frontend && npm run build && npx vitest run` зелёные (весь набор: `f2-block3-*`, `fg-block1-*`, `fg-block2-*`, `fg-block3-*`,
  `pv-*`); бэкенд не тронут (иначе `cd backend && go build ./... && go test ./...`).

## Вне скоупа

- Итоги разделов (`totalMarks`, `SpendTotal`): строка «−шаг» остаётся списанием раздела — владелец 2026-10-26 («итоги разделов не
  трогать»); показ досрочки в «Тратах» месяца иначе — хвост, если понадобится.
- Ручная сверка «это та досрочка?» в UI, `opId` у досрочки, показ пары в листе операции (как FG-15).
- Якорь: досрочка до сверки, строка после новой сверки — пара всё равно берётся (как сдвиги Блока 2, e2e `fg-block2` A).
- Общая карта «оба»: досрочку записал один, строка — в выписке другого → вычтется (правило FG-15 «чужой сдвиг не берётся»).
- Строка досрочки, совпавшая суммой с платежом кредита по графику (`matchCandidates` задаёт вопрос «это платёж по …?») — прежнее
  поведение сопоставления, не трогаем.
- Личные счета и валютные досрочки (`PrepaySheet` — только тенговые счета) — нет; `SalaryRow` (FG-Х6) — хвост.
