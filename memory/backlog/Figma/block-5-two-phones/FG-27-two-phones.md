# FG-27 — Второй свой телефон с несвежими операциями не откатывает запись потраченного со счёта (фронт)

Блок 5 · MVP · Репо/каталог: `frontend/src` · Зависит от: — (Блок 3 на проде) · Роли: участник (свои записи); viewer не пишет

Хвост **FG-Х7** (приёмка Блока 3, 2026-10-26; судьба — владелец 2026-10-26: «отдельной задачей режима M»). Тот же человек на
двух устройствах / в двух вкладках: телефон с **несвежей копией своих операций** получает документ семьи фоном
(`BACKGROUND_SYNC_MS` 60 с — тянет только документ, не операции), наблюдатель счёта для трат просыпается и пересчитывает
`accountSpent` **по своим старым операциям**, затирая запись свежего телефона; свежий при своём синке пишет обратно — «На карте»
прыгает (стенд приёмки: взнос партнёра в цель и досрочка партнёра — 112 500 → 12 500 → 112 500). Класс — FG-15 (уже на проде) и
FG-18. Режим **M** (Р-4: запись денег); данных и миграций нет (Р-10); экраны не меняются.

## Задача

1. **Наблюдатель счёта для трат** (`:1142-1160`): перед пересчётом по сигналу документа — убедиться, что свои операции свежие:
   `void pull().then(() => { if (all.value.length && pulledOk) writeAccountSpent(totalMarks(all.value).marked) })`. Смысл:
   (а) успешный `pull` подтягивает выписку, загруженную с другого своего телефона, — запись считается по тем же операциям, что у
   него; (б) телефон, у которого в этой сессии не было ни одного успешного `pull` (`pulledOk === false`: новый вход, офлайн со
   старта), **не пишет** — запись другого устройства важнее нуля/старья; (в) офлайн после успешного `pull` — документ фоном всё
   равно не придёт, а свои действия (сдвиг рукой, досрочка) пишутся по локальной копии, как раньше. Демо и viewer — `pull`
   возвращает `[]` сразу: демо пишет по локальной копии (у него нет сервера), viewer не пишет.
2. **Частые срабатывания**: `pull` и так сериализован; добавить дешёвый порог — если `Date.now() - lastPullAt < PULL_FRESH_MS`
   (например 5 000), новый запрос не слать, а ждать идущий/считать копию свежей (`pulling`). Константа — рядом с
   `CURSOR_OVERLAP_MS`, одна строка JSDoc.
3. **Фоновый круг движка** (`syncEngine.ts` `sync()`): для участника (`auth.isMember`) вместе с документом тянуть и операции —
   `void useOperationsStore().pull()` (тот же порог п. 2 не даст дублей): документ и операции приходят одним кругом, наблюдатель
   п. 1 чаще находит копию уже свежей. Без сети — `pullOnce` выходит сам.
4. Чистые функции `lib/finance.ts` (`spentSince`, `accountBalance`), `lib/statements/matching.ts`, типы — **без изменений**; итоги
   разделов (`writeTotals`) и их наблюдатели — не трогать (вне скоупа). Handoff: цифры стенда (без данных семьи) — «На карте» у
   двух телефонов A до/после выписки и после фонового синка.

## Критерии приёмки

- Стенд (Go на моках `8305` + Vite `5305`, Chrome 390, обе темы): семья из двух, **две вкладки A** (один вход) + вкладка B; A1
  грузит выписку → «На карте» X; B вносит взнос с карты A → через фоновый круг (или фокус) у A1, A2 и B одно число X − взнос,
  запись `card:a` на сервере одна и не прыгает (смотреть документ семьи на моках через 2–3 круга); то же с досрочкой партнёра.
  Один телефон на человека — всё как раньше (регрессия Блоков 2–3: e2e `fg-block2-*`, `fg-block3-*`).
- `cd frontend && npm run build && npx vitest run` зелёные (весь набор); бэкенд не тронут (иначе `cd backend && go build ./... &&
  go test ./...`).
