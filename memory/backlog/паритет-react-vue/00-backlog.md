## 1. Цель

Вернуть во Vue всё, что семья потеряла при переносе с React (кроме нового входа партнёра):
расширенный калькулятор «копить или гасить», правку кредита, обязательства, покупок и
валютного счёта, честные расчёты (ставка «по сроку», инфляция, прогноз цели), тексты и
мелочи оболочки. И сделать калькулятор лучше React: выбранный план «Сначала долги» ведёт
семью месяц за месяцем, поставленные на паузу цели объясняют, почему стоят, а каждый платёж
по кредиту показывает, сколько ушло в долг и сколько банку. Успех: каждый пункт сверки
закрыт проверкой против React (файл:строка) и сценарием в `frontend/e2e/`; план проверен на
двух профилях; данные прода не потеряны ни одним деплоем.

Режим процесса: **M**; блоки 2 и 3 — **L** (деньги: якоря и отметки Блока 1 RP, бюджет,
досрочки; ревью — `frontend`). Деплой после каждого блока (Р-17).

## 2. Зафиксированные решения

- **Р-1. Скоуп** — все пункты А сверки, кроме А-10; все пункты Б (Б-12…Б-22); три хвоста §4
  `развитие-приложения` — закрытый кредит в плане, кит окон (Н-9, Н-10, подпись `Field`), тема
  на старте; новое — выбранный план и разбивка «в долг / проценты» с графиком. **Не-скоуп:**
  А-10 и «по коду без сессии» (хвост «новые семьи» в `memory/STATE.md`); `mergeObligation`
  (хвост §4 RP); Отбасы в плане (RP-23); бэкенд. **После MVP:** —.
  *(ответ владельца, раунды 1–2)*
- **Р-2. Эталон — React `src/`** (файл:строка — в сверке): поведение, поля, тексты и выводы как
  в React; вид — паттерны Vue и кит (Р-29 RP), цвет только из токенов. React `src/` не
  трогать («Уборка старого» — отдельная S-задача, Р-2 RP). *(дефолт)*
  **Исключения (владелец 2026-09-25, `memory/decisions/r2-exceptions-pv-block2.md`):** раздел в
  модалке обязательства; «в месяц / за год» у годового обязательства — по реальной доле.
  **Исключение (владелец 2026-09-25, `memory/decisions/r2-exception-goal-monthly-input.md`):**
  «Откладывать в месяц» на экране цели — полем ввода вместо ползунка (PV-19 п. 5).
- **Р-3. Калькулятор возвращается целиком:** горизонт «год/два/три», «Что не останавливать»,
  «Сначала подушка», «Вложить уже накопленное», «без процентных долгов через N мес.», вывод в
  обе стороны («копить выгоднее на…»), заметка о беспроцентных. Расчёт — `simulateStrategy`
  (`finance.ts`, перенесён построчно), остатки — производные из записей Блока 1 RP
  (геттер `financeStore.credits`), закрытые кредиты не участвуют. *(ответ владельца, раунд 1)*
- **Р-4. «Выбрать этот план» — план ведёт каждый месяц.** План хранится в общем документе, его
  видят оба. Отмеченные цели показывают «На паузе ради плана» с переходом к плану и
  объяснением. Их взносы в Бюджете и «Свободно» становятся строкой «Досрочно по плану». Каждый
  месяц план называет одну сумму досрочки в самый дорогой процентный долг, её вносят одним
  нажатием через досрочку Блока 1 RP (счёт — по Р-5 RP). Пропущенный месяц не упрекает: план
  пересчитывается от факта, дата закрытия сдвигается. *(ответ владельца, раунд 2)*
- **Р-5. Конец плана.** Закрыт самый дорогой долг — его платёж идёт в следующий по ставке.
  Закрыт последний долг с процентами — цели снимаются с паузы сами, план уходит в историю с
  итогом «сэкономили N ₸ процентов». Отменить план можно в любой момент: цели возобновятся,
  история останется. *(ответ владельца, раунд 2)*
- **Р-6. Экран плана:** план и факт по месяцам; что не ушло в цели (по каждой цели на паузе —
  сумма и сдвиг даты); выигрыш против «копим как сейчас» (прогноз на момент выбора и факт по
  досрочкам); шаг плана в «Ритуале» и в строке кредита вместо `credits[0]`.
  *(ответ владельца, раунд 2)*
- **Р-7. Подушка в плане — цель, отмеченная при выборе.** Взносы в неё не останавливаются.
  Пока в ней меньше месяца обязательных списаний, шаг плана — пополнить её. Цели нет — план
  предложит её завести. «Ритуал» больше не угадывает подушку по слову «подушка» в названии.
  *(ответ владельца, раунд 3)*
- **Р-8. Разбивка «в долг / проценты»** (`creditSplit`, снимок `Payment.principal`): строка
  кредита — следующий платёж; отметки «Оплатил» и досрочки — с итогом за всё время; Бюджет —
  «из них проценты банку N ₸ в месяц»; график платежей по кредиту, при активном плане — с
  досрочками. *(ответ владельца, раунд 2)*
- **Р-9. Пауза цели выводится из активного плана и не хранится в цели.** `Goal.monthly` не
  переписывается, отмена плана не правит цели. План — запись с id в новом списке верхнего
  уровня `SyncDoc.plans` (`defaultSyncDoc`, явно в `mergeDocs`, Р-14 RP). Активный план один,
  завершённые остаются историей. Если двое выбрали разные планы офлайн, побеждает поздний.
  *(дефолт)*
- **Р-10. Досрочка по плану — по умолчанию «сократить срок»**, как считает `simulateStrategy`:
  платёж не меняется, и хвост «снизить платёж по LWW» не разрастается. Режим можно сменить в
  окне досрочки, план пересчитается от факта. *(дефолт)*
- **Р-11. Хвост §4 RP «досрочка при платеже меньше процентов» (`lumpPlan` → null) — в блок
  плана** (PV-14). Иначе план назначит шаг в долг (кредитку с минимальным платежом), который
  нельзя применить. *(дефолт)*
- **Р-12. viewer не выбирает и не отменяет план**, форм правки не видит (как Р-13 RP). *(дефолт)*
- **Р-13. Кит окон:** `Sheet`, `Select`, `Row` со слотом действия, токен затемнения, подпись
  `Field` без обёртки групп кнопок. Все новые и возвращённые окна строятся на ките. Старые
  копии переводятся на кит только на экранах, которые блок и так трогает.
  *(ответ владельца, раунд 1)*
- **Р-14. Испорченные данные правим руками в вернувшихся формах**, скрипта нет. Приёмка
  Блока 2 (с «да» владельца, прод только на чтение) выписывает подозрительные записи:
  обязательства `d4` без оценки, кредиты под 0%, цели с минусом. *(ответ владельца, раунд 3)*
- **Р-15. Контракт Go не меняется.** Ошибки входа (Б-13) переводятся на фронте по текстам Go.
  *(дефолт)*
- **Р-16. Календарные границы плана** (месяц шага, пропуск) — по Asia/Almaty, хелперы
  `today()` / `monthKey()` из `lib/dates.ts` (Р-30 RP). *(дефолт)*
- **Р-17. Порядок и деплой.** Старт — после 🏁 Блока 1 `развитие-приложения`. Блок 2 RP ждёт 🏁
  последнего блока паритета. Деплой — после каждого блока. Ветки — `pv-block-N-<тема>` от
  `main`, ID задач — `PV-NN`. *(решение владельца в сверке 2026-09-24; порядок — раунд 3;
  ветки и ID — дефолт)*
  **Уточнение владельца 2026-09-24 (ночной прогон):** роли Блока 1 идут ночью подряд
  субагентами. Ветка `pv-block-1-calculator` берётся от `rp-block-1-payments` **после** клинапа
  Блока 1 RP (без деплоя), а не от `main`. Приёмка Блока 1 **ночью не деплоит**. Утром с
  владельцем: деплой Блока 1 RP (перезапуск PWA на обоих телефонах, смоук) → деплой Блока 1
  паритета → 🏁. Push веток `pv-block-*` ради CI разрешён; в `main` — ничего без владельца.
  Подробно — §5.
- **Р-18. Судьбы хвостов §4 `развитие-приложения`** (проставлены составителем 2026-09-25):
  «потери переноса», Н-9/Н-10 (кит), «тема на старте», «закрытый кредит в плане» → этот бэклог
  (PV-01, PV-08, PV-09; RP-12 закрытый кредит больше не делает); «по коду…» + А-10 → хвост
  «новые семьи» в `memory/STATE.md`; «досрочка при платеже меньше процентов» → PV-14 (Р-11);
  «Что уже есть» в ТЗ RP-23 переписывает критик Блока 3: калькулятор и план — факт, Отбасы
  встраивается в план. *(раунд 1 + дефолт)*
- **Р-19. Инфляция — одна константа `INFLATION = 0.102` в `frontend/src/lib/finance.ts`.**
  В React это была настройка устройства без UI (`defaultSettings.inflation`, `useStore.ts:144-149`),
  то есть фактически константа; во Vue настроек нет (`Settings` в `types/finance.ts:299` не
  используется). Стор настроек и поле в документе не заводим (правило 10). Читают `Deposit.vue`
  и `GoalDetail.vue`. *(дефолт составителя — владелец согласился 2026-09-25)*
- **Р-20. Оформление остаётся делом устройства** (как в React: «В общий документ не
  попадает»): тема, акцент и «Цвета разделов» — `localStorage` (`ff_theme`, `ff_accent`,
  новый ключ для цветов разделов), в `SyncDoc` не пишутся. *(дефолт составителя — владелец
  согласился 2026-09-25)*
- **Р-21. Калькулятор — отдельный компонент `components/StrategyCompare.vue`** (граница как в
  React `StrategyCompare`), а не ещё 150 строк в `Capital.vue` (уже ~1 750 строк): так его
  можно SSR-тестировать с нужным состоянием. Чекбоксы — нативный `<input type="checkbox">` с
  токенами внутри компонента; в кит не выносить, пока нет третьего места.
  *(дефолт составителя — владелец согласился 2026-09-25)*
- **Р-22. «Пропустить» в мастере — флаги пропуска шагов при сохранении в `finish()`**, а не
  посчаговое сохранение React: во Vue `joining`/`steps` — `computed`, и запись на шаге жилья
  схлопнула бы шаги до `['income']` (React замораживал их через `useState`). Введённое в полях
  остаётся, но не пишется. *(дефолт составителя — владелец согласился 2026-09-25)*

  без запросов. Viewer: `useAuthStore().isViewer` — форм и кнопок правки нет; сервер и так
  отвергает push (403).
- **Производные остатки (RP-06):** геттеры `financeStore.credits` / `accounts` /
  `householdAccounts` отдают копии с `principal` / `amount` = база − отметки после якоря
  (`creditBalance(c, payments)`, `accountBalance`). **Никогда не звать `creditBalance` /
  `accountBalance` на результате геттера — вычтет отметки второй раз.** Сырой
  `householdDoc.credits[i].principal` — база на момент ручного ввода; якоря
  `Credit.principalSetAt`, `Account.amountSetAt` ставит только ручной ввод остатка
