## Задача

1. Форма «Подписка или обязательство»: «В какой раздел бюджета» (кнопки из
   `financeStore.categories` без d3/d5; пустой список → запасные имена из одной константы
   `DEFAULT_CATEGORY_NAMES`, которую использует и `setCategoryAmount`), флажок «Сумма плавает —
   показывать как оценку», подсказка про годовую сумму (число — `finance.ts`). Дефолты как
   React (`d4`, оценка снята).
2. Модалка обязательства на `Sheet`: все поля React (название, сумма сейчас с полным текстом
   подсказки, день, как часто, месяц (сетка `MONTHS_NOM`), «Чьё это», оценка); планирование —
   placeholder `plain(current)`, autofocus, разница с годовой суммой, подсказка о месяце,
   очистка поля после «Запланировать»; «История суммы» по правилу React; `SavedMark`
   (`useSavedMark`); текст удаления React. `PaidRow` пересчитывает `obligationDue` после правки
   дня/периодичности/месяца.
3. `updateObligation` — `unchanged()`-защита (RP-01). Разница «в месяц / за год» — `finance.ts`.
4. Viewer: полей и кнопок нет; история и цифры видны.

## Критерии приёмки

- Браузер: завести «Интернет» в «Еда и быт» без оценки → подписка (вопрос «Оставить?» по
  правилам RP-09); завести коммуналку с оценкой → отметка спрашивает сумму; поправить день и
  «Чьё это» у аренды → Бюджет и второй профиль обновились; история суммы после планирования
  показывает две строки.
- `cd frontend && npm run build && npm test` зелёные.
