## Задача

1. **Х-12 — порог доставки по сумме:** доставка — привычка месяца при сумме **от 20 000 ₸** (вместо «от 4 раз»);
   остальные привычки — по числу раз, как были. Константа рядом с `HABIT_MIN_PER_MONTH` (`lib/statements/habits.ts`).
2. **Х-11 — демо как настоящая выписка:** такси a ≈ 95 000 ₸ в месяц, доставка b ≈ 40 000 ₸ в месяц три прошлых месяца
   (итоги «Кафе» b — не меньше доставки). Прочие экраны демо (точка у «Кафе», «до плана», старые тесты) не сломаны.
3. **Х-9 — перенос запомнен:** «Перенести» пишет в общий документ запись `imageMoves` (раздел, мечта, сумма, кто, когда;
   id случайный — отмена = надгробие, как `planShifts`); «Отменить» в тосте снимает её. Пока у раздела есть живая запись
   на ту же мечту — у образа вместо кнопки тихое «✓ N в мечту» (`habitImages` → поле `moved`, кнопки нет). Новая
   мечта первой в очереди — кнопка снова есть. Поле — тип, дефолт `[]`, `mergeList` по id.
4. **Х-10 — одна плашка:** когда в листе раздела есть и плашка «до плана: +N в мечту …», и образ «N % мечты» той же
   мечты — образ с кнопкой (или ✓) внутри плашки, одной плашкой; другие образы — строкой, как были.

## Тесты

- `habits.test.ts`: доставка 3 раза на 20 000 — привычка, 5 раз на 15 000 — нет.
- `habitImages.test.ts`: запись переноса → `moved`, без действия; запись на другую мечту / надгробие — кнопка есть.
- `merge` — записи двух телефонов, надгробие сильнее; DOM — ✓ вместо кнопки, образ внутри плашки; e2e Блока 7 —
  перенос на телефоне 1 → ✓ у телефона 2, «Отменить» → кнопка снова.
- демо-тест: строки образов с новыми суммами.

## Критерии приёмки

- `cd frontend && npm run build && npx vitest run` зелёные (весь `e2e/`); Go не меняется.
- Браузер: демо 390 / 375 px, обе темы — «Кафе» → одна плашка с образом → «Перенести в мечту» → «Перенести» → ✓ на
  месте кнопки → (новый лист) «Отменить» в тосте → кнопка снова; «Транспорт» — образ такси с новыми суммами.
