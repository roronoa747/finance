# AU-27 — Привычки по операциям и их итоги в общем документе (фронт)

Блок 7 · MVP · Каталог: новый `frontend/src/lib/statements/habits.ts`, `stores/operations.ts`, `types/finance.ts`, `stores/finance.ts`, `lib/merge.ts` · Зависит от: Блок 2 🏁 · Роли: member (пишет свои итоги), все (читают)

## Контекст (что уже есть)

- Р-24: каждый телефон находит привычки по **своим** операциям; в общий документ уходят только итоги привычек (как
  итоги разделов); на экране — сумма семьи, участников не сравниваем. Р-30: образ — только привычке, которая держится
  3 месяца подряд; пороги частоты и сумм — константы в коде. Р-29: список привычек — в коде.
- Операции — личные (`Operation`, `lib/statements/types.ts`: `date` — день без времени, `amount` — минус у списания,
  `merchant` очищен, `categoryId`, `internal`; списание — `isSpend` `lib/statements/model.ts:275`), стор
  `useOperationsStore().all`; итоги разделов пишет `writeTotals(periods)` (`stores/operations.ts:355-383`, `spendTotals`
  `model.ts:282`) — образец «итоги своих операций → общий документ, без продавцов».
- Словарь продавцов (`lib/statements/dictionary.ts:83-94`): такси — `yandex go`, `yandex taxi`, `indrive`, `uber`,
  `taxi`, `такси` → `sc_transport`; доставка — `yandex eda`, `wolt`, `glovo`, `chocofood` → `sc_cafe`; кофейни и кафе —
  `coffee`, `кофе`, `кофейня`, `espresso`, `starbucks` и рестораны/фастфуд → `sc_cafe` (кофе от ресторанов словарь не
  отличает — нужен свой список). Помощник слов — `words(...)` там же.
- Настоящие выписки для сверки правил — `memory/secrets/statements` (не в git).
- Новое поле документа — по трём шагам §6 индекса.

## Задача

1. `lib/statements/habits.ts`: правила `HABITS` — `{ id, categoryId, test(op) }` для `taxi` (такси-сервисы),
   `coffee` (кофейни: свой список слов; чек ≤ 3 000 ₸), `delivery` (сервисы доставки еды), `lunch` (`sc_cafe` в будни,
   1 500–7 000 ₸, не кофе и не доставка), `marketplace` (маркетплейсы и Kaspi-покупки ≤ 5 000 ₸; список продавцов
   сверить по настоящим выпискам). Порог «привычки» в месяц — константы (дефолт: такси ≥ 8 поездок, кофе ≥ 10,
   доставка ≥ 4, обеды ≥ 8, маркетплейсы ≥ 10). Операция попадает не больше чем в одну привычку.
2. `habitTotals(ops, by, period)` → `HabitTotal[]` = `Tracked & { id: by:period:habit, by, period: 'YYYY-MM', habit,
   count, amount }` — только списания, без внутренних переводов; ниже порога — не пишется.
3. `SyncDoc.habitTotals?: HabitTotal[]` (слияние `mergeList` по id, LWW), запись — там же, где `writeTotals` (те же
   периоды, тот же «не писать одинаковое второй раз»); хранить 4 последних месяца на участника. Демо — локально.
4. Ничего, кроме счётчика и суммы, в документ не уходит (ни продавцов, ни дат).

## Тесты

- `habits.test.ts`: каждая привычка на наборе операций (такси Yandex Go и inDrive; кофе 1 200 ₸ — да, ресторан 9 000 —
  нет; обед в субботу — нет; доставка Wolt; маркетплейс 4 500 — да, 12 000 — нет); порог (7 поездок — нет, 8 — да);
  внутренний перевод — не трата; операция в одной привычке.
- Стор: загрузка выписки → итоги привычек в документе; повтор — без записи; партнёр видит итоги, продавцов — нет.
- На настоящей выписке владельца (обезличенно) — какие привычки нашлись и суммы — в Handoff.
