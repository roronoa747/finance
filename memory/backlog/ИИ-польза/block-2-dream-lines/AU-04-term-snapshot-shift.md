# AU-04 — Снимок срока и сдвиг мечты с причиной (фронт, `finance.ts` + документ)

Блок 2 · MVP · Каталог: `frontend/src/lib/finance.ts`, `types/finance.ts`, `stores/finance.ts`, `lib/merge.ts` · Зависит от: Блок 1 🏁 · Роли: member (пишет снимок), viewer и партнёр (читают)

## Контекст (что уже есть)

- Р-6: метка на карточке мечты — сдвиг срока в обе стороны («+2 недели · кафе выше плана», «на 3 недели ближе ·
  отложили больше»); снимок срока на начало месяца — в общем документе; причина — самый крупный вклад (взнос меньше
  плана, раздел выше плана, новый платёж); в первый месяц после выката метки нет. Р-18: `monthPlan` считает траты по
  плану, поэтому сдвиг меряется **деньгами этого месяца по факту** и переводится в дни `closerDays` (метка — от 7 дней,
  неделями).
- План месяца — `monthPlan(state, ctx)` (`finance.ts:3377`): очередь `queue[]` с `goalId`, `want` (просит), `given`
  (даёт план из остатка), `put` (уже отложено в этом месяце), `paused`. Траты участника `PlanSpend {by, plan, fact,
  rows}` (:3251); факт — `null`, если выписки месяца нет. Платежи месяца — `dues[]` (`MonthDue`, у каждого `targetId`,
  `name`, `amount`). Доход — `income.total`.
- Сравнение по разделам — `spendCompare` (AU-01): `rows[{categoryId, name, amount, plan}]` — даёт «какой раздел выше
  плана».
- Темп и дни: `goalPace(goal, key)` :2480, `closerDays(amount, pace)` :2490 (`amount / pace × 30,4`, целые дни).
- Документ: новое поле по трём шагам §6 индекса (`SyncDoc` → `defaultSyncDoc` → правило в `mergeDocs`); viewer пушить не
  может; демо — без сервера.

## Задача

1. **Снимок.** `SyncDoc.termSnaps?: TermSnap[]`, `TermSnap = Tracked & { id: 'YYYY-MM', at, income, dueIds: string[],
   goals: { goalId, given, doneMonth }[] }` — цели и фонды очереди месяца (`kind !== 'debt'`) с `given` и `doneMonth`
   плана, доход месяца и id платежей (`targetId`). Функция `termSnapOf(plan: MonthPlan, at)` — в `finance.ts`.
2. **Кто и когда пишет.** Стор `ensureTermSnap()`: участник (не viewer), месяц — текущий по Алматы, снимка месяца в
   документе **после подтягивания** документа нет → записать. Звать после успешного pull общего документа при старте и
   при смене месяца (тот же путь, где оболочка освежает документ); без сети — после первого pull. Демо — пишет локально.
   Хранить не больше 3 снимков (старшие — надгробия). Слияние: `mergeList` по id, при двух снимках одного месяца
   побеждает **ранний** `at` (снимок начала месяца, своё правило в `mergeDocs`).
3. **Сдвиг.** `dreamShift(state, ctx, snap, goalId)` → `{ days, reason, name? } | null`:
   - «сколько мечта получит в этом месяце» сейчас: `max(givenByFact, put)`, где `givenByFact` — `given` цели из
     `monthPlan`, посчитанного с тратами по факту: строка трат участника = `max(plan, fact)` (факт `null` — план).
     Добавить в `monthPlan` необязательный флаг контекста `byFact` (по умолчанию — как сейчас), а не копию функции;
   - `delta = snap.given − now` (> 0 — мечта получит меньше, срок дальше); `days = closerDays(|delta|, goalPace)` со
     знаком; `|days| < 7` или нет снимка/цели в снимке/темпа → `null`;
   - причина — самый крупный вклад в деньгах: дальше — `spend` (раздел выше плана: наибольший `amount − plan` по
     `spendCompare`, `name` — раздел), `due` (новый платёж: `dues`, которых нет в `snap.dueIds`, наибольший, `name`),
     `less` (прочее: доход меньше снимка, взнос меньше — остаток `delta`); ближе — `put` (отложили больше: `put −
     snap.given`), `freed` (платёж ушёл из месяца), `income` (доход больше).
   - Подпись `shiftLabel(shift)` рядом: «+2 недели · кафе выше плана» / «на 3 недели ближе · отложили больше» (недели —
     `round(days / 7)`; ≥ 9 недель — месяцы); слова причин — константы, финал — `/ux`.
4. Цели, заведённые после снимка, на паузе (`paused`) и сбывшиеся — без метки.

## Тесты

- `finance` (новый `dreamShift.test.ts`): `termSnapOf` по плану семьи; кафе выше плана на 30 000 при взносе 60 000 →
  `days ≈ +15`, причина `spend` «Кафе…»; новый платёж → `due` с именем; отложили сверх плана → отрицательные дни,
  `put`; сдвиг < 7 дней → `null`; цель без снимка → `null`; `byFact: false` — `monthPlan` прежний (регрессия
  `monthPlan.test.ts`).
- `merge.test.ts`: два снимка одного месяца → ранний `at`; > 3 → старшие надгробия.
- Стор: участник без снимка месяца → записан один раз; viewer — не пишет; повторный вызов — без записи.
