## Задача

1. Тело: `{ reason: "month" | "salary" | "refresh", facts: [{id, about, value, raw}] (1…30), candidates: [{id, kind,
   about, value, effect}] (0…3) }`, строго (лишнее поле → 400); id фактов `f<N>`, кандидатов `c<N>`, без дублей; `kind` —
   `move|prepay|cushion`; строки ≤ 200 символов; ≤ 32 КБ.
2. Инструкция `reviewSystemV2` (рядом с прежней, прежнюю удалить вместе с v1-веткой): что изменилось за месяц и почему,
   через мечту / подушку / свободу от долгов; `good` и `risk` — по одному предложению до 14 слов; `step.text` — до 8
   слов; **ни одной цифры** — число только ссылкой `{fN}` на факт; `step.candidate` — id кандидата, если шаг про него,
   иначе `null`; без имён и сравнения участников; «мы».
3. Схема ответа: `{good, risk, step: {text, candidate}}`, `candidate` — `enum` из присланных id или `null`
   (`additionalProperties: false` на каждом объекте).
4. Проверка ответа: цифра `[0-9]` вне `{fN}` или ссылка на неприсланный id → брак → один повтор с названными нарушениями;
   кандидат вне списка → `null` (не брак). Затем подстановка `{fN}` → `value`; `CheckNumbers(подставленные тексты, тело
   запроса)` — брак → тот же повтор (если он ещё не был), иначе 502.
5. Ответ 200 `{good, risk, step: {text, candidate|null}}` — уже с подставленными значениями. Ничего из тела и ответа не
   логируется; сервер ничего не добавляет к присланному. Расход — `Spend` как сейчас.
6. README бэкенда — контракт ручки v2 (одним абзацем).
