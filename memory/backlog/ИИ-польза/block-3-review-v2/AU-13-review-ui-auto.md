## Задача

1. **Модель разбора v2.** `AiReview` + необязательные `v?: 2`, `reason?: 'month' | 'salary' | 'refresh'`, `reasonKey?`
   (`month:<YYYY-MM>` или `salary:<personId>:<YYYY-MM>`), `step?: { text, candidate: StepCandidate | null }`; `sent` —
   `ReviewPayload` (v2) или сводка (v1). Старые разборы читаются как были.
2. **`runReview(key, reason)`** v2: `buildReviewFacts` → `apiClient.aiReview({reason, facts, candidates})` → сохранить с
   кандидатом из `byId` по id ответа. Состояния и ошибки — прежние (`ai_limit` → «ИИ вернётся 1 <месяца>»; `ai_off` →
   `fetchMe`).
3. **Лист v2:** «Хорошо», «Риск», «Шаг» — текст и справа небольшая `secondary sm` «Сделать» (member, кандидат есть и
   ещё применим: эффект пересчитан `finance.ts` при открытии; неприменим — кнопки нет) → `DoSheet` с кандидатом
   (AU-06); после подтверждения лист разбора остаётся, кнопка — «✓ Сделано» (сдвиг с той же целью в этом месяце).
   «что ушло» — `factsLines`. v1-разбор — прежняя разметка (шаги-ссылки).
4. **Разбор сам** — `useAutoReview()` (вызывается из оболочки после успешного pull общего документа и после
   `markSalary` своей зарплаты): условия — `ai.available`, согласие `on` v2, сеть, не демо, текущий месяц, разбора с тем
   же `reasonKey` в документе нет; `salary` — только первая отметка `kind: 'salary'` участника в месяце (аванс и недели —
   не повод). Согласие v1 `on` → лист согласия v2 **один раз** в этот момент (закрыл без ответа — до следующего повода).
   Запрос в фоне, без «Думаю…» на экране; 429 / 502 / сеть — молча, повтор того же повода — не чаще раза в сутки на
   устройстве (ключ устройства в `LOCAL_KEYS`).
5. **Точка «новый разбор»:** разбор месяца есть и не открыт на этом устройстве (`ff_ai_review_seen`) → точка на
   сегменте «Месяц» (`PlanSwitch`, новый проп) и на вкладке «План» (`TabItem.dot?`); открыл лист — точки ушли; ✦ с точкой
   — как сейчас. Viewer — точка тоже (видит сохранённый).
6. «Обновить» — повод `refresh`, раз в сутки (прежнее правило).

## Тесты

- DOM `AiReviewSheet`: v2 — три блока и «Сделать» → `DoSheet`; viewer — без «Сделать»; кандидат неприменим — без
  кнопки; v1-разбор — прежние шаги; «что ушло» — факты.
- `stores/ai` / `useAutoReview` (фейковый клиент со счётчиком): месяц без разбора → 1 запрос, повторный вход — 0; разбор
  партнёра в документе → 0; «Пришла» своя первая → 1 (`salary`), вторая (аванс) → 0; «Не надо» → 0; v1 `on` → лист;
  офлайн → 0; 429 → тишина, без повтора в тот же день; демо → 0; viewer → 0.
- DOM `Tabs` / `PlanSwitch` / `AppShell`: точка при неоткрытом разборе, исчезает после открытия.

## Критерии приёмки

- `cd frontend && npm run build && npx vitest run` зелёные.
- Стенд с ключом (Go + БД, семья с флагом, 390 px обе темы): вход 1-го (подставить дату) → разбор пришёл сам, точка на
  «Плане» и «Месяце»; партнёр после синка — тот же разбор без запроса (Network); «Сделать» → `DoSheet` → план месяца
  изменился; viewer — без кнопок; «Пришла» → второй разбор (`salary`).
- Handoff по правилу 12: главное действие («Сделать») — у шага разбора; звать — точкой на «Плане»/«Месяце»; что скрыто
  («что ушло»).
