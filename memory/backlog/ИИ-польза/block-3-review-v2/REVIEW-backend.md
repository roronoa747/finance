## Проверено независимо (не по Handoff-у)

- **Старый лимит снесён полностью:** grep `AI_MONTHLY_LIMIT` / `.Used(` / `AIMonthlyLimit` по коду — только комментарий
  конфига «не читается», тест `TestOldRequestLimitNotRead` и строки README. `Spent` заменил `Used` и в SQL

  админку; админка отдаёт `limit_micros` (`admin_ai.go:46`).
- **Оплаченные неудачи приближают край:** `AIGate.Spend` (`handlers/ai.go:84-102`) пишет токены и при `ok=false`, запись —
  `context.WithoutCancel`. Тест `billed failure spends toward the limit` (`ai_test.go:449-468`): два брака у края → 502,
  `cost = limit + 6 000`, следующий → 429 без вызова модели.
- **Откуда берётся цена:** `Usage.Model` — это модель из env (`ai/ai.go:128`, `req.Model`), а не ответ API; неизвестное
  имя → `CostMicros` 0 (`ai/price.go:17-19`). Отсюда Н-1 — воспроизвёл временным тестом (удалён, дерево чистое).
- **Ручка v2:** порядок — гейт → строгое тело (`decodeStrictJSONBody`, 32 КБ) → `valid()` → до двух вызовов в общем окне 55 с
  (`reviewDeadline`; каждый ≤ `ai.DefaultTimeout` 45 с). Брак первой проверки (`defects`: ссылка на неприсланный факт, цифра
  вне `{fN}` и вне присланных «названий») и второй (`CheckNumbers` по подставленному тексту против `about/value/raw` и строк
  кандидатов) → один повтор с названными нарушениями → 502. Не-JSON и пустой блок — без повтора, но оплачены
  (`TestReviewBilledFailures`). В модель — только `id/about/value` фактов, кандидаты и повод (тест сравнивает тело целиком,
  утечек семьи/почты/даты нет).
- **Слова-числа (AU-33):** генерация порядковых «основа × окончание» не задевает частые слова (таблица «Пятница, мама, майка,
  марка…» — не брак); месяц словом без года — брак, если слова нет во входе; срок этого года, пришедший фактом «к декабрю»,

- **Конфиг:** «0», «-1», «abc», «2.5», «два» → $2; старое `AI_MONTHLY_LIMIT=50` ничего не меняет.

## Находки

### Н-1 · высокая · Модель вне таблицы цен выключает лимит в деньгах

`backend/internal/ai/price.go:16-20` + `backend/internal/handlers/ai.go:68-77`. `CostMicros` для модели, которой нет в `prices`,
возвращает 0 — так задумано для админки («≈ —», Р-14 «ИИ»). Но с AU-09 этот же `cost_micros` — единственный лимит: если в
`AI_MODEL_REVIEW` / `AI_MODEL_SELLERS` стоит имя не из таблицы (снимок с датой `claude-opus-5-5-20261001`, новая модель
`claude-fable-5-1`, опечатка регистра), `Spent` всегда 0 и `LimitReached` не срабатывает никогда. При лимите «30 запросов»
та же ошибка стоила максимум 30 запросов; теперь — сколько угодно, а «разбор сам» (AU-13) зовёт ручку без нажатия.
Проверил временным тестом в `handlers`: модель `claude-opus-5-5-20261001`, лимит $2 — 50 разборов подряд, все 200,
`{Requests:50 … CostMicros:0}`. Ни один тест этот случай не держит.

**Рекомендация.** Минимально и без нового env: в `price.go` модель вне таблицы для счёта стоит **как самая дорогая из таблицы**
(сейчас Opus 400/2000) — лимит срабатывает раньше, а не никогда; плюс один `log.Printf` при сборке роутера (`server.go`) для
каждой модели из конфига, которой нет в `prices` («цены нет — считаю по самой дорогой»), чтобы владелец увидел это в логах
Vercel. Тест: `CostMicros` неизвестной модели = цене Opus; гейт с неизвестной моделью у края → 429. Ветка «≈ —» в `Admin.vue`
для новых строк станет недостижимой — её судьбу решает ревью frontend/клинап (оставить для старых строк или убрать).
Р-14 «ИИ» («≈ —» для неизвестной модели) этим уточняется, а не пересматривается: Р-11 «ИИ-польза» сделал цену лимитом — в
Handoff клинапа записать как минимальное локальное решение.

**Вердикт: клинап** — защита денег, правка в одну функцию + строка лога + 2 теста.

### Н-2 · средняя · `&`, `<`, `>` в названиях уходят в модель экранированными

`backend/internal/handlers/ai.go:251` (`modelText` → `json.Marshal`). `json.Marshal` по умолчанию пишет `&` как `&`:
мечта «Дом & сад» доходит до модели как `«Дом & сад»` (проверил временным тестом). Инструкция велит писать названия «как
в about» — если модель перепишет буквально, в тексте окажутся цифры `0026` вне присланных названий (`names` собраны из
неэкранированных строк) → брак «цифры в тексте» → повтор, при втором таком же — 502 и оплаченные токены. Рядом ручка продавцов
уже выключила это ровно по этой причине (`ai.go:559-561`, `SetEscapeHTML(false)` — «Cash&Carry as printed») — конвенции
разъехались.

**Рекомендация.** В `modelText` — `json.NewEncoder` + `SetEscapeHTML(false)` + `strings.TrimSpace`, как у продавцов. Тест в
`TestReviewSendsOnlyInstructionFactsAndCandidates` (или отдельный): название с `&` — в тексте модели сырой `&`, нет `&`
(нынешний `reflect.DeepEqual` после `Unmarshal` экранирование не видит).

**Вердикт: клинап** — три строки, одна конвенция на обе ручки.

### Н-3 · низкая · «Запрос лимита» и цена разбора устарели после AU-09 / AU-33

Лимит теперь в деньгах, «запрос» — только счётчик админки, а слова остались прежние:
- `backend/internal/handlers/ai.go:544` — «One batch is one request of the limit (Р-14)»;
- `backend/README.md:159` — «Одна пачка — один запрос лимита»;
- `backend/internal/handlers/ai_test.go:276`, `:294`, `:450` — «one request of the limit», «Not a request of the limit», «no
  request of the limit»;
- `backend/README.md:141` — «≈ $0,017 за разбор» (замер AU-12); после Х-17 (AU-33) живой перезамер — **≈ $0,022**, 6–10 с.

**Рекомендация.** «Одна пачка — один запрос в счётчике админки; лимит — её цена»; в тестах — «one request in the admin
counter»; README:141 — добавить замер 2026-10-17 после Х-17 (8/8, ≈ $0,022, 6–10 с).

**Вердикт: клинап** — слова, без кода.

### Н-4 · низкая · Перерасход у края описан в запросах, а не в деньгах

`backend/README.md:122-123`, `backend/internal/ai/limit.go:15-16` — «перерасход в 1–2 запроса допустим». Худший разбор —
2 попытки × (≈ 2 200 вход + 16 000 `max_tokens`) по цене Opus ≈ **$0,66**, то есть разбор, начатый при $1,99, теоретически
закончится на ~$2,65. Живые разборы стоят ≈ $0,02, обрезка по `max_tokens` на них не встречалась.

**Рекомендация.** Ничего; если владелец когда-нибудь опустит лимит до $1 — пересмотреть `max_tokens` ручки.

**Вердикт: не делаем** — реальный перерасход в ~30 раз меньше худшего, допуск у края уже принят (README).

### Н-5 · низкая · `texts()` и `numbers()` почти повторяют друг друга, `raw` разбирается дважды

`backend/internal/handlers/ai.go:256-269` и `:362-371`: обе обходят факты и кандидатов; `numbers()` = те же строки + `raw`,
причём `raw` декодируется второй раз (первый — `validRaw`, `:180-204`).

**Рекомендация.** Можно строить `numbers()` из `texts()` + разобранных `raw`.

**Вердикт: не делаем** — две функции по 10 строк с разным назначением (имена в «» vs вход второй проверки) и разным порядком;
общий помощник ради одного места — абстракция «на будущее» (правило 10).

### Н-6 · низкая · Окно 55 с на второй вызов не покрыто тестом

`backend/internal/handlers/ai.go:421-431`: если первая попытка (брак) шла ~50 с, второй вызов получает остаток окна и падает
по таймауту → 502 с оплаченной первой попыткой. Логика — одна строка `context.WithTimeout` на оба вызова; теста с медленным
фейком нет.

**Вердикт: не делаем** — поведение очевидно из кода и совпадает с README («весь разбор — 55 с»); тест со сном на десятки
секунд дорог для набора, а живые ответы 5–11 с.
