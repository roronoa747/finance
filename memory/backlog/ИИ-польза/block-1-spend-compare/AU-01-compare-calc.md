# AU-01 — Сравнение трат по разделам и справка РК (фронт, `finance.ts`)

Блок 1 · MVP · Каталог: `frontend/src/lib/finance.ts`, `lib/statements/dictionary.ts` · Зависит от: Блок 3 «ИИ» 🏁 (Р-15) · Роли: все (чистые функции)

## Контекст (что уже есть)

- Р-5: на «Месяце» — вся семья, все разделы; в листе раздела — сумма, % дохода, «обычно у вас» (среднее за 3 прошлых
  месяца с выписками; минимум 2, иначе только план), план раздела, рекомендация в цифрах («до плана: +N в мечту, на M
  раньше»), справка РК (3 группы, Алматы). Точка — где трат больше обычного; в текущем месяце — только когда сумма уже
  выше обычной **за весь месяц** (не пропорция дней). Участников не сравниваем. Р-1: всё — код, без ИИ.
- Итоги выписок — `SpendTotal` в общем документе (§6 индекса): `kind: 'month'`, `period: 'YYYY-MM'`, `by`, `categoryId`,
  `amount`. Семейные траты месяца по разделам уже считает `monthSpendByCategory(people, totals, categories, key, uploads)`
  (`finance.ts:3881`): только участники, чья выписка задевает месяц (`uploadedBy` :3359 — **хотя бы день**), раздел
  платежей — неотмеченной частью (`spentOf` :1320), `_unknown` отдельно.
- «Полный» месяц для «обычно» этим не годится: выписка с 20-го дала бы треть трат и заниженное «обычно». Покрытие
  загрузками — `UploadPeriod {slot, period_from, period_to}` (:4373), `daysInMonth` (`lib/dates.ts`).
- План раздела — сумма `SpendPlan.amount` участников по `categoryId` (`planSpendOn` :1324 — живые, > 0, не раздел
  платежей). Доход месяца — `monthPlan(...).income.total` (:3377).
- Мечта для рекомендации — первая цель очереди (`mainGoal` :3087 или первый `kind === 'goal'` в `monthPlan().queue`);
  темп — `goalPace(goal, key)` :2480; остаток — `goalRemaining` :790.
- Разделы — `DEFAULT_SPEND_CATEGORIES` (`dictionary.ts:12-32`): `sc_food` Продукты, `sc_cafe` Кафе и рестораны,
  `sc_transport` Транспорт, `sc_telecom`* Связь, `sc_subscriptions`* Подписки, `sc_health` Здоровье и аптеки, `sc_home`
  Дом и быт, `sc_shopping` Одежда и покупки, `sc_fun` Развлечения, `sc_people` Переводы людям, `sc_credit`* Кредиты,
  `sc_utilities`* Коммуналка, `sc_education` Образование, `sc_travel` Путешествия, `sc_cash` Наличные, `sc_fees`
  Комиссии, `sc_other` Прочее, `sc_rent`* Аренда (* — `plannedElsewhere`, живут в «Платежах»). Семья может завести свои
  разделы (id не из словаря).
- Справка РК (бриф, разведка 2026-10-16): stat.gov.kz, «Структура денежных расходов», Алматы, II кв. 2025: продукты
  53,8 %, непродовольственные товары 19,1 %, платные услуги 24,3 %.

## Задача

1. **Полный месяц.** `monthCovered(key, uploads, by)` — загрузки участника вместе покрывают каждый день месяца;
   `usualMonths(people, totals, uploads, key, n = 3)` — до `n` последних месяцев **строго до** `key` (смотреть не дальше
   6 назад), где у каждого живого участника с итогами месяца выписка покрывает месяц целиком и такой участник есть.
2. **«Обычно у вас».** `usualSpend(...)` — среднее по разделу за `usualMonths` (раздел без трат в месяце — 0 в этом
   месяце; целые тенге, округление `Math.round`); меньше 2 месяцев — `null` («обычно» нет). Сумма раздела за месяц — та
   же правда, что `monthSpendByCategory` (переиспользовать, не дублировать).
3. **Строки сравнения.** `spendCompare(state: MonthPlanState, ctx: MonthPlanCtx)` → `{ income, usualFrom: string[],
   rows: SpendCompareRow[] }`, строка — `{ categoryId, name, amount (факт месяца семьи; выписок нет — null), plan
   (сумма планов участников; нет — null), usual (null — мало месяцев), share (% дохода от amount, целые; дохода нет —
   null), over (boolean), advice, group }`. Строки — разделы с фактом > 0 или планом > 0, **кроме** разделов платежей
   (`plannedElsewhere`) и `_unknown`; по убыванию `amount ?? plan`.
4. **Точка.** `over = usual !== null && amount !== null && amount > usual` с порогом шума: больше и на 10 %, и на 5 000 ₸
   (константы `OVER_SHARE`, `OVER_MIN` рядом с функцией; порог — дефолт составителя, `/ux` может предложить другой).
   Одно правило для текущего и прошлых месяцев (сумма за весь месяц, без пропорции).
5. **Рекомендация.** `advice = { amount: N, goalId, goalName, days } | null`: только при `plan` и `usual`, когда `usual
   > plan`; `N = usual − plan` (столько семья тратит сверх плана обычно); мечта — первая цель очереди; `days` — на
   сколько дней раньше при +N в месяц: `round((remaining / pace − remaining / (pace + N)) × 30.4)`; нет мечты или темпа —
   `days: null` (строка без «на M раньше»). Подпись «на N недель/месяцев раньше» — функция форматирования рядом
   (`earlierLabel(days)`: < 14 — дни, < 61 — недели, дальше — месяцы).
6. **Справка РК.** В `dictionary.ts` (или рядом) — константа групп `RK_SPEND_GROUPS` (`food` / `goods` / `services`:
   доля, подпись, источник `stat.gov.kz`, «Алматы, II кв. 2025», дата сверки) и сведение разделов к группам
   `RK_GROUP_BY_CATEGORY`: `sc_food` → food; `sc_home`, `sc_shopping`, `sc_health` → goods; `sc_cafe`, `sc_transport`,
   `sc_fun`, `sc_education`, `sc_travel`, `sc_telecom`, `sc_subscriptions`, `sc_utilities`, `sc_rent` → services;
   прочие и свои разделы — без группы (справки нет). **Цифры и сведение сверить** с публикацией stat.gov.kz (WebFetch);
   расхождение — значения из источника, запись в Handoff. `rkShare(state, ctx, group)` — доля группы в тратах семьи за
   месяц (по всем разделам с группой, включая разделы платежей, целые %) — для строки «у вас X % · в Алматы Y %».
7. Всё — целые тенге и целые проценты; новых зависимостей нет.

## Тесты

- `finance.test.ts` (или новый `spendCompare.test.ts`): `monthCovered` — выписка с 1-го по последний, две загрузки
  встык, дыра в день, у одного участника нет; `usualMonths` — пропуск неполного месяца, не дальше 6, ровно 3.
- `usualSpend`: среднее с нулём в месяце без трат раздела; 1 месяц → `null`; 2 → среднее двух.
- `spendCompare`: раздел платежей и `_unknown` не в строках; раздел только с планом (факт `null`/0); `share` от дохода;
  `over` — выше на 10 % и 5 000 (граница: ровно порог — нет); текущий месяц без пропорции; `advice` при `usual > plan`
  и `null` при `usual ≤ plan` или без плана; `days` против ручного расчёта; без мечты — `days: null`.
- Справка: каждая группа — сумма разделов; свой раздел без группы; доли РК — числа из константы.
