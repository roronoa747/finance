# Бриф «Хвосты»

## Контекст

Бэклог «Фидбек» закрыт 2026-10-23 (все 5 блоков на проде, архив — `memory/archive/Фидбек/`). Владелец назначил
судьбы его хвостов (`memory/decisions/fb-tails.md`): десять — чинить в новом бэклоге, начиная с брифа (правило 1).
Подробные описания хвостов, места в коде и варианты — таблица хвостов в `memory/archive/Фидбек/00-backlog.md` §4.

## Что хочется получить и зачем

Закрыть мелкие неточности, которые нашли на проде и на стенде: цифры экранов сходятся, «нашли в выписке» не путает
кофейню с подпиской, возврат магазина и вторая подписка заводятся без обхода, первый запуск на Android не предлагает
выбор из одного варианта.

## Эпики / крупные куски (хвосты, решения владельца 2026-10-23)

- **Х-21** «Нашли N в выписке» — только похожее на платежи; кофейня и такси мимо.
- **Х-7** вторая подписка того же продавца через «В платежи» — правило платежа по продавцу **и сумме**.
- **Х-20** «В платежи» у строки кредита — в форму кредита с остатком, а не в подписку.
- **Х-5** лист раздела платежей «Недели» — крупная сумма и список считаются одинаково (как на «Месяце»).
- **Х-6** «Месяц → Траты» — тихая строка «Платежи без отметки», чтобы сумма строк сошлась с «потрачено».
- **Х-14** лист «Наличные» (и переводы людям) — без плана и «обычно 0», только операции.
- **Х-3** «Мне вернули» — возвраты «+» от того же магазина; кешбэк и бонусы кандидатами не предлагать.
- **Х-2** ответы «Нет, это другое» / «Потом» — в личный документ (видны всем телефонам человека).
- **Х-1** разбор ИИ ждёт выписки (не «K находок из 0 операций»).
- **Х-22** первый запуск на Android — плитки только при двух путях; с одним — фото мечты, заголовок и кнопка.

## Резюме бриф-интервью

Разведка: архив «Фидбек» §4 (описания хвостов), `lib/statements/firstRun.ts` (`detectRecurring`, `foundPayments`,
`recurringOf`, `KIND_BY_CATEGORY`), `lib/statements/model.ts` (`refundCandidates`, Р-12), `lib/statements/matching.ts` и
`stores/operations.ts` (ответы «Нет, это другое» — `localStorage` устройства), `components/money/DebtsWidget.vue` (форма долга).
Два раунда вопросов, все ответы — по рекомендации.

- **Цель одной строкой:** десять хвостов «Фидбека» починены на проде — цифры сходятся, платежи из выписки заводятся
  без ошибок и обходов.
- **Скоуп:** Х-1, Х-2, Х-3, Х-5, Х-6, Х-7, Х-14, Х-20, Х-21, Х-22. · **Не-скоуп:** всё сверх этих десяти — отдельным
  брифом *(ответ владельца, раунд 2)*. · **После MVP:** Х-19. · **Принятый долг:** Х-4.
- **Решения (кандидаты в Р-*):**
  - Р-1 «Нашли в выписке» (Х-21): словарные виды (подписки, связь, кредиты, коммуналка, аренда) — как сейчас; прочие
    продавцы — только если **ровно одна похожая сумма (±5 %) в месяц два месяца подряд** (садик, спортзал). Несколько
    списаний в месяц (кофейня, такси) — мимо. «В платежи» у строки (`recurringOf`) не меняется *(ответ владельца, раунд 1)*.
  - Р-2 Правило платежа по продавцу и сумме (Х-7): списание продавца относится к его платежу с **ближайшей суммой**;
    две подписки одного продавца различаются, подорожавшая не уходит в траты и даёт «Подорожало» *(ответ владельца,
    раунд 1)*. Уже записанные правила «продавец целиком» продолжают работать *(дефолт)*.
  - Р-3 Строка кредита (Х-20): «В платежи» у строки вида `credit` открывает **лист кредита поверх «Месяца»** —
    платёж и день заполнены, спрашивает остаток долга; кредит заводится с остатком, как в «Деньгах → Долг» *(ответ
    владельца, раунд 1)*.
  - Р-4 Возврат магазина (Х-3): кандидат «Мне вернули» — приход «+» от того же продавца, не больше покупки, ±14 дней
    (окно Р-12); **первым в списке**, отмечает человек одним нажатием, сам не ставится. Кешбэк и бонусы банка
    кандидатами не бывают *(ответ владельца, раунд 2; уточнение `fb-tails.md`)*.
  - Р-5 Ответы по операции (Х-2): «Нет, это другое» и «Потом» живут в личном документе; ответы, уже записанные на
    устройстве, переезжают туда при первом синке *(дефолт)*.
  - Р-6 Разбор ИИ (Х-1): автоматический разбор стартует после того, как выписки подтянулись; нового на экране нет
    *(дефолт)*.
  - Р-7 «Месяц → Траты» (Х-6): тихая строка «Платежи без отметки» с суммой неотмеченных строк разделов платежей;
    нажатие — список этих строк с их действием «это платёж по …?» *(бриф `fb-tails.md`; что в листе — дефолт)*.
  - Р-8 Лист раздела платежей «Недели» (Х-5) отсеивает отмеченные строки, как «Месяц» *(бриф)*.
  - Р-9 Лист «Наличные» и переводов людям (Х-14): только операции, без плана, доли дохода и «обычно 0» *(бриф)*.
  - Р-10 Шаг «Тратьте как обычно» (Х-22): плитки выбора — только при двух путях (iPhone); с одним — фото мечты,
    заголовок и одна кнопка *(бриф)*.
  - Р-11 Экраны не согласуются заранее: строим по текущим паттернам, на `/ux` — артефакт 390 px «до | после»
    *(ответ владельца, раунд 2)*.
  - Р-12 Каждый блок после приёмки — на прод отдельно, с откатом promote прошлого деплоя; миграций БД не ждём
    (личный документ уже есть) *(ответ владельца, раунд 1)*.
- **Эскиз блоков** (порядок = приоритет; зависимость: 2 после 1 — строка Х-6 про платежи):
  1. **«Платежи из выписки»** — Х-21, Х-7, Х-20.
  2. **«Цифры сходятся»** — Х-5, Х-6, Х-14.
  3. **«Операции»** — Х-3, Х-2, Х-1.
  4. **«Первый запуск»** — Х-22.
- **Режим процесса:** блоки 1 и 3 — M с `/ux`; блоки 2 и 4 — S *(ответ владельца, раунд 1)*.
- **Критерии готовности** *(дефолт)*: по каждому хвосту — тест на правило + e2e на стенде, проверка в Chrome 390;
  приёмка — стенд с новой семьёй (три недели выписки: «нашли» = только подписка), демо; на проде — смоук по блоку.
