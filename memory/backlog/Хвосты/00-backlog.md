## 1. Цель

Десять хвостов «Фидбека» починены на проде: цифры экранов сходятся, «нашли в выписке» не путает кофейню с подпиской,
вторая подписка, кредит и возврат магазина заводятся без обходов, ответы по операции помнят все телефоны человека,
первый запуск на Android не предлагает выбор из одного. Успех — по каждому хвосту тест на правило + e2e, проверка в
Chrome 390, смоук на проде после каждого блока.

Режим: Блоки 1 и 3 — **M с `/ux`**, Блоки 2 и 4 — **S** (без `/ux`; правило 12 проверяет критик явным пунктом).

## 2. Зафиксированные решения

- **Р-1. «Нашли в выписке» (Х-21)**: словарные виды (подписки, связь, кредиты, коммуналка, аренда) — как сейчас; прочие
  продавцы — только если **ровно одна похожая сумма (±5 %) в месяц два месяца подряд** (садик, спортзал). Несколько списаний
  в месяц (кофейня, такси) — мимо. «В платежи» у строки (`recurringOf`) не меняется. *(интервью р.1)*
- **Р-2. Правило платежа по продавцу и сумме (Х-7)**: списание продавца относится к его платежу с **ближайшей суммой**; две
  подписки одного продавца различаются, подорожавшая не уходит в траты и даёт «Подорожало». *(интервью р.1)* Уже записанные
  правила «продавец целиком» продолжают работать. *(дефолт)*
- **Р-3. Строка кредита (Х-20)**: «В платежи» у строки вида `credit` открывает **лист кредита поверх «Месяца»** — платёж и
  день заполнены, спрашивает остаток долга; кредит заводится с остатком, как в «Деньгах → Долг». *(интервью р.1)*
- **Р-4. Возврат магазина (Х-3)**: кандидат «Мне вернули» — приход «+» от того же продавца, не больше покупки, ±14 дней
  (окно Р-12 «Фидбека»); **первым в списке**, отмечает человек одним нажатием, сам не ставится. Кешбэк и бонусы банка
  кандидатами не бывают. *(интервью р.2; уточнение `fb-tails.md`)*
- **Р-5. Ответы по операции (Х-2)**: «Нет, это другое» и «Потом» живут в личном документе; ответы, уже записанные на
  устройстве, переезжают туда при первом синке. *(дефолт)*
- **Р-6. Разбор ИИ (Х-1)**: автоматический разбор стартует после того, как выписки подтянулись; нового на экране нет.
  *(дефолт)*
- **Р-7. «Месяц → Траты» (Х-6)**: тихая строка «Платежи без отметки» с суммой неотмеченных строк разделов платежей;
  нажатие — список этих строк с их действием «это платёж по …?». *(бриф `fb-tails.md`; что в листе — дефолт)*
- **Р-8. Лист раздела платежей «Недели» (Х-5)** отсеивает отмеченные строки, как «Месяц». *(бриф)*
- **Р-9. Лист «Наличные» и переводов людям (Х-14)**: только операции, без плана, доли дохода и «обычно 0». *(бриф)*
- **Р-10. Шаг «Тратьте как обычно» (Х-22)**: плитки выбора — только при двух путях (iPhone); с одним — фото мечты,
  заголовок и одна кнопка. *(бриф)*
- **Р-11. Экраны не согласуются заранее**: строим по текущим паттернам, на `/ux` — артефакт 390 px «до | после».
  *(интервью р.2)*
- **Р-12. Прод по блоку**: каждый блок после приёмки — на прод отдельно, с откатом promote прошлого Production; миграций БД
  не ждём (личный документ уже есть). *(интервью р.1)*

**После Блока 1** (критик, ветка `tl-block-1-found-payments`):
- У продавца может быть **несколько правил `payment`** (разные цели). Выбор — `model.ts` `ruleFor(op, rules, amountOf?)`
  (`pick`: последнее правило — платёж и их ≥ 2 → ближайшее по сумме цели, ничья — последнее); суммы целей —
  `matching.ts` `paymentAmount(state)`, в сторе `ops.amountOf` (computed). Без `amountOf` `ruleFor` даёт последнее — «платёж
  ли это» от этого не меняется. Запись — `finance.addMerchantRules`: правило платежа новой цели — своя запись рядом (наследует
  `restCategoryId`), та же цель — правка; раздел — «остальным» каждого правила платежа; «между своими» / «кому → что» —
  первое заменяют, прочие надгробия. **`acceptMatch` идёт тем же путём** — «Да» на «это платёж по …» у продавца с другим
  платежом добавляет правило, а не заменяет.
- `addToPayments(opId, targetId)` — цель обязательство **или кредит** (вид — по id); `AddPaymentSheet` у строки вида `credit`
  открывает `NewDebtSheet` (`prefill {name, payment, day}`, `z`, эмит `created(id)`).
- «Нашли в выписке» (`foundPayments`): не-словарные продавцы — только `monthlyOnce` (ровно одно списание в двух подряд
  месяцах, ±5 %); одна строка на продавца — вторая подписка того же продавца в «нашли» не попадает, заводится «В платежи»
  у строки (`recurringOf` → `secondPayment`).
