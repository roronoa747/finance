## Контекст (что уже есть)

- Критерий готовности брифа: на настоящих выписках владельца разбор находит ≥ 2 вещей, которых нет на экранах (утечка в
  год, новое списание или «что раздуло»), каждая с кнопкой туда, куда ждёшь; все числа текста совпадают с кодом; цена — в
  админке, лимит $2 не превышен. Р-1: очевидное без «почему» и «что делать» — брак. Р-24: замеренный текст инструкции —
  в SESSION дословно (клинап иначе перепишет).
- Корпус — `memory/secrets/statements/<банк>/` (вне git, Kaspi и Freedom; `README.md` там — список файлов). Загрузка на
  стенде — экран «Неделя» → выписка (парсер в браузере); операции остаются на телефоне, `reviewFinds` и итоги — в
  документе (RZ-01). Документ стенда можно снять `GET` документа семьи (ручка синка — grep `householdDoc` в
  `api/client.ts`) или из `localStorage` (как читает `stores/finance.ts` — grep `readStorage`) и обезличить руками: имена участников, продавцов из находок в Handoff **не писать**
  (§5: продавцов — типом «аптека», «кофейня», суммы округлять).
- Тело для живого теста — `AI_LIVE_BODY` (файл JSON v3) у `TestLiveReviewV3` (RZ-04); собрать его — `buildReviewFacts`
  на документе стенда: временный vitest-скрипт в scratchpad или `console.log(JSON.stringify(payload))` в `requestReview`
  на стенде (откатить). Цена — `ai.CostMicros` по `Usage` (Opus 5.5: $4 / $20 за MTok); лимит семьи $2 = 2 000 000 µ$.
- Замер v2 для сравнения: 8/8 про перемену, 6–10 с, ≈ $0,022 за разбор (2 198 токенов входа).

## Задача

1. Стенд (§6: Go `:8161` на моках + ключ из `memory/secrets/anthropic.md`, Vite `:5261`): семья владельца — настоящие
   выписки обоих участников за ≥ 3 месяца (если второго нет — одного), документ — копия демо без операций или свой; дата —
   1-е число следующего месяца (часы браузера) → разбор сам. Снять: что нашёл код (`reviewFindings` — виды, счётчики,
   `yearly`, без продавцов), payload (размер, число фактов и действий), живые ответы.
2. `TestLiveReviewV3` на этом payload: `AI_LIVE_N=8`, effort `medium`. Считать: ответов 200 с первой попытки / с повтором /
   502; советов на ответ; доля советов про находки (не про остаток и сроки); «очевидных» советов (без «почему» / с
   действием, не отвечающим находке) — по чек-листу Р-1; время; цена за разбор (среднее, макс.) и токены входа.
3. Если ≥ 2 из 8 ответов «очевидные» или советы без находок при их наличии — поправить инструкцию (формулировки
   приоритета находок, пример хорошего совета без чисел) и перемерить 8 раз; финальный текст инструкции — в
   «Промпты/Handoff» SESSION **дословно** и в `ai.go`. Тесты `TestReviewSystemV3` — на слова финального текста.
4. Пороги Р-14 на настоящих выписках: если утечек 0 при явно частых продавцах или > 5 шума — поправить константы в
   `finds.ts` (в пределах одной правки, с записью «было → стало» в Handoff; изменение сути порогов — хвост §4, не
   переделка).
5. Handoff: таблица замера (8 строк: попытки, советы, действия, цена, время), 2–3 обезличенных примера советов,
   `work` (N / K / X), цена v3 против v2, запас до лимита ($2 ÷ цена разбора — сколько разборов в месяц), вывод по
   критерию «≥ 2 вещей, которых нет на экранах».

## Критерии приёмки

- Handoff содержит таблицу замера и примеры; на настоящих выписках код нашёл ≥ 2 находок разных видов, модель выбрала
  их в советы с кнопками в ≥ 6 из 8 ответов; числа ответов — только из фактов (200 с первой попытки ≥ 6 из 8); цена
  разбора ≤ $0,05 (иначе — хвост владельцу с цифрой, Р-11 не меняем).
- `cd backend && go test ./...` и `cd frontend && npx vitest run` зелёные после правок инструкции / порогов.
- Ничего из выписок (имена, продавцы, суммы семьи) не попало в git и в Handoff.
