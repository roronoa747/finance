## 1. Цель

Владелец на `/admin` в карточке «Семьи» сразу видит, какие семьи живые, и быстро находит нужную, чтобы включить ей ИИ.
Успех: живые семьи — сверху с зелёной точкой и «сегодня / вчера / N дней назад», на экране не больше 10 строк, любая
семья находится по части почты. **Режим S** — одна задача, без блоков.

## 2. Зафиксированные решения

- **Р-1 Активность** (владелец 2026-10-20): у семьи — зелёная точка (`--ok`), если кто-то из семьи заходил за последние
  7 дней, и тихая подпись «сегодня / вчера / N дней назад» по последнему входу. Источник — тот же, что у «Активные за
  7 дней» в `GET /api/admin/metrics` (событие `app_open` в `app.events`), чтобы цифры не расходились. Дни — по Алматы.
- **Р-2 Короче список** (владелец 2026-10-20): порядок — сначала семьи с ИИ и активные, по свежести входа; на экране
  первые 10, остальные — тихой кнопкой «Ещё N». Строка — в одну линию (почта обрезается, тумблер ИИ справа как сейчас).
- **Р-3 Поиск** (владелец 2026-10-20): поле над списком, фильтр на лету по части почты участников без учёта регистра,
  на клиенте; при вводе — все совпадения без лимита 10. Пусто — «Никого не нашли».
- Правило 12 CLAUDE.md: одно главное действие — тумблер ИИ у семьи (как есть), текста минимум, цвет — только токены.

## Handoff ADM-01 (исполнитель, 2026-10-20)

**Что сделано.**
- Go: `GET /api/admin/families` — у каждой семьи новое поле `last_active_at` (последний `app_open` любого нынешнего
  участника, `null` — не заходили). Доступ — только `ADMIN_EMAILS`, как был. Порядок ответа: ИИ сверху → свежий вход →
  не заходившие в конце → при равенстве новые (`ai_repo.go`, SQL и мок одинаково). Мок стенда видит события
  (`MockAIRepo.Events`). README бэкенда — поле и порядок.
- Фронт `/admin`, карточка «Семьи»: в одной линии — точка (`bg-ok`, вход за 7 суток), почты (обрезаются), тихое «сегодня /
  вчера / N дней назад» (`agoLabel` в `lib/dates.ts`, дни Алматы), тумблер справа. Первые 10 + тихая «Ещё N»; поиск по
  части почты (без регистра, пробелы по краям не мешают) — все совпадения; ничего — «Никого не нашли».

**Как считается активность.** Метрика «Активные за 7 дней» = `count(DISTINCT user_id)` по `app_open` с `at > now − 7 дней`.
Семье — `max(at)` по `app_open` её участников (`app.household_members` → `app.events.user_id`); точка — `now − last < 7
суток` (то же скользящее окно). Значит, семья с точкой ⇔ хотя бы один её участник посчитан в «Активные за 7 дней».
Подпись — разница календарных дней Алматы, поэтому на границе окна возможно «7 дней назад» и с точкой, и без
(6 суток 23 ч — точка есть, 7 суток 1 ч — нет); тест фиксирует.

**Правило 12 по экрану.** Главное действие — тумблер ИИ у своей семьи (не менялся). Ушло в подсказку — ничего нового.
Скрыто — семьи после 10-й (за «Ещё N»). Новых крупных цифр нет: подпись входа — `type-meta`.

**Отклонения / локальные решения.**
1. Поле поиска показывается, только когда семей больше 10 (при ≤ 10 весь список и так на экране — поле было бы шумом).
2. Строка расхода ИИ («N запросов · ≈ $X из $2») у семей с ИИ или тратами осталась второй тихой строкой (решение
   бэклога «ИИ», AI-04, Р-7 — не пересматриваю); активность к ней ничего не добавила, обычная строка — одна линия.
3. Порядок «ИИ, затем свежесть» — на сервере; на клиенте порядок ответа не меняется (тумблер не прыгает под пальцем,
   новое место — при следующем открытии).
4. Поле — `inputmode="search"`, а не `type="search"`: у search Chrome рисует свой синий крестик — цвет не из токена.
5. Не заходившие семьи — без точки и без подписи (пустое место под точкой держит почты ровно).
