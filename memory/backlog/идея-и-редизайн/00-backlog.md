## 1. Цель

Превратить Family Finance из инструмента одной семьи в B2C-продукт для пар и одиночек
Казахстана: главный экран продаёт мечту (цель с фото и «до мечты N%»), а ритм держит
еженедельная выписка банка, разобранная прямо на телефоне; тот же код доводится до сайта,
Google Play и App Store. Успех: незнакомые семьи загружают вторую выписку в течение 14 дней и
возвращаются каждую неделю; данные прода не потеряны ни одним деплоем; выписка не покидает
телефон.

Режим процесса: **M**; блоки 1, 3, 4, 6, 8 и блоки пивота 3 (9, 10, 11) — **L** (пометки в §4).
Блок 2 — без кода (отклонение — §5). Деплой веб-версии после каждого блока с кодом; магазины —
релизы Блоков 7 и 8. Блоки с дизайном (9–11) принимаются со снимками рядом с макетом (Р-41).

- **Р-5. Данные выписок.** Операции — личные: у каждого участника своё хранилище на сервере (без
  ФИО и номеров счетов: продавец, дата, сумма, категория, банк), партнёру операции не видны. В
  общий документ уходят итоги по категориям за неделю и месяц с суммами — партнёр видит категории
  до тенге. Переводы между партнёрами и между своими счетами и банками — внутренние, в траты не
  входят (сопоставление по сумме и дате); переводы людям — своя категория с памятью «кому → что».
  Повторная загрузка того же периода не удваивает операции (отпечаток операции). *(владелец,
  раунд 1; внутренние переводы и отпечаток — дефолт)*
- **Р-6. Выписка предлагает сопоставление с отметками по одному решению:** «похоже, это платёж по
  Автокредиту — отметить?», «это зарплата Ильяса?»; «да» запоминается по продавцу и назначению, и
  дальше такие строки отмечаются сами (снять можно); ручные «Оплатил» и «Пришла зарплата»
  остаются. Модель записей `payments` не меняется — сопоставление ставит ту же запись с пометкой
  источника «выписка». *(владелец, раунд 1; модель записи — дефолт)*

  `(user_id, id)`, `id` — отпечаток операции; клиент забирает по курсору `updated_at`). Итоги по
  категориям — записи `SyncDoc.spendTotals` (id = `участник:вид:период:категория`, LWW по id) —
  их считает телефон загрузившего из всех его операций периода и пишет в общий документ.
  *(дефолт составителя — развилка брифа)*
- **Р-22. Словарь и память.** Разделы трат — список `SyncDoc.spendCategories` (сеется дефолтным
  набором при первой загрузке, семья правит названия и цвета, хардкода справочника в экранах
  нет). Стартовый словарь «слово в названии → раздел» — данные в коде (`lib/statements/
  dictionary.ts`). Память семьи «продавец → раздел» и «кому → что» — записи `merchantRules` в
  **личном** документе (переводы людям не утекают партнёру), поэтому слияние личного документа
  (бывший RP-15) входит в Блок 1. *(дефолт составителя — развилка брифа)*
- **Р-23. Парсер — две ступени:** файл → строки (pdf.js ленивым чанком; xlsx — по корпусу) →
  операции (чистые функции, свои у каждого банка). Фикстуры тестов — обезличенные строки, снятые
  с корпуса скриптом. В результате парсера нет последовательностей из 6 и более цифр (номера
  карт, счетов, ИИН) и полных ФИО — имена остаются такими, как печатает банк (имя и инициал).
  *(дефолт составителя)*
- **Р-24. Идентификаторы и ветки.** ID задач — `B2C-NN`; ветки — `b2c-block-N-<тема>` от `main`.
  Merge в `main` + push = прод-деплой (Vercel Production из `origin/main`) — только в деплоящей
  роли и с «да» владельца в той сессии; push ветки блока ради CI — с согласия. *(дефолт)*
- **Р-25. Google на сервере и в оболочках.** Go проверяет ID-токен Google по JWKS Google (RS256
  через уже подключённый `golang-jwt`), допустимые аудитории — `GOOGLE_CLIENT_IDS` (веб, Android,
  iOS через запятую). В веб — Google Identity Services; в оболочках Capacitor — нативный плагин
  входа Google (WebView не допускает OAuth Google), тот же ID-токен на ту же ручку. Пользователь без
  семьи получает JWT без `household_id`; ручки семьи отвечают ему 409 `no household`.
  *(дефолт составителя)*
- **Р-26. Push.** Веб — Web Push (VAPID, библиотека `webpush-go`); оболочки — FCM (Android, а iOS
  через APNs средствами Firebase). Одна таблица `app.push_subscriptions` с видом `web` / `fcm`;
  день и час напоминания — поля семьи. Рассылка — расписание **GitHub Actions cron ежечасно**
  (как «будильник» базы `.github/workflows/keep-supabase-awake.yml`; Vercel Cron на бесплатном

  заголовком `Authorization: Bearer <CRON_SECRET>` (секрет — в env Vercel и в Secrets GitHub).
  *(дефолт составителя)*
- **Р-27. События метрики** — таблица `app.events` (`kind`, `at`, пользователь, семья; без

**Грабли среды**
- **`cmd/migrate` в прод запускает владелец** в своём терминале (клинап Б1): агенту чтение
  `memory/secrets/supabase-db.md` не разрешено автопроверкой прав, а коннектор Supabase прод-проект

  прошлого бэклога смотрел в живую базу; ветка без env → функция отвечает 500 «server is not
