# B2C-24 — Go: удаление аккаунта вместе с данными (бэкенд)

Блок 4 · MVP · Каталог: `backend/` · Зависит от: B2C-22 · Роли: любой вошедший (member, viewer, без семьи)

## Контекст (что уже есть)

- Р-14: удаление аккаунта вместе с данными — обязательно до публичного запуска (и обязательный
  пункт ревью Apple и формы данных Google Play).
- Схема `app` (после Блоков 1–3): `users`, `households` (`created_by` FK **ON DELETE RESTRICT**),
  `household_members` (CASCADE по обоим), `household_docs`, `private_docs` (CASCADE),
  `household_invites` (`created_by` CASCADE, `used_by` SET NULL), `statement_uploads`,
  `operations` (CASCADE по `user_id`), `photos` (CASCADE по `user_id`, `household_id`). Позже:
  `events` (B2C-28, `user_id` SET NULL), `push_subscriptions` (Блок 5, CASCADE).
- `UserRepository.Delete(id)` есть (компенсация в `Register`). Middleware B2C-22 проверяет
  пользователя в базе на каждом запросе — токен удалённого сразу 401.
- Общий документ семьи содержит записи участника (`people[slot]`, взносы, отметки `by`) — это
  данные семьи, сервер документ не правит (партнёр видит имя ушедшего; текст — на фронте).

## Задача

1. `DELETE /api/account` — в одной транзакции: подписки на пуш (если таблица есть), фото
   автора, операции и загрузки, личный документ, членство; **если пользователь был
   последним участником семьи** — семья целиком (документы, приглашения, фото семьи, загрузки);
   если не последним и он `created_by` семьи — `created_by` переписать на оставшегося участника
   (иначе RESTRICT не даст удалить пользователя; миграция `000005_account_deletion.sql`: FK
   `households.created_by` → `ON DELETE SET NULL` с `NULL`-колонкой — выбрать одно, записать в
   README); затем `users` (каскады добивают остальное). Ответ 204. Повторный запрос → 401.
2. Репозиторий: `AccountRepository.DeleteAccount(userID)` (pg — транзакция с явным порядком;
   мок — по коллекциям), `server.Repos`.
3. `runLiveServerE2EFlow`: партнёр удаляет аккаунт → второй продолжает пользоваться семьёй,
   его данные и общий документ целы; последний удаляет → семья исчезла, код приглашения не
   работает.
4. README: что удаляется, что остаётся у семьи (записи в общем документе).

## Тесты

- Хендлеры на моках: 204; после — `Me` 401; партнёр цел.
- `TestPostgres…`: все таблицы пользователя пусты после удаления (запросы по каждой), семья
  последнего участника удалена целиком, у не-последнего семья и документ на месте, `created_by`
  не мешает; оба DSN.

## Критерии приёмки

- `go build/vet/test` + PG + корень `api/` зелёные; CI зелёный; стенд с Postgres: удаление
  участника — сверка таблиц SQL (в Handoff).
