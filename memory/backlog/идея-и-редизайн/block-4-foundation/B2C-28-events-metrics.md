# B2C-28 — События и страница цифр для владельца (бэкенд + фронт; Р-16, Р-27)

Блок 4 · MVP · Каталог: `backend/`, `frontend/src/stores/events.ts` (новый), `views/Admin.vue` (новый) · Зависит от: B2C-22 · Роли: все пишут события; `/admin` — только email из `ADMIN_EMAILS`

## Контекст (что уже есть)

- Р-16: метрика удержания — свои события в Postgres; «вторая выписка в течение 14 дней» — из
  записей загрузок; минимальные события (открыл, завершил неделю, дошёл до цели в первом
  запуске) без третьих сторон; страница цифр для владельца. Р-27: таблица `app.events`,
  `/admin` для email из `ADMIN_EMAILS`.
- `app.statement_uploads` (B2C-06): `household_id`, `user_id`, `created_at`. Middleware B2C-22
  даёт пользователя (email через `GetByID`). `decodeJSONBody`, `respondJSON`; репозитории
  pg + мок; `/auth/me`.
- Фронт: стор операций (момент «загрузка отправлена»), первый запуск `/start` (B2C-19: шаг цели и
  финиш), неделя `/week` (B2C-21: «итог недели» после решений), `stores/syncEngine.ts` (старт
  приложения). Демо — без запросов.

## Задача

1. Миграция `000006_events.sql` (номер по каталогу): `app.events` — `id bigserial pk`,
   `household_id` FK CASCADE NULL, `user_id` FK **SET NULL**, `kind text` CHECK (`app_open`,
   `week_done`, `first_run_goal`, `first_run_done`, `push_open`), `at timestamptz`, `created_at`;
   индекс `(kind, at)`, `(household_id, at)`. `households` — `reminder_weekday`/`reminder_hour`
   не здесь (Блок 5).
2. `POST /api/events` `{kind, at?}` — любой вошедший (семья может быть `null`); `app_open` — не
   чаще раза в сутки на пользователя (сервер молча игнорирует повтор по дате Алматы);
   тело ≤ 1 КБ, неизвестный `kind` → 400. Ничего кроме `kind`/времени не принимается.
3. `GET /api/admin/metrics` — только если email пользователя ∈ `ADMIN_EMAILS` (env, через
   запятую; без переменной — 404 для всех); ответ JSON: пользователей и семей всего; семей с
   ≥ 1 загрузкой; **доля семей, у которых вторая загрузка случилась в течение 14 дней после
   первой** (по `statement_uploads`, семьи с первой загрузкой старше 14 дней — знаменатель);
   активных за 7 и 28 дней (`app_open`); воронка первого запуска (создали семью → загрузили →
   `first_run_goal` → `first_run_done`) за 28 дней; таблица по неделям за 8 недель (новые семьи,
   загрузки, `week_done`). SQL — в `MetricsRepository` (pg; мок — константы), тест на PG с
   фикстурами.
4. Фронт: `stores/events.ts` — `track(kind)`: очередь в `localStorage`, отправка батчем при
   сети, в демо — нет; вызовы: старт приложения (`app_open`), финиш недели (`/week` после
   решений), `/start` шаги цели и финиша. `views/Admin.vue` (`/admin`, ленивый) — таблицы цифр
   без библиотек графиков; пункт в настройках виден только если `me.admin === true` (`/auth/me`
   отдаёт флаг).
5. README: `ADMIN_EMAILS`, ручки.

## Тесты

- Go: `app_open` дважды в день → одна строка; неизвестный `kind` → 400; `/admin/metrics` для
  не-админа → 404, без переменной → 404; PG: метрика «вторая за 14 дней» на фикстуре (3 семьи:
  да / нет / слишком свежая → 50 %), воронка, недели.
- Фронт: очередь и батч (фейковый клиент), демо не шлёт; SSR `Admin` (таблицы), пункт настроек
  по флагу.

## Критерии приёмки

- `go build/vet/test` + PG; `npm run build && npm test` зелёные; стенд: владелец с
  `ADMIN_EMAILS` видит `/admin` с цифрами после двух загрузок с двух профилей; партнёр — 404.

## Вне скоупа

- События пушей — Блок 5 добавляет `push_open`. Графики, экспорт — после MVP.
