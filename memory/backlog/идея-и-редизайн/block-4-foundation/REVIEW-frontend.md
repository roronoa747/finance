## Проверено независимо (не по Handoff-у)

- **Dev-форма не в проде.** `dist` обычной сборки и сборки с `VITE_GOOGLE_CLIENT_ID`: строки «Вход по почте» и чанка
  `DevLogin` нет (grep обеих). Условный `import()` под `import.meta.env.DEV` (`Access.vue:15`) работает.
- **GIS по требованию.** Скрипт `accounts.google.com/gsi/client` добавляется в `<head>` только из `renderGoogleButton`
  (`lib/googleSignIn.ts:33-46`), которую зовёт один `Access.vue` на `onMounted`; лэндинг и приложение его не грузят.
  **Находка сборки:** без `VITE_GOOGLE_CLIENT_ID` сборщик выбрасывает код GIS целиком (`googleClientId` — константа,
  `if (!googleClientId) return`) — строки URL в `dist` нет; с переменной — URL в `index-*.js`. Отсюда Н-1.
- **Картинки лэндинга.** `public/landing/*.webp` — 12–72 КБ, `og.jpg` — 52 КБ; `globPatterns` PWA (`vite.config`:
  `js,css,html,svg,png,woff2`) их не берёт — установившим приложение 300 КБ лэндинга не качаются. Герой — `preload`
  из `index.html` только анониму на «/» (ключи `ff_auth_token`, `ff_theme` и правило темы совпадают с `lib/theme.ts`);
  остальные — `loading="lazy"`.
- **Токены.** `Who`, `Access`, `Landing`, `Admin`, `Privacy`, `Root`, `DevLogin`, `DangerZone` — ни hex, ни `rgb()`,
  ни палитры Tailwind (`white/black/gray…`); цвета — `--brand`, `--surface`, `--ink-2`, `--warn-*`.
- **Очередь событий** (`stores/events.ts`): по одному, голова удаляется по ссылке (вытеснение лимитом 50 не теряет
  неотправленное), 4xx — выброс, 5xx/сеть/401 — ждать; `reset()` в `clearAuth`; ключ — в `LOCAL_KEYS`; в демо и без
  семьи ничего не шлёт. Тесты `events.test.ts` покрывают всё это и `Admin.vue`.
- **401 → вход.** `apiClient.onUnauthorized` только при запросе с токеном (`client.ts:101`, и для фото `:279`) —
  неверный пароль и отказ Google на `/access` (токена нет) экран не уводят; `expire()` не трогает демо.
- **Старые тесты не ослаблены.** Правки e2e прошлых блоков (`block0-tails`, `block3-screens`, `pv-block5`,
  `b2c-block10/17`) — замена входа в демо через `Access` на `startDemo()`/лэндинг и текстов `/access`; проверки
  ошибок кода переехали в `authScreens.test.ts` («По коду» — ошибка русским текстом).

## Находки

### Н-1 · средняя · `VITE_GOOGLE_CLIENT_ID` — константа сборки: без неё прод собирается без входа

`frontend/src/lib/googleSignIn.ts:9`, `frontend/src/views/Access.vue:37-40`. Vite подставляет переменную при сборке,
а сборщик выбрасывает недостижимый код GIS (проверено двумя сборками, см. выше). Если переменная заведена в Vercel
после сборки, только для Preview или с опечаткой — на проде «Вход через Google недоступен», а формы пароля в проде нет:
войти не может никто (вошедшие работают до истечения токена). Код верен; риск — в порядке деплоя.

**Рекомендация.** В клинапе: env (шаг 2) для **Production** — до merge (шаг 4), как и написано; после деплоя до смоука —
`curl` главного JS прода и grep `accounts.google.com/gsi/client` (или `/access` в браузере: кнопка Google, а не строка
«недоступен»). Добавить строку в «Факты для деплоя» README фронта.

**Вердикт: клинап** (шаг деплоя + одна строка README; кода нет).

### Н-2 · средняя · Состав семьи «по серверу» посчитан в трёх местах по-разному

`frontend/src/views/Settings.vue:36-46` (`rows`: участники с сервера, имя — из документа, без ответа — люди документа),
`frontend/src/components/SyncBadge.vue:39-43` (тот же `rows` второй копией, другая форма записи — `viewer: boolean`
вместо `role`), `frontend/src/views/Settings.vue:57` (`canInvite` = `useInvite.canInvite` по `people` документа **и**
`member` с сервера < 2), `frontend/src/components/useInvite.ts:27-29` (`canInvite` — только по `people`). Р-124 п. 1
(клинап) переводит `canInvite` на `auth.members` — без сведения это четвёртая версия правила, и `Start.vue`/`Who.vue`
(тоже `useInvite`) будут считать иначе, чем настройки. Ветка `SyncBadge` «viewer — другой участник» не покрыта
(тест `SyncBadge.test.ts:65` — только viewer сам).

**Рекомендация.** Одно место — `useInvite.ts` (уже общий для `Who`, `Start`, `Settings`): экспорт `useMembers()` →
`rows` (с сервера, иначе живые люди документа) и `fullMembers` (число `member`); `canInvite` = не viewer, не демо и
`fullMembers < 2` (с сервера, без ответа — живые `people`) — это и есть Р-124 п. 1. `Settings` и `SyncBadge` берут
`rows`, из `Settings.vue:57` своё условие уходит. Тест: шторка синка показывает партнёра-viewer «только просмотр»;
`canInvite` после ухода партнёра (в `people` надгробие/запись ушедшего, `members` — один) — `true`.

**Вердикт: клинап** (вместе с Р-124 п. 1 — одна правка, а не две).

### Н-3 · средняя · Предупреждение удаления без ответа сервера говорит партнёру «удалятся бюджет, мечты»

`frontend/src/views/Settings.vue:62-66`. `deleteWarning` выбирает текст по `authStore.members.length > 1`; если
`GET /household/members` не ответил (нет сети при открытии настроек, сбой), `members` пуст — участнику семьи из двоих

Ошибка в безопасную сторону, но это текст необратимого действия — он должен быть верным (замечание приёмки).

**Рекомендация.** Считать по тому же источнику, что Н-2: `members` с сервера, без ответа — живые `people` документа
(`!deletedAt`) > 1. Тест в `authScreens.test.ts`: `householdMembers` бросает, в документе двое → «Общий бюджет
останется у семьи».

**Вердикт: клинап.**
