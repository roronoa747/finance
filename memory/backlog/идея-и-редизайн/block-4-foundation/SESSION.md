# Блок 4 — Фундамент для чужих · сессии

**Цель блока:** в приложение может войти незнакомая семья — через Google, шаг «с кем», без
мастера; её данные можно удалить одной кнопкой; есть домен, политика и проверенная база;
лэндинг с демо ведёт к «Начать»; владелец видит цифры удержания. После блока — веб-проверка
гипотезы на 5–10 семьях.

Сессии: исполнитель ⬜ · критик ⬜ · приёмка ⬜ · ревью backend ⬜ · ревью frontend ⬜ · клинап ⬜

## Промпт исполнителя — уровень build · Opus 5 · effort high (ultrathink)

```
/worker идея-и-редизайн 4 ultrathink
```

Блок-специфика:

- Ветка `b2c-block-4-foundation` от `main` (после деплоя Блока 3). Push — с согласия; `main` и
  прод-БД не трогать (миграции `000004`–`000006` в прод — клинап).
- Задачи по порядку: B2C-22 (Go) → B2C-23 (Go) → B2C-24 (Go) → B2C-25 → B2C-26 → B2C-27 →
  B2C-28. Домен (B2C-26) покупает владелец — заранее спросить имя (AskUserQuestion с
  вариантами), пока идут Go-задачи.
- **Секреты и внешние аккаунты:** веб-клиент OAuth создаёт владелец в Google Cloud Console
  (агент даёт пошаговую инструкцию; authorized origins — localhost, старый и новый домены);
  id — `memory/secrets/google-oauth.md`, env Vercel `GOOGLE_CLIENT_IDS` и `VITE_GOOGLE_CLIENT_ID`
  (выставляет агент с «да»); `ADMIN_EMAILS` — почта владельца. В доки — только имена.
- Auth (L): middleware по факту базы на каждом запросе (B2C-22) — проверить, что ни одна ручка
  не доверяет семье из старого токена; 409 без семьи; 401 удалённого.
- Среда: Postgres одноразовый; два профиля с настоящим входом Google + viewer; прод-сборка
  (`vite preview`) для проверки отсутствия формы пароля.
- Верификация — стандарт §6 + браузер по критериям ТЗ; Lighthouse для лэндинга.
- Следующий шаг — `/critic идея-и-редизайн 4 ultracode`.


Блок-специфика:

  `email_verified`; middleware обновляет роль/семью из базы; 409 без семьи на всех ручках семьи

## Промпт клинапа — уровень build · Opus 5 · effort high

```
/cleanup идея-и-редизайн 4
```

Блок-специфика:

- Выполнить «клинап»-вердикты обоих ревью.
- **Деплой — каждый шаг с «да» владельца:** (1) ID текущего Production-деплоя; (2) env Vercel:
  `GOOGLE_CLIENT_IDS`, `VITE_GOOGLE_CLIENT_ID`, `ADMIN_EMAILS` (значения — из
  `memory/secrets/`, не в чат); (3) `cmd/migrate` (000004–000006); (4) merge
  `b2c-block-4-foundation` → `main`, push; (5) домен: alias без редиректа; оба телефона —
  синк без `unsent` → переустановка PWA с нового домена → только потом редирект старого
  (отдельное «да»). Смоук на проде: вход Google обоих (привязка по почте — данные на месте),
  лэндинг и демо анонимом, `/privacy`, `/admin` у владельца, будильник базы `workflow_dispatch`.
  **Откат:** promote записанного деплоя (старый клиент входит по почте — ручки остались);
  миграции остаются.
- «Итоги пост-приёмки», 🏁 в §4, `STATE.md`. Следующий шаг — `/worker идея-и-редизайн 5`.
