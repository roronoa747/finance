# Блок 4 — Фундамент для чужих · сессии

**Цель блока:** в приложение может войти незнакомая семья — через Google, шаг «с кем», без
мастера; её данные можно удалить одной кнопкой; есть домен, политика и проверенная база;
лэндинг с демо ведёт к «Начать»; владелец видит цифры удержания. После блока — веб-проверка
гипотезы на 5–10 семьях.

### Возврат приёмки (исполнитель, 2026-10-09)

**Коммит:** `ba2029f` (B2C-23) — только **В-1**; каталожные мелочи «Приёмки» не брались (правило 10).

**Сделано.** `JoinHousehold` выдаёт первый слот из `a`/`b`/`c`, который не занят **ни участником, ни записью в
`people` общего документа** (`usedSlotsSQL` в `household_repo.go`: `UNION` слотов `household_members` и `people[].id`
из `household_docs.data`; не-массив `people`, не-объекты и записи без `id` пропускаются). Мок
(`MockDocRepo.peopleSlots`) — так же. Ушедший остаётся ушедшим: его запись (имя, оклад, `onboardedAt`, записи по
слоту) в документе не меняется, новый по коду получает свой слот, у слота нет записи → свой первый запуск под своим
именем. Миграции нет, документ сервер по-прежнему не правит. README backend — правило слота.

**Почему так (из двух способов приёмки).** «Не выдавать слот с записью в `people`» — одно место в Go, без правки
документа сервером и без фронта; «надгробие ушедшего с переносом» потребовало бы правки JSON документа при удалении
(ревизия, слияние на телефонах) и всё равно оставило бы записи `by`/`payer`/желания по слоту новому владельцу слота.

**Отклонения и последствия (для критика):**
- Семья из трёх слотов: каждый ушедший «съедает» слот навсегда — семья из двоих после одного ухода принимает ещё одного
  (`c`), дальше — 400 `household has maximum members` (стенд: четвёртый — 400). Для B2C-пары достаточно; больше —
  решение владельца, не исполнителя.

  унаследует демо-партнёра с `onboardedAt` (раньше миновал бы свой первый запуск — та же болезнь, что В-1). Демо-«Партнёр»
  остаётся в документе; приглашение из интерфейса в такой семье и так скрыто (`useInvite`: живых в `people` уже 2).
- Ушедший по-прежнему считается живым там, где фронт фильтрует только `deletedAt` (план месяца, аватары) — так было и
