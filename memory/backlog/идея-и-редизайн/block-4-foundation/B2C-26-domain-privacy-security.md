## Контекст (что уже есть)

  схему `app`; старые таблицы `public` и ключи React — в «Уборку старого», не здесь); домен —
  покупает владелец (исключение из бесплатных тарифов). Хвост `STATE.md` → сюда: `data` синка с
  `\u0000` или одиночным суррогатом → 500 (надо 400).
- Прод: `family-finance-ff.vercel.app`; API — тот же origin (rewrites), CORS не нужен;
  Google OAuth — authorized origins по домену (B2C-22/25); установленные PWA владельца и
  партнёра живут на старом origin — **редирект старого домена на новый обнулит их
  `localStorage` и SW**: сначала синк без `unsent` на обоих телефонах, потом переустановка PWA с
  нового домена; до этого старый домен — без редиректа.
- Supabase: проект `tpkyopaovfdkcmdhauws` (URL публичный, в `.env`); в `public` — таблицы
  React с RLS (старое), в `app` — прод Go. PostgREST отдаёт только «Exposed schemas» (по
  умолчанию `public`, `graphql_public`). Подключение Supabase MCP: `get_advisors`,
  `list_tables`, `execute_sql` (только чтение здесь). «Будильник базы»
  `.github/workflows/keep-supabase-awake.yml` дёргает PostgREST `public.households` — после
  «Уборки старого» сломается; `GET /api/health` ходит в базу.
- `handlers/sync.go`: проверка `utf8.Valid`; `\u0000` внутри валидной строки JSON проходит до
  Postgres → 500.
- Магазины требуют URL политики; Apple — ещё и удаление аккаунта (B2C-24).

## Задача

1. **Домен** (владелец покупает; имя — решение владельца, агент предлагает 3 варианта с
   проверкой доступности): добавить в проект Vercel (`add_project_domain` — с «да»), DNS у
   регистратора (инструкция владельцу), HTTPS автоматически; старый домен — alias без
   редиректа до переустановки PWA (план в Handoff и в промпте клинапа); Google OAuth —
   добавить origin; манифест PWA и `theme-color` не зависят от домена.
2. **Политика конфиденциальности** — `/privacy` (публичный маршрут, статический текст, лёгкий
   чанк; ссылка в футере лэндинга B2C-27, в настройках и в магазинах): кто мы, что храним
   (почта и id Google, имя, общий документ семьи, личные операции без ФИО и номеров, итоги,
   фото, подписки на уведомления, события использования без третьих сторон), что **не** храним
   (файл выписки — не покидает телефон), где хранится (Vercel, Supabase — регион), кому
   передаём (Google — вход; Gemini — только по явному действию, если включено; ничего для
   рекламы), удаление (кнопка в настройках, что остаётся у семьи), контакт (email владельца —
   публичный адрес поддержки, решение владельца), дата. Русский; краткая английская версия —
   для ревью магазинов (подзаголовок на той же странице).
3. **Безопасность базы** (только чтение, с «да» владельца): `get_advisors` (security,
   performance) и настройка Exposed schemas — убедиться, что `app` не выставлена через
   PostgREST (запрос `rest/v1/` к таблице `app.*` с anon-ключом → не 200); RLS-советы по
   `public` — записать в Handoff как вход для «Уборки старого»; проверить, что `DATABASE_URL`
   функции — роль с правами только на `app` (если нет — записать рекомендацию, не менять).
   Итог — в Handoff без ключей.
4. **Проверка данных синка**: `\u0000` и одиночные суррогаты в `data` → 400 (проверка
   `json.Valid` + сканирование строк); тесты в `sync_test.go`; PG-тест на одиночный суррогат.
5. «Будильник базы» → `curl <домен>/api/health` (ответ `db: connected`), без ключей Supabase.

## Тесты

- Go: `\u0000` в строке JSON → 400; одиночный суррогат → 400; обычный юникод проходит.
- SSR: `/privacy` открывается без входа, содержит разделы п. 2.
- Workflow — прогон `workflow_dispatch` после деплоя (в клинапе).

## Критерии приёмки

- Домен отвечает по HTTPS, `/privacy` на домене; старый домен работает без редиректа; в
  Handoff — итоги проверки Supabase и план переустановки PWA; `go test`/`npm test` зелёные.

## Вне скоупа

- «Уборка старого» (React `src/`, таблицы `public`, Edge Function) — отдельная S-задача с «да»
  владельца (хвост `STATE.md`). Смена роли БД, ротация секретов — по итогам, отдельно.
