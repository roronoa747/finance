## Контекст (что уже есть)

- Макет — `../pivot-3/dreams-week.html`, секция «Вопрос 4 · Анимации», колонка **«2 · Живо»** (кнопки
  «Проиграть» показывают вживую). Классы макета: `.press` (`transform .14s`, `:active scale(.97)`),
  `.fx-in` (`fadeUp .32s`: `opacity 0 → 1`, `translateY(8px) → 0`), `.fill` (`width 1.1s
  cubic-bezier(.2,.8,.2,1)`). Уровень 3 (фото раскрывается в экран цели, конфетти) — **не делаем**.
- Решение Р-45: CSS и `<Transition>`/`<TransitionGroup>` Vue, **без новых библиотек**; длительности
  150–400 мс, бег цифр ≤ 1 с; `prefers-reduced-motion: reduce` выключает всё.
- `style.css` ~341–348: правило `prefers-reduced-motion` уже есть (`animation-duration` и
  `transition-duration: 0.01ms !important` для `*`). Бег цифр на JS (`requestAnimationFrame`) это правило
  **не выключает** — нужна своя проверка `matchMedia('(prefers-reduced-motion: reduce)')`.
- Сейчас анимаций почти нет: один `<Transition>` в `kit/SavedMark.vue`. Шапка и вкладки — `AppShell.vue`
  (`<router-view>` внутри `main`); кит: `ui/Button.vue`, `kit/Card.vue`, `kit/ProgressBar.vue`,
  `kit/StackBar.vue` (полоса долей), `kit/Sheet.vue` (лист — свой переход, проверить).
- Числа выводят `money()`/`plain()`/`pct()` из `lib/money.ts` — форматирование не меняется; бег — только
  отображение промежуточных целых значений (деньги — целые, инвариант 6).
- SSR-тесты экранов (`renderScreen`) рендерят разметку на сервере — компонент бега цифр в SSR обязан
  сразу отдавать **конечное** значение (иначе тесты сумм сломаются).

## Задача

1. **Токены движения** в `style.css`: `--motion-fast` (~150 мс), `--motion-base` (~320 мс), `--motion-slow`
   (~400 мс), одна кривая `--ease-out` (как в макете); утилиты (`@utility`) `press` и `fx-in` по макету.
2. **Нажатие:** `ui/Button.vue`, нажимаемые строки и плитки (строка цели/желания, квадраты «Денег»,
   `Chip`) — `press`.
3. **Появление:** смена экрана — `<Transition>` вокруг `router-view` в `AppShell` (короткий fade/сдвиг,
   без «прыжка» шапки и капсулы вкладок); карточки первого экрана — `fx-in`.
4. **Бег цифр:** компонент `kit/CountUp.vue` (или composable `useCountUp`) — от прошлого значения к новому
   ≤ 1 с, `requestAnimationFrame`, промежуточные — целые, форматтер передаётся (`money`/`plain`/`pct`);
   SSR и reduced-motion — сразу конечное. Применить к крупным числам: % мечты, сумма недели, «Свободно».
5. **Полосы:** `ProgressBar` и `StackBar` — заполнение от 0 при появлении (`transition: width
   var(--motion-slow)`… до 1,1 с как в макете — в пределах Р-45 «бег ≤ 1 с»: взять ≤ 1 с).
6. **Списки по очереди:** строки списков (цели, желания на «Мечтах»; «Прошлые недели») — `fx-in` с
   задержкой по индексу (`--i` × ~40 мс, не больше ~6 строк с задержкой).
7. Проверить, что `prefers-reduced-motion` выключает всё (CSS — существующим правилом, CountUp — своей
   проверкой).

## Тесты

- `kit/CountUp` (DOM-тест, happy-dom): SSR/первый рендер — конечное значение; при `matchMedia` reduce —
  без промежуточных; при смене значения — промежуточные целые, финал равен цели (заглушка
  `requestAnimationFrame`).
- `style.tokens.test.ts`: токены движения есть; правило `prefers-reduced-motion` на месте.
- Существующие SSR-тесты экранов с суммами — зелёные без правок ожиданий.

## Критерии приёмки

- Браузер 390 px (и телефон владельца на воротах): переход между вкладками, появление карточек, нажатие
  кнопки, бег % мечты и суммы недели, заполнение полос, строки списков по очереди — видно; в эмуляции
  `prefers-reduced-motion: reduce` (DevTools / Playwright `reducedMotion: 'reduce'`) — ничего не движется,
  числа сразу конечные.
- Нет сдвига разметки (CLS) при появлении; прокрутка не дёргается.
- `cd frontend && npm run build && npm test` зелёные.
