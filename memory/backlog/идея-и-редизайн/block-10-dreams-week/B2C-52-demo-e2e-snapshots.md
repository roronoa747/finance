# B2C-52 — Демо из демо-операций, e2e Блока 10, снимки «макет | стенд» (фронт)

Блок 10 · MVP · Каталог: `frontend/src/views/Access.vue`, `frontend/e2e/`, `block-2-design/DESIGN.md` · Зависит от: B2C-49, B2C-50, B2C-51 · Роли: демо, member, viewer

## Контекст (что уже есть)

- Хвост критика Б9 (§4): **демо-итоги `spendTotals` не сходятся с демо-операциями** «Истории». Демо
  заводит `views/Access.vue` ~230–290: `doc.spendTotals = [...]` — итоги руками (неделя, прошлая неделя,
  месяц, разделы `sc_food`, `sc_cafe`, `sc_transport`, `sc_shopping`, `sc_credit`, `_unknown`, участники
  `a` и `b`); затем `ops.seedDemoUploads([...])` (две загрузки `a`/`b` с 1-го числа по сегодня) и
  `ops.seedDemoOperations([...])` (17 своих операций `a` за ≤ 13 дней, `op(n, ago, amount, merchant,
  categoryId)`, одна `internal`, одна без раздела «ИП Абенова»).
- Итоги из операций в живом приложении считает стор операций при отправке разбора (`lib/statements` —
  функция итогов по неделе/месяцу и разделу; найти по `spendTotals` в `stores/operations.ts` и
  `lib/statements/model.ts`) — демо должно звать **её же**, не дублировать сумму (Р-50, инвариант 6).
  Итоги партнёра (`b`) в демо — своих операций у демо-«Аруны» нет: допустимо оставить ручные итоги `b`
  или завести её демо-операции той же функцией — на выбор, записать в Handoff.
- e2e: накопительный набор `frontend/e2e/` (`b2c-block9-money.test.ts` — образец: два телефона через
  `support/family.ts`). Снимки «макет | стенд» — способ из Handoff «Возврат смоука» Блока 3
  (`block-3-screens/SESSION.md` ~642–649): Playwright (`playwright-core` из корневого `node_modules`,
  Chromium `chromium-1223`, `MSYS_NO_PATHCONV=1`), скрипты в scratchpad, в репо не кладутся.

## Задача

1. **Демо:** итоги `spendTotals` своих демо-операций (`a`, неделя / прошлая неделя / месяц) — той же
   функцией, что считает итоги при отправке разбора; на «Неделе» демо сумма недели и «Не разобрано»
   сходятся с «Историей». Даты демо-операций — так, чтобы у текущей и прошлой недели были траты
   (иначе нет чипа сравнения); в начале месяца — учесть, что неделя может начаться в прошлом месяце.
2. Демо показывает обе вкладки «как в макете»: на «Мечтах» — главная мечта, 2 цели, 3+ желания с фото
   (шаблоны), строка «Свободно»; на «Неделе» — карточка недели и хотя бы два решения в очереди (например,
   незнакомый продавец «ИП Абенова» и «остались деньги?»/«пришла зарплата?» — что даёт дата).
3. **e2e `e2e/b2c-block10-dreams-week.test.ts`** (два телефона, как Б9): часть 1 — «Мечты»: строка
   «Свободно» = `freeByFact`, на главном нет недельного; часть 2 — очередь: ответ на продавца у A → итоги
   и «Свободно» у B пересчитались, счётчик «N из M» растёт; часть 3 — «Свободно» одно (сводка «Денег» —
   «останется на счетах», «Доход» — без слова); часть 4 — viewer: «Мечты» и «Неделя» без решений и
   загрузки; часть 5 — демо: сумма недели = сумме демо-операций недели (+ итоги `b`).
4. Старые e2e, проверявшие главный с картиной недели/решением, — переведены в B2C-48; здесь — прогнать
   весь набор, удалённые сценарии — с причиной в Handoff.
5. **Снимки «макет | стенд»** 390 px, обе темы: «Мечты» (с мечтой, без мечты), «Неделя» (с решением, без
   решений, разбор), «Деньги» (сводка и «Доход» — новые слова), кружки участников; анимации — короткая
   запись (GIF/видео) или серия кадров для владельца. В Handoff — таблица «экран → расхождение → правка →
   совпадает».
6. `DESIGN.md`: пометки пивота 3 в затронутых секциях проставлены (B2C-46, 48, 50, 51) — сверить.
