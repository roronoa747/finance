# B2C-75 — Маленькая картинка со страницы не ставится фото желания (фронт) · возврат смоука 2 Блока 12

Блок 12 (возврат смоука 2) · MVP · Репо/каталог: `frontend/src/` · Зависит от: B2C-66, B2C-68 · Роли: member · Ветка: `b2c-block-12-smoke-2`

## Контекст (что уже есть)

- Смоук владельца 2 (2026-10-03, снимок листа «кофта»): ссылка Pinduoduo (`mobile.yangkeduo.com/goods1.html?…`) ставит
  фото **значка приложения**, и оно плохого качества. Причина: `backend/internal/linkpreview/linkpreview.go` берёт
  `og:image` → `twitter:image` → `image_src`; мобильная страница Pinduoduo собирается скриптами, в её `og:image` —
  общий логотип, маленький, в плитке — пиксели.
- Решение владельца (AskUserQuestion, 2026-10-03): **маленькие картинки не брать** (короткая сторона меньше ~300 px) —
  плитка остаётся без фото, человек ставит своё камерой; только телефон, Go не трогаем. Разбор страницы Pinduoduo на
  сервере — не делаем. Уже поставленный логотип у «кофты» владелец удалит сам (× в листе) — автоочистки нет.
- Путь картинки со страницы на телефоне — два места: вставка ссылки `lib/photos/useLinkPreview.ts` (`client.linkPreview`
  → `Wishes.vue` `applyLink`/`createWish`, `WishSheet.vue` `onLink` → `onFile`) и обход старых желаний
  `lib/photos/wishLinkPhotos.ts` (`deps.preview` → `deps.compress`). `compressImage` (`compress.ts`) возвращает
  `{ blob, width, height }` и не увеличивает (`fitSize`), так что размеры выхода у маленькой картинки = исходные.

## Задача

1. **Порог** — одна константа и проверка в `lib/photos/` (напр. `MIN_LINK_PHOTO_SIDE = 300`, `bigEnough(w, h)` —
   `Math.min(w, h) >= 300`); размеры — из `compressImage` (или декодирования до сжатия — на выбор исполнителя, без
   второго декодирования по возможности).
2. **Вставка ссылки** (`Wishes.vue`, `WishSheet.vue`): маленькая картинка не загружается (`uploadPhoto` не зовётся),
   фото желания не ставится; название со страницы по-прежнему подставляется. Без текста ошибки — как при «картинки нет».
3. **Обход** (`fillWishPhotos`): маленькая картинка = «фото не нашлось» — адрес в `tried`, загрузки нет.
4. Без новых кнопок и текста (правило 12): плитка остаётся с иконкой-заглушкой, своё фото — существующей кнопкой камеры.

## Тесты

- Юнит порога: 120×120 и 1200×200 → нет; 300×300 и 800×600 → да.
- `wishLinkPhotos.test`: превью отдаёт картинку 120×120 → `upload` не вызван, адрес в `tried`, повторно не спрашивается.
- DOM вставки (`Wishes.link.dom.test.ts` / лист): маленькая картинка → `uploadPhoto` не вызван, название подставлено.

## Критерии приёмки

- Стенд (мок ручки превью): картинка 120×120 — желание без фото, название есть; 800×800 — фото ставится, как раньше.
- На телефоне владельца: ссылка Pinduoduo — логотипа больше нет, плитка без фото; ссылка Kaspi — фото как раньше.
- `cd frontend && npm run build && npx vitest run` зелёные.

  «логотипов» по адресам.
