  `uploadPhoto` — `lib/photos/store.ts`; API — `api/client.ts` ~200–221.

## Задача

1. `api/client.ts`: `linkPreview(url)` → `{ title, blob }` (base64 → `Blob` типа `imageType`) или типизированная ошибка.
2. Добавление и правка желания: поле «Ссылка» (вставка из буфера); после вставки — превью: фото (сжатое
   `compressImage` из полученного `Blob`) и название (подставляется в «Название», правится); цена — пустая, вводит
   пользователь; «Добавить» — загрузка фото (`uploadPhoto`) и запись желания как сейчас. Ссылку на товар сохранить
   в уже существующее `WishItem.url?` (`types/finance.ts` ~126).
3. Не вышло (ошибка, нет картинки, таймаут) — одна строка «Фото не нашли — загрузите своё» и та же кнопка файла,
   название — что удалось взять; ничего не ломается.
4. Демо и viewer: поля ссылки нет (демо — тихая строка «по ссылке — в приложении»).

## Тесты

- `api/client.test.ts` (или рядом): base64 → `Blob` нужного типа; ошибки 400/422 → типизированные.
- DOM-тест листа желания: вставка ссылки → превью (мок клиента) → «Добавить» пишет желание с фото, названием и
  ссылкой; ошибка → строка «загрузите своё», желание без фото добавляется.
- SSR: viewer и демо — без поля ссылки.

## Критерии приёмки

- На стенде (Go локально с B2C-65): ссылка Kaspi на товар → фото и название; партнёр видит желание с фото.
