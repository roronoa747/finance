# B2C-71 — Фото хранятся на телефоне (фронт) · возврат смоука 2 Блока 12

Блок 12 (возврат смоука 2) · MVP · Репо/каталог: `frontend/src/` · Зависит от: B2C-17 · Роли: все, кто видит фото (member, viewer) · Ветка: `b2c-block-12-smoke-2`

## Контекст (что уже есть)

- Смоук владельца 2 (2026-10-03): «фото прогружаются долго; когда обновишь — не сразу появляются». Решение владельца:
  **фото хранить на телефоне** — после обновления/перезапуска видны сразу, без повторной загрузки; выход стирает.
- `lib/photos/store.ts`: `photoUrl(id)` → `client.getPhoto(id)` (`GET /api/photos/{id}` с `Authorization`) → object URL;
  кэш `urls`/`pending`/`missing` — **только в памяти на сессию**. Ответ ручки уже `Cache-Control: private,
  max-age=31536000, immutable`, но `fetch` с токеном + object URL постоянного кэша не даёт. Фото по id неизменны
  (замена фото = новый id), поэтому копию на телефоне не нужно сверять с сервером.
- `forgetPhoto(id)` — после удаления/замены; `releasePhotos()` — в `clearAuth` (`stores/auth.ts`), освобождает URL.
  Документы семьи на телефоне стирает `finance.clearLocal()` (выход без «keep», вход в другую семью — `claimFor`).
- Подарок-сюрприз (`hidden`) отдаётся только автору — его копия ляжет только на телефон автора.

## Задача

1. **Хранилище байтов фото на устройстве** — `lib/photos/disk.ts`: интерфейс `{ get(id): Promise<Blob | null>;
   put(id, blob): Promise<void>; remove(id): Promise<void>; clear(): Promise<void> }` на **Cache API**
   (`caches.open('ff-photos')`, ключ — синтетический адрес по id). Нет `caches` (старый браузер, тест без него) или любая
   ошибка хранилища (квота, приватный режим) → тихо как сейчас: читать из сети, не падать, ничего не показывать.
2. **`photoUrl`**: память → диск → сеть. С диска — object URL сразу, без запроса. Из сети — положить на диск (не
   дожидаясь записи для показа). 404 на диск не пишется; сбой сети — как сейчас (не кэшируется).
3. `forgetPhoto(id)` и `deletePhoto(id)` убирают и копию на диске. **Стирание** — вместе с документами семьи: в
   `finance.clearLocal()` (выход без «keep», вход в другую семью) — `disk.clear()`. `releasePhotos()` по-прежнему
   только память (истёкший вход с «keep» — та же семья, фото остаются).
4. Демо — как сейчас (фото демо не грузятся с сервера). Без кнопок, текста, спиннеров (правило 12).

## Тесты

- Юнит `store` (диск — подменённый in-memory по интерфейсу): второй `photoUrl` после «перезапуска» (сброс памяти без
  `clear` диска) — 0 вызовов `getPhoto`; 404 не на диске; `forgetPhoto` убирает с диска; диск бросает → фото всё равно
  из сети.
- Юнит `disk` (если в среде теста есть `caches` — иначе подмена `globalThis.caches`): `put`/`get`/`remove`/`clear`.
- `finance` / `auth`: выход (`clearLocal`) зовёт `disk.clear()`; выход «keep» — нет.

## Критерии приёмки

- Стенд: открыли «Желания» с фото → перезагрузка страницы → фото видны без `GET /api/photos/*` (сеть Chrome); выход →
  кэш `ff-photos` пуст.
- На телефоне владельца: после перезапуска PWA фото в «Желаниях» и «Мечтах» появляются сразу.
- `cd frontend && npm run build && npx vitest run` зелёные.

## Вне скоупа

- Кэш в service worker; ограничение размера/вытеснение (фото сжаты, их десятки); предзагрузка всех фото семьи;
  изменения Go-ручки.
