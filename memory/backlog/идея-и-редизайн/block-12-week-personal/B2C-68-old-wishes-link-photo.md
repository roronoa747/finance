# B2C-68 — Фото у старых желаний со ссылкой (фронт) · возврат смоука Блока 12

Блок 12 (возврат смоука) · MVP · Репо/каталог: `frontend/src/` · Зависит от: B2C-66 · Роли: member · Ветка: `b2c-block-12-smoke`

## Контекст (что уже есть)

- Смоук владельца на проде 2026-10-03: «с ссылок фотки не подтягиваются» — у желаний, где ссылка Kaspi была сохранена
  **до** Блока 12. B2C-66 берёт фото только в момент вставки ссылки (`useLinkPreview.schedule` в `Wishes.vue` и
  `WishSheet.vue`); сохранённую ссылку никто не обходит. Логи Vercel: с телефонов ни одного `POST /api/photos/preview`.
- Модель: `WishItem { url?: string; photoId?: string | null; deletedAt? }` (`types/finance.ts`). Путь фото со страницы:
  `apiClient.linkPreview(url)` → `File` → `compressImage` → `uploadPhoto` → `finance.setWishPhoto(id, photoId)` — весь
  есть в `Wishes.vue` (`applyLink` + `createWish`) и `WishSheet.vue` (`onLink` → `onFile`).
- Ручка `POST /api/photos/preview` без лимита запросов (хвост §4 → B2C-26): обход должен быть бережным.
- Демо: фото не загружаются (`isDemo`), как у B2C-66.

## Задача

1. **Обход при открытии «Желаний»** (`Wishes.vue`): живые желания с `url` (https) и без `photoId` — по одному,
   последовательно, **не больше 10 за открытие экрана**; у каждого: превью → сжатие → `uploadPhoto` → `setWishPhoto`.
   Перед записью проверить, что желание ещё живо и без фото (партнёр мог удалить или поставить своё).
2. **Без повторов**: адрес, по которому фото не нашлось (или ручка отказала), запоминается на телефоне
   (`readStorage`/`writeStorage` из `lib/storage`, ключ `ff_link_photo_tried`, список адресов, ≤ 200 записей) и в
   следующий раз не запрашивается. Успех помечать не нужно — у желания появляется `photoId`.
3. Без новых кнопок и текста (правило 12): фото просто появляются в плитках и строках, пока человек смотрит список;
   `PhotoSlot`/плитка — без спиннера. Один общий «идёт» не нужен.
4. Логику обхода — в `lib/photos/` рядом с `useLinkPreview` (функция с зависимостями `deps` по образцу
   `goalPhoto.ts`: `preview`, `compress`, `upload`, `tried`), экран только вызывает её после загрузки списка.
   Отмена при уходе с экрана (`onScopeDispose`), чтобы ответ не записывался в размонтированный экран.

## Тесты

- Юнит (`lib/photos`): три желания со ссылкой без фото + одно с фото + одно без ссылки → ровно три превью, по очереди;
  отказ («no image») → адрес в `tried`, повторный вызов его не запрашивает; желание удалено между превью и записью →
  `setWishPhoto` не вызван; лимит 10.
- DOM (`Wishes.*.dom.test.ts`, по образцу `Wishes.link.dom.test.ts`): открыли «Желания» с двумя старыми желаниями
  Kaspi → у обоих появилось фото, `uploadPhoto` дважды; демо — ни одного вызова.

## Критерии приёмки

- На проде у владельца: открыть «Желания» — у старых желаний со ссылкой Kaspi появляются фото; у ссылок без картинки
  — ничего не меняется, повторных запросов в логах нет.
- `cd frontend && npm run build && npm test` зелёные.

## Вне скоупа
