# B2C-72 — Фото по ссылке ищутся при запуске, в фоне (фронт) · возврат смоука 2 Блока 12

Блок 12 (возврат смоука 2) · MVP · Репо/каталог: `frontend/src/` · Зависит от: B2C-68, B2C-71 · Роли: member (viewer — нет, ручка 403) · Ветка: `b2c-block-12-smoke-2`

## Контекст (что уже есть)

- Смоук владельца 2 (2026-10-03): «пока не зайдёшь — не прогружаются». Решение владельца: искать **при запуске, в
  фоне** — после входа и первого синка, не дожидаясь «Желаний»; та же бережность, лимит, память, гейт участника.
- B2C-68: `fillWishPhotos(store, deps?, signal?)` (`lib/photos/wishLinkPhotos.ts`) — кандидаты `wishesNeedingPhoto`,
  по одному, ≤ `LINK_PHOTOS_PER_OPEN` (10) запросов за вызов, память `ff_link_photo_tried`, `inFlight` по id (второй
  вызов то же не грузит), исключение (сеть, 401, 429, 5xx) — обход прерван. Сейчас зовётся только в `Wishes.vue`
  `onMounted` с гейтом `canEdit` и отменой в `onScopeDispose`. Критик Б12 заметил: на первом открытии после входа
  документа ещё нет — кандидатов нет.
- Старт приложения: `stores/syncEngine.ts` `startSyncEngine` — первый круг `syncHousehold()` при входе; вход в семью —
  `finance.enterFamily` (`Access.vue`) → `pullHousehold`. Демо — `finance.isDemo`, viewer — `auth.isViewer`.

## Задача

1. **Запуск обхода в фоне** — один раз за запуск приложения, **после первого успешного синка/загрузки документа
   семьи** (запуск с уже выполненным входом и вход в семью в этой же сессии). Условия: вошёл, не демо, не viewer, сеть
   есть. Место — рядом с движком синка (`syncEngine.ts` или маленький модуль в `lib/photos/`, зовущий его), без нового
   UI. Отмена (`AbortController`) — при выходе.
2. Вызов на «Желаниях» (`onMounted`) **остаётся** — он подхватывает желания, добавленные позже; дублей нет за счёт
   `inFlight` и `tried`. Лимит 10 — на каждый вызов (запуск + открытие экрана ≤ 20 за сессию).
3. Никаких спиннеров и текста (правило 12): фото появляются в «Мечтах» и «Желаниях», когда готовы. Фото, загруженное
   обходом, сразу ложится на телефон (B2C-71, через `uploadPhoto` → показ — по общему пути).

## Тесты

- Юнит (по образцу тестов `syncEngine`/`wishLinkPhotos`, deps подменены): после первого успешного синка — один вызов
  обхода; второй синк (фокус, интервал) — повторного запуска нет; демо, viewer, нет сети — 0 вызовов; выход — `signal`
  отменён.
- DOM `Wishes.*`: открыли «Желания», пока фоновый обход идёт, — тот же адрес не запрашивается дважды.

## Критерии приёмки

- Стенд: перезагрузка на «Неделе» (не заходя в «Желания») с двумя старыми желаниями со ссылкой без фото → превью ровно
  по двум, фото на сервере; потом «Желания» — 0 новых запросов. Viewer — 0 вызовов. Демо — 0 вызовов.
- `cd frontend && npm run build && npx vitest run` зелёные.

## Вне скоупа
