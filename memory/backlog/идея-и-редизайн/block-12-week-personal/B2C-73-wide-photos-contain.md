# B2C-73 — Широкие фото желаний целиком (фронт) · возврат смоука 2 Блока 12

## Контекст (что уже есть)

- Смоук владельца 2 (2026-10-03): «широкие плохо видно» — у баннеров Kaspi (контроллер, стол с надписями) в квадратной
  плитке видна середина, края срезаны. Решение владельца: **заметно шире квадрата — вписать целиком на мягком фоне
  плитки** (токен); квадратные и высокие — как сейчас, на всю плитку.
- Фото желания показывают: `components/goals/WishTile.vue` (квадрат `aspect-square bg-surface-3`, `<img … object-cover>`),
  `components/goals/WishSheet.vue` → `PhotoSlot.vue` (`h-[180px] bg-surface-3`, `object-cover`; `PhotoSlot` общий с
  целями), «Мечты» → `components/kit/ThumbRow.vue` (миниатюры желаний), «Желания» → `components/goals/WishRow.vue`
  (строки купленных/подарков).

## Задача

1. **Правило «широкое»** — одно место (`lib/photos/`, напр. `fit.ts`): по `naturalWidth / naturalHeight` после `load`
   картинки — `≥ 1.25` → «вписать» (`object-contain`), иначе `object-cover`. Порог — константа рядом с правилом.
2. Применить к **фото желаний**: `WishTile` и фото в `WishSheet` (в `PhotoSlot` — опцией, цели не меняются), а также
   к миниатюрам желаний в `ThumbRow`/`WishRow`, если они квадратные и режут так же. Фон под вписанным — существующий
   фон плитки (`bg-surface-3` — токен с парой для тёмной темы), без новых цветов и рамок.
3. До `load` — как сейчас (`object-cover`), без мигания-заглушки; переключение класса — без анимации.
4. Без текста и действий (правило 12).

## Тесты

- Юнит правила: 1200×400 → contain, 800×800 и 600×900 → cover, 0×0 (битая) → cover.
- DOM `WishTile`: событие `load` с подменёнными `naturalWidth/naturalHeight` → класс `object-contain`; квадратное —
  `object-cover`.

## Критерии приёмки

- Стенд (390 px, обе темы): желание с широким фото (1200×400) — видно целиком на мягком фоне; квадратное — на всю
  плитку; лист желания — так же. Снимки — scratchpad, путь в Handoff.
- `cd frontend && npm run build && npx vitest run` зелёные.

## Вне скоупа
