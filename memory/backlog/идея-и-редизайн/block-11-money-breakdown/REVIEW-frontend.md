## Находки

### Н-1 · средняя · Карточка «Пришла зарплата» разбирает на части собственные строки `finance.ts`

`frontend/src/views/Statements.vue:405`, `frontend/src/lib/finance.ts:3015`, `:3494-3497`. `usualCard` склеивает `meta` из двух
частей через « · », а экран режет её обратно `decision.meta.split(' · ')[0]` / `[1]`, чтобы покрасить «останется N ₸» /
«не хватает N ₸». Адрес «Ваш порядок» собирается так же: `` `/week/order?${path.split('?')[1]}` `` из адреса кольца. Если в
подпись попадёт ещё одна « · » (имя, месяц) или у `breakdownPath` поменяется вид — карточка молча покажет не то, тесты на
полный текст этого не поймают.

**Рекомендация.** `usualCard` возвращает части: `{ question, lead: 'Как в сентябре' | 'По вашему порядку', outcome:
'останется N ₸' | 'не хватает N ₸', meta }` (`meta` = `` `${lead} · ${outcome}` `` для очереди/главного); экран берёт `lead` и
`outcome`. Адрес — общий помощник `` withQuery(path, query) `` в `finance.ts`, `breakdownPath` и путь «Ваш порядок» — через него
(`orderPath(source)`). Тест `finance.test.ts`: `usualCard` даёт `lead`/`outcome`; DOM-тест карточки как есть.

**Вердикт: клинап**

### Н-2 · средняя · «Разложить как обычно» без счёта уводит на кольцо — ветка без теста

`frontend/src/views/Statements.vue:208-211`. Если счёт не известен (`breakdownAccount` → `undefined`), а разбор двигает деньги
(взнос в копилку, досрочка), карточка не пишет запись, а открывает кольцо — там спросят счёт. Все DOM-тесты карточки
отмечают зарплату с `accountId: null` («не двигать») (`Statements.dom.test.ts:128,173,236…`), e2e Блока 11 — со счётом;
ветку `undefined` не проходит ни один тест — мутация «убрать `return`» выживет и запишет разбор без счёта.

**Рекомендация.** DOM-тест в `Statements.dom.test.ts`: отметка зарплаты без `accountId`, у семьи есть счёт и копилка с
недобранным порогом (взнос «Запаса» > 0), порядок пройден → «Разложить как обычно» → маршрут кольца
(`/week/breakdown?from=salary…`), `allocations` пусты. Проверить мутацией.

### Н-3 · средняя · «Ваш порядок» не загружает выписки — подсказка «по выпискам прошлого месяца» пропадает

`frontend/src/views/YourOrder.vue:28,99-102`. Подсказка суммы «Жизни» и «Трат» берёт `ops.uploads`, но экран их не грузит:
загрузки есть, только если до него открывали «Неделю», «Деньги», «Мечты» или кольцо. Открытый по ссылке, после перезапуска
PWA или из истории браузера — `articleFact` → `null`, кнопки «по выпискам прошлого месяца 180 000 ₸» нет. Ровно эту ошибку
исполнитель нашёл на стенде у кольца и закрыл `Breakdown.vue:44` (Handoff B2C-60, «Найдено на стенде»); у соседнего экрана
она осталась.

**Рекомендация.** `onMounted(() => void ops.loadUploads())` в `YourOrder.vue` с той же строкой-причиной, что у
`Breakdown.vue:43`; DOM-тест в `YourOrder.dom.test.ts` по образцу кольца: стор без загрузок, ответ API с загрузкой прошлого
месяца → лист «Жизни» показывает подсказку; мутацией убедиться, что ловится.

### Н-4 · средняя · Лист «Траты»: «Не разобрано» входит в базу долей, но строки не получает

`frontend/src/lib/finance.ts:2834-2853`, `frontend/src/components/money/LivingWidget.vue:46-58`. База доли —
`monthSpentByFact` (с «Не разобрано»), строки — без него (`:2841`). Два следствия: строки не добивают до суммы виджета (приёмка,
наблюдение 1: демо — 83 200 из 94 000 ₸, 89 %), и доли разделов занижены против черты — нормы (`norms.ts`) считаны без
незнакомых трат, поэтому при заметном хвосте ИП статус склоняется к «в норме». Сейчас это не ошибка денег (суммы верны), а
вопрос подачи; хвост незнакомых сокращает B2C-61 «Хвост ИП пачкой» (Блок 12).

**Рекомендация.** Два пути, выбор — владельцу: (а) строка «Не разобрано» внизу листа без черты, тег считает только разобранное
(база тега — без неё); (б) база долей без «Не разобрано», а под строками — тихая строка «ещё N ₸ не разобрано». Делать вместе
с B2C-61, когда станет видно, сколько хвоста остаётся.
