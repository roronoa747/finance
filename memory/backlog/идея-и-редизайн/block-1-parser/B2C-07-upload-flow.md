## Задача

1. **Стор операций** `stores/operations.ts`: собственные операции пользователя — локальная копия
   (`localStorage['ff_operations']`, курсор `ff_operations_cursor`; при входе в другую семью /
   выходе — очищается, как документ), `pull()` по курсору, `pending` — батчи, не ушедшие без сети
   (повтор на `online` и при следующем `pull`). Список загрузок семьи — `uploads` (`GET
   /api/statements`, обновляется при открытии экрана).
2. **Экран `/statements`** («Выписки», ленивый чанк): список загрузок семьи (кто — имя из
   `people` по `slot`, банк, период, число операций); кнопка «Загрузить выписку» (member; в демо —
   разбор и итоги локально, без запросов, список загрузок — локальный); **простая картина**:
   таблица «эта неделя / этот месяц» по разделам трат из `spendTotals` обоих участников
   (`categoryName` из `spendCategories`, `_unknown` — «не разобрано»), пометка «без выписки
   <имя>», если у участника нет загрузки за период.
3. **Поток загрузки** (файл → предпросмотр → вопросы → отправка), всё на устройстве:
   - выбор файлов (`accept` pdf/xlsx, несколько) → `detectBank` → разбор; не распознан → спокойный
     текст «Пока понимаю выписки Kaspi и Freedom»;
   - `seedSpendCategories`, `applyRules` (память из личного документа), `pairInternalTransfers`,
     подсказка «это перевод партнёру?» для `counterparty`, совпадающего с именем участника;
   - предпросмотр: период, число операций, «из них уже были» (id есть в локальной копии), суммы
     списаний / поступлений / внутренних, список **незнакомых** продавцов и получателей с
     `Select` раздела (или «внутренний перевод» / «кому → что» текстом) — ответ пишет правило
     в личный документ и пересчитывает; пропустить можно;
   - «Отправить»: `POST /api/statements` → батчи `POST /api/operations/batch` (по 500) → локальная
     копия → **пересчёт `spendTotals`** по затронутым неделям и месяцам из **всех** своих операций
     периода (не только новых) → `mutateHouseholdDoc` (записи по id, замена целиком) → список
     загрузок обновлён. Без сети — батчи в `pending`, итоги считаются сразу, экран честно говорит
     «отправится при сети».
   - Повторная загрузка того же периода: те же id → upsert, итоги те же; предпросмотр показывает
     «все N уже были».
4. **Входы**: лист «+» — «Загрузить выписку» первым действием; в Ритуале — карточка «Выписки
   недели» со ссылкой на `/statements`.
5. **Смена категории задним числом**: в таблице картины нажатие на раздел открывает список
   незнакомых/спорных продавцов периода с `Select` — правило + пересчёт итогов (простая форма;
   «по одному решению» — Блок 3).

- `e2e/b2c-block1-parser.test.ts` (стенд двух телефонов + фейковые ручки B2C-06): A загружает
  фикстуру Kaspi → фейковый сервер получил запись загрузки и операции A; документ семьи содержит
  `spendTotals` A; B видит итоги и запись загрузки, **не** видит операций (в его сторе пусто);
  A загружает тот же файл снова → операций столько же, итоги те же; B загружает Freedom → таблица
  картины складывает обоих; A офлайн → `pending`, после `online` — на сервере.

## Критерии приёмки

- Браузер, локальный стенд с Postgres (`DATABASE_URL` одноразовой БД), два профиля, 390px:
  настоящая выписка из корпуса → предпросмотр без имён с 6+ цифрами, вопросы, отправка; во
  вкладке Network **нет** запроса с файлом (только JSON без сырых строк выписки); в таблице
  `app.operations` нет 6+ цифр подряд в текстовых полях (SQL-проверка); партнёр видит итоги и
  запись загрузки, операции — нет; повторная загрузка не удваивает; офлайн-загрузка досылается.
- `cd frontend && npm run build && npm test` зелёные; чанки pdf.js/xlsx грузятся только на
  `/statements`.
