# Блок 1 — Парсер и операции · сессии

**Цель блока:** выписки Kaspi и Freedom разбираются на телефоне в личные операции без ФИО и
номеров, семья видит итоги по разделам, повторная загрузка ничего не удваивает — владелец и
партнёр начинают недельный ритм ещё до редизайна; замер незнакомых названий решает судьбу
Блока 6.

Сессии: исполнитель ⬜ · критик ⬜ · приёмка ⬜ · ревью backend ⬜ · ревью frontend ⬜ · клинап ⬜

## Промпт исполнителя — уровень build · Opus 5 · effort high (ultrathink)

```

```

Блок-специфика:

- **Предусловие:** корпус выписок владельца лежит в `memory/secrets/statements/kaspi/` и
  `memory/secrets/statements/freedom/` (вне git). Нет — остановиться на B2C-01, написать в
  Handoff и попросить владельца; дальше не идти.
- Ветка `b2c-block-1-parser` от `main`. Push — с согласия владельца; `main` не трогать;
  **прод-БД не трогать** (миграция `000002` в прод — клинап).
- Задачи по порядку: B2C-01 → B2C-02 → B2C-03 → B2C-04 → B2C-05 → B2C-06 (Go) → B2C-07 →
  B2C-08. Формат выписок — только из `CORPUS.md` (B2C-01), не по памяти.
- Среда: для B2C-06/B2C-07 нужен реальный Postgres — локальный/Docker одноразовый
  (`TEST_DATABASE_URL` и `DATABASE_URL` для `go run ./cmd/server`, **не** Supabase; строка — в
  `memory/secrets/`, в Handoff — только ссылка); на моках — хендлер-тесты. Два профиля
  браузера (владелец и партнёр), 390px.
- Приватность (L): ни одно текстовое поле операции не содержит 6+ цифр подряд и полного ФИО
  (Р-23) — проверяется тестами парсеров, гвардом сервера и SQL-запросом на стенде; файл
  выписки на сервер не уходит (Network). В Handoff — ни имён, ни сумм из корпуса.
- Новые зависимости, разрешённые ТЗ: `pdfjs-dist` (B2C-01); одна библиотека xlsx — только если
  Freedom в корпусе xlsx (B2C-04). Другие — нет.
- Верификация: `cd frontend && npm run build && npm test` (фикстуры, e2e); `cd backend && go
  build ./... && go vet ./... && go test ./...` + PG-режим; корень `go vet ./api/... && go test
  ./api/...`; браузер по критериям B2C-07.
- Handoff: помимо обычного — цифры замера B2C-08 и строка в §4 «Блок 6 открыт/отменён»;
  сколько файлов корпуса разобрано без `skipped`.
- Следующий шаг — `/critic идея-и-редизайн 1 ultracode`.

## Промпт критика — уровень review · Opus 5 · effort xhigh (ultracode)

```
/critic идея-и-редизайн 1 ultracode
```

Блок-специфика:

- Приватность: перебрать все пути текста из выписки до сервера (парсер → `sanitize` →
  правило → батч → SQL) — цифры 6+ и ФИО нигде не просачиваются; фикстуры и `CORPUS.md` без
  имён/сумм; логи Go без тел операций.
- Деньги: `spendTotals` = сумма списаний по разделам, внутренние переводы и приходы исключены;
  пересчёт итогов из **всех** операций периода, а не только новых; повторная загрузка — те же id.
- Личный документ: 409, правка во время запроса, два устройства одного человека; правило
  продавца не утекает партнёру.
- Go: миграция `000002` только добавляет, `app.`-квалификация, PK `(user_id, id)`, курсор без
  пропусков, viewer 403, чужая семья ничего не видит.
- Актуализировать промпт Блока 2 (дизайн): что реально показывает загрузка (поля операции,
  разделы трат, «без выписки <имя>», незнакомые) — дизайнеру нужны факты, не догадки; и
  промпт Блока 3 в части фактов кода (стор операций, экран `/statements`).
- Решение по Блоку 6 (B2C-08) — проверить арифметику и запись в §4/шапке.
