# B2C-03 — Парсер Kaspi (фронт)

Блок 1 · MVP · Каталог: `frontend/src/lib/statements/parsers/` · Зависит от: B2C-02 · Роли: —

## Контекст (что уже есть)

- `CORPUS.md` (B2C-01) — фактический формат выписки Kaspi: шапка с периодом и признаками
  банка, колонки таблицы, форматы даты и суммы, виды операций, многострочные детали. **Формат
  брать оттуда, не по памяти.** Ожидание до инвентаризации (уточняется): таблица «Дата · Сумма ·
  Операция · Детали», сумма вида `- 12 500,00 ₸` / `+ 250 000,00 ₸`, операции «Покупка»,
  «Перевод», «Пополнение», «Снятие», «Разное»; в шапке — ФИО держателя и номер карты (в
  результат не попадают).
- Строки — `pdfToRows` (B2C-01, `PdfRow = { page, y, cells: { x, text }[] }`); фикстуры —
  `lib/statements/fixtures/kaspi-NN.rows.json`.
- Модель — B2C-02: `Operation`, `OperationKind`, `fingerprint`, `sanitize`,
  `ParsedStatement`.
- Р-23: результат без 6+ цифр и полных ФИО; имена переводов — как печатает банк (имя и инициал).

## Задача

1. `parsers/kaspi.ts`: `isKaspi(rows): boolean` (признаки шапки) и `parseKaspi(rows):
   ParsedStatement`: период из шапки; колонки по `x` (границы — по заголовку таблицы, не по
   константам); дата → `YYYY-MM-DD`; сумма → целые тенге со знаком (тиын отбрасываются);
   «Операция» → `OperationKind` (таблица соответствий — данные модуля); «Детали» → `merchant`
   (покупки) или `counterparty` (переводы человеку: имя и инициал) + `note`; многострочные
   детали склеиваются; строки не-операций (итоги, «нет операций», колонтитулы) пропускаются;
   `id` — `fingerprint` с `ordinal` внутри дня; `sanitize` на всех текстовых полях.
2. Ошибки: не Kaspi → `StatementFormatError('not-kaspi')`; таблица не найдена / нет ни одной
   строки → `StatementFormatError('empty')`; неразобранная строка внутри таблицы — не падать,
   считать в `skipped` (поле результата) и логировать в dev.
3. Реестр `parsers/index.ts`: `detectBank(rows): BankId | null`, `parseStatement(rows):
   ParsedStatement` (Kaspi здесь, Freedom — B2C-04 добавляет).

## Тесты

- `parsers/kaspi.test.ts` на всех фикстурах Kaspi: количество операций и `skipped`; период; для
  проверенных вручную строк — дата, сумма, вид, `merchant`/`counterparty`; суммы по видам за
  файл (эталон посчитан руками по фикстуре и записан в тесте); идемпотентность — два разбора
  одной фикстуры дают те же id; два одинаковых платежа в день — разные id.
- Гвард: ни в одном поле результата нет 6+ цифр; `merchant` не пустой у покупок.
- Не-Kaspi строки (фикстура Freedom или синтетика) → `not-kaspi`.

## Критерии приёмки

- `cd frontend && npm run build && npm test` зелёные.
- Прогон по **всему корпусу Kaspi** локально (скрипт B2C-01 + временный вызов парсера в Node
  или тест-замер B2C-08 в режиме «только парсер»): по каждому файлу — число операций против
  итога банка в выписке (если банк печатает итоги), `skipped` = 0 или объяснён; результат — в
  Handoff (без сумм и имён).
