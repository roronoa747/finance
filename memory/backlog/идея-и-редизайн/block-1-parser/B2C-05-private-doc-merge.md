# B2C-05 — Личный документ: слияние и синк как у общего (фронт; бывший RP-15)

Блок 1 · MVP · Каталог: `frontend/src/stores/finance.ts`, `stores/syncEngine.ts`, `lib/merge.ts` · Зависит от: — (B2C-02 добавляет `merchantRules`) · Роли: все

## Контекст (что уже есть)

- Р-22: память семьи `merchantRules` живёт в личном документе; у одного человека два устройства
  (телефон + ноутбук) — личный документ получает правки с обоих, как общий. Позже туда же —
  скрытые подарки (Блок 3, B2C-18).
- Стор `stores/finance.ts`: `privateDoc` (`Record<string, unknown>`, сейчас `accounts`),
  `privateRev`, `privateUnsent`; `pullPrivateDoc` кладёт серверную копию **поверх** локальной;
  `pushPrivateDoc(data)` пушит с `privateRev` **без слияния** — при 409 бросает ошибку;
  `mutatePrivateDoc` — путь правки. Общий документ для сравнения: `syncHousehold` (GET →
  `mergeDocs` → push, до 4 попыток на 409, `unsent`/`forceReplace`, защита правок, пришедших во
  время запроса) и `pullHousehold`.
- Хвост RP (§4, судьба — эта задача): неудачный push личного (нет сети; 409 — личный не сливается,
  ревизия не обновится до входа, все следующие push тоже 409) ждёт следующей личной правки или
  входа.
- Сервер: `GET/POST /api/sync/private` — тот же протокол ревизий (`last_seen_rev`, 409 с
  `server_doc`); ключи верхнего уровня, которых нет в push, сервер сохраняет.
- `lib/merge.ts`: `mergeList` по id (LWW + надгробия, поля проигравшего не теряются),
  `mergeUnknownKeys`. Движок `stores/syncEngine.ts` — синк общего документа по событиям
  (`online`, `focus`, `visibilitychange`, интервал 60 с); где синкается личный сейчас — проверить.
- Демо: личный документ в демо на сервер не ходит.

## Задача

1. `mergePrivateDocs(local, remote)` в `lib/merge.ts`: `accounts` и `merchantRules` — `mergeList`
   по id; незнакомые ключи — как `mergeUnknownKeys` (списки с id — по id, иначе LWW/локальный).
2. Синк личного документа по схеме общего: GET → слить → push, повтор на 409 (до 4), правка во
   время запроса не затирается; `pullPrivateDoc` при `privateUnsent` сливает, а не перекрывает.
   Переиспользовать механику `syncHousehold` (параметризовать: документ, ревизия, флаг, клиент,
   слияние), а не копировать; если параметризация раздувает код — решение и причина в Handoff.
3. Движок синкает и личный документ теми же событиями и интервалом (если сейчас не синкает);
   неудачный push личного повторяется на следующем круге, а не ждёт правки.
4. Бейдж синка учитывает личный документ (неотправленная личная правка — «ждёт отправки»,
   ошибка личного — «не сошлось»).

## Тесты

- `lib/merge.test.ts`: личные документы с двух устройств — счета и правила объединяются,
  надгробие побеждает, незнакомый ключ не теряется.
- `stores/finance.test.ts`: 409 на личном push → слияние и повтор, правка цела; правка во время
  запроса не затёрта; неудачный push (сеть) → следующий круг движка досылает.
- `e2e/two-clients-sync.test.ts`: один пользователь, два клиента, разные личные правки офлайн →
  обе на сервере; партнёр личного не видит (как раньше — ожидания не меняются).

## Критерии приёмки

- Существующая изоляция личного (`two-clients-sync.test.ts`) зелёная без правок ожиданий.
- `cd frontend && npm run build && npm test` зелёные; браузер: два профиля одного пользователя
  (один email, два входа) — правило продавца с одного видно на другом после синка.
