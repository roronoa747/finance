# B2C-01 — Инвентаризация корпуса, стенд pdf.js, обезличенные фикстуры (фронт)

Блок 1 · MVP · Каталог: `frontend/` (+ `memory/backlog/идея-и-редизайн/block-1-parser/CORPUS.md`) · Зависит от: корпус владельца в `memory/secrets/statements/` · Роли: —

## Контекст (что уже есть)

- Р-4: выписка разбирается на телефоне, банки на старте — Kaspi и Freedom, корпус владельца
  лежит вне git в `memory/secrets/statements/` (каталог в `.gitignore`, pre-commit-хук блокирует
  файлы из `secrets/`). Р-23: парсер — две ступени (файл → строки → операции), фикстуры тестов —
  обезличенные строки, снятые с корпуса; в результате нет последовательностей из 6+ цифр и
  полных ФИО.
- **Предусловие:** владелец кладёт выписки в `memory/secrets/statements/kaspi/` и
  `memory/secrets/statements/freedom/` (имена файлов любые). Каталога нет или он пуст →
  остановиться, написать в Handoff и попросить владельца; дальше не идти.
- Кода парсера в репо нет; `pdfjs-dist` в зависимостях нет (`frontend/package.json`:
  `vue`, `pinia`, `vue-router`, `radix-vue`, `@phosphor-icons/vue`; dev — `vitest`, `happy-dom`,
  `vite-plugin-pwa`). Тесты — Vitest в Node без DOM (§6). Ленивые чанки — образец
  `router/index.ts` (`() => import(...)`).
- pdf.js в Node: legacy-сборка (`pdfjs-dist/legacy/build/pdf.mjs`) читает текст без `canvas`;
  в браузере — обычная сборка, worker подключается как URL пакета (`?url` во Vite).
- Секрет-хук ловит строки, похожие на пароли и ключи, — обезличенные фикстуры не должны
  содержать «password: …» и т.п.

## Задача

1. **Инвентаризация корпуса** → `block-1-parser/CORPUS.md` (в git; **только структура, без
   имён, номеров и сумм**): по каждому банку — формат (PDF / xlsx / оба), сколько файлов и за
   какие месяцы, страниц в файле, что в шапке (период, признаки банка), колонки таблицы и их
   порядок, форматы даты и суммы (разделители, знак, символ валюты), виды операций и как
   печатаются перевод человеку, перевод между своими счетами/банками, зарплата, платёж по
   кредиту, подписка, комиссия, снятие наличных; многострочные «Детали»; что меняется от месяца
   к месяцу; какие поля содержат ФИО, номера карт/счетов/ИИН (что именно вычищать).
2. **Ступень «файл → строки»**: `frontend/src/lib/statements/pdf.ts` — `pdfToRows(data:
   ArrayBuffer): Promise<PdfRow[]>` (`PdfRow = { page, y, cells: { x, text }[] }`): текстовые
   элементы страницы группируются в строки по `y` с допуском, внутри строки — по `x`; функция
   группировки — чистая (`groupItems(items)`) и тестируется без PDF. Загрузка `pdfjs-dist` в
   приложении — ленивая (`import()`), worker — из пакета; в Node (скрипты, тесты) — legacy-сборка
   (выбор по среде в одном месте). Добавить `pdfjs-dist` в `dependencies`.
3. **Снятие строк с корпуса**: `frontend/scripts/statement-rows.mjs` (Node): читает файлы из
   `STATEMENTS_DIR`, пишет `rows.json` по каждому файлу **в scratchpad / каталог вне git**
   (путь — аргументом). Для xlsx (если формат есть в корпусе) — записать в `CORPUS.md`, какая
   библиотека нужна (B2C-04), строки xlsx снимать не обязательно.
4. **Обезличенные фикстуры** `frontend/src/lib/statements/fixtures/<bank>-<NN>.rows.json`
   (по 2–3 на банк, из разных месяцев; покрыть: покупки, перевод человеку, перевод между своими
   счетами, зарплата, платёж по кредиту, подписка, комиссия, наличные, многострочные детали,
   граница месяца/страницы). Обезличивание — скриптом `frontend/scripts/statement-anon.mjs`
   с проверяемыми правилами: ФИО/имена → «Имя Ф.» из фиксированного списка, названия
   продавцов реальные оставить (они и есть словарь), цифровые последовательности 6+ → убрать,
   суммы → детерминированно заменить (тот же знак и порядок величины), период → сдвинуть.
   Что заменено и как — в шапке `CORPUS.md`.
5. Тест-гвард фикстур `fixtures.test.ts`: ни в одной фикстуре нет последовательности из 6+
   цифр, слов «password», IBAN-подобных строк (`KZ` + 18 знаков), фамилий владельца и партнёра
   (список — в `memory/secrets/statements/README.md`, тест читает его только если файл есть;
   в CI — базовые правила).

## Тесты

- `lib/statements/pdf.test.ts`: `groupItems` — элементы с близким `y` в одной строке, порядок по
  `x`, разрыв строки по допуску, две страницы не смешиваются.
- `lib/statements/fixtures.test.ts`: гвард п. 5 по всем файлам каталога фикстур.
- Скрипты п. 3–4 — проверяются прогоном на корпусе (результат — в Handoff: сколько файлов
  снято, сколько строк).

## Критерии приёмки

- `CORPUS.md` заполнен по обоим банкам; в нём нет имён, сумм и номеров.
- Фикстуры в репо, гвард зелёный; `cd frontend && npm run build && npm test` зелёные.
- На локальном стенде (Vite dev) выбранный PDF из корпуса даёт строки в консоли через
  временный вызов `pdfToRows` (worker грузится, ошибок нет) — способ проверки записать в Handoff.
- Сборка: `pdfjs-dist` не попал в главный чанк (отдельный чанк в `frontend/dist/assets`).
