## Задача

1. **`/week`** («Неделя»): экран B2C-07 в дизайне §2/§5 — состояние до загрузки (что за
   неделя, кто загрузил), загрузка, предпросмотр, карточки решений (незнакомые продавцы →
   раздел; сопоставления B2C-15; «оставить подписку?» `keepQuestions`; «остались деньги?»
   `monthEndAsk`), итог недели, «без выписки <имя>». «Пришла зарплата» (карточка B2C-15 или
   ручная) → **раскладка** (бывший Ритуал): разовая сумма → взносы в цели, досрочка
   (хвост: разовый источник вносит досрочку записью `applyPrepayment` со счёта раскладки),
   подушка, «это приближает» (B2C-18); **решение раскладки записывается** — новый список
   `SyncDoc.allocations[]` (`{ id, source: 'salary' | 'rest' | 'freed', sourceId, period,
   by, at, parts: { goalId | 'prepay:' + creditId, amount }[] } & Tracked`, явно в `mergeDocs`);
   повторный заход или партнёр видят записанное, а не раскладывают снова.
2. **`/money`**: список входов (Бюджет, Капитал, План «Сначала долги», Вклады, История семьи и
   итог месяца) по §3; экраны внутри — на кит и токены, без перерисовки логики: `Budget`
   (`/money/budget`), `Capital` (`/money/capital`; viewer без форм; `PayoffSheet` на
   `AccountChoice`), `DebtPlan` (`/money/plan`), `Deposit` (`/money/capital/:id`), «История и
   итоги» (`/money/history`: `progressMoments`, `MonthSummaryCard`, «Впереди» из `Overview`).
   Калькуляторы и график — за «подробнее» (свёрнуты по умолчанию).
3. Разделы трат: правка названий и цветов `spendCategories` и список правил `merchantRules`
   (удалить правило) — в настройках разбора (`/settings` → «Разбор выписок»).
4. Удалить: `Overview.vue`, `Ritual.vue` (логика — в `/week`), мёртвые компоненты; старые пути —
   редиректы (B2C-13).
5. Демо-документ: итоги выписок за две недели, главная цель с шаблоном, пара обязательств —
   лэндинг Блока 4 покажет «Попробовать» на новых экранах.
6. e2e: адаптировать сценарии старых экранов к новым путям и текстам, сохранив проверки денег;
   новые сценарии блока — `b2c-block3-screens.test.ts` (части 1–4 из B2C-14/15/18/19 + часть 5:
   раскладка записана — второй заход и партнёр не раскладывают повторно).

## Критерии приёмки

- Браузер (стенд, два профиля, 390px, обе темы): неделя от загрузки до раскладки зарплаты,
  партнёр видит записанную раскладку; «Деньги» — все прежние операции (правка кредита,
  обязательства, счёта, план) работают; viewer без форм; демо открывает новый главный.
- `cd frontend && npm run build && npm test` зелёные; главный чанк без предупреждения о
  размере (ленивые второго уровня).
