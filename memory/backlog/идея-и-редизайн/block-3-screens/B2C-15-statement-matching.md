# B2C-15 — Сопоставление выписки с отметками по одному решению (фронт)

Блок 3 · MVP · Каталог: `frontend/src/lib/statements/matching.ts` (новый), `lib/finance.ts`, `stores/`, `components/` · Зависит от: B2C-13 · Роли: member; viewer видит отметки

## Контекст (что уже есть)

- Р-6: выписка предлагает сопоставление по одному решению («похоже, это платёж по Автокредиту —
  отметить?», «это зарплата Ильяса?»); «да» запоминается по продавцу и назначению, дальше такие
  строки отмечаются сами (снять можно); ручные «Оплатил» / «Пришла зарплата» остаются; модель
  `payments` не меняется — та же запись с пометкой источника «выписка». `DESIGN.md` §5 карточка
  решения, §6 тексты.
- Записи `SyncDoc.payments` (§6 индекса): `kind` `obligation` / `credit` / `prepay` / `salary`,
  `targetId`, `period`, `amount`, `principal?`, `accountId`, `by`, `at`; стор `markPaid(kind,
  targetId, period, { amount, accountId, by })`, `markSalary`, `unmarkPaid`, `editPaid`;
  `countedPayments` схлопывает пару `kind:targetId:period`; `creditDueAmount(c)`,
  `creditSplit`, `monthlyAmount(o, key)`, `salaryAt(p, key)`, `isSubscription(o)`,
  `paidFor(...)`. Листы отметки — `components/PaidRow.vue` и `SalaryRow.vue` (дословная копия
  ~80 строк — хвост RP → здесь один компонент), `AccountChoice.vue`.
- Операции: стор операций (B2C-07): свои операции с `kind`, `amount`, `merchant`,
  `counterparty`, `categoryId`; правила `merchantRules` в личном документе (B2C-02: `to` —
  раздел / внутренний / «кому → что»).
- Обязательства и кредиты — `Obligation` (`day`, `versions`, `every`, `estimate`, `category`),
  `Credit` (`payment`, `day`); люди — `Person` (`salary`, `payday`).

## Задача

1. Модель: `Payment.source?: 'manual' | 'statement'`, `Payment.opId?: string` (id операции);
   `MerchantRule.to` — новый вариант `{ payment: { kind: 'obligation' | 'credit' | 'salary';
   targetId } }`; `Operation.matchedPaymentId?` — в локальной копии операций (и на сервер полем
   `note`? нет: отдельное поле не нужно — связь хранится в записи `payments`).
2. `lib/statements/matching.ts` (чистые функции): `matchCandidates(ops, state, rules)` →
   предложения `{ opId, kind, targetId, period, confidence, text }`: платёж по обязательству —
   сумма операции равна `monthlyAmount` (±2 % или точно для не-оценки) и дата в окне ±5 дней от
   `day`, ещё не отмечено за период; кредит — сумма = `creditDueAmount` (±2 %) или `payment`;
   зарплата — приход ≈ `salaryAt` того участника (±10 %) в окне от `payday`; подписка —
   `isSubscription`. Одна операция → максимум одно предложение (лучшее); отмеченный период —
   пропуск. Правило семьи с `payment` → предложение с `confidence: 'rule'` (применяется
   автоматически без вопроса).
3. Применение (стор): «да» → `markPaid`/`markSalary` с `source: 'statement'`, `opId`, суммой
   операции, `accountId: null` (выписка — факт, счета приложения не двигаем; изменить можно в
   листе отметки); + правило `merchantRules` по продавцу/получателю → назначение; операция
   получает раздел с `plannedElsewhere` (кредиты / коммуналка / аренда — по виду цели). «Нет» —
   запоминается на этот период (`localStorage`, как ответ «Остались деньги?»), не правило.
   «Снять отметку» — как сейчас (`unmarkPaid`), операция возвращается в траты; правило не
   удаляется автоматически (удалить — в настройках разбора B2C-21).
4. UI: карточки решений по одной (компонент кита B2C-12) — на экране недели после загрузки
   (сейчас `/statements`→`/week` B2C-07; B2C-21 доводит) и в `nextDecision` (B2C-14). Один лист
   отметки `components/MarkSheet.vue` вместо `PaidRow` + `SalaryRow` (детали, «Снять отметку»,
   «Другая сумма или счёт», источник «из выписки»); `PaidRow`/`SalaryRow` — на него.
5. Автоотметка: при загрузке (B2C-07) после `applyRules` — `matchCandidates` с правилами →
   `rule`-совпадения отмечаются сами; в предпросмотре строка «Отмечено по выписке: N».

## Тесты

- `matching.test.ts`: обязательство ±2 % и окно дней; кредит по `creditDueAmount`; зарплата по
  участнику; уже отмеченный период — нет предложения; одна операция — одно предложение; правило
  → `rule`; подписка.
- Стор: «да» пишет запись с `source`/`opId` и правило; «снять» убирает; повторная загрузка
  того же файла не создаёт вторую отметку (пара схлопнута); автоотметка по правилу.
- SSR/DOM: карточка решения → запись; `MarkSheet` для платежа и зарплаты (DOM-тест как у
  `PaidRow.test.ts`).
- e2e (часть 2 `b2c-block3-screens.test.ts`): A загружает выписку с платежом по кредиту →
  «похоже, платёж по Автокредиту — отметить?» → «да» → у B отметка видна, остаток кредита
  уменьшился на тело (`creditSplit`); следующий месяц — отметилось само; «снять» у B —
  вернулось в траты у A после синка итогов.

## Критерии приёмки

- Браузер (стенд, два профиля): сценарий e2e руками на настоящей выписке (кредит, аренда,
  зарплата); `cd frontend && npm run build && npm test` зелёные.

- Досрочки из выписки — не предлагаем (ручная механика остаётся).
