# B2C-80 — Тенге зарплаты месяца во всех расчётах и в сопоставлении выписки (фронт)

Блок 13 · MVP · Репо/каталог: `frontend/src/lib/`, потребители · Зависит от: B2C-79 · Роли: —

## Контекст (что уже есть)

- `salaryAt(p, key, book?)` — тенге оклада (B2C-78); обмены — `SyncDoc.fxExchanges`, приход — `payments` `kind:
  'salary'` с `foreign` (B2C-79).
- Потребители денег месяца: `totalIncome` (`finance.ts` ~927), `budgetAmounts` ~1016, `untilPayday` ~1467, разбор
  `breakdownArticles` / `monthBreakdown` (~3221/3418; живёт до Блока 14), `decisionQueue` ~2984, `markSalary`
  (сумма по умолчанию), `components/SalaryRow.vue`, `IncomeWidget.vue`, `PaidRow.vue`, `MarkSheet.vue`,
  `money/PaymentLine.vue`, `views/Money.vue`.
- Сопоставление выписки: `lib/statements/matching.ts` ~89/191 — приход зарплаты в допуске `SALARY_TOLERANCE` (0,1) от
  `salaryAt(p, period)`; первый запуск — `lib/statements/firstRun.ts` `salaryOpOfMonth` ~133 (`INCOME_TOLERANCE`).
- Решение: Р-74 (обменянное по своему курсу + необменянное по курсу на день зарплаты; до прихода — по курсу
  последнего дня книги; допуск ±10 % от этой суммы).

## Задача

1. `finance.ts`: `salaryTenge(p, key, ctx: { book, payments, exchanges })` — одна функция тенге зарплаты месяца
   по Р-74 (KZT — как `salaryAt`, без изменений поведения). Части наружу (`exchanged`, `left`, `rateDay`) — для
   подписи «обменяно … · остальное по курсу …».
2. Перевести потребителей «денег месяца» на неё (книга и обмены — параметром из стора); оставшиеся вызовы
   `salaryAt` — только там, где нужен именно оклад (форма, подписи). Список переведённых — в Handoff.
3. Сопоставление выписки: ожидаемая сумма прихода валютного участника — тенге обмена или `salaryTenge` дня (у
   валютной зарплаты в тенговую выписку приходит обмен, а не оклад: каждое зачисление в допуске от записанного
   обмена — его отметка; приход на валютный счёт выписка тенгового счёта не видит). Тенговым участникам — без
   изменений.
4. Тексты: в «Доходе» и карточке зарплаты — тенге из п. 1; расчёт не дублируется в компонентах.

## Тесты

- `salaryTenge`: KZT = `salaryAt`; EUR без прихода (по последнему курсу), после прихода без обмена (курс дня
  зарплаты), два обмена + остаток (сумма частей до тенге), обмен больше прихода не уходит в минус (явное поведение).
- Регрессия: весь набор `finance`/`matching`/`firstRun` зелёный без правок ожиданий для тенговых участников.
- `matching`: зачисление 257 300 ₸ против обмена 257 500 ₸ — совпало; оклад в евро не ищется в тенговой выписке как
  оклад.
- Ручной расчёт: тест-таблица на 2 месяца (оклад 1 500 €, два обмена, курс на день зарплаты) — числа в комментарии.

## Критерии приёмки

- `npm run build && npm test` зелёные.
- Стенд: «до зарплаты», «Доход», разбор месяца у валютного участника показывают тенге по Р-74; после обмена суммы
  меняются сразу; у тенгового участника цифры прежние (снимок до/после в Handoff).
