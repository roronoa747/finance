# B2C-79 — «Пришла зарплата» в валюте на валютный счёт и «Обменял» частями → ворота владельца (фронт)

Блок 13 · MVP · Репо/каталог: `frontend/src/` · Зависит от: B2C-78 · Роли: member (viewer видит)

## Контекст (что уже есть)

- «Пришла зарплата»: стор `markSalary(personId, { period, amount, accountId, … })` (`stores/finance.ts` ~1213) —
  запись `payments` `kind: 'salary'` (`amount` — целые тенге, счёт по умолчанию — прошлого прихода); карточка —
  `components/SalaryRow.vue` (на «Неделе» и в сводке «Денег»), очередь «Недели» — `decisionQueue` (карточка
  `allocate`). Остаток счёта — `accountBalance(a, payments)` (`finance.ts` ~1179): база + зачисления − списания после
  `amountSetAt`.
- Валютный счёт: `Account.currency`, `foreignAmount` (база в валюте), `rate`, `rateAt` (ручной курс), `amount` —
  тенге = `fxToTenge(foreignAmount, rate)` (`AccountSheet.vue` ~54/59); оплаты — только с тенговых
  (`payableAccounts`). Список счетов — `components/money/CapitalLists.vue` ~67.
- Правило новых данных (Р-19, §6 «Документ и слияние»): записи с id в отдельном списке, остатки выводятся; новый
  список — тип `SyncDoc` → `defaultSyncDoc()` → явно в `known` `mergeDocs` (`mergeList` по id).
- Решения: Р-73 (обмен — `fxExchanges`, остаток выводится, тенге по книге), Р-36 брифа (Д-36), правило 12.

## Задача

1. Приход валютной зарплаты: запись `payments` `kind: 'salary'` получает `foreign?: number` и `currency?` (сумма в
   валюте), `amount` — тенге по курсу Нацбанка на день прихода (книга; Р-74 уточняет в B2C-80). Счёт по умолчанию —
   валютный счёт той же валюты (нет — предложить создать одним нажатием «Евро-счёт»). Тенговый счёт валютную зарплату
   не получает.
2. Список `SyncDoc.fxExchanges: FxExchange[]` — `{ id, by, accountId (валютный), toAccountId (тенговый, может быть
   null — «не записывать»), currency, foreign, rate, tenge (= fxToTenge), period, at, updatedAt, deletedAt? }`;
   слияние — `mergeList` по id; отмена — надгробие.
3. `finance.ts`: остаток валютного счёта в валюте = `foreignAmount` (база после ручной сверки) + приходы зарплаты
   (`foreign`) − обмены после сверки; в тенге — `fxToTenge(остаток, rateOn(book, cur, сегодня, account.rate))`.
   Тенговый счёт получает `tenge` обмена (как зачисление). Капитал (`netWorth` и т. п.) считает валютный счёт по
   этому тенге.
4. Карточка «Пришла зарплата» валютного участника на «Неделе»: после прихода — тихая кнопка «Обменял» → лист: сумма
   в валюте (по умолчанию — необменянный остаток месяца), **курс** (вводит человек; подсказка — курс Нацбанка
   сегодня), итог «= N ₸» крупно, счёт зачисления; одна брендовая «Записать». Обменов в месяце сколько угодно;
   под карточкой — одна строка «обменяно 1 000 € из 1 500 €».
5. Демо: у Ильяса оклад в евро, приход и один обмен в текущем месяце.

## Тесты

- `finance.ts`: остаток в валюте и тенге при приходе и двух обменах; сверка `foreignAmount` после обмена не удваивает;
  отмена обмена (надгробие) возвращает остаток; капитал сходится до тенге.
- Слияние: два обмена с двух телефонов офлайн — оба остаются; надгробие сильнее правки.
- Стор: приход валютной зарплаты пишет `foreign`/`currency`; «Обменял» пишет запись и не трогает `payments`.
- DOM: лист «Обменял» — сумма по умолчанию, итог, одна брендовая кнопка; viewer не видит «Обменял».

## Критерии приёмки

- `npm run build && npm test` зелёные.
- Стенд 390 px, обе темы: пришла зарплата 1 500 € → евро-счёт +1 500 €; «Обменял» 500 € по 515 → тенговый счёт
  +257 500 ₸, евро-счёт 1 000 €; второй обмен 300 € — «обменяно 800 € из 1 500 €»; партнёр видит то же после синка.
- **Ворота владельца:** статусы §4 B2C-76…B2C-79 ✅, Handoff «Часть 1», снимки стенда 390 px в обеих темах («Доход»
  с окладом в евро, форма оклада, «Пришла зарплата» с «Обменял», лист обмена, валютный счёт в «Капитале») —
  артефактом владельцу; **остановиться, не начиная B2C-80**. Замечания — первыми во второй части (`B2C-7x: ворота — …`).
