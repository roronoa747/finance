# Бриф «Блок 6 миграции Go + Vue: прод-инфраструктура и cutover»

## Контекст

Блоки 1–5 бэклога `migrate-go-vue` закрыты: Go-бэкенд и Vue-фронтенд готовы по коду,
CI бэкенда зелёный (ветка `mgv-ci`). Прод — React + Supabase на
`family-finance-ff.vercel.app`, деплой из `origin/main`; Supabase `tpkyopaovfdkcmdhauws`;
одна семья, два участника, живой документ (rev ~400). Деплой Блока 1 перенесён сюда
решением владельца 2026-09-24.

## Что хочется получить и зачем

«Инструменты останутся те же, просто переход на Go + Vue» (владелец, 2026-09-24):
те же Vercel и Supabase, пользователи переходят на новый стек без потери данных.

## Разведка (факты из репо, не спрашивались)

- Схемы `supabase/migrations/20260907_init.sql` и `backend/migrations/000001_init.sql`
  совпадают по таблицам и колонкам; отличие — FK на `auth.users` против своей `users`.
  Перенос — копирование с сохранением UUID и `rev`.
- Go-миграция создаёт таблицы с `IF NOT EXISTS` под теми же именами, что живые таблицы
  React в `public` → на живой базе молча пропустит создание. Нужна своя схема.
- Vue ходит на относительный `/api` → Go-функция на том же домене Vercel, CORS не нужен.
- `main.go` запускает миграции на старте и держит долгоживущий процесс — для
  Vercel-функции нужен адаптер и отдельный шаг миграций; advisory lock сессионный —
  через транзакционный пулер Supavisor не работает.
- Регрессы Vue против React: **нет PWA** (у React `vite-plugin-pwa`), **курс Нацбанка —
  заглушка** (`frontend/src/lib/fx.ts`; React зовёт Edge Function `fx-rate`, её исходника
  в репо нет). Других заглушек grep не нашёл.
- Подтверждения почты нет ни в Go, ни в текущем решении «до запуска без подтверждения»
  (NEXT.md) — совпадает. Сброса пароля нет ни в React, ни в Go.
- Рамки NEXT.md: бесплатные тарифы (Supabase free, Vercel hobby), офлайн и синк двух
  устройств, данные не теряются при обновлении.

## Резюме бриф-интервью

- **Цель одной строкой:** перевести прод `family-finance-ff.vercel.app` с React + Supabase
  на Go + Vue на тех же Vercel и Supabase — с переносом семьи и паролей, без потери данных
  и с возможностью отката.
- **Скоуп:** готовность Go к проду (fail-fast, схема `app`, коды ошибок 400/413,
  `GET /api/fx-rate`); Go как Vercel-функция + миграции отдельным шагом + пулер Supabase;
  PWA во Vue и смена service worker React; скрипт переноса данных и пользователей
  (и обратный — для отката); репетиция на preview-адресе с копией живых данных;
  переключение прода и смоук.
  **Не-скоуп:** новый хостинг/БД, свой домен, подтверждение почты, сброс пароля,
  liveness/readiness, OAuth/Face ID.
  **После cutover (хвост):** удаление React `src/`, таблиц React в `public` и
  пользователей Supabase Auth — через 2 недели стабильной работы и с «да» владельца.
- **Решения (кандидаты в Р-*):**
  - Р-6. Инфраструктура та же: Vue и Go (Vercel-функция) на Vercel, PostgreSQL — Supabase,
    бесплатные тарифы. *(ответ владельца, 2026-09-24)*
  - Р-7. Таблицы Go — в отдельной схеме `app` того же проекта Supabase; таблицы React в
    `public` не трогаются до уборки. *(ответ владельца, раунд 1 — рекомендация)*
  - Р-8. Пользователи переносятся с паролями: `id`, `email`, bcrypt-хеш из `auth.users`
    в `app.users`; UUID и `rev` документов сохраняются. *(раунд 1 — рекомендация)*
  - Р-9. Cutover разом с окном: репетиция + смоук на preview → окно (оба устройства
    синхронизированы → финальная копия → push в `main`) → тот же адрес. Откат —
    redeploy React-сборки + обратный скрипт для записей, сделанных в Go после
    переключения. *(раунд 1 — рекомендация)*
  - Р-10. PWA во Vue возвращается до cutover. *(раунд 1 — рекомендация)*
  - Р-11. Курс Нацбанка — эндпоинт `GET /api/fx-rate` в Go (с кэшем) до cutover;
    Vue не зависит от Supabase. *(раунд 3 — рекомендация)*
  - Р-12. Секреты: строку подключения Supabase владелец кладёт в `memory/secrets/`;
    агент генерирует `JWT_SECRET`, выставляет env в Vercel и выполняет SQL через
    коннекторы — каждый прод-шаг только с согласия владельца. *(раунд 2 — рекомендация)*
  - Р-13. Хвосты Блока 1: fail-fast прода и коды ошибок 400/413 — в Блок 6;
    liveness/readiness (Н-10) закрывается как неактуальный для serverless.
    *(раунд 2 — рекомендация)*
  - Р-14. Переносятся все пять таблиц (`households`, `household_members`,
    `household_docs`, `private_docs`, `household_invites`); сверка — и по `private_docs`
    (`rev` каждого участника). *(дефолт — владелец согласился, 2026-09-24)*
  - Р-15. Сессия Supabase не переносится: после cutover каждый участник один раз входит
    заново старым паролем; кэш React в `localStorage` Vue не читает. *(дефолт — владелец согласился, 2026-09-24)*
- **Эскиз задач Блока 6** (по порядку, детали — в бэклоге):
  1. Go к проду: fail-fast при `APP_ENV=production`, схема `app`, коды 400/413, `/api/fx-rate`.
  2. Vercel: адаптер Go-функции, конфиг сборки Vue + SPA-роутинг, миграции отдельной
     командой, подключение через пулер.
  3. PWA во Vue + корректная замена service worker React; Vue использует `/api/fx-rate`.
  4. Скрипт переноса (Supabase → `app`, с паролями) и обратный скрипт; тесты на PG.
  5. Репетиция на preview с копией живых данных: вход старыми паролями, сверка данных
     и экранов с React, синк двух устройств, офлайн, прогон отката.
  Само переключение прода — в клинапе (L: деплой уезжает в клинап).
- **Критерии готовности:** оба участника входят старыми паролями; запрос «данные целы»
  из NEXT.md по `app.household_docs` даёт те же `rev`, имена, зарплаты, число целей,
  обязательств и кредитов, что по `public.household_docs` в момент копии, и `rev`
  `app.private_docs` совпадают с `public.private_docs`; правка на
  одном телефоне видна на другом; PWA ставится и открывается без сети; курс валют
  показывается; откат отрепетирован на preview.
- **Режим процесса:** L (живые данные, пароли, секреты, прод); каталожные ревью —
  `backend` и `frontend`. *(раунд 2 — рекомендация)*
- **Отложено владельцем:** уборка старого (хвост, через 2 недели после cutover).
- **Риск для исполнителя:** проверить, передаёт ли Supavisor `search_path` из строки
  подключения; если нет — квалифицировать имена таблиц схемой в SQL. Проверить, что
  рантайм Go на Vercel собирает `go 1.27.0` из `backend/go.mod`; если нет —
  минимальное локальное решение + Handoff.

**Подтверждение владельца:** 2026-09-24, «подтверждаю» (включая Р-14, Р-15).
