# MGV-03 — Аутентификация, JWT и управление домохозяйством (бэкенд)

Блок 1 · MVP · Каталог: `backend/` · Зависит от: MGV-02 · Роли: все

## Контекст (что уже есть)
- Репозитории пользователей и домохозяйств из MGV-02.
- В Supabase вход был по email + password, и создавался household с участником slot='a'.
- Приглашение второго участника происходило по 6-значному коду инвайта (`household_invites`), который назначал slot='b'.

## Задача
1. Реализовать сервис безопасности (`internal/auth/`):
   - Хеширование паролей через `golang.org/x/crypto/bcrypt`.
   - Генерация и валидация JWT-токенов (`github.com/golang-jwt/jwt/v5`).
   - Middleware авторизации: извлечение claims (`user_id`, `household_id`, `role`, `slot`) и добавление в context запроса.
2. Реализовать HTTP-обработчики (`internal/handlers/auth.go`):
   - `POST /api/auth/register` — регистрация: создает пользователя, новое домохозяйство и участника (slot='a'), возвращает токен.
   - `POST /api/auth/login` — вход по email и паролю, возвращает токен.
   - `GET /api/auth/me` — возвращает профиль пользователя, текущий household и слот.
3. Реализовать HTTP-обработчики инвайтов (`internal/handlers/household.go`):
   - `POST /api/household/invites` — создание инвайта (генерация уникального кода).
   - `POST /api/household/join` — присоединение партнёра по коду инвайта (назначает slot='b').

## Тесты
- Юнит-тесты хеширования и валидации JWT.
- HTTP-тесты цепочки регистрации, логина и защищенного эндпоинта `/api/auth/me`.

## Критерии приёмки
- Защищенные роуты возвращают `401 Unauthorized` без валидного токена.
- Полный сценарий: Регистрация User 1 ➔ Создание инвайта ➔ Регистрация User 2 ➔ Присоединение по инвайту ➔ Оба состоят в одном `household_id`.
- `cd backend && go test ./internal/handlers/...` проходит успешно.

## Вне скоупа
- Синхронизация JSON-документов казны (задача MGV-04).
