# MGV-19 — Репетиция cutover на preview и ранбук переключения (эксплуатация)

Блок 6 · MVP · Репо/каталог: preview-адрес ветки блока, живая база (схема `app`), `memory/backlog/migrate-go-vue/block-6-prod-cutover/` · Зависит от: MGV-16, MGV-17, MGV-18 · Роли: оба участника (вход, синк)

## Контекст (что уже есть)

- После MGV-16/17: preview-адрес ветки блока отдаёт Vue + Go, env Preview выставлены, схема `app`
  создана миграциями. После MGV-18: `cmd/transfer forward|back [-replace] [-dry-run]` со сверкой.
- Прод: React на `family-finance-ff.vercel.app` из `origin/main`, живые данные в `public`
  (rev ~400). **`main` не пушится** до переключения (это делает клинап).
- Р-9: переключение разом с окном — оба устройства синхронизированы → финальная копия →
  push в `main` → тот же адрес. Откат — redeploy React-сборки (Vercel: промоут предыдущего
  Production-деплоя) + `transfer back` для записей, сделанных в Go после переключения.
- Р-15: после переключения каждый участник один раз входит заново старым паролем.
- Грабли: у preview Vercel может стоять Deployment Protection — телефонам участников нужен
  обходной доступ (ссылка-share или отключение защиты для preview — с согласия владельца).

## Задача

Каждый шаг, пишущий в живую базу или Vercel, — **с явного согласия владельца** (Р-12).

1. **Копия живых данных**: `transfer forward -replace` на живую базу (React не затронут —
   `public` только читается); отчёт сверки — в Handoff (без email и содержимого документов).
2. **Проверки на preview** (по критериям брифа):
   - оба участника входят **старыми паролями** (владелец с двух устройств или владелец + агент
     по его паролю — как решит владелец; пароли в чат/доки не пишутся);
   - экраны Vue на копии показывают то же, что React на проде: имена, зарплаты, цели,
     обязательства, кредиты, капитал (сверка владельцем по списку);
   - правка на одном устройстве видна на другом; правка офлайн → после сети синкается;
   - PWA ставится, открывается без сети; курс валют показывается;
   - замена SW React: на устройстве с установленной React-PWA — невозможно проверить на
     preview-домене (другой origin) → сделано в MGV-17 локально; здесь — только отметка.
3. **Прогон отката**: `transfer back -dry-run` на живой базе — зелёный; найти и записать ID
   текущего Production-деплоя React (кандидат для промоута при откате).
4. **Ранбук** `CUTOVER.md` в каталоге блока — пошагово для клинапа, с командами и точками
   «стоп — согласие владельца»:
   окно (оба устройства онлайн и синхронизированы; React-правки прекращены) → `transfer forward
   -replace` → сверка → Production-env Vercel (`APP_ENV`, `DATABASE_URL`, новый `JWT_SECRET` —
   только имена) → merge ветки в `main` + push → смоук на `family-finance-ff.vercel.app` →
   участники входят заново. Раздел «Откат» — промоут записанного React-деплоя + `transfer back`
   + повторная сверка. Критерий «откатываем», если смоук красный.
5. Данные репетиции в `app` остаются до финальной копии (её `-replace` их сотрёт); тестовые
   пользователи, заведённые на preview, — удалить.

## Тесты

- Новых автотестов нет (задача эксплуатационная); регрессия: `go test ./...`, `npm test`,
  накопленный e2e-набор `frontend/e2e/` — зелёные на HEAD ветки.
- Результат каждой проверки п.2–3 — строкой в Handoff (что, где, кто, итог).

## Критерии приёмки

- Все критерии готовности брифа выполнены на preview: вход старыми паролями; сверка «данные
  целы» `app` = `public` в момент копии, `rev` `private_docs` совпали; синк двух устройств;
  PWA офлайн; курс; откат отрепетирован (`back -dry-run` зелёный, ID React-деплоя записан).
- `CUTOVER.md` существует, каждый пишущий шаг помечен «согласие владельца», секретов нет.
- React-прод всё это время работает как прежде (владелец подтверждает).

## Вне скоупа

- Push в `main`, Production-env, финальная копия, прод-смоук — клинап блока по `CUTOVER.md`.
- Уборка React/таблиц `public`/`auth.users` — хвост (через 2 недели и с «да» владельца).
