# Блок 1 — «Оплатил», досрочка, подписки · сессии

**Цель блока:** одно нажатие «оплатил» для всего по графику — остатки счетов и кредитов
честно выводятся из записей и не теряются при двух офлайн-телефонах; досрочку можно
применить и видеть сэкономленное; подписки собраны в группы и спрашивают «оставить?» без
надоедания.

Сессии: исполнитель ✅ · критик ✅ · приёмка ✅ · ревью frontend ⬜ · клинап ⬜

- Задачи по порядку: `RP-06` → `RP-07` → `RP-08` → `RP-09`. RP-06 — фундамент (модель,
  слияние, математика, стор): не переходить к UI, пока его тесты не зелёные.
- **Деньги (L):** каждая сумма, попадающая в документ или на экран, — из `finance.ts`,
  целая; в компонентах арифметики с деньгами нет. Слияние `payments` — явное (§6), не через
  страховку RP-02 для незнакомых ключей.
- Что оставил Блок 0 (факты кода, сверены критиком 2026-09-24):
  - **`payments` в слиянии:** тип `SyncDoc` → `defaultSyncDoc()` → объект `known` в
    `mergeDocs` (`lib/merge.ts`). Больше никуда: незнакомым считается всё, чего нет в `known`
    (списка `KNOWN_KEYS` больше нет). Документы до Блока 1 приходят без `payments` — читать
    `doc.payments ?? []`.
  - **`payments: []` в `defaultSyncDoc()` обязателен:** сервер (RP-03) хранит ключи верхнего
    уровня, которых нет в push, — «Сбросить данные» (`resetDoc` шлёт `defaultSyncDoc()`)
    обнулит `payments` на сервере, только если ключ прислан.
  - **`mergeList` берёт `{ ...проигравший, ...победитель }`:** поле очищать `null`, не
    `undefined` (в JSON ключ пропадёт, значение проигравшего воскреснет). «Не списывать» —
    `accountId: null`; снятие отметки — надгробие `deletedAt`.
  - **Флаг неотправленного** (`unsent` / `privateUnsent` / `hasUnsent`, ключ `ff_unsent`)
    ставит `mutateHouseholdDoc` / `mutatePrivateDoc` — отметки только через них, иначе выход
    сотрёт их без вопроса. Демо (`financeStore.isDemo`) — отметки работают локально, запросов
    нет.
  - **Защита RP-01** `unchanged()` в сторе (`setAccountAmount`/`updateAccount`, `setDeposit`,
    `correctSalary`, `correctObligation`, `setCategoryAmount`, `setPerson`) сравнивает с тем,
    что отдаёт стор. После производных остатков `setAccountAmount` с тем же видимым остатком
    не пишет ни базу, ни якорь — это верно (остаток не изменился), не «чинить». У
    `updateCredit` защиты нет — якорь при смене `principal` ставить явно.
  - Поле суммы, коммитящее по blur, — `NumFieldBlur` (коммит только изменённого, `numChanged`
    в `lib/num.ts`).
- Среда: локальный стенд (§6), два профиля браузера, телефонная ширина. Офлайн-сценарий —
  DevTools → Offline в обоих профилях, отметки, затем онлайн.
- Верификация: `cd frontend && npm run build && npm test` (весь `e2e/`).

     последний платёж обрезает `creditDueAmount`. Но на экране нарушено «при том же сроке»
     (Р-6, RP-08). По аудиту, с `Math.ceil` остаётся 14 случаев из 15 983. Предложение —
     клинап: однострочник и тест.
  2. **Неточный текст снятия досрочки** (`Capital.vue:1707-1709`). У досрочки «Не
     списывать» подтверждение говорит «Остаток долга и деньги на счёте вернутся к прежним», хотя
     со счёта ничего не уходило. «Платёж — тоже» обещается и тогда, когда стор платёж не вернёт
     (его меняли после досрочки — правило из Handoff). Деньги верны, неточен только текст.
  3. **Оценка `saved` описана как общий закон.** Фразы «отличается на доли процента» (JSDoc) и
     «≤ 150 ₸ / 0,3%» (тест) верны только для тестовых случаев. На реалистичных кредитах
     расхождение с помесячным графиком доходит до 1 991 ₸ и 4,25% (последний неполный месяц в
     непрерывной модели). Надо уточнить формулировку; переходить ли на помесячный график,
     решает владелец.
  4. `prepaySaved` учитывает досрочки удалённого кредита, а снять их нельзя: модалка
