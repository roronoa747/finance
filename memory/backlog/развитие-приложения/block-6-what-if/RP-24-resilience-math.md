# RP-24 — Расчёт запаса прочности (фронт: `finance.ts`)

Блок 6 · MVP · Каталог: `frontend/` · Зависит от: Блоки 2, 5 · Роли: —

## Контекст (что уже есть)

- Р-23: «А если…» — снять один доход (или урезать) → «продержимся N месяцев, вот что
  поставить на паузу»; расчёт в `finance.ts` (родня `simulateStrategy`). Отвечает на открытый
  вопрос о декрете сценарием, а не допросом.
- `finance.ts`: `simulateStrategy` (`:319`, помесячная симуляция с долгами, подушкой, `keep`),
  `salaryAt`, `totalIncome`, `budgetAmounts` (`d1` жильё, `d2` кредиты+обязательства, `d3`
  цели, `d4` быт + прочие, `d5` свободно), `mandatoryMonthly`, `liquidCash`,
  `cushionMonths` (сейчас нигде не показан), `emergencyCoverage`, производные остатки
  (RP-06), группы подписок (RP-09 — у групп и подписок есть «оставить?», значит их можно
  «поставить на паузу»), жилищный вклад и цели с частями (RP-21…RP-23), `keep` — часть
  взносов, которую нельзя ставить на паузу (декретный депозит).
- Деньги — целые тенге; месяцы — целые (или с одним знаком, как `cushionMonths`, — выбрать
  и держать единообразно).

## Задача

1. Чистая функция сценария: вход — какой доход убрать или на сколько урезать (участник,
   новая сумма), с какого месяца; выход — сколько месяцев семья продержится на ликвидных
   деньгах при обязательных платежах (месяц за месяцем, с учётом кредитов, которые
   закрываются по графику и освобождают платёж), и упорядоченный список «что поставить на
   паузу» с эффектом каждого пункта в месяцах (взносы в цели кроме неприкасаемых, подписки
   вне рабочих групп, досрочные доплаты). Порядок — от наименее болезненного (описать
   правило).
2. Жилищный вклад (Отбасы) — пауза пополнений учитывается с потерей премии года
   (функции RP-22), чтобы совет был честным.
3. Всё в `finance.ts`, без UI.

## Тесты

- Ручной расчёт на живых числах заказчика (зарплаты, аренда, кредиты — из тестовых данных
  блоков, записать в тест): без одного дохода → N месяцев совпадает с расчётом вручную
  (шаги расчёта — в комментарии теста).
- Урезание дохода вместо снятия; кредит, закрывающийся внутри горизонта; нет ликвидных денег
  → 0 месяцев; доход не меньше расходов → «не кончатся» (без бесконечного цикла).
- Список пауз: неприкасаемые (`keep`, рабочие подписки) не предлагаются.

## Критерии приёмки

- Число месяцев сверено с ручным расчётом на живых числах (тест).
- `cd frontend && npm run build && npm test` зелёные.
