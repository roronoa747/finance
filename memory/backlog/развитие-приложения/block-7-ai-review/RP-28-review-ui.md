# RP-28 — Разбор в общем документе и кнопки «Разобрать» (фронт)

Блок 7 · MVP · Каталог: `frontend/` · Зависит от: RP-27 · Роли: member (запуск), все (чтение)

## Контекст (что уже есть)

- Р-25: кнопка «Разобрать» — в итоге месяца и на «Обзоре», без чата. Р-27: разбор
  сохраняется в общий документ — партнёр видит тот же текст, повторного запроса нет; тон
  «мы». Р-13: viewer не запускает (и сервер вернёт 403).
- Карточка итога месяца — компонент RP-13 на `views/Overview.vue`. Экран «что уйдёт» и
  сводка — RP-26; ручка и ответ `{good, risk, steps[{text, screen?}]}` — RP-27. Признак «ИИ
  включён» — RP-18.
- Правило новых данных (§6): список записей с id верхнего уровня, явное слияние по id.

## Задача

1. Модель: список разборов в общем документе (id, месяц, когда, кто запустил — слот, ответ);
   явно в `mergeDocs`. Для месяца показывается последний живой разбор.
2. «Разобрать» — в карточке итога месяца и на Обзоре: если разбора за месяц нет, ИИ включён,
   есть сеть и роль `member` → экран «что уйдёт» (RP-26) → запрос → разбор сохранён в
   документ → виден обоим. Если разбор есть — показывается он, без запроса.
3. Показ: «что хорошо», «где риск», 2–3 шага; шаг с экраном — ссылка внутри приложения.
   Отметка, что это подсказка модели по цифрам приложения.
4. Ошибки RP-27 — спокойный текст; ИИ выключен — кнопки нет.

## Тесты

- `lib/merge.test.ts`: разборы с двух устройств объединяются по id; показывается последний.
- Стор: при существующем разборе месяца кнопка не делает запрос (фейковый клиент со
  счётчиком); viewer — кнопки нет.
- e2e Блока 7: разбор по кнопке виден второму клиенту после синка; исходящий запрос
  (фейковый бэкенд) не содержит имён, заметок, данных личного документа.

## Критерии приёмки

- Браузер: разбор по кнопке виден обоим; повторного запроса нет (Network); ссылки шагов
  ведут на экраны.
- `cd frontend && npm run build && npm test` зелёные.

## Вне скоупа

- ИИ-чат (Р-1, после MVP).
- Разбор прошлых месяцев задним числом (только текущий/итоговый месяц карточки).
