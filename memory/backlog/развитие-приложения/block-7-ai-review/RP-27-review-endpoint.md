# RP-27 — Go: ручка разбора бюджета и проверка чисел (бэкенд)

Блок 7 · MVP · Каталог: `backend/` · Зависит от: RP-26 · Роли: member

## Контекст (что уже есть)

- Р-25: короткий разбор — что хорошо, где риск, 2–3 следующих шага со ссылками на экраны
  приложения; модель сама денег не считает; **число в ответе, которого нет во входных
  данных, — брак ответа (проверяется)**. Та же интеграция Gemini, что в Р-17. Р-27: тон «мы»,
  без упрёков и сравнения участников. Р-28: бесплатный тариф, тариф = ключ в env. §3:
  только `member`.
- Клиент Gemini — RP-18 (пакет, структурный JSON-ответ, таймаут, 429, без логов содержимого,
  ИИ выключен без ключа → 503). Признак «ИИ включён» для фронта — RP-18.
- Хелперы: `decodeJSONBody(w, r, limit, dst)` (413/400), `respondJSON`; роль — `auth.GetRole`.
- Сводка — JSON из RP-26 (формат — в его Handoff).
- Экраны приложения для ссылок: `/`, `/budget`, `/goals`, `/capital`, `/ritual` + маршруты
  блоков 3–6 (экран участника, «А если…») — список брать из `frontend/src/router/index.ts`.

## Задача

1. Ручка разбора бюджета (под `/api`, защищённая, `member`): тело — сводка (лимит небольшой,
   например 64 КБ), в модель уходит **только** сводка + фиксированная инструкция (роль,
   тон «мы», запрет считать и вводить новые числа, формат). Ничего от сервера (id семьи,
   email) в запрос не добавляется.
2. Структурный ответ модели: `good` (что хорошо), `risk` (где риск), `steps` (2–3 шага, у
   каждого — экран из **белого списка** маршрутов; неизвестный экран → шаг без ссылки).
3. Проверка чисел: все числа в тексте ответа (с учётом русского форматирования — пробелы
   тысяч, `₸`, запятая дробей, проценты) должны встречаться во входной сводке (с
   разумной нормализацией — описать правила и допуски, например счёт шагов «2–3» и порядковые
   не считаются числами денег). Брак → одна повторная попытка со строгой инструкцией; снова
   брак → ошибка «разбор не получился, попробуйте позже» (не показываем непроверенное).
4. Ошибки: ИИ выключен → 503; лимит → 429; таймаут/5xx модели → 502 с понятным текстом.
   Содержимое сводки и ответа не логируется.

## Тесты

- Фейковый Gemini (`httptest`): тело исходящего запроса = инструкция + присланная сводка и
  **ничего сверх** (нет id семьи, email, слота — тест фиксирует, что сервер ничего не
  добавляет; обезличивание самой сводки — RP-26).
- Проверка чисел: ответ только с числами сводки → принят; с выдуманным числом → повтор →
  второй выдуманный → ошибка; форматы «220 000 ₸», «1,5», «33%» распознаются.
- Экран вне белого списка → шаг без ссылки. Viewer → 403. Нет ключа → 503.

## Критерии приёмки

- `cd backend && go build ./... && go vet ./... && go test ./...` + корень `api/` зелёные; CI
  `ci-backend` зелёный.
- Живой вызов локально с ключом на сводке из тестовых данных: ответ проходит проверку чисел.

- Кэш разборов на сервере (разбор хранится в документе — Р-27).
