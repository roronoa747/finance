Блок 3 · MVP · Каталог: `backend/` (+ корневой `go.mod`, если нужна зависимость) · Зависит от: Блок 1 · Роли: member, viewer

  только добавляют. Матрица прав — §3 индекса (чужая семья и чужое скрытое — 404).
- Роутер `backend/server/server.go:111-131`: всё под `/api`, защищённая группа
  `auth.Middleware(tokenService)`, роль проверяется в хендлере (`auth.GetRole`,
  `GetUserID`, `GetHouseholdID`, `GetSlot` — `internal/auth/middleware.go`).
- Хелперы: `decodeJSONBody(w, r, limit, dst)` (413 на превышение), `respondJSON`
  (`internal/handlers/auth.go:132, 148`). Бинарное тело — через `http.MaxBytesReader`.
- Репозитории: интерфейсы в `internal/repository` (`DocRepository` и др.), pg-реализации

## Задача

1. Миграция `000002_wish_photos.sql`: таблица фото в `app` — id, семья, автор (`user_id`),
   признак «скрытое» (фото скрытого желания), тип (`image/webp`, `image/jpeg`), байты,
   размер, дата. FK на `households`/`users` с поведением при удалении, как у соседних таблиц.
   Только добавление.
2. Ручки (под `/api`, защищённые):
   - загрузить: тело — байты картинки, `Content-Type` из белого списка, лимит (порядка 512 КБ —
     с запасом к ~100 КБ); признак «скрытое» — параметром; ответ — id. Только `member`.
   - выдать по id: своя семья; скрытое — только автору, иначе 404. Заголовки: верный
     `Content-Type`, `Cache-Control: private` с долгим сроком (фото по id не меняется),
     `X-Content-Type-Options: nosniff`.
   - удалить по id: автор (или любой `member` для не-скрытого — выбрать и записать); viewer —
     403.
3. Проверка содержимого: первые байты соответствуют заявленному типу (webp/jpeg), иначе 400.
4. `backend/README.md` — ручки одной-двумя строками.

## Тесты

- Хендлеры на моках: загрузка member → 201 и id; viewer → 403; неверный тип / подмена
  сигнатуры → 400; больше лимита → 413; выдача своей семье → 200 и тот же байт-в-байт;
  чужой семье → 404; скрытое партнёру → 404, автору → 200; удаление по правилам.
- `TestPostgres…`: миграция применяется на чистой и на уже мигрированной БД; те же сценарии
  на pg; удаление семьи/пользователя не ломается FK.
- `server_e2e_test.go`: добавить загрузку и выдачу в общий сценарий (оба режима).

## Критерии приёмки

- `cd backend && go build ./... && go vet ./... && go test ./...`, PG-режим, корневые
  `go vet ./api/... && go test ./api/...` — зелёные; CI `ci-backend` зелёный.
- Запрос от имени партнёра к скрытому фото — 404 (тест + ручная проверка на локальном стенде
  с PG).
