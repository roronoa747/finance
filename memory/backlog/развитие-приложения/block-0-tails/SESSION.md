# Блок 0 — Хвосты переключения · сессии

**Цель блока:** закрыть хвосты переключения на Go + Vue — правка партнёра больше не
затирается тапом по полю, статус синка честный, демо стало черновиком будущей семьи — и
подготовить слияние к новым данным блоков 1–7, чтобы ни один деплой не терял данные (Р-14).

Сессии: исполнитель ⬜ · критик ⬜ · приёмка ⬜

## Промпт исполнителя — уровень build · Opus 5 · effort high

```
/worker развитие-приложения 0
```

Блок-специфика:

- Ветка `rp-block-0-tails` от `main`. Push ветки — с согласия владельца (CI); `main` не
  трогать (это деплой приёмки).
- Задачи по порядку: `RP-01` → `RP-02` → `RP-03` → `RP-04` → `RP-05`. RP-03 — единственная
  задача Go в блоке (тот же `sync.go`, pg + моки).
- Среда: локальный стенд из §6 (`go run ./cmd/server` на моках + `npm run dev`), два профиля
  браузера для сценариев двух клиентов. Preview Vercel не использовать (§6, грабли).
- RP-05 опирается на `logout`, который чистит стор (RP-04), — не дублировать сброс.
- Верификация: `cd frontend && npm run build && npm test`; `cd backend && go build ./... &&
  go vet ./... && go test ./...` + PG-режим для RP-03 (одноразовая БД в Docker/локальном
  Postgres; если поднять негде — записать в Handoff, CI `integration` покроет).

## Промпт критика — уровень review · Opus 5 · effort xhigh

```
/critic развитие-приложения 0
```

Блок-специфика:

- `merge.ts`: коммутативность и идемпотентность сохранены на новых правилах (незнакомые
  ключи, поля проигравшего); явный `null` не воскрешает старое значение.
- RP-03: слияние ключей атомарно с проверкой ревизии (нет окна между чтением и записью);
  `resetDoc` нового клиента по-прежнему обнуляет всё, что он знает.
- RP-04/05: выход из аккаунта не теряет неотправленное молча; демо не шлёт ни одного
  запроса; вход по коду из демо не смешивает документы.
- Живые доки: `frontend/README.md` / `backend/README.md` — только если там описаны синк или
  демо.
- Промпт Блока 1 актуализировать по факту: как именно RP-02 сливает незнакомые ключи
  (нужно RP-06 для `payments`), где флаг «неотправленное».

## Промпт приёмки — уровень review · Opus 5 · effort xhigh

```
/accept развитие-приложения 0
```

Блок-специфика:

- Критерии брифа Блока 0 на локальном стенде, два профиля браузера: правка «Еда и быт» на
  клиенте A не затирается тапом по полю на B; в демо нет запросов к `/api` и нет «не
  сошлось»; демо → регистрация → «да» → заполненное видно после входа с другого профиля;
  демо → вход по коду приглашения → данные семьи не изменились.
- Регрессия: весь `frontend/e2e/` + `npm test`, `go test ./...`, CI `ci-backend` и
  `ci-frontend` зелёные на HEAD ветки.
- Сценарии приёмки — в `frontend/e2e/` (файл Блока 0).
- **Деплой (M):** с «да» владельца — записать ID текущего Production-деплоя Vercel (откат),
  merge `rp-block-0-tails` → `main`, push; смоук на `family-finance-ff.vercel.app`: вход,
  данные на месте, правка «Еда и быт» видна на втором устройстве, бейдж без сети — «нет
  сети». **Откат:** promote записанного деплоя в Vercel.
- После деплоя попросить владельца открыть приложение на обоих телефонах (старый JS
  отработает последний раз, дальше — код с RP-02) — до начала Блока 1.
- Следующий шаг — `/worker развитие-приложения 1 ultrathink`.
