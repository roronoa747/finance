# RP-05 — Демо без сервера и перенос демо при регистрации (фронт)

Блок 0 · MVP · Каталог: `frontend/` · Зависит от: RP-04 · Роли: аноним (демо), новый member

## Контекст (что уже есть)

- Р-32: демо — черновик будущей семьи. В демо нет запросов на сервер, вместо статуса
  синхронизации — метка «демо». Демо стартует с примером. При **регистрации новой семьи** —
  вопрос «Взять то, что вы заполнили в демо?»; «Да» переносит весь демо-документ в новую
  семью, имя участника — из регистрации. При входе в существующий аккаунт или по коду
  приглашения демо не переносится и не смешивается, и это прямо сказано.
- Вход в демо: `views/Access.vue:99-144` `startDemoMode()` → `authStore.setAuthData({ token:
  DEMO_TOKEN, … })` (пишет `ff_auth_token='demo-token'`, `ff_user`, `ff_household`,
  `ff_member`) → пример данных инлайн (`:118-142`) через `mutateHouseholdDoc` → `/`.
  Флаг — `stores/auth.ts:17` `DEMO_TOKEN`, `:34` `isDemo`.
- **Н-7:** движок пропускает демо (`syncEngine.ts:23`), но `mutateHouseholdDoc` →
  `scheduleSync` (`finance.ts:255-261`) → `syncHousehold` без проверки демо → 401 → бейдж
  «не сошлось». То же у `setHouseholdDoc` без ревизии и `resetDoc`.
- **Регистрация сейчас:** `auth.ts:69-88` `register` → `POST /api/auth/register` (Go создаёт
  семью, участника слот `a`, пустые `household_docs`/`private_docs` `{}` — начальный документ
  сервер не принимает) → `Access.vue:60-66` → `/setup`. Локальный документ остаётся каким
  был (демо!) и **молча** уезжает на сервер первым синком: `syncHousehold` видит пустой
  серверный документ (`isEmptyDoc`) и пушит локальный как есть.
- **Вход/приглашение сейчас:** `login` → `pullHousehold()`; `join` (`auth.ts:144-163`,
  `Access.vue:67-81`) → `pullHousehold()`. После RP-04 выход чистит стор, но из демо в
  аккаунт можно попасть и без выхода — демо-документ со статусом `dirty` **сольётся** с
  семьёй.
- Мастер `views/Setup.vue`; роутер-гард (`router/index.ts:84-115`) шлёт на `/setup`, если
  `!setupDone && !hasBudgetData`.

## Задача

1. Демо не ходит на сервер: `syncHousehold`/`scheduleSync`/push личного документа в демо —
   ранний выход; бейдж в демо — метка «демо» (без «синхронизировано» и «не сошлось»).
   Демо по-прежнему стартует с примером.
2. Выход из демо в регистрацию/вход — через `/access` (как сейчас есть путь из демо — найти
   и оставить; если его нет в шапке/настройках — добавить понятный вход «Создать семью /
   Войти» в демо).
3. **Регистрация из демо:** после успешного `register` — вопрос «Взять то, что вы заполнили
   в демо?». «Да» → демо-документ (весь) пушится в новую семью как первый документ; имя
   участника `a` — `display_name` из регистрации; `setupDoneAt` сохраняется, если в демо
   настройка пройдена (тогда мастер не открывается). «Нет» → пустой документ, мастер.
   Регистрация не из демо — как сейчас, но без случайного переноса остатков чужого
   локального документа.
4. **Вход / код приглашения из демо:** демо-документ отбрасывается до `pullHousehold`, данные
   семьи — с сервера; пользователю одной спокойной строкой сказано, что демо не
   перенесено, потому что у семьи уже есть свои данные.
5. Личный документ демо (если в демо заводили личные счета) — «Да» переносит и его; при
   входе — отбрасывается.

## Тесты

- `stores/finance.test.ts`: в демо правка не вызывает запросов клиента (фейковый `ApiClient`
  с счётчиком), статус не `error`.
- `e2e/`: новый файл сценария Блока 0 — демо → правка → регистрация → «да» → фейковый бэкенд
  получил демо-документ с именем из регистрации; демо → «нет» → пустой документ; демо →
  join по коду → документ семьи не изменился (ревизия и данные те же), демо отброшено.
- Вход без демо — как раньше (регрессия `two-clients-sync.test.ts`).

## Критерии приёмки

- Браузер (локальный стенд): в демо во вкладке Network нет запросов к `/api` при правках;
  бейдж «демо». Демо → регистрация → «да» → вход той же почтой во втором профиле браузера →
  заполненное в демо видно. Демо → вход по коду приглашения → данные семьи не изменились.
- `cd frontend && npm run build && npm test` зелёные.

## Вне скоупа

- Серверный приём начального документа при регистрации (не нужен: пустой серверный
  документ + первый push).
- Перенос демо при входе в существующий аккаунт (запрещён Р-32).
