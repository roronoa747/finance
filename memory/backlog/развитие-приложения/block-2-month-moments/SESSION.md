# Блок 2 — Моменты месяца · сессии

**Цель блока:** встроить приложение во второй и третий момент месяца — «пришла зарплата» и
«месяц кончается» — и дать спокойное чувство движения: строки прогресса и итог месяца «мы»
без сравнений.

Блок-специфика:

- Ветка `rp-block-2-month-moments` от `main` (после деплоя Блока 1). Push — с согласия
  владельца; `main` не трогать.
- Задачи по порядку: `RP-10` → `RP-11` → `RP-12` → `RP-13`.
- Опора — записи `payments` Блока 1 (факты кода, сверены критиком Блока 1 2026-09-24):
  - **Запись** `Payment` (`types/finance.ts`): `id`, `kind: 'obligation' | 'credit' | 'prepay'`,
    `targetId`, `period` (`YYYY-MM` месяца по графику; у досрочки — месяц применения),
    `amount` (целое, сколько ушло), `principal?` (тело кредита, снимок), `accountId`
    (`null` — «не списывать»), `by`, `at` (момент оплаты — с ним сравнивается якорь),
    поля досрочки `saved`/`mode`/`prevPayment`/`newPayment`, `updatedAt`/`deletedAt`.
    Список — `SyncDoc.payments?` (старые документы без ключа → `?? []`), в `defaultSyncDoc()`
    и в `known` `mergeDocs` (`mergeList` по id) — новые `kind` туда же, отдельного слияния не надо.
  - **RP-10 — зарплата = новый `kind`** (например `'salary'`, `targetId` = `PersonId`):
    `countedPayments` схлопывает пару `kind:targetId:period` (ранняя по `at`, досрочки не
    схлопываются) — зарплате подходит как есть. **`accountBalance` сейчас вычитает `amount` у
    каждой учитываемой записи со счётом** — знак зачисления вводится там (и только там:
    `shiftedBase` и стор берут остаток из неё). `creditBalance` берёт только `credit`/`prepay`.
    `ScheduledKind = 'obligation' | 'credit'` (аргумент `paidFor`/`markPaid`/`unmarkPaid`) —
    расширить или завести своё действие; запись строит внутренний `newPayment(fields,
    accountId, at?)` стора (счёт по умолчанию — `lastAccountFor(payments, targetId, accounts)`,
    Р-5; без истории — `null`). Снятие — `unmarkPaid` (надгробие на пару), правка суммы/счёта —
    `editPaid(record, {amount, accountId})` (новая запись с `at` исходной).
  - **Якорь** `Account.amountSetAt` ставит только ручной ввод остатка (`setAccountAmount`);
    сдвиги — взнос в цель со счёта, внеплановый доход — `shiftAccountAmount(id, delta)` без
    якоря. Зарплата — запись, а не сдвиг и не `setAccountAmount`.
  - **Функции:** «оплачено за период» — `paidFor(payments, kind, targetId, period)`;
    «следующий платёж» — `nextObligationDue` / `nextCreditDue(x, payments, now = today())` →
    `Due { kind, targetId, period, day, amount }`; `creditDueIn(c, payments, key)` — ждёт ли
    кредит платежа (закрытый — нет, кроме месяца закрытия); `creditBalance` 0 = долг закрыт
    (RP-12: момент — запись, обнулившая остаток). `untilPayday(state)` → `due` (без
    оплаченного), `paid`, `dueTotal`; пункты несут `kind`/`targetId`/`paid`; `state` —
    **геттеры стора** (`householdAccounts`, `credits` — производные остатки) + `payments`, как в
    `Overview.vue`, не сырой `householdDoc` (RP-10 п.5 — «до зарплаты» переключается на
    следующую зарплату — здесь).
  - UI: строка «Оплатил» — `components/PaidRow.vue` (пропсы `kind`, `targetId`, `period`,
    `title`, `note`, `accent`, `clickable`, `more`, `dense`; оценку берёт из обязательства);
    viewer — отметки видны, кнопок нет. Время — `today(d?)`/`monthKey(d?)` по Алматы,
    `atLabel(iso)` — день отметки.
  - **Хвост §4 про закрытый кредит в плане** (`budgetAmounts` d2 и «Свободно» считают платёж
    закрытого долга; Бюджет и Обзор передают ей сырой `householdDoc`; `Ritual` — `credits[0]`)
    касается RP-12 «освободилось N ₸»: если владелец отдал его в RP-12 — делать там.
  - RP-13 «оплачено за месяц» — по `period`; в записи есть `by`, но в итог разрезы по
    участникам не выводить (Р-22).
- Все новые числа — функции `finance.ts` (итог месяца, доля свободного на зарплату,
  моменты прогресса); компоненты только показывают.
- Среда: локальный стенд (§6), два профиля; для «конца месяца» — мок времени в тестах.
- Верификация: `cd frontend && npm run build && npm test`.
