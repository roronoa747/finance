# RP-10 — «Пришла зарплата» (фронт)

Блок 2 · MVP · Каталог: `frontend/` · Зависит от: Блок 1 · Роли: member

## Контекст (что уже есть)

- Р-18: каждый отмечает свою зарплату; сумма из оклада месяца (премия — правкой),
  зачисляется на счёт по умолчанию (зеркало Р-5, Р-7); дальше экран раскладки `/ritual`.
  Р-13: viewer не отмечает. Р-30: месяц — по Алматы.
- Записи — `SyncDoc.payments` (RP-06): записи с id, дедупликация пары (цель, период),
  производный остаток счёта (после якоря), снятие — надгробие. `kind` досрочки — RP-08.
  Точные имена полей и функций — в Handoff Блока 1.
- `finance.ts`: `salaryAt(p, key)` — оклад месяца по версиям; `Person.payday` — день зарплаты.
- Где видна зарплата: `views/Budget.vue` `events` — зарплаты по `payday` (клик →
  `SalaryDialog`); `views/Overview.vue` «До зарплаты» (`untilPayday`: чья ближайшая
  зарплата, через сколько дней).
- Слот текущего пользователя — `useAuthStore().member.slot` (`PersonId`).
- `views/Ritual.vue` (`/ritual`, без параметров): сумма = первое обязательство с `nextChange`
  delta < 0 (`:34-38`); «горшки» — цели (цель с «подушка» в имени получает эффект
  `emergencyCoverage`), «Досрочно по кредиту» (`credits[0]`, `prepayment`), «Качество
  жизни»; шаги по 10 000; `confirm()` сохраняет только прибавки к `goal.monthly`
  (`setGoalMonthly`), кредит и «жизнь» не сохраняются.

## Задача

1. Запись зарплаты — тот же список `payments` с `kind` зарплаты: цель — участник, период —
   месяц, сумма по умолчанию `salaryAt`, счёт по умолчанию — прошлый для этой зарплаты;
   **зачисление** (плюс к производному остатку счёта). `finance.ts` учитывает знак.
2. Кнопка «Пришла зарплата» — только для своего участника (`member.slot`), там, где видна
   зарплата: событие зарплаты в Бюджете и «До зарплаты» на Обзоре (когда день настал или
   близко — выбрать разумное окно). Сумма по умолчанию, правка — исключение (премия).
   Снятие — как у платежа.
3. После отметки — переход в `/ritual` с источником «зарплата»: сумма раскладки — свободный
   остаток месяца, приходящийся на эту зарплату (посчитать в `finance.ts`: доля свободного
   `budgetAmounts(...).d5` пропорционально доходам — или другое честное правило;
   описать в комментарии и Handoff).
4. `Ritual.vue` принимает источник суммы (освободившийся платёж — как сейчас; зарплата);
   подпись экрана отражает источник. Существующее поведение без параметров не ломать.
5. «До зарплаты» после отметки переключается на следующую зарплату.

## Тесты

- `lib/finance.test.ts`: зарплата зачисляет на счёт (производный остаток растёт); повтор с
  другого устройства не удваивает; снятие возвращает; доля свободного на зарплату.
- SSR: кнопка видна только своему участнику и не видна viewer.
- e2e Блока 2: «пришла зарплата» → счёт вырос, открыта раскладка с суммой из `finance.ts`.

## Критерии приёмки

- Браузер: «пришла зарплата» зачисляет на карту и открывает раскладку; партнёр видит
  зачисление после синка, но кнопку своей зарплаты — только у себя.
- `cd frontend && npm run build && npm test` зелёные.

## Вне скоупа

- Второй вход в `/ritual` в конце месяца — RP-11.
- Сохранение в Ritual распределения на кредит и «качество жизни» (не просили; если мешает
  — хвост).
- Валюта зарплаты (Р-1, не-скоуп).
