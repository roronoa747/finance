## 1. Цель

Встроить приложение в реальные денежные моменты семьи на двоих — оплата, зарплата,
продление подписки, покупка у витрины, конец месяца — одним нажатием с честными
остатками, и дать тягу: желания с фото, квартира с Отбасы, видимый прогресс и
спокойствие «мы выдержим». Успех: владелец и партнёр отмечают платежи и зарплаты
вместо переписки «оплатил?», остатки счетов и кредитов сходятся с `finance.ts` до
тенге, ни одна правка не теряется при синке и деплое.

Режим процесса: **M**; блоки 1, 3, 4, 7 — **L** (пометки в §4). Деплой после каждого блока.

## 2. Зафиксированные решения

- **Р-1. Скоуп** — хвосты переключения; «Оплатил», досрочка, подписки; моменты месяца;
  желания с фото; быстрый вход желаний; цель из частей и Отбасы; «А если…»; ИИ-разбор
  бюджета. **Не-скоуп:** личные траты / кошелёк / личные обязательства; валюта у зарплаты
  и подписок; вложенные долги; push-уведомления; чат в обзоре семьи; ИИ-чат со свободными
  вопросами. **После MVP:** домен → вход через Google (Apple — против правила бесплатных
  тарифов, перепроверить), Face ID после домена; выписки Kaspi/Halyk; ИИ-чат.
  *(ответ владельца, раунды 1, 3, 4)*
- **Р-2. `migrate-go-vue` закрыт по DoD и в архиве** (выполнено составителем 2026-09-24,
  коммит `be4d7af`); его хвосты — Блок 0. «Уборка старого» — отдельная S-задача не раньше
  2026-10-08 и с «да» владельца, в эту инициативу не входит. *(ответ владельца, раунд 1)*
- **Р-3. «Оплатил» — одна механика для всего по графику** (аренда, подписки, кредиты,
  рассрочки): одно нажатие, сумма подставлена (правка — исключение), сразу виден следующий
  платёж. Неотмеченный платёж нейтрален, без упрёка. *(ответ владельца, раунд 1)*
- **Р-4. Отметка по кредиту уменьшает остаток на тело платежа** по аннуитету; разбивку на
  тело и проценты считает `finance.ts`. *(ответ владельца, раунд 1)*
- **Р-5. Отметка и досрочка списывают сумму со счёта.** По умолчанию — счёт, с которого этот
  платёж оплачивали в прошлый раз; сменить счёт или «не списывать» — исключение. «До
  зарплаты» считает по честному остатку. *(ответ владельца, раунд 2)*
- **Р-6. Досрочку можно применить**: выбор «сократить срок» / «снизить платёж», видно,
  сколько процентов не отдадим банку; счётчик «сэкономлено на процентах» по всем досрочкам.
  *(бриф — NEXT.md п.1; идея заказчика из `credits-flow`)*
- **Р-7. Отметки платежей и зарплат — записи с id в документе**, объединяются по id (как
  взносы целей). Остаток кредита и счёта выводится из записей, а не перезаписывается: две
  офлайн-отметки с двух телефонов не теряются. Один платёж за один период — одна отметка,
  повтор с другого устройства не удваивает. Снять ошибочную отметку можно — деньги
  возвращаются. *(дефолт — владелец согласился)*
- **Р-8. Фото желаний — в своей таблице Postgres через Go-ручку загрузки**; в документе только
  id. Фото сжимается на телефоне (порядка 100 КБ, webp). Добавить желание можно офлайн,
  прикрепить фото — только с сетью. *(ответ владельца, раунд 1; офлайн — дефолт)*
- **Р-9. Скрытые желания-подарки живут в `private_docs`**: партнёр не видит ни записи, ни
  фото (Go проверяет владельца при выдаче фото). Остальные желания общие.
  *(ответ владельца, раунд 2)*
- **Р-10. У каждого участника свой список желаний**; вход — нажатием на никнейм или аватар в
  шапке. Желание связано с деньгами: досрочка и освободившиеся деньги показывают «это
  приближает вот это». *(бриф — NEXT.md п.2 и п.6 «Ближайшего»)*
- **Р-11. Части у любой цели**, а не особый экран «Квартира»: у части свободное название,
  сумма и срок; итог и дата цели считаются. У части может быть «будущий платёж» (ипотека) —
  экран сравнивает его с обязательством, которое он заменит (человек выбирает, какое; у
  заказчика это аренда 220 000). *(ответ владельца, раунд 2)*
- **Р-12. Отбасы полностью**: вклад с госпремией; строки «свои / проценты банка / премия
  государства»; подсказка перед концом года «добрать до лимита»; прогноз цели с премией;
  учёт в «копить или гасить» (не советовать останавливать пополнения, пока правила не
  сверены). Правила премии исполнитель сверяет по актуальным источникам, по памяти не берёт.
  *(ответ владельца, раунд 2)*
- **Р-13. Роль `viewer` отмечать платежи и менять данные не может**, как сейчас.
  *(дефолт — владелец согласился)*
- **Р-14. Новые поля документа старые установленные PWA не теряют при слиянии**; данные в
  проде не теряются ни при одном деплое (правило заказчика 8). *(дефолт — владелец согласился)*
- **Р-15. «Можно ли это купить?»**: ввести цену → ответ по данным приложения («до зарплаты
  хватает» / «отодвинет <цель> на N дней»), считает `finance.ts`; из ответа одной кнопкой —
  в желания. Трат не вводит и не хранит. *(ответ владельца, раунд 3)*
- **Р-16. «Поделиться → в приложение» через Web Share Target PWA (Android)**: ссылка или
  картинка становится желанием. На iOS путь — загрузить скриншот; разбор одинаков на обеих
  платформах. *(ответ владельца, раунд 3)*
- **Р-17. ИИ-разбор скриншота (название + цена) — Gemini API, бесплатный тариф**, вызов только
  из Go, ключ в env. Разбор — подсказка, поля правятся; запуск явной кнопкой; в UI прямо
  сказано, что картинка уходит в Google. Исполнитель сначала проверяет доступность
  бесплатного тарифа из региона Go-функции (Vercel `icn1`, Сеул); нет — разбор выключается,
  остаётся ручной ввод, решение за владельцем. *(ответ владельца, раунд 3; кнопка и
  оговорка — дефолт; регион — разведка, раунд 6)*
- **Р-18. «Пришла зарплата»**: каждый отмечает свою; сумма из оклада месяца (премия —
  правкой), зачисляется на счёт по умолчанию (зеркало Р-5, Р-7); дальше экран раскладки
  `/ritual`. *(ответ владельца, раунд 3)*
- **Р-19. Вопрос в конце месяца об остатке**: второй вход в `/ritual` в последние дни месяца.
  Тон без упрёка. *(ответ владельца, раунд 3)*
- **Р-20. Подписки группируются свободными группами через существующий `parentId`**
  (названия любые, без хардкода). У группы флаг «рабочие — не спрашивать». Для остальных —
  «оставить?»: у годовых перед каждым продлением, у ежемесячных — не чаще раза в квартал.
  «Отменить» — надгробие подписки. *(ответ владельца, раунд 3; частота — дефолт)*
- **Р-21. Моменты прогресса**: закрытый долг, половина цели, сэкономленное досрочкой — одна
  спокойная строка в истории семьи на «Обзоре»; закрытый долг ведёт в `/ritual`
  («освободилось N ₸»). Без конфетти, значков и серий. *(ответ владельца, раунд 3)*
- **Р-22. Итог месяца на двоих** — одна карточка «мы»: что оплачено, что закрыто, насколько
  приблизились к желаниям. Никаких сравнений участников. *(ответ владельца, раунд 3)*
- **Р-23. «А если…»**: снять один доход (или урезать) → «продержимся N месяцев, вот что
  поставить на паузу»; расчёт в `finance.ts` (родня `simulateStrategy`).
  *(ответ владельца, раунд 3)*
- **Р-24. Одна инициатива, деплой после каждого блока.** *(ответ владельца, раунд 3)*
- **Р-25. ИИ-разбор бюджета — по кнопке «Разобрать»** в итоге месяца и на «Обзоре», без
  чата: что хорошо, где риск, 2–3 следующих шага со ссылками на экраны. Модель получает
  цифры `finance.ts` и сама денег не считает; число в ответе, которого нет во входных
  данных, — брак ответа (проверяется). Та же интеграция Gemini, что в Р-17.
  *(ответ владельца, раунд 4; проверка чисел — дефолт)*
- **Р-26. В Gemini уходит только сводка**: цифры `finance.ts` и названия статей; имена людей
  заменены на «участник 1/2», заметки и всё из `private_docs` не уходят. Перед отправкой
  видно, что именно уйдёт. *(ответ владельца, раунд 4)*
- **Р-27. Разбор сохраняется в общий документ**: партнёр видит тот же текст, повторного
  запроса нет. Тон «мы»: без упрёков и сравнения участников. *(ответ владельца, раунд 4)*
- **Р-28. Gemini — бесплатный тариф, пока пользователей двое.** Условия бесплатного тарифа
  разрешают Google использовать присланное для обучения и показывать разметчикам — в экране
  «что уйдёт» это сказано прямо. Код не привязан к тарифу: сменить тариф = сменить ключ в
  env. *(ответ владельца, раунд 5; строка в UI — дефолт)*
- **Р-29. UI**: новые экраны на существующих паттернах Vue (`frontend/src/views`, компоненты
  оболочки и `components/kit/`), цвет только из токенов, светлая и тёмная темы, телефон —
  основной экран. Тон спокойный, «мы», без упрёков. *(дефолт, раунд 6)*
- **Р-30. Календарные границы** — «месяц», «последние дни месяца», «раз в квартал», «перед
  продлением», «конец года» для Отбасы — по Asia/Almaty, как в `backend/internal/fx`.
  *(дефолт, раунд 6)*
- **Р-31. Откат**: код — promote прошлого деплоя Vercel. Миграции схемы только добавляют и
  ничего не удаляют (прошлый деплой работает на новой схеме). Новые поля документа старый
  клиент сохраняет (Р-14). *(дефолт, раунд 6 — владелец согласился)*
- **Р-32. Демо — черновик будущей семьи, а не песочница.** В демо нет запросов на сервер,
  вместо статуса синхронизации — метка «демо». Демо стартует с примером. При **регистрации
  новой семьи** — вопрос «Взять то, что вы заполнили в демо?»; «Да» переносит весь
  демо-документ, имя участника — из регистрации. При входе в существующий аккаунт или по
  коду приглашения демо-данные не переносятся и не смешиваются, и об этом прямо сказано.
  *(ответ владельца, раунды 6–7)*

## 5. Протокол

По `memory/process/BACKLOG-GUIDE.md`. Отклонения и уточнения:

- **M-блоки (0, 2, 5, 6):** исполнитель → критик → приёмка; деплой — в приёмке.
- **L-блоки (1, 3, 4, 7):** исполнитель (`ultrathink`) → критик (`ultracode`) → приёмка
  (`ultracode`, **не деплоит**) → `/dir-review` по каждому каталогу из коммитов блока →
  клинап (деплой + смоук + 🏁). Каталоги названы в §4 по плану; ревью проводится только по
  каталогам, реально затронутым коммитами Handoff-а. Критика и приёмку денежного Блока 1
  владелец вправе поднять до Fable 5.1 (`MODELS.md`, уровень deep) — тогда отметить здесь.
- **Ветки:** каждый блок — в ветке `rp-block-N-<тема>` от `main`. Merge в `main` + push
  = прод-деплой (Vercel деплоит Production из `origin/main`) — только в деплоящей роли и
  только с «да» владельца в этой сессии. Push ветки блока до этого — тоже с согласия (даёт
  CI; preview-деплой Go — см. §6, грабли).
- **Миграции схемы** (Блок 3, может понадобиться в 4/7): в прод — `cmd/migrate` перед
  merge в `main`, с «да» владельца; миграции только добавляют (Р-31).
- **Секреты** (Блок 4: `GEMINI_API_KEY`): значение — только в `memory/secrets/` и env Vercel;
  выставляет агент с «да» владельца; в доки — имя переменной.
- **Откат любого деплоя** (Р-31): promote прошлого Production-деплоя в Vercel (его ID
  деплоящая сессия записывает в SESSION.md до merge); миграции не откатываются.

## 6. Технический контекст

Факты, нужные двум и более задачам. Факт одной задачи — в её ТЗ.

**Где что лежит**
- Прод: `family-finance-ff.vercel.app`, Vercel, регион функций `icn1` (`vercel.json`); Go —
  одна функция `api/index.go` (корневой модуль `finance-vercel`, `replace finance-backend =>
  ./backend`; новая зависимость бэкенда — и в корневой `go.mod`). Vue — `frontend/`, сборка
  `frontend/dist`. `/api/(.*)` → Go, остальное → `index.html`.
- БД: Supabase Postgres, схема `app` (`backend/migrations/000001_init.sql`: `users`,
  `households`, `household_members`, `household_docs`, `private_docs`, `household_invites`).
  Миграции — встроенные `backend/migrations/*.sql`, следующая — `000002_<имя>.sql`, каждая в
  своей транзакции (без `CONCURRENTLY`); в прод — только `cmd/migrate` вручную (функция не
  мигрирует), подключение сессионное (5432). Строки подключения — `memory/secrets/supabase-db.md`.
- React в `src/` — эталон до «Уборки старого», **не трогать**.

**Документ и слияние (сердце всех блоков)**
- Типы — `frontend/src/types/finance.ts` (`SyncDoc`, `Tracked`, `Goal`, `WishItem`,
  `Obligation`, `Account`, `Credit`, `Person`). Слияние — `frontend/src/lib/merge.ts`
  `mergeDocs(local, remote)`: описательные поля — LWW по `updatedAt`, удаление (`deletedAt`)
  сильнее правки и **не воскресает**; append-only списки (взносы `Goal.movements`, версии
  обязательств) — объединение по id, суммы пересчитываются. После RP-02 незнакомые ключи
  верхнего уровня и поля сущностей не теряются.
- **Правило для новых данных (Р-7, Р-14):** всё, что может прийти с двух устройств офлайн, —
  записи с id в отдельном списке верхнего уровня, остатки выводятся из записей. Новый список
  добавляется в тип `SyncDoc` и в `defaultSyncDoc()` (`stores/finance.ts`) и **явно** в
  `mergeDocs` (по id, как `wishlist`; своя `combine` — только если у элемента есть вложенный
  append-only список). Общее правило RP-02 для незнакомых ключей — страховка старых клиентов,
  а не способ слияния новых данных. Повтор «снять → отметить снова» — **новая** запись с новым
  id (надгробие по старому id вечное).
- Стор `frontend/src/stores/finance.ts`: `mutateHouseholdDoc(fn)` / `mutatePrivateDoc(fn)` —
  единственный путь правки (ставит `dirty`, пишет `localStorage`, `scheduleSync`);
  `householdDoc`, `privateDoc` (`Record<string, unknown>`, сейчас там только `accounts`);
  `accounts` = общие + личные. Личный документ (`/api/sync/private`) до RP-15 пушится без
  слияния.
- Сервер хранит `data` как есть (`backend/internal/handlers/sync.go`, `internal/repository/
  doc_repo.go`); `POST /api/sync/household` — только `role = member` (иначе 403); конфликт
  ревизий → 409 с `server_doc`, клиент сливает и повторяет (до 4 раз).

**Деньги и время**
- Деньги — целые тенге в состоянии. Все расчёты — `frontend/src/lib/finance.ts` (чистые
  функции); аннуитетная математика там считает в дробях → результат, который попадает в
  документ или на экран как сумма, округляется в `finance.ts` (`Math.round`), не в компоненте.
- Существующее: `annuityPayment`, `annuityMonths`, `prepayment` (режим «сократить срок»:
  платёж + extra), `lumpSum` (разовый взнос, платёж тот же), `debtCost`, `halfOverpayExtra`,
  `simulateStrategy`, `untilPayday(state)`, `budgetAmounts(state)`, `amountAt`/`dueIn`/
  `nextChange` (обязательства), `salaryAt`, `cushionMonths`, `netWorth`, `live*`-фильтры.
  Разбивки платежа на тело/проценты **нет** (появится в RP-06).
- Время: `frontend/src/lib/dates.ts` (`monthKey()` — по времени устройства). Р-30: границы —
  по Asia/Almaty = фиксированный UTC+5 (как `var almaty` в `backend/internal/fx/fx.go:33`).
  Хелпер «сегодня/месяц по Алматы» заводит RP-06 в `lib/dates.ts`; дальше все задачи
  используют его.

**Роли и доступ**
- JWT (HS256) с `user_id`, `household_id`, `role`, `slot`; хелперы `auth.GetUserID/
  GetHouseholdID/GetRole/GetSlot` (`backend/internal/auth/middleware.go`); роль проверяется
  в хендлере. Фронт: `useAuthStore()` — `isMember`, `isViewer`, `isDemo` (`DEMO_TOKEN`),
  `member.slot`. Токен — `localStorage['ff_auth_token']`, заголовок `Authorization: Bearer`
  (`frontend/src/api/client.ts`) → `<img src="/api/...">` токен не несёт.
- Участники: `PersonId = 'a' | 'b' | 'c'`, цвет участника — токен `var(--p${id})`.

**UI (Р-29)**
- Экраны `frontend/src/views/*.vue`, оболочка `components/AppShell.vue` (шапка с аватарами
  участников, нижняя навигация, лист быстрых действий «+»), кит `components/kit/*`
  (Card, Section, Row, Field, Hint, NumField, NumFieldBlur, Segmented, Callout, DangerZone,
  SavedMark, Tag, Stat, Hero), `components/ui/Button.vue`, `Input.vue`. Иконки —
  `@phosphor-icons/vue`.
- Цвет — только токены `frontend/src/style.css` (`:root` + пара в `.dark`); новый токен —
  обязательно в обоих. Правило заказчика: строгий банковский вид, без «ИИ-слопа».

**Верификация и тесты**

  среда Node, **без DOM**: тесты вью — стор + SSR `renderToString`, см. `views/Budget.test.ts`).
