# Блок 5 — Цель из частей и Отбасы · сессии

**Цель блока:** большая пугающая цель «Квартира» превращается в понятные части с итогом и
датой, с честным ответом «ипотека против аренды», а вклад Отбасы наконец считает
госпремию — накопления по квартире перестают быть заниженными.

Сессии: исполнитель ⬜ · критик ⬜ · приёмка ⬜

## Промпт исполнителя — уровень build · Opus 5 · effort high

```
/worker развитие-приложения 5
```

Блок-специфика:

- Ветка `rp-block-5-goal-parts-otbasy` от `main` (после деплоя Блока 4). Push — с согласия
  владельца; `main` не трогать.
- Задачи по порядку: `RP-21` → `RP-22` → `RP-23`.
- **RP-22 начинается со сверки правил Отбасы по первичным источникам** (веб-поиск, дата и
  ссылки — в Handoff); неоднозначность → вопрос владельцу, не выбор молча. По памяти цифры
  не брать.
- Параметры премии — данные с дефолтами, не константы (правило «без хардкода», МРП меняется
  ежегодно).
- Верификация: `cd frontend && npm run build && npm test`; браузер — локальный стенд.

## Промпт критика — уровень review · Opus 5 · effort xhigh

```
/critic развитие-приложения 5
```

Блок-специфика:

- Сверить расчёт премии с источниками из Handoff независимо (пересчитать один пример);
  дефолты = источник; целые тенге.
- Части цели: слияние по id внутри цели, `need` не расходится с суммой частей.
- «Копить или гасить»: совет не останавливает пополнения Отбасы без явной выгоды.
- Промпт Блока 6 актуализировать: какие функции Блоков 2 и 5 нужны «А если…» (зарплаты,
  обязательства, жилищный вклад, цели с `keep`).

## Промпт приёмки — уровень review · Opus 5 · effort xhigh

  аренды»; вклад Отбасы показывает премию отдельной строкой по сверенным правилам.
- Регрессия: весь `frontend/e2e/` + `npm test`; CI `ci-frontend` зелёный.

  Отбасы → премия отдельной строкой. **Откат:** promote записанного деплоя.
