## Задача

1. В `foundPayments` оставить кандидатов двух сортов:
   - **словарные виды** (`credit`, `rent`, `utilities`, `subscription`) — как сейчас;
   - **прочие продавцы (`obligation`)** — только если в каждом из **двух подряд идущих календарных месяцев** (в окне 3 месяцев)
     у продавца (`groupKey`) **ровно одно списание**, и эти суммы в ±5 % друг от друга. Два и больше списаний продавца хотя бы
     в одном из этих месяцев — мимо (кофейня, такси, магазин).
2. Правило — чистая функция рядом с `foundPayments` (имя на усмотрение, например `monthlyOnce`); порог ±5 % — тот же
   `RECURRING_TOLERANCE`, новых констант-«на будущее» не заводить.
3. Экран не меняется: подпись «нашли N в выписке» и список считают тем же `foundPayments`.

## Критерии приёмки

- На новой семье с тремя неделями выписки «нашли» = только подписка; садик-подобный платёж за два месяца — в списке.
- «В платежи» у строки в листе операции и в листе раздела работает как прежде (`recurringOf` не тронут).
- `cd frontend && npm run build && npx vitest run` зелёные; стенд Chrome 390: строка «Платежи» «Месяца» новой семьи.
