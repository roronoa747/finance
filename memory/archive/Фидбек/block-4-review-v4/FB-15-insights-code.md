## Задача

1. **`by` у разбора (Р-26).** `reviewFindings`, `reviewScenario`, `reviewWork`, `whereRows`, `habitImages` получают
   `by?: PersonId` последним параметром — как экраны Блока 3: с `by` — только записи этого участника (`reviewFinds`,
   `spendTotals`, `habitTotals`), «обычно» — по его месяцам (`usualMonths(…, by)`), `spendCompare(…, by)`; без `by` — как
   было (старые разборы v3 и их тесты не меняются). Образ утечки и сценарий — мечта семьи (мечты общие).
2. **Новые находки по своим операциям** — чистые функции в `finds.ts` (вход — свои операции `all`, месяц, правила; выход —
   данные карточки с id операций; **в документ не пишутся**, имена людей не покидают телефон): `peopleShare` (сумма и
   число переводов людям месяца — раздел `sc_people` после ответов «Кому → что»), `cashShare` (`sc_cash`), `unknownShare`
   (`UNKNOWN_CATEGORY`), `oneOffLike` (крупная покупка у нового продавца — порог Р-24), `dearerWeek` (неделя месяца
   дороже обычной — порог Р-24; самая крупная своя трата недели), `smallBuys` (покупки < `SMALL_MAX` ₸: число и сумма),
   `weekendShare` (доля свободных трат в сб–вс и доля дней). Пороги — именованные константы рядом (владелец правит числом).
   Разовые (`oneOff`) и возвращённое (`spendOf` 0) — мимо всех, кроме самих «разовых».
3. **Карточки — `reviewCards(state, ctx, ops, by)` в `finance.ts`** (правило 6: числа считает `finance.ts`): виды, число,
   строка, кнопка и цель кнопки — по таблице Р-24; v3-виды (`reviewFindings(…, by)`) превращаются в карточки Р-24
   (leak → «Мелочь», grew → «Поставить план», recurring → «В платежи», pricier → «Обновить сумму», double → «Разобрать»);
   карточка без исполнимой кнопки не выходит (Р-24 «нет кнопки — нет карточки»). Порядок и лимит — Р-24. Тип —
   `ReviewCard = {id, kind, title, figure: {value: number; unit: 'money' | 'pct'}, line, button, target, monthly}`;
   `target` — дискриминированное объединение по кнопке (`op` — id операции → `OpSheet`; `cat` — лист раздела месяца;
   `unknown` — лист «Не разобрано»; `pay` — id операции → `AddPaymentSheet`; `image` — действие `ImageMoveSheet`; `do` —
   `StepCandidate`; `plan` — `{categoryId, amount}` → «Изменить план»; `obligation` — id). Строки — короткие (правило 12:
   заголовок 1–3 слова, строка ≤ 1 строки 390 px), без годовых чисел; имена людей — только в строке карточки людей и только
   из своих операций.
4. **«Куда ушло» на всю сумму (Р-25)** — `whereSplit(state, ctx, by)`: свои траты месяца находок четырьмя частями
   (продавцы · люди · наличные · платежи) — суммы целые, Σ частей = свой факт месяца (с разовыми; правило сходимости —
   тест); `whereRows(…, by)` — разделы продавцов как были; выходные — из `weekendShare` (по своим операциям; на телефоне).
5. **Х-8 (Р-29).** `dreamShift(…, by?)`: причина `spend` называет раздел, только если он выше плана **у `by`**; иначе
   причина `spend` без `name` → «траты выше плана». Вызовы «Мечт» и цели (`Dreams.vue:80`, `GoalDetail.vue:171`,
   `aiFacts.ts:200`, `finance.ts:4465`) передают `by: me` (viewer — без `by`, как было).

## Тесты

- `finds.test.ts` (или `finds-v4.test.ts` рядом): каждая новая функция — порог «на границе» и «на шаг ниже»; разовая и
  возвращённая трата не попадают; перевод с ответом «Кому → что» не считается людям; имени человека нет ни в одном поле,
  кроме строки карточки людей.
- `reviewCards.test.ts`: таблица Р-24 — по одной семье на каждый вид (карточка, число, кнопка, цель); «Не разобрано»
  > 10 % — первой; лимит `REVIEW_CARDS_MAX`; карточка без исполнимой цели не выходит (нет `move`-кандидата → нет «Мелочи»;
  `recurringFor` null → нет «В платежи»); партнёрские итоги в документе не влияют на мои карточки (`by`).
- `whereSplit`: Σ четырёх частей = `PlanSpend.fact` участника (с разовыми и «Не разобрано»); у партнёра — его суммы.
- `by` у `reviewFindings` / `whereRows` / `habitImages` / `reviewWork`: семья из двух — свои находки и операции; без `by`
  — прежний результат (снимок прежних тестов не меняется).
- Х-8: раздел выше плана только у партнёра → «траты выше плана» без имени; у меня → имя раздела.
- Мутанты (откат копией файла): порог «Не разобрано первой», фильтр `by` в `reviewFindings`, Σ `whereSplit` — красные.

## Критерии приёмки

- Таблица Р-24 покрыта тестами вид за видом; Σ «Куда ушло» сходится с фактом участника; без `by` — старое поведение.
- Имена людей не попадают ни в общий документ, ни в тип, уходящий в модель (проверка FB-16 опирается на это).
- `cd frontend && npm run build && npx vitest run` — зелёные.
