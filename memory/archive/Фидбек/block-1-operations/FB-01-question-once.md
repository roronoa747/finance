# FB-01 — Баг «вопрос трижды»: воспроизведение на данных владельца и починка (фронт)

Блок 1 · MVP · Каталог: `frontend/src/views/Week.vue`, `stores/operations.ts`, `lib/statements/model.ts`, `lib/statements/matching.ts`, `lib/finance.ts` (`decisionQueue`), `lib/storage.ts` · Зависит от: — · Роли: member (вопросы «Недели»); viewer вопросов не видит

## Контекст (что уже есть)

Владелец: «три раза спрашивало, что Замире Ш я отправил 30к — это возврат долга». Разведка составителя (код на
`origin/main` `21a46189`), три дороги, по которым один перевод человеку спрашивается снова:

1. **«Потом» не помнится.** `Week.vue:256` — `deferred` живёт в компоненте и сбрасывается при каждом монтировании; «Потом»
   у пачки «Без раздела» (`UnknownBatch.vue` → `later` → `defer`) откладывает её только до следующего открытия экрана;
   ключ пачки в `decisionQueue` (`finance.ts:5549-5560`) постоянный `unknownBatch`. У перевода «возврат долга» подходящего
   чипа человек может не найти → «Потом» → тот же вопрос при каждом заходе.
2. **Пуш и строка выписки — разные операции с разными ключами.** Пуш банка о переводе человеку приходит с сервера как
   `merchant` «Перевод Имя Ф.» и **пустым `counterparty`** (`backend/internal/applepay/push.go:343-378`, тест-таблица
   `push_test.go:30-70`; Р-23 Apple Pay). `categorize` (`model.ts:250`): `transfer-out` **без** `counterparty` — не
   `sc_people`, `KIND_CATEGORY` его не знает → `null` → строка в пачке «Без раздела» с подписью «Перевод Имя Ф.»;
   «Кому → что» в `CategoryChips` не предлагается (`counterparty` false). Ответ пишет правило `{merchant: 'перевод имя ф'}`
   (`ruleMatchOf` :240). Строка выписки о том же переводе (Kaspi `parsers/kaspi.ts:119-120`: `merchant` = «Имя Ф.»,
   `counterparty` = «Имя Ф.»; Freedom `PERSON_LEAD`) имеет ключ `{counterparty: 'имя ф.'}` — правило пуша к ней не
   подходит; сама она ложится в «Переводы людям» молча. Итог: ответ человека не переживает замену пуша выпиской
   (`replacedByStatement`), а два источника одного перевода ведут себя по-разному.
3. **«Нет, это другое» помнит пару, не операцию.** `declineMatch` (`stores/operations.ts:243`) пишет `kind:targetId:period` в
   `ff_match_declined` устройства; `matchCandidates` (`matching.ts:204`) `declined` не получает, фильтр — после отбора
   (`openMatches` :168). Пока отклонённая пара не отмечена, операция занята ею и второй раз не спрашивается; но когда
   пару «цель · месяц» отмечают руками или другой строкой (`paidFor`), операция освобождается и уходит к следующей цели
   с похожей суммой (у семьи несколько платежей ≈ 30 000) → новый вопрос «Похоже, это платёж по …?» по той же строке;
   второй телефон (`declined` на устройстве) спросит ещё раз.

Вопрос «Недели» об операции — один из: `match` («Похоже, это платёж по … — отметить?», `MatchCandidate.meta` с
продавцом), `unknownBatch` («Без раздела · N»). Другие места, где спрашивают о той же операции: «История»
(`HistorySquare.vue:242` → `OpCategorySheet`) и лента (`WeekFeedSheet.vue:33`) — по нажатию, не сами.

Данные для воспроизведения: настоящие выписки владельца — `C:\Users\SW\finance\memory\secrets\statements\` (только
чтение; в Handoff — без имён и сумм семьи); пуш перевода — синтезировать по формату `push_test.go:30` через
`POST /api/wallet/push` стенда (или положить операцию `source: 'push'` в копию в тесте). Хранилище ключей устройства —
`lib/storage.ts:20 OPERATIONS_STORAGE_KEYS`.

## Задача

1. **Воспроизвести.** На стенде (§6: PG `54491`, Go `8191`, Vite `5291`) семья владельца не нужна — своя семья из двух;
   загрузить выписки владельца за последний месяц, добавить пуш «Перевод <Имя Ф.>» на ту же сумму и день, что перевод
   человеку в выписке. Пройти «Неделю» → «Разобрать» → ответить всеми способами (чип раздела; «Кому → что»; «Потом»;
   «Нет, это другое» у `match`, если он есть), закрыть/открыть экран, перезагрузить, подтянуть второй телефон. Записать в
   Handoff, какие из дорог 1–3 дают повтор на данных владельца (и есть ли четвёртая — тогда описать и починить её же).
2. **Р-15 (а):** «Потом» помнится на устройстве сутки: `ff_decisions_deferred` в `OPERATIONS_STORAGE_KEYS` (или отдельный
   ключ `lib/storage.ts`) — `{ [key]: untilIso }`; `Week.vue` читает при монтировании, чистит протухшее; ключ пачки —
   `unknownBatch:<week>` (новая неделя — новая пачка). «N из M» и закрытие листа без вопросов — как были.
3. **Р-15 (б):** у операции с телефона `kind` `transfer-out`/`transfer-in`, без `counterparty`, с `merchant` вида
   `^Перевод (\p{Lu}\p{Ll}+(?: \p{Lu}\p{Ll}+)? \p{Lu}\.)$` — `counterparty` = имя (одно место: `fromWire` в
   `stores/operations.ts` или чистая функция `phoneCounterparty(op)` в `model.ts`, вызываемая из `fromWire` и `settlePhone`;
   `isPhoneStub` не трогать — «Перевод» без имени остаётся заглушкой). Следствия сами: `categorize` → «Переводы людям»,
   `ruleMatchOf` → `{counterparty}`, «Кому → что» в чипах, `unknownGroups` объединяет пуш и строку выписки. На сервер
   `counterparty` пуша **не отправлять** (это вывод клиента; `toWire` шлёт `counterparty ?? null` — проверить, что
   операция с телефона в `pending` не попадает с выведенным полем, либо что сервер её не трогает — батч пуш-операций
   пишет только `category_id`/`internal`; если шлёт — выводить поле на чтении, не в копии).
4. **Р-15 (в):** `declined` хранит и операцию: запись `opId` + пара (`${opId}|${kind}:${targetId}:${period}`); `openMatches`
   отбрасывает кандидатов с отклонённой **операцией**; старые записи без `opId` читаются как раньше (миграции
   хранилища — чтение обоих форматов). `markedOps(…, declined)` (`matching.ts:163`) — тот же разбор ключа.
5. Если воспроизведение показало причину вне 2–4 — починить минимально в этой же задаче; если причина в двух устройствах
   (`declined` на устройстве) — починка (в) достаточна на одном телефоне, перенос в личный документ — хвост §4 с
   описанием.

## Критерии приёмки

- Воспроизведение в Handoff: какие дороги дали повтор на данных владельца, сколько раз спрашивалось до и после (0 повторов
  после).
- Перевод человеку (пуш и/или строка выписки) спрашивается не больше одного раза; любой ответ («раздел», «Кому → что»,
  «Между своими», «Нет, это другое», «Потом» в пределах суток) держится после закрытия экрана, перезагрузки, `pull`, замены
  пуша выпиской и повторной загрузки той же выписки.
- Правило по получателю одно на пуш и выписку (в «Разбор трат» настроек — одна строка).
- `cd frontend && npm run build && npx vitest run` зелёные; стенд 390 px, обе темы — сценарий п. 1 после починки.
