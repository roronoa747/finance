# MGV-14 — Сквозная приёмка, E2E тесты двух клиентов (фронт + бэк)

Блок 5 · MVP · Каталог: `frontend/`, `backend/` · Зависит от: MGV-13 · Роли: все

## Контекст (что уже есть)
- Завершены все экраны приложения: `Access`, `Setup`, `Overview`, `Budget`, `Ritual`, `Capital`, `Goals`, `Deposit`.
- Все маршруты в роутере ведут на полноценные экраны (компонент `PlaceholderView.vue` выведен из эксплуатации).
- Запущен и протестирован Go бэкенд на порту 8080 с миграциями PostgreSQL.
- Накоплены E2E тесты: `smoke.test.ts`, `block3-screens.test.ts`, `block4-budget-ritual.test.ts`.

## Задача
1. Реализовать полный сквозной E2E-тест совместной работы двух пользователей в одном домохозяйстве (`frontend/e2e/two-clients-sync.test.ts`):
   - Клиент 1 (Ильяс, слот `a`) регистрирует домохозяйство, проходит онбординг, создает инвайт-код.
   - Клиент 2 (Аруна, слот `b`) входит по инвайт-коду, присоединяется к семье.
   - Клиент 1 добавляет общий счет и цель; Клиент 2 видит обновление через слияние `mergeDocs`.
   - Клиент 1 создает приватный счет (`private_docs`); Клиент 2 не имеет доступа к приватному счету Клиента 1.
   - Клиент 1 запускает Ритуал высвобождения средств; результат отражается в общих взносах на цели для обоих партнеров.
2. Провести аудит и удаление временных заглушек (`PlaceholderView.vue`).
3. Полный прогон тестов бэкенда и фронтенда (`backend: go test ./...`, `frontend: npm test && npm run build`).

## Тесты
- E2E тест совместной работы двух клиентов и слияния изменений.
- E2E тест изоляции приватных документов между участниками.

## Критерии приёмки
- Зелёный статус всех тестов бэкенда и фронтенда.
- 0 неиспользуемых компонентов-заглушек.
- Успешная сквозная верификация в браузере.
