# MGV-07 — Клиент синхронизации API и хранилище Pinia (фронт)

Блок 2 · MVP · Каталог: `frontend/` · Зависит от: MGV-06 · Роли: все

## Контекст (что уже есть)
- Go API эндпоинты: `/api/auth/*`, `/api/household/*`, `/api/sync/household`, `/api/sync/private`.
- Реализованный алгоритм слияния `merge.ts` из MGV-06.
- Поведение старого клиента синхронизации: `src/store/sync.ts` и `src/store/useStore.ts`.

## Задача
1. Создать API-клиент `frontend/src/api/client.ts` с авторизацией (JWT bearer token) и обработкой ошибок.
2. Создать Pinia-хранилище `useAuthStore` (`frontend/src/stores/auth.ts`) для управления сессией, токеном, текущим пользователем и домохозяйством.
3. Создать Pinia-хранилище `useFinanceStore` (`frontend/src/stores/finance.ts`):
   - Локальное хранение текущего документа казны и личного кошелька (IndexedDB / localStorage).
   - Очередь отправки изменений.
   - Механизм разрешения конфликтов: при получении `409 Conflict` автоматически вызывается `merge()`, обновляется локальный стейт и повторяется `POST /api/sync/household`.

## Тесты
- Юнит-тест клиента API с моком HTTP-ответов.
- Интеграционный тест Pinia store: проверка автоматического слияния при конфликте версий.

## Критерии приёмки
- Запуск цикла синхронизации успешно читает и сохраняет документ казны на бэкенде.
- При искусственном конфликте версий (409) хранилище корректно вызывает слияние и досылает результат.
- `cd frontend && npm test` успешно проходит.

## Вне скоупа
- Пользовательские интерфейсы и экраны (Блок 3, MGV-08+).
