# Бриф «Миграция на Go + Vue 3» (migrate-go-vue)

## Контекст
Приложение «Казна / Family Finance» — PWA для ведения семейных финансов с поддержкой двух участников.
Текущая реализация: React 19 + TypeScript + Vite + Zustand + Supabase.
Цель владельца: осознанный перевод проекта на стек Go (бэкенд) + Vue 3 SPA (фронтенд) с базой данных PostgreSQL.

## Что хочется получить и зачем
1. Полноценный, независимый Go-бэкенд с REST API для авторизации, версионирования и синхронизации семейного бюджета.
2. Фронтенд на Vue 3 SPA (Vite + Pinia + Tailwind CSS), полностью повторяющий всю функциональность текущего приложения (8 экранов, математика, графики, адаптивность).
3. База данных PostgreSQL для хранения данных домохозяйств, документов и приватных кошельков.
4. Сохранение 100% существующей бизнес-логики:
   - Математика аннуитета, досрочного погашения, вкладов (`finance.ts`).
   - Алгоритм бесконфликтного слияния данных (`merge.ts`).
   - Доменные инварианты (целые числа, токены цветов).

## Эпики
- **Эпик 1: Go Backend (Блок 1, L-режим)**:
  - Структура Go-сервера (`backend/`), чистый роутинг, CORS, конфигурация.
  - Подключение к PostgreSQL, схема миграций (`households`, `members`, `household_docs`, `private_docs`).
  - Аутентификация (регистрация, вход, выдача JWT токенов).
  - Эндпоинты синхронизации документов с проверкой ревизий `rev`.
- **Эпик 2: Vue 3 Core + Математика (Блок 2, M-режим)**:
  - Инициализация `frontend/` на Vue 3 + Vite + TypeScript + Tailwind.
  - Портирование `lib/finance.ts`, `lib/money.ts`, `lib/dates.ts` с Vitest-тестами.
  - Pinia-хранилище с поддержкой `merge.ts` и синхронизации через Go API.
- **Эпик 3: Базовые экраны (Блок 3, M-режим)**:
  - `Access.vue` (авторизация/приглашения), `Setup.vue` (мастер настройки).
  - `Overview.vue` (сводка, капитал, свободные деньги).
- **Эпик 4: Бюджет и Ритуал (Блок 4, M-режим)**:
  - `Budget.vue` (План, Календарь, Список обязательств).
  - `Ritual.vue` (перераспределение высвободившихся средств).
- **Эпик 5: Капитал, Кредиты и Цели (Блок 5, M-режим)**:
  - `Capital.vue` (счета, калькулятор и досрочка по кредитам).
  - `Goals.vue`, `GoalDetail.vue`, `Deposit.vue`.
  - Сквозная верификация и E2E приёмка.

## Явно НЕ делаем на этапе миграции
- Новые не проверенные фичи не добавляются во время миграции: цель — воспроизвести текущую функциональность 1-в-1 на новом стеке, сохранив математическую точность.

## Резюме бриф-интервью

- **Цель одной строкой:** Миграция приложения с React+Supabase на независимый стек Go (бэкенд) + Vue 3 (фронтенд) + PostgreSQL без потери логики и данных.
- **Скоуп:** 5 блоков (Go Backend, Vue Core, Экраны 1-3, Бюджет/Ритуал, Капитал/Кредиты/Цели).
- **Решения (кандидаты в Р-*):**
  - **Р-1 (Стек):** Бэкенд на Go (Go 1.27+), фронтенд на Vue 3 + Vite + Pinia, БД — PostgreSQL. *(источник: бриф и выбор владельца)*
  - **Р-2 (Архитектура репо):** Монорепозиторий: каталог `backend/` и каталог `frontend/`. Исходный `src/` остаётся эталоном до полной приемки. *(источник: решение архитектора, согласовано владельцем)*
  - **Р-3 (Протокол синхронизации):** Go API воспроизводит логику версионирования Supabase: клиент присылает номер ревизии и документ, сервер проверяет конфликты. *(источник: бриф)*
- **Эскиз блоков:**
  1. `block-1-backend` (Go + PostgreSQL + Auth + Sync API) — **L**
  2. `block-2-vue-core` (Vue 3 + Vite + Pinia + Finance math) — **M**
  3. `block-3-screens-base` (Access + Setup + Overview) — **M**
  4. `block-4-budget-ritual` (Budget + Calendar + Ritual) — **M**
  5. `block-5-capital-goals` (Capital + Credits + Goals + E2E) — **M**
- **Режим процесса:** Блок 1 — L (безопасность, БД, API), остальные — M.
