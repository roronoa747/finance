# MGV-09 — Экран Overview.vue (сводка, капитал, графики) (фронт)

Блок 3 · MVP · Каталог: `frontend/` · Зависит от: MGV-08 · Роли: все

## Контекст (что уже есть)
- Завершена задача MGV-08: роутер, навигация, экраны входа и первичной настройки.
- Финансовая математика `frontend/src/lib/finance.ts`, форматирование `money.ts`, `num.ts`, `dates.ts`.
- Pinia-хранилище `useFinanceStore` со списком счетов, долгов, целей, категорий, участников.
- Эталонная верстка экрана: `src/screens/Overview.tsx`.
- Компоненты графиков: `src/components/charts.tsx`.

## Задача
1. Создать компонент `Overview.vue` (`frontend/src/views/Overview.vue`):
   - Карточки сводки:
     - Общий капитал (активы на счетах минус остаток по кредитам).
     - Доходы месяца (сумма зарплат участников).
     - Обязательные расходы (план по категориям + ежемесячные платежи по кредитам).
     - Свободный остаток / дельта.
   - Подушка безопасности (прогресс-бар покрытия обязательных расходов в месяцах по формуле `emergencyCoverage`).
   - Блок ближайших платежей и целей с прогрессом накоплений.
   - Круговая диаграмма / распределение расходов по категориям.
2. Реализовать переиспользуемые UI-компоненты карточек и графиков:
   - `frontend/src/components/MetricCard.vue` — карточка с крупным числом, меткой и трендом/долей.
   - `frontend/src/components/CategoryBar.vue` — визуальная полоса распределения расходов по токенам цветов (`--d1`..`--d5`).
   - `frontend/src/components/EmergencyBanner.vue` — статус подушки безопасности.
3. Подключить экран к роутеру на маршрут `/` в `AppShell.vue`.

## Тесты
- Юнит-тесты расчёта показателей для экрана `Overview.vue`:
  - Корректный расчёт совокупного капитала при наличии нескольких счетов и кредитов.
  - Расчёт месячной дельты (доходы минус расходы).
  - Отображение статуса подушки безопасности.
- Тест рендеринга `Overview.vue` с моковыми данными хранилища.

## Критерии приёмки
- Экран `Overview.vue` открывается по умолчанию после авторизации и завершения настройки.
- Все числа соответствуют доменным инвариантам (форматируются через `money.ts`, считаются через `finance.ts`).
- При изменении данных в `financeStore` показатели реактивно обновляются.
- `cd frontend && npm test && npm run build` проходит чисто (0 ошибок).
