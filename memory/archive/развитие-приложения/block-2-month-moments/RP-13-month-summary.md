# RP-13 — Итог месяца на двоих (фронт)

Блок 2 · MVP · Каталог: `frontend/` · Зависит от: RP-10, RP-12 · Роли: все

## Контекст (что уже есть)

- Р-22: итог месяца — одна карточка «мы»: что оплачено, что закрыто, насколько
  приблизились к желаниям. Никаких сравнений участников. Р-30: месяц — по Алматы.
- Блок 7 (RP-28) добавит в эту карточку кнопку «Разобрать» — карточка должна быть одним
  компонентом, куда легко добавить действие.
- Данные: `payments` (платежи, зарплаты, досрочки — RP-06, RP-08, RP-10), моменты прогресса
  (RP-12), `Goal.movements`, вишлист `WishItem` (`price`, `bought`, `boughtOn`).
- `views/Overview.vue` — место карточки (рядом с вопросом конца месяца RP-11 — не
  дублировать).

## Задача

1. `finance.ts`: итог месяца по ключу месяца — оплачено (сколько платежей и сумма),
   закрыто (кредиты), досрочки (сэкономлено), отложено в цели (сумма взносов), приближение к
   желаниям (например, сколько процентов прибавила ближайшая цель/желание — выбрать честную
   меру и описать). Никаких разрезов по участникам в результате функции.
2. Карточка «Наш <месяц>» на Обзоре: показывается в конце месяца и в первые дни следующего
   (за прошлый месяц) — окно выбрать и описать; плюс доступ к прошлому месяцу, если это не
   требует нового экрана (иначе — только текущий/прошлый).
3. Тон «мы», без оценок «плохо/хорошо», без сравнения участников.

## Тесты

- `lib/finance.test.ts`: итог на наборе записей и взносов; записи другого месяца не
  попадают; надгробия не считаются; нет полей по участникам.
- SSR Обзора: карточка в окне, текст без имён участников в сравнительном смысле.

## Критерии приёмки

- Браузер: итог месяца виден обоим одинаковым, без сравнения участников; цифры совпадают с
  `finance.ts`.
- `cd frontend && npm run build && npm test` зелёные.

## Вне скоупа

- ИИ-разбор («Разобрать») — RP-28.
- Графики трат по категориям (отвергнуто владельцем).
