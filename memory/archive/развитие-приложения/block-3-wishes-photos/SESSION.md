# Блок 3 — Желания с фото · сессии

**Цель блока:** желание перестаёт быть строчкой — у него фото, у каждого свой список, вход
по аватару, подарки-сюрпризы скрыты от адресата вплоть до фото, и видно, что именно
приближают досрочка и освободившиеся деньги.

Сессии: исполнитель ⬜ · критик ⬜ · приёмка ⬜ · ревью backend ⬜ · ревью frontend ⬜ · клинап ⬜

## Промпт исполнителя — уровень build · Opus 5 · effort high (ultrathink)

```
/worker развитие-приложения 3 ultrathink
```

Блок-специфика:

- Ветка `rp-block-3-wishes-photos` от `main` (после деплоя Блока 2). Push — с согласия
  владельца; `main` не трогать; **прод-БД не трогать** (миграция в прод — клинап).
- Задачи по порядку: `RP-14` (Go) → `RP-15` → `RP-16` → `RP-17`.
- Среда: для фото нужен реальный Postgres — локальный/Docker одноразовый (`TEST_DATABASE_URL`
  и `DATABASE_URL` для `go run ./cmd/server`, **не** Supabase); на моках — только хендлер-тесты.
  Два профиля браузера для скрытых желаний.
- Безопасность (L): права на фото — по матрице §3 индекса; 404 вместо 403 там, где 403
  раскрыл бы существование скрытого.
- Верификация: `cd backend && go build ./... && go vet ./... && go test ./...` + PG-режим;
  корень `go vet ./api/... && go test ./api/...`; `cd frontend && npm run build && npm test`.
- **Факты кода после Блоков 1–2 и паритета** (сверены критиком Блока 2, 2026-09-26; ТЗ писались раньше):
  - `WishItem` (`types/finance.ts`) не менялся: `id`, `name`, `price`, `by`, `addedOn`, `url?`, `bought`,
    `boughtOn?` (ISO; у старых записей прода — «dd.mm.yyyy») + `Tracked`.
  - **Действия стора желаний уже есть** (PV-18 паритета): `addWish`, `updateWish`, `removeWish`,
    `toggleBought` в `stores/finance.ts`; `Goals.vue` вызывает их (`:135`, `:150`, `:300`), прямых
    `mutateHouseholdDoc` для желаний нет — **п. 5 RP-16 сделан**, RP-16 добавляет только фото.
  - Шапка `AppShell.vue:78-96`: аватары — `<span>` без действия; рядом с заголовком — `SyncBadge` (шторка
    синка, PV-20) — вход в список участника его не трогает. Маршруты — ленивые (PV-22), дети оболочки:
    `''`, `budget`, `goals`, `goals/:id`, `capital`, `capital/:id`, `ritual`, `plan`.
  - Итог месяца RP-13 (`monthSummary` → `MonthSummaryCard`, «один для обоих») считает «Купили из списка» по
    `finance.wishlist` (общий документ). **Скрытые подарки из личного документа в этот вход не подмешивать** —
    итог разъедется между телефонами (RP-13: «виден обоим одинаковым»).
  - «Это приближает» на `/ritual` (RP-17 п. 3): у Ритуала два режима суммы — разовая (`?from=salary`,
    `?from=rest`, флаг `once`: взносы в цели сейчас) и ежемесячная (без параметра, `?from=credit`:
    прибавка к `Goal.monthly`). Функция `finance.ts` принимает режим явно.
  - Зарплата может лечь на личный счёт: запись в общем `payments` ссылается на id счёта из личного документа —
    слияние RP-15 id счетов не меняет. `AccountChoice` принимает подписи `label`/`none`.
