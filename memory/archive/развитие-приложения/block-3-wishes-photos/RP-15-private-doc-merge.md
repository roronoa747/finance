# RP-15 — Слияние личного документа (фронт)

Блок 3 · MVP · Каталог: `frontend/` · Зависит от: Блок 1 · Роли: все

## Контекст (что уже есть)

- Р-9: скрытые желания-подарки живут в `private_docs`. У одного человека два устройства
  (телефон + ноутбук) — личный документ получает правки с обоих, как общий.
- Стор `stores/finance.ts`: `privateDoc` (`Record<string, unknown>`, сейчас — `accounts`),
  `privateRev`; `pullPrivateDoc` кладёт серверную копию **поверх** локальной;
  `pushPrivateDoc(data)` пушит с `privateRev` **без слияния** — при 409 бросает ошибку;
  `mutatePrivateDoc` (`:448`) — путь правки. Общий документ для сравнения: `syncHousehold`
  (GET → `mergeDocs` → push, до 4 попыток на 409, `localEdits`/`syncRuns` защищают от
  затирания правок, пришедших во время запроса) и `pullHousehold`.
- Сервер: `GET/POST /api/sync/private` — тот же протокол ревизий (`last_seen_rev`, 409 с
  `server_doc`); после RP-03 — не теряет ключи верхнего уровня.
- `lib/merge.ts`: `mergeList` по id (LWW + надгробия; после RP-02 — поля проигравшего не
  теряются), `mergeDocs` для общего документа.
- Движок `stores/syncEngine.ts` — синк общего документа по событиям; личный — посмотреть,
  где и когда синкается сейчас.
- Демо (RP-05): личный документ в демо на сервер не ходит.

## Задача

1. Слияние личного документа: `accounts` и будущие списки (скрытые желания — RP-17) — по id,
   как в общем; незнакомые ключи не теряются (правило RP-02).
2. Синк личного документа по той же схеме, что общий: GET → слить → push, повтор на 409,
   правка во время запроса не затирается; `pull` сливает при неотправленном (как RP-04).
   Переиспользовать механику общего синка, а не копировать её (параметризовать — если это не
   раздувает код; решение в Handoff).
3. Движок синка синкает и личный документ (события, интервал) — если сейчас не синкает.
4. Статус бейджа учитывает и личный документ (неотправленная личная правка — «ждёт
   отправки»).

## Тесты

- `lib/merge.test.ts`: личные документы с двух устройств — счета объединяются, надгробие
  побеждает.
- `stores/finance.test.ts`: 409 на личном push → слияние и повтор, правка цела.
- `e2e/two-clients-sync.test.ts`: один пользователь, два клиента, разные личные правки
  офлайн → обе на сервере; партнёр личного не видит (как раньше).

## Критерии приёмки

- Существующая изоляция личного (`two-clients-sync.test.ts`) зелёная без правок ожиданий.
- `cd frontend && npm run build && npm test` зелёные.

- Изменения серверного API личного документа.
