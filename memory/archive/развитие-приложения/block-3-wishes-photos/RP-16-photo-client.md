# RP-16 — Фото на телефоне: сжатие, загрузка, показ (фронт)

Блок 3 · MVP · Каталог: `frontend/` · Зависит от: RP-14 · Роли: member (загрузка), все (показ)

## Контекст (что уже есть)

- Р-8: фото сжимается на телефоне (~100 КБ, webp); в документе только id; добавить желание
  можно офлайн, прикрепить фото — только с сетью. Р-9: фото скрытого — только автору.
- Ручки RP-14 (точные пути, параметр «скрытое», лимит — из Handoff RP-14): загрузка → id,
  выдача по id, удаление.
- `api/client.ts`: базовый URL `/api`, токен из `localStorage['ff_auth_token']` в
  `Authorization: Bearer`; `ApiError(status)`. **`<img src="/api/...">` токен не несёт** —
  картинку надо получать `fetch` с заголовком и показывать через `URL.createObjectURL`
  (или другой способ без утечки токена в URL — не класть токен в query).
- `WishItem` (`types/finance.ts`): `id, name, price, by, addedOn, url?, bought, boughtOn?`
  + `Tracked`. Вишлист — вкладка `views/Goals.vue` (`?tab=wish`): `createWish` (`:127-151`)
  и `toggleWishBought` (`:153-165`) пишут через `mutateHouseholdDoc` напрямую (действий стора
  нет), удаления/правки желания нет.
- PWA: `vite-plugin-pwa` `generateSW`, `navigateFallbackDenylist: [/^\/api\//]` — ответы
  `/api` в кэш SW не попадают.
- Тесты — Node без DOM: canvas/`createImageBitmap` в тестах недоступны.

## Задача

1. Сжатие на клиенте: картинка (камера/галерея/скриншот) → webp ~100 КБ (длинная сторона —
   разумный предел, качество подбирается до целевого размера); если браузер не умеет webp
   на выходе (старый Safari) — jpeg. Модуль отдельный (`lib/…`), параметры — константы с
   комментарием.
2. Прикрепить фото к желанию: с сетью — загрузить, записать id в желание (новое поле
   `WishItem`); без сети — желание сохраняется без фото, кнопка «прикрепить» честно говорит,
   что нужна сеть.
3. Показ: загрузка по id с токеном → object URL; кэш в памяти на сессию (и, по желанию,
   Cache Storage) — без повторных запросов при каждом рендере; освобождение URL.
   Нет фото / 404 — спокойная заглушка без стоковых картинок.
4. Замена/удаление фото у желания (удаление на сервере — по правилам RP-14).
5. Действия стора для желаний (добавить, изменить, отметить купленным, удалить-надгробие) —
   вынести из `Goals.vue` в `stores/finance.ts`; Goals переходит на них.

## Тесты

- Логика подбора размера/качества — чистая функция (без canvas) с тестами.
- Клиент API: загрузка шлёт байты с нужным `Content-Type` и токеном; выдача → blob.
- Стор: действия желаний; офлайн-добавление без фото.

## Критерии приёмки

- Браузер (телефонная ширина, локальный стенд с PG или моками): желание с фото из галереи —
  фото ≤ ~150 КБ на сервере, видно партнёру во втором профиле; офлайн — желание без фото,
  после сети фото прикрепляется.
- `cd frontend && npm run build && npm test` зелёные.
