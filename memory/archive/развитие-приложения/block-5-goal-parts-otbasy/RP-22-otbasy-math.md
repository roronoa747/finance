## Контекст (что уже есть)

- Р-12: Отбасы полностью — вклад с госпремией; строки «свои / проценты банка / премия
  государства»; подсказка перед концом года «добрать до лимита»; прогноз цели с премией;
  учёт в «копить или гасить» (не советовать останавливать пополнения, пока правила не
  сверены). **Правила премии исполнитель сверяет по актуальным источникам, по памяти не
  берёт.** Р-30: «конец года» — по Алматы. Правило заказчика: без хардкода.
- NEXT.md «Отбасы: вклад с государственной премией»: заказчик пользуется, премия начисляется
  за год; сейчас вклад считается как обычный — накопления по квартире занижены; «жилищный»
  тип: обычные проценты плюс премия на пополнения года в пределах лимита; Отбасы —
  единственный инструмент, который может обыграть 33% годовых по кредиту.
- Вклады: `Account.kind = 'deposit'`, `Account.deposit {annualRate, months, monthlyTopUp,

  (сложный процент с капитализацией), `realRate`. Цель ссылается на счёт накоплений
  `Goal.accountId`; части цели — RP-21.
- Суммы — целые тенге; все расчёты — `finance.ts`.

## Задача

1. **Сверка правил (до кода, результат — в Handoff и в комментарии у расчёта с источником и
   датой):** размер госпремии, база (пополнения за год? остаток?), годовой предел (в МРП и
   значение МРП на текущий год), условия получения (минимальный срок, что при досрочном
   расторжении), ставка банка по вкладу, когда начисляется премия. Первичные источники
   (Отбасы банк, нормативные акты). Если правила неоднозначны — записать варианты и спросить
   владельца, не выбирать молча.
2. Модель: жилищный вклад — признак и параметры у вклада (ставка премии, предел, МРП года и
   т.п.) — **полями с дефолтами из сверки**, а не константами в коде (МРП меняется каждый
   год, правило «без хардкода»); к цели — через существующий `Goal.accountId`.
3. `finance.ts`: прогноз жилищного вклада по месяцам — отдельно «внесено своих», «проценты
   банка», «премия государства»; сколько ещё можно внести в этом году до предела премии и
   что это даст; прогноз даты цели с учётом премии.

- Handoff: правила со ссылками и датой сверки; дефолты параметров совпадают с ними.
- Расчёт премии сверен вручную на одном примере (записан в Handoff).
- `cd frontend && npm run build && npm test` зелёные.
