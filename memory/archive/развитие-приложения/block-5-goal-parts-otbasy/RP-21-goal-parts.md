# RP-21 — Части цели и «ипотека против аренды» (фронт)

Блок 5 · MVP · Каталог: `frontend/` · Зависит от: Блок 1 · Роли: member (правка), все (просмотр)

## Контекст (что уже есть)

- Р-11: части у любой цели, а не особый экран «Квартира»: у части свободное название, сумма
  и срок; итог и дата цели считаются. У части может быть «будущий платёж» (ипотека) — экран
  сравнивает его с обязательством, которое он заменит (человек выбирает, какое; у заказчика —
  аренда 220 000). Правило заказчика: без хардкода (части называются свободно).
- `Goal` (`types/finance.ts`): `id, name, need, seed, have (= seed + Σ movements, всегда
  пересчёт), monthly, hue, planPct, movements, accountId?` + `Tracked`. Слияние —
  `lib/merge.ts` `mergeGoal` (движения — объединение по id, `have` пересчитывается; остальное
  — LWW по цели целиком, после RP-02 — поля проигравшего сохраняются).
- Экраны: `views/Goals.vue` (список, кольца `components/Ring.vue`), `views/GoalDetail.vue`
  (`/goals/:id`: срок/платёж, слайдер взноса → `setGoalMonthly`, пополнить/снять, история,
  правка → `updateGoal`, удалить).
- `finance.ts`: `goalMonths(remaining, monthly)`, `goalMonthly(remaining, months)`,
  `amountAt(o, key)` (сумма обязательства в месяце), `liveObligations`.
- Правило новых данных (§6): части редактируются с двух устройств → список с id внутри цели,
  слияние по id (LWW по части + надгробия), а не LWW всей цели.

## Задача

1. Модель: у цели необязательный список частей (id, свободное название, сумма, срок —
   месяц, необязательный «будущий платёж»: ежемесячная сумма и id обязательства, которое он
   заменит) + `Tracked`. Слияние частей по id внутри `mergeGoal`.
2. `finance.ts`: у цели с частями `need` = сумма частей (вычисляется, не хранится вторым
   источником — решить, как не разойтись со старым полем `need`, и описать); дата цели —
   из сроков частей и темпа взносов (честное правило — в комментарий); по части —
   сколько откладывать в месяц к её сроку. Сравнение «будущий платёж против заменяемого
   обязательства»: разница в месяц и вывод «потянем ли» (платёж ≤ текущий + свободный остаток
   месяца — или другое честное правило, описать).
3. UI в `GoalDetail`: добавить/изменить/удалить часть; итог и дата наверху; блок «ипотека
   против аренды» у части с будущим платежом (выбор заменяемого обязательства из списка).
   Цель без частей работает как раньше.
4. Карточка цели в списке показывает итог по частям.

## Тесты

- `lib/merge.test.ts`: правка разных частей одной цели на двух устройствах — обе; удаление
  части — надгробие; взносы не теряются.
- `lib/finance.test.ts`: итог и дата по частям; сравнение платежа с арендой 220 000 на
  живых числах заказчика (ипотека — тестовое значение) — разница и вывод.
- SSR `GoalDetail`: части и блок сравнения.

## Критерии приёмки

- Браузер: цель «Квартира» из частей (взнос, ипотека как будущий платёж, ремонт, мебель,
  сделка) показывает итог, дату и «ипотека против аренды».
- Старые цели без частей — без изменений цифр.
- `cd frontend && npm run build && npm test` зелёные.
