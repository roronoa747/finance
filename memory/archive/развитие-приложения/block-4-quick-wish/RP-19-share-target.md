# RP-19 — «Поделиться», загрузка скриншота и разбор в желание (фронт)

Блок 4 · MVP · Каталог: `frontend/` · Зависит от: RP-18 · Роли: member

## Контекст (что уже есть)

- Р-16: «Поделиться → в приложение» через Web Share Target PWA (Android): ссылка или картинка
  становится желанием. На iOS — загрузить скриншот; разбор одинаков. Р-17: разбор —
  подсказка, поля правятся, запуск явной кнопкой, в UI прямо сказано, что картинка уходит в
  Google. Р-28: в экране «что уйдёт» прямо сказано, что на бесплатном тарифе Google может
  использовать присланное для обучения и показывать разметчикам.
- PWA — `frontend/vite.config.ts`: `vite-plugin-pwa`, `registerType: 'autoUpdate'`,
  стратегия `generateSW`, `manifest: {...}` (`:19`), `workbox` (`:34`) с
  `navigateFallback: 'index.html'`, `navigateFallbackDenylist: [/^\/api\//]`. SW — `/sw.js`,
  scope `/` — **не менять** (прошлые установки PWA на телефонах). Тест сборки
  `frontend/e2e/pwa-build.test.ts` проверяет манифест и `sw.js`.
- Share Target: `GET` покрывает только `title/text/url`; **файлы требуют `POST`
  multipart и обработчика `fetch` в SW** (в `generateSW` — через `workbox.importScripts` со
  своим файлом или переход на `injectManifest`; выбор — исполнителя, с обоснованием в
  Handoff; предпочтителен меньший сдвиг).
- Желания: действия стора (RP-16), фото — загрузка/показ (RP-16), списки по людям (RP-17).
- Ручка разбора и признак «ИИ включён» — RP-18 (пути и формат — из Handoff RP-18).

## Задача

1. Манифест: `share_target` — ссылка/текст и картинка. Приём: маршрут (например `/share`)
   открывает черновик желания: ссылка → поле `url` (и название из `title`, если есть);
   картинка → фото желания (через сжатие RP-16).
2. На любой платформе в форме желания — «загрузить скриншот» (выбор файла/камера).
3. Кнопка «Разобрать» (только если ИИ включён, есть сеть, есть картинка): сначала экран
   «что уйдёт» — эта картинка уйдёт в Google (Gemini); на бесплатном тарифе Google может
   использовать её для обучения и показывать людям-разметчикам; — «Отправить» / «Не надо».
   После ответа — название и цена подставлены в поля, всё правится; ошибки/лимит — спокойный
   текст, ручной ввод всегда доступен.
4. ИИ выключен (нет ключа / Р-17 решение владельца) — кнопки нет, остальное работает.
5. Viewer: «Поделиться» открывает приложение, но вместо формы — честный текст, что
   добавлять желания может участник; «Разобрать» недоступен (403 на сервере).

## Тесты

- `e2e/pwa-build.test.ts`: в собранном манифесте есть `share_target` с верными полями;
  `sw.js` на месте и scope прежний.
- Разбор параметров `/share` → черновик желания (чистая функция).
- Стор/клиент: «Разобрать» шлёт картинку на ручку, подставляет ответ; 503 → кнопка
  скрыта/текст; `price: null` → цена пустая.

## Критерии приёмки

- На Android (установленная PWA из прод-сборки или локальная по `vite preview` на телефоне в
  одной сети) «Поделиться» из браузера создаёт черновик желания со ссылкой; картинка —
  с фото. Если поставить PWA локально нельзя — проверка переносится в смоук клинапа на проде
  (записать в Handoff).
- Скриншот (iOS или любой браузер) разбирается в название и цену после экрана «что уйдёт»
  (или разбор честно выключен по Р-17).
- `cd frontend && npm run build && npm test` зелёные.
