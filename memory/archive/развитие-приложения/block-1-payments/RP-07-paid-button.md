# RP-07 — «Оплатил» в интерфейсе и следующий платёж (фронт)

Блок 1 · MVP · Каталог: `frontend/` · Зависит от: RP-06 · Роли: member (viewer — только видит)

## Контекст (что уже есть)

- Решения: Р-3 (одно нажатие, сумма подставлена, правка — исключение, сразу виден
  следующий платёж; неотмеченный — нейтрален, без упрёка), Р-5 (счёт по умолчанию — прошлой
  оплаты; сменить счёт / «не списывать» — исключение), Р-7 (снять ошибочную отметку),
  Р-13 (viewer не отмечает), Р-29 (паттерны Vue, токены, телефон).
- Где сейчас видны платежи по графику:
  - `views/Budget.vue`: вкладки `plan | calendar | list`; `events` (`:87-142`) — зарплаты,
    обязательства (`dueIn`, годовые — только в свой месяц, клик → `/capital?obligation=id`),
    кредиты (`day`, `payment`, клик → `/capital?credit=id`), синтетические «Взносы в цели»;
    календарь (`:289-434`), выбранный день → `dayEvents`; список (`:437-463`).
  - `views/Overview.vue`: «До зарплаты» (`:272-327`, `untilPayday`), «Впереди»
    (`:330-352`, все платежи месяца по дню, прошедшие не отфильтрованы).
  - `views/Capital.vue`: модалка кредита (`:994-1043`, только просмотр + симулятор + удалить),
    модалка обязательства (`:1115-1206`); query `?credit=<id>`, `?obligation=<id>`.
- Роль: `useAuthStore().isViewer`. Стор-действия отметки/снятия и «следующий платёж» — из
  RP-06.

## Задача

1. Одна переиспользуемая кнопка/строка «Оплатил» для обязательства и кредита (компонент в
   `components/`), встроенная там, где человек видит платёж: события Бюджета (календарь и
   список), «До зарплаты» и «Впереди» на Обзоре, модалки кредита и обязательства в Капитале.
2. Одно нажатие = отметка с суммой из графика и счётом по умолчанию. Сразу после — видно
   «следующий платёж: <дата> · <сумма>» (и для кредита — новый остаток).
3. Исключения — не на главном пути: поправить сумму, выбрать другой счёт, «не списывать».
   Первая оплата цели без прошлого счёта — спросить счёт один раз (с вариантом «не
   списывать»).
4. Отмеченный платёж выглядит «закрытым» спокойно; «снять отметку» — с подтверждением,
   деньги возвращаются на счёт.
5. Неотмеченный прошедший платёж — нейтральный вид: никакого красного, «просрочено»,
   восклицаний (Р-3, тон).
6. Viewer видит отметки, но кнопок нет.
7. «Впереди» на Обзоре: оплаченное в этом месяце — не как предстоящее (ушло вниз / помечено).

## Тесты

- SSR-рендер (`renderToString`, как `views/Budget.test.ts`): неотмеченный платёж — кнопка
  есть; отмеченный — вид «оплачено» и следующий платёж; viewer — кнопки нет.
- Стор + рендер: отметка кредита меняет остаток в модалке Капитала; снятие возвращает.
- e2e Блока 1: «оплатил аренду» → следующий платёж виден, карта уменьшилась; второй клиент
  после синка видит то же.

## Критерии приёмки

- Браузер, телефонная ширина: «оплатил аренду» одним нажатием → видно следующий платёж,
  остаток карты уменьшился; во втором профиле после синка — то же. Снятие отметки
  возвращает деньги. Под viewer кнопок нет.
- Светлая и тёмная темы — цвета только из токенов.
- `cd frontend && npm run build && npm test` зелёные.
