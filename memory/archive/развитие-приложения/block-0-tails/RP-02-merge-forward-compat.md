# RP-02 — Слияние не теряет незнакомые поля (фронт)

Блок 0 · MVP · Каталог: `frontend/` · Зависит от: — · Роли: все

## Контекст (что уже есть)

- Р-14: новые поля документа старые установленные PWA не должны терять при слиянии; данные
  не теряются ни при одном деплое. Блоки 1–7 добавляют в документ новые списки (`payments`
  и др.) и новые поля сущностей (`Account.amountSetAt`, `Obligation`-флаги, `Goal.parts`, …).
- `lib/merge.ts` `mergeDocs` строит результат **только из известных ключей** (`setupDoneAt`,
  `people`, `categories`, `goals`, `wishlist`, `obligations`, `accounts`, `credits`) — любой
  другой ключ верхнего уровня выпадает. `mergeList` берёт победителя по `updatedAt` целиком
  (`{ ...winner }`) — поля, которые знает только проигравшая версия, пропадают.
- Путь потери: устройство со старым JS (PWA `autoUpdate` — старый код отрабатывает ещё один
  запуск после деплоя) получает документ с `payments`, сливает, пушит без `payments` →
  сервер хранит как есть → отметки пропали у обоих.
- Сейчас это нужно **новому** коду, чтобы следующий переход (Блок 1 → 2 и т.д.) был
  безопасен: после деплоя Блока 0 «старым клиентом» для всех будущих блоков будет уже
  этот код. Страховка от самого первого перехода — RP-03 (сервер).

## Задача

1. `mergeDocs`: ключи верхнего уровня, которых функция не знает, не теряются. Правило для
   незнакомого ключа: если значение — массив объектов с `id` (с обеих сторон или с одной),
   слить как список по id (надгробия сильнее, LWW по `updatedAt`); иначе — взять сторону,
   где ключ есть (при обеих — local; результат должен остаться коммутативным для
   одинаковых значений и детерминированным — описать выбор в комментарии).
2. `mergeList`: при выборе победителя поля, которых у победителя **нет** (ключ отсутствует),
   берутся у проигравшей версии (`{ ...loser, ...winner }`). Удаление поля намеренно
   (присвоение `undefined`/`null`) не должно «воскресать»: явный `null` у победителя —
   это значение, не отсутствие.
3. То же для вложенных элементов, которые сливаются по id (`movements`, версии обязательств)
   — только если это не усложняет код; если усложняет — оставить как есть и записать в
   Handoff (они append-only и не редактируются).
4. Комментарий в шапке `merge.ts` дополнить третьим правилом («незнакомое не теряется»).

## Тесты

- `lib/merge.test.ts`:
  - документ с незнакомым списком `payments` (объекты с id) слит с документом без него →
    `payments` на месте; с обеих сторон разные записи → объединение; надгробие побеждает;
  - незнакомый скаляр/объект верхнего уровня сохраняется;
  - сущность с незнакомым полем (`accounts[0].amountSetAt`) проиграла по времени версии без
    поля → поле сохранилось; явный `null` у победителя сохраняется как `null`;
  - коммутативность и идемпотентность на этих случаях (как существующие тесты файла).

## Критерии приёмки

- Все старые тесты `merge.test.ts` и `e2e/two-clients-sync.test.ts` зелёные без правок
  ожиданий.
- `cd frontend && npm run build && npm test` зелёные.
