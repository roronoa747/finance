## Контекст (что уже есть)

- **Офлайн-бейдж** (хвост Handoff Блока 6 `migrate-go-vue`): открыть приложение без сети →
  шапка показывает «синхронизировано». `components/SyncBadge.vue:72-93` берёт
  `financeStore.status` (`idle` → «синхронизировано», `offline` → «нет сети», `error`/
  `conflict` → «не сошлось», `dirty` → «ждёт отправки», `syncing`). `offline` ставится только
  событием `offline` (`stores/syncEngine.ts:34-36`, если вошли) и ранним выходом
  `syncHousehold` при `navigator.onLine === false` (`stores/finance.ts:115-118`). Статус при
  старте — `'idle'` (`finance.ts`, `ref<SyncStatus>('idle')`), до первого события сети.
- **Н-6** (`memory/archive/migrate-go-vue/block-6-prod-cutover/REVIEW-frontend.md`):
  правка → синк падает (например, истёк вход, 401) → статус `error`, правка только в
  `localStorage` → вход заново в той же вкладке (`views/Access.vue:48-49` login →
  `financeStore.pullHousehold()`; join — `:72-76`) → `pullHousehold` (`finance.ts:197-223`)
  сливает только при `dirty`/новых правках, иначе **кладёт серверную копию поверх** →
  правка потеряна.
- Прямая правка «сливать при любом не-`idle`» небезопасна, пока `logout` (`stores/auth.ts:
  165-167` → `clearAuth()`, чистит только ключи входа) не сбрасывает документ стора:
  иначе вход другим человеком в той же вкладке смешает документы. Выход —
  `AppearancePanel.vue:56-58`.
- Движок: `stores/syncEngine.ts` — `online` → sync, `offline` → `offline`, `focus`/
  `visibilitychange` → sync, интервал 60 с, стартовый полный синк если вошли; при `idle` —
  `pullHousehold`, иначе `syncHousehold`.

## Задача

1. Статус при старте и при потере сети честный: если `navigator.onLine === false` на
   старте движка — `offline`; при `online` — синк (как сейчас). Бейдж без сети никогда не
   говорит «синхронизировано».
2. Неотправленные правки помечаются так, чтобы их можно было отличить после ошибки/выхода:
   `error`/`offline`/`conflict` с непротолкнутыми правками → при следующем pull — слияние,
   не замена (например, флаг «есть неотправленное», сохраняемый в `localStorage`).
3. `logout` сбрасывает стор `finance` (документ, ревизию, статус, личный документ и их ключи
   в `localStorage`) — **но** если есть неотправленные правки, выход сначала предупреждает
   (спокойно, без паники) и даёт синхронизировать или выйти с потерей. Текст — в тоне
   приложения.
4. После п.3 `pullHousehold` сливает при любом статусе, кроме чистого `idle` без
   неотправленного.

## Тесты

- `stores/finance.test.ts` / `stores/syncEngine.test.ts`: старт без сети → `offline`;
  событие `online` → синк.
- Н-6 сценарий (рекомендация ревью): правка → push падает 401 → `error` → «вход заново»
  (новый токен, `pullHousehold`) → правка цела и уходит на сервер.
- `logout` без неотправленного → стор пуст, `localStorage` без документа; с неотправленным →
  флаг предупреждения (логика стора; сам диалог — SSR-рендер или ручная проверка).
- Вход вторым пользователем в той же вкладке после `logout` → документ первого не смешан.

## Критерии приёмки

- Локальный стенд: DevTools → Offline → перезагрузка → бейдж «нет сети»; сеть вернулась →
  «синхронизировано» после синка.
- Н-6 в браузере: остановить `go run ./cmd/server` (или протухший токен), сделать правку,
  перезапустить, выйти/войти → правка на месте у второго клиента.
- `cd frontend && npm run build && npm test` зелёные.
