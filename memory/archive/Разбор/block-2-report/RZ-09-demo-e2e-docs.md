## Задача

1. Документ демо: сидировать `reviewFinds` демо-семьи за 3 закрытых месяца (в `startDemo` рядом с привычками):
   утечка у «Кофейня у дома» — нет, это привычка; взять `leak` «Магазин у дома» (`sc_food`, 9 покупок ≈ 2 300 ₸ у a),
   `recurring` «Онлайн-кинотеатр» 2 490 (нет в плане, у b), `top` для `sc_cafe` с двумя покупками (ресторан 38 000 и
   доставка 12 500), `pricier` — нет. Суммы — чтобы `reviewFindings` дало утечку (≈ 250 000 ₸ в год ≈ 12 % мечты «Поездка в
   Японию»), новое списание и `grew` кафе «покупками».
2. `DEMO_REVIEW` v3: `where` — «Кафе выросло из-за двух крупных вечеров — это две недели мечты.» (черновик, без цифр:
   значения приложение не подставляет — в демо цифры только в `figure`); советы: (1) «Магазин у дома» — `figure` факт
   «за год», `open` → `seller`; (2) «Новое списание» — `figure` факт «в месяц», `open` → `seller` / `cat`; (3) «Отложить в
   подушку» — `do` → `cushion`; `work` — из `reviewWork`. `demoReview(doc, input)` собирает всё по фактам и действиям
   `buildReviewFacts` демо (`figure` и `action` — по `about`-поиску, как кандидат `cushion` сейчас) — ни одного числа в
   словах заготовки; нет действия — совет без него не показывается (Р-6).
3. e2e `e2e/rz-block2-report.test.ts`: (а) телефон 1 — разбор v3 сам → `?review=1` → отчёт: карточки по порядку, счётчик,
   «Куда ушло» с полосами, 2 совета с кнопками; (б) «Сделать» → подтвердил → «✓ Сделано», `planShifts` у обоих;
   (в) «Открыть» раздела → `/month?cat=…` лист раздела открыт, отчёт закрыт; (г) телефон 2 — отчёт без запроса, точка
   гаснет после открытия; (д) viewer — без «Сделать», «Открыть» есть; (е) v3-разбор прошлого месяца в документе → карточка
   «Итог прошлого месяца» со «Сделано ✓»; (ж) демо — «Пример», карточки, «Сделать» → «✓ Сделано», запросов 0;
   (з) `card=2` — старт со второго совета. Старые e2e, ждавшие лист (`data-review`, `data-review-step-v2`), — переведены
   на отчёт.
4. DESIGN.md: §5 «Месяц» — абзац «Разбор v3 (бэклог «Разбор», Блок 2)»: пилюля «✦ Разбор», отчёт-оверлей по адресу,
