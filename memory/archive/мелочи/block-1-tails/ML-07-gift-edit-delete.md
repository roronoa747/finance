# ML-07 — Сюрприз можно исправить и удалить (фронт)

Блок 1 · MVP · Репо/каталог: `frontend/src/components/goals`, `frontend/src/views/Wishes.vue` · Зависит от: ML-06 · Роли: member (viewer — только смотрит)

## Контекст (что уже есть)

Хвост §4 `идея-и-редизайн` **955** (жив, сверено 2026-10-08):

- `updateGift` / `removeGift` — `stores/finance.ts:2071`, :2079 (экспорт :2247-2248); из `.vue` не вызываются;
  `updateGift` — только через `toggleGiftBought` (:2088).
- Строки сюрпризов — `views/Wishes.vue:242-258`: только переключатель «куплено», открыть нельзя. `GiftSheet`
  (`components/goals/GiftSheet.vue:63`) умеет только добавлять. Образец правки — `WishSheet.vue` (режим правки).
- Удаление фото — `deletePhoto` (`lib/photos/store.ts:90`), образец — `GoalDetail.vue:236`, :266. Сюрприз скрыт от
  партнёра (скрытое фото) — удаление обязано чистить фото.

## Задача

1. Нажатие на строку сюрприза открывает `GiftSheet` в режиме правки (имя, цена, фото) — по образцу `WishSheet`.
2. «Удалить» — тихой кнопкой внизу листа (`DangerZone`, как у кредита), удаляет сюрприз и его фото (`deletePhoto`).
3. Viewer: строка открывает лист только для чтения, без «Удалить» (как прочие листы, `authStore.isViewer`).
4. Правило 12: главное действие листа — «Сохранить» (одна брендовая), «Удалить» — тихая.

## Тесты

- DOM `GiftSheet`/`Wishes`: правка имени и цены сохраняется; удаление зовёт `removeGift` и `deletePhoto`; viewer без
  «Удалить».

## Критерии приёмки

- На стенде (member): исправил цену сюрприза, удалил другой — фото исчезло из хранилища; viewer — только чтение.
- `npm run build && npx vitest run` зелёные. В Handoff — главное действие, что скрыто (правило 12).

## Вне скоупа

- Новые поля сюрприза, показ сюрприза партнёру — нет.
