# Бриф «мелочи»

## Контекст

Приложение — семейные финансы B2C (Go + Vue, прод `family-finance-ff.vercel.app`, база — Postgres в проекте
Supabase, схема `app`). Бэклог `идея-и-редизайн`: Блоки 0–3, 9–17 🏁; осталось 4 (фундамент для чужих), 5, 7, 8.
Перед Блоком 4 владелец хочет закрыть мелочи.

## Резюме бриф-интервью

- **Цель одной строкой:** до Блока 4 закрыть накопленные хвосты, убрать остатки старого стека и научить «Долги»
  обязательствам перед людьми.
- **Скоуп:**
  1. **Хвосты §4** — «до Блока 4» и видимые мелочи:
     - **уборка старого**: из репо — React `src/`, корневые `vite.config.ts`/`package.json`/`index.html`/`tsconfig*`
       React, `supabase/`, `public` React, `frontend/e2e/pwa-build.test.ts` перестаёт читать `../../public/favicon.svg`;
       в Supabase — **только части React**: таблицы схемы `public`, пользователи Supabase Auth, Edge Function
       `fx-rate`; env Preview ветки `mgv-block-6-prod` в Vercel. **Схема `app` (наши данные) не трогается.** Бэкап
       `public` до удаления; удаление в Supabase выполняет владелец по готовой инструкции (агент секрет прод-БД
       не читает);
     - **пакет «Свободно после раскладки»** (строки §4 951, 952, 958, 959, 960, 966, 967): сначала сверка каждого
       хвоста с нынешним кодом (после Блоков 9–17 многое переписано). Устаревшие хвосты закрываются записью
       «устарел — <чем закрыт>», живые чинятся. Деньги считает только `finance.ts`;
     - **видимые мелочи**: название и фото желания по ссылке Kaspi (993, 995), центы в валютной сумме (1000),
       правка и удаление сюрприза (955), дубль «без выписки» в шапке «Недели» (992), даты недели дважды (986),
       текст «Остались деньги?» (991). Каждая тоже начинается со сверки «жив ли хвост».
  2. **«Кредиты шире»** (Р-121) — оба вида обязательств перед людьми:
     - **долг человеку** — займ с остатком без процентов и с именем («брат — 500 000, отдаю частями»): строка
       в «Долгах» рядом с кредитами (остаток, полоса «погашено», платёж);
     - **регулярный платёж людям** («маме», алименты, школа) — платёж без остатка; в «Долгах» свёрнутой строкой
       «Людям · N» (как «Подписки · N»), в сумму остатков не входит.
- **Не-скоуп:** **ИИ** — вынесен в отдельный бриф (см. Р-кандидат ниже). Хвосты, привязанные к Блокам 4 и 5 (вход
  через Google, семья, пуши, B2C-23/25/26/28/30), остаются там. Технические хвосты без видимого эффекта (две очереди
  решений 970, суммы разделов недели 987/989, e2e-хелперы 988, «Не разобрано» в «Тратах» 990) — не берём.
- **После MVP / позже:** бриф ИИ — **после Блока 4**.
- **Решения (кандидаты в Р-*):**
  - Р-1. Инициатива «мелочи» — **отдельный бэклог** `memory/backlog/мелочи/`; решения §2 `идея-и-редизайн` остаются
    в силе, взятые хвосты §4 там закрываются ссылкой на задачи «мелочей». *(дефолт составителя — по команде брифа)*
  - Р-2. Хвосты — «до Блока 4» + видимые мелочи (список в скоупе). *(ответ владельца, раунд 1)*
  - Р-3. Каждый хвост — **сначала сверка с кодом**, устаревший закрывается записью, а не чинится. *(дефолт
    составителя, раунд 1 — в описании варианта)*
  - Р-4. Уборка старого: код из репо + в Supabase только React (`public`, Auth, `fx-rate`) с бэкапом; схему `app`
    не трогать; **пауза или удаление проекта Supabase запрещены** — это прод-база. Шаги в Supabase и Vercel —
    владелец по готовой команде. *(ответ владельца, раунд 2 — повтор после уточнения)*
  - Р-5. «Кредиты шире»: два вида — долг человеку (займ без процентов с именем) и регулярный платёж людям.
    *(ответ владельца, раунд 1)*
  - Р-6. Раздел остаётся «Долги»: долг человеку — обычной строкой рядом с кредитами; регулярные платежи людям —
    свёрнутая строка «Людям · N», в сумму остатков не входят. Меняет Р-110 (`идея-и-редизайн`) только добавлением
    строк. *(ответ владельца, раунд 2)*
  - Р-7. Долг человеку входит в сумму долгов, в «без долгов — к <месяц>» и в план «Сначала долги» — **последним**
    (0 %, как рассрочка); ручного порядка нет. *(ответ владельца, раунд 2)*
  - Р-8. Порядок: **Хвосты → «Кредиты шире» → Блок 4 `идея-и-редизайн` → бриф ИИ.** Каждый блок деплоится отдельно
    в приёмке. *(ответ владельца, раунд 2)*
  - Р-9. ИИ — отдельный бриф после Блока 4: где помимо ИП (в том числе анализ бюджета); **платный тариф без обучения
    на данных**; по умолчанию выключен, включает владелец конкретным людям из админки (подписки нет). Записано в
    память агента. *(ответ владельца, раунд 1)*
  - Р-10. «Кредиты шире» начинается с **ворот макета** (как Р-120): артефакт «до | после» экранов «Долги», листа
    долга человеку и формы добавления, 390 px → «ок» владельца → код. *(дефолт составителя — практика Блоков 16–17)*
  - Р-11. Роли — как у кредитов и платежей: member заводит, правит и отмечает «Оплатил», viewer только смотрит.
    *(дефолт составителя — матрица прав §3 `идея-и-редизайн`)*
  - Р-12. Данные — в документе семьи, без новых таблиц и миграций Go. Модель долга человеку и пометки «людям»
    у платежа выбирает бэклог (кандидат: `Credit` со ставкой 0 и признаком «человеку», `Obligation` с признаком
    «людям»); старые документы читаются без миграции. *(дефолт составителя)*
- **Эскиз блоков:**
  1. **Хвосты и уборка** — сверка, починка живых хвостов, видимые мелочи, уборка репо; шаги в Supabase и Vercel —
     владелец. Режим **M** (фронт, немного Go в `linkpreview`). Конвейер: исполнитель → критик → `/ux` → приёмка
     с деплоем.
  2. **«Кредиты шире»** — ворота макета → модель и расчёты в `finance.ts` (долг человеку в сумме, сроке и плане;
     «Людям · N») → экраны «Долги», форма, лист → «Оплатил» у строки. Режим **M + ворота макета**. Конвейер:
     исполнитель ч. 1 (макет) → ворота → ч. 2 → критик → `/ux` → приёмка с деплоем. Зависит от блока 1.
- **Режим процесса:** M (исключений до L нет: Supabase трогает владелец по инструкции, данные `app` не меняются).
- **Критерии готовности:** блок 1 — каждый взятый хвост в §4 `идея-и-редизайн` закрыт («сделано `<коммит>`» или
  «устарел»), репо без React и `supabase/`, сборка и тесты зелёные, бэкап `public` есть, смоук прода ✅. Блок 2 —
  на стенде и проде: завёл долг брату и «маме», оба видны в «Долгах», «Оплатил» уменьшает остаток займа, срок
  «без долгов» и план учитывают займ последним; снимки «до | после» — «ок» владельца.
- **Отложено владельцем:** ИИ — отдельный бриф после Блока 4 (Р-9).
