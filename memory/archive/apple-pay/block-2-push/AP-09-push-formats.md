## Задача

1. Таблица форматов `internal/applepay/push.go`: по банку — список правил (регулярка по заголовку и/или тексту → вид
   операции, группа суммы, группа продавца/имени); банк определяется по полю `app` триггера (название приложения:
   «Kaspi.kz», «Freedom», «Halyk», «Homebank») или по заголовку («Kaspi Gold»…). Покрыть: покупка (в т. ч. Kaspi QR и
   онлайн), оплата услуг, перевод человеку, перевод между своими (если банк пишет так), пополнение / входящий перевод,
   зарплата (если банк её помечает), снятие наличных; отклонено / отказ / код подтверждения / реклама — **не операция**
   (разобрано, но `ignore`).
2. `ParsePush(app, title, body string) (PushOp, Result)`: `Result` ∈ `op` | `ignore` | `unknown`; `PushOp` — банк, вид
   (`purchase` / `transfer-out` / `transfer-in` / `income` / `cash`), знак, валюта и минорные (через `ParseAmount`),
   продавец (`CleanMerchant`; перевод — «Перевод <Имя Ф.>»: полное ФИО сокращать как `shortenFullNames` фронта —
   «Имя Ф.»). Строка «Доступно …» и маски карт в результат не попадают.
3. Ничего не логировать (ни заголовок, ни текст).

## Тесты

- Таблица ≥ 3 образцов на каждый вид каждого банка (синтетические суммы, формы с NBSP / U+202F, с обрезанным
  заголовком Freedom «…»): ожидаемые банк, вид, знак, сумма, продавец; «Доступно» не путается с суммой операции
  (первая сумма с «Пополнение:» / «+» / «Покупка» — операция); полное ФИО → «Имя Ф.»; отказ / код / реклама → `ignore`;
  чужой текст → `unknown`.
- Образцы владельца — в тестах с заменёнными суммами (форма строки та же).
