# AP-10 — Ручка пуша: склейка, перевод себе, приходы, счётчик (бэкенд, миграция 000009)

Блок 2 · MVP · Каталог: `backend/` · Зависит от: AP-09 · Роли: внешний клиент (ключ member); админ — счётчик

## Контекст (что уже есть)

- Р-8 (перевод себе — списание в одном своём банке + пополнение той же суммы в другом в пределах 10 мин → обе
  внутренние; входящие — приход), Р-9 (касание и пуш одной покупки — равная сумма, ≤ 10 мин → одна; тот же источник ≤ 2
  мин → одна), Р-10 (незнакомое не записывается, счётчик в админке), Р-21 (склейка: продавец касания, если не пуст и не
  «Apple Pay», иначе из пуша; банк и вид — из пуша), Р-23 (счётчик — таблица миграции `000009`).
- Из Блока 1: мидлварь ключа, `POST /api/wallet/tap` (образец хендлера), поиск недавней операции с телефона и лимит
  200/сутки, колонки `source` / `occurred_at` / `fx_*` (AP-01). `pairInternalTransfers` фронта не трогает операции с
  `counterparty`; пары пушей помечает сервер (`internal = true` у обеих), телефон их уважает (`categorize` без правила
  `internal` не снимает).
- Админ-метрики: `GET /api/admin/metrics` (`handlers/events.go:84-99`, `isAdmin` :78-80, 404 не-админу),
  `MetricsRepository` (`repository/events_repo.go`), фронт — `views/Admin.vue`. События `app.events` с CHECK видов
  (`000006_events.sql:10`) — **не расширять** (их пишет клиент); счётчик пушей — своя таблица.
- Миграции: `000008` — Блок 1; эта — **`000009_push.sql`**.

## Задача

1. Миграция `000009_push.sql`: `app.push_stats (day DATE, bank TEXT, parsed INT NOT NULL DEFAULT 0, ignored INT NOT
   NULL DEFAULT 0, unknown INT NOT NULL DEFAULT 0, PRIMARY KEY (day, bank))` — без пользователя и текста (Р-11); `bank`
   не узнан — `unknown`.
2. `POST /api/wallet/push` (мидлварь ключа), тело `{app?, title, body}` ≤ 4 КБ: `ParsePush` → счётчик дня (+1 в свою
   колонку) → `ignore` / `unknown` → 200 `{"status":"skipped","reason":"format"}`; `op` →
   - лимит 200/сутки (общий с касанием) → 429;
   - тот же источник `push`, та же сумма и валюта, ≤ 2 мин → `duplicate`;
   - покупка: касание той же суммы и валюты ≤ 10 мин (до или после) → **обновить** операцию касания (банк, вид;
     продавец — по Р-21; `source` остаётся `tap`, отметка склейки не нужна) → `duplicate`; иначе — новая `source =
     'push'`;
   - приход / списание без получателя: парная операция противоположного знака, той же суммы, **другого банка**, ≤ 10 мин,
     обе не internal → обе `internal = true` (`updated_at` двигается — телефон подтянет);
   - перевод человеку, приход, наличные — новая операция по Р-23 (`category_id` null).
   Касание (AP-03) при записи тоже ищет пуш ≤ 10 мин (порядок прихода любой) — правка AP-03-хендлера одной функцией
   склейки, общей для обоих.
3. Метрики админа: `push_stats` за 7 и 30 дней по банкам (разобрано / пропущено / не разобрано) — поле в ответе
   `/api/admin/metrics`.
4. Env `APPLEPAY_PUSH_SHORTCUT_URL` (Р-17; та же проверка префикса iCloud) → поле `push_shortcut_url` в `GET
   /api/wallet`. `backend/README.md` — строка env и абзац о ручке пуша.

## Тесты

- Хендлер (моки, фиксированное `now`): покупка из пуша → `source: push`; касание, потом пуш через 3 мин → одна
  операция (банк из пуша, продавец касания); пуш, потом касание → одна (продавец касания); через 11 мин — две; списание
  Kaspi + пополнение Freedom той же суммы через 4 мин → обе internal; того же банка — нет; через 11 мин — нет; перевод
  человеку → `transfer-out`, продавец «Перевод Имя Ф.», `counterparty` пуст; приход → `transfer-in`, сумма положительная;
  `unknown` → счётчик +1, операции нет; viewer → 403; тело не в логах.
- PG: `push_stats` upsert суммирует; миграция `000009` после `000008` (и с `000007` ИИ, и без).
- Метрики: админ видит, не-админ — 404 (регрессия).

## Критерии приёмки
