## Проверено независимо (не по Handoff-у)

- **Правило 6.** Умножение на курс — только `fxToTenge` (`finance.ts:793`), через `phoneOpTenge`. Деление
  `fx.amount / 100` (минорные → единицы) — там же. Ни в сторах, ни в компонентах Apple Pay арифметики денег нет
  (`grep` диффа). Допуск 3 % — `withinShare` из `finance.ts`. Целые тенге: `fromWire` берёт `amount` сервера,
  `settlePhone` пишет только результат `phoneOpTenge`.
- **Надгробия и итоги.** `send` убирает заменённые из копии до `remember`, их периоды — в `writeTotals`. Надгробия идут
  отдельной задачей очереди (`deleted: true`). `pull` убирает надгробие из копии, а его период пересчитывает (`gone`).
  Живая копия трат, чьё надгробие ждёт в очереди, не возвращается (`buried`). `got` включает надгробия, поэтому
  `send` переписывает итоги, когда пришло чужое. Сумма 0 у непересчитанной валютной траты валидна для сервера
  (`validateOperation` её не режет): надгробие фантома в валюте очередь не заклинит. `isSpend` и `unknownGroups`
  непересчитанную трату (сумма 0) не считают и не спрашивают.
- **`replacedByStatement`.** Те же эксперименты, что у приёмки, плюс варианты исправления (таблица в Н-1). Мутант

## Находки

### Н-1 · средняя · Р-16 п. 2: касание последнего дня остаётся рядом со своей строкой выписки (хвост приёмки 4)

`frontend/src/lib/statements/phone.ts:53-56`. Касание той же суммы в соседний день (кофе каждый день, у Apple и банка
разные названия — п. 1 не срабатывает) делает строку неоднозначной: два кандидата → ни одного. Касание накануне
уходит фантомом по п. 3, касание последнего дня остаётся вторым рядом со строкой выписки. «Неделя» сразу после
загрузки завышена на сумму покупки до следующей выписки, чей период накроет этот день не последним. Самолечится
только у Kaspi/Freedom. Эксперимент (период 01–15.10, Kaspi, 1 200 ₸):

| Сценарий | Сейчас | Приёмка «кандидаты без фантомов» (X) | Предлагаемое (V) |
|---|---|---|---|
| A: строки 14 и 15, касания 14 и 15 | p14 (**p15 — дубль**) | p14, p15 ✓ | p14, p15 ✓ |
| B: строка 15; касание 14 отклонено, касание 15 | p14 (**p15 — дубль**) | ✓ | ✓ |
| C: строка 14; касание 15 после выгрузки (его в выписке нет) | p14 ✓ | p14, **p15 — убрано лишнее** | p14 ✓ |
| D: тест критика «вторая выписка с перекрытием» (k1 Kaspi 14, c1 карта 15) | k1 ✓ | k1, **c1 — касание другой карты убрано навсегда** | k1 ✓ |

Вариант приёмки как записан (X) **ломает существующий стор-тест критика** (`operations.applepay.test.ts`, «вторая
выписка с перекрытием»: c1 банка `card` уходит надгробием навсегда) и сценарий C.

**Рекомендация.** V — фантом этой же выписки не делает строку неоднозначной, только если не-фантом ближе по дате:

```ts
const phantom = (ph: Operation) => files.some((f) => ph.bank === f.bank && ph.date >= f.from && dayNumber(ph.date) < dayNumber(f.to))
// (2): единственный кандидат — как было; или единственный не-фантом, который ближе любого фантома этой выписки
// (фантом уходит по п. 3 в любом случае).
const real = candidates.filter((ph) => !phantom(ph))
const pick = candidates.length === 1 ? candidates[0]
  : real.length === 1 && candidates.every((ph) => ph === real[0] || gap(st, ph) > gap(st, real[0])) ? real[0] : undefined
```

Цикл п. 3 — через тот же `phantom`. Тесты `phone.test.ts`: A и B — оба убраны, C — p15 остаётся. Все прежние тесты
(в т. ч. «два кандидата — не заменять» без периода и стор-тест критика) — без правок. V пары по п. 2 только сужает
относительно X. «Единственная» по-прежнему означает «единственная, которая не уходит фантомом», слова Р-16 не
меняются (трактовка приёмки).

**Вердикт: клинап** (V, не X). Часть хвоста про банк `card` — Н-6.

### Н-2 · средняя · `pull` откатывает раздел, поставленный другим устройством (хвост приёмки 5)

`frontend/src/stores/operations.ts:671` (`phone.add` — всякая пришедшая трата с телефона), `:695`, `:709`.
`settlePhone` раскладывает правилами **этого** телефона и трату, пришедшую уже с разделом. Эксперимент: в ленте
`category_id: 'sc_cafe'`, правила здесь ещё старые → в копии `null`, на сервер ушло `['a5', null]`. Гонка
штатная: возврат в приложение запускает в одном такте `sync()` → `syncPrivate` (правила) и `pullOnReturn()`
(`syncEngine.ts:111-115`). Ответил «куда отнести?» на компьютере → iPhone откатывает раздел, итог партнёра уходит в
«Без раздела», вопрос возвращается. Строки выписок `pull` и так не перераскладывает: изменённые правила
перераскладывает устройство, где правило поменяли (`recategorizeAll`). Трата с телефона с разделом — уже
разложенная, ей нужно то же.

**Рекомендация.** Перераскладывать только «сырые» с сервера и ждущие курса: `list = all.filter((o) => (arrived.has(o.id)
&& o.categoryId === null) || (o.fx && o.amount === 0))`. Итоги — по периодам всех пришедших и `gone`, как сейчас.
Тест: пришла с `category_id` при отставших правилах — раздел тот же, назад ничего не ушло. Р-2 «телефон после
подтягивания пересчитывает» по-прежнему выполняется для новых трат: сервер пишет их с `null`.

**Вердикт: клинап.**

### Н-3 · средняя · Гонка `settlePhone` (ждёт курс) и `send`: `TypeError` гасится, пришедшие траты не разложены (хвост приёмки 5)

`frontend/src/stores/operations.ts:695-713`. `list` снят до `await ensureRates` (:701). Если за это время `send` убрал
пришедшую трату надгробием (:484), `ops.value[o.id]` — `undefined`, и `prev.amount` (:712) бросает. Эксперимент
(лента: Magnum Kaspi, Coffee Boom Halyk с правилом, USD; выписка с Magnum, курс отдан после тоста):
`lastError` = «Cannot read properties of undefined (reading 'amount')». Следующий `flush` из `pull` в `send`
**затирает ошибку в `null`** (:619), поэтому её не видно. Coffee Boom остаётся `categoryId: null`, в итоге
«Без раздела» (4 489 ₸ вместо раздела «Кафе»), и правило есть, а вопрос «куда отнести?» снова задан. Курсор уже
сдвинут, следующий `pull` эту трату не перераскладывает. Окно реальное: курс сегодняшнего дня часто приходит
`partial`, а это 3 повтора × 2 с (`FX_RETRY_MS`) ≈ тост 6 с. Сценарий: «открыл приложение и сразу загрузил выписку».

**Рекомендация.** После `await` пересобрать список из текущей копии:
`const list = all.value.filter((o) => ids.has(o.id))` (`ids` — снятые до ожидания). **Не** `prev?.amount`:
отсутствующая операция попала бы в `changed`, и `remember` воскресил бы убранную трату, а итог партнёра удвоился бы
до следующего `pull`. Тест — сценарий выше: ни ошибки, ни воскрешения, Coffee Boom в разделе.

**Вердикт: клинап.**
