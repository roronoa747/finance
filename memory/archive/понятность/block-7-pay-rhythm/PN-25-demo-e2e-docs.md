## Контекст (что уже есть)

- Демо `lib/demo.ts`: люди `a` «Вы» (оклад 1 500 € с прошлого года, пришла) и `b` «Партнёр» (тенге, :55-61); демо

## Задача

1. Демо: партнёр «b» — ритм `advance` (аванс 15-го 150 000, зарплата 30-го остаток) — виден второй ритм без ломки
   демо-цифр (сумма месяца прежняя); недельный ритм в демо не вводить (демо и так зависит от дня недели). Гвард
   `Access.demo.dom.test.ts` — ожидания.
2. e2e `frontend/e2e/pn-block7-pay-rhythm.test.ts` (фиксированные даты `at`): (а) участник с недельной зарплатой
   150 000 по пятницам: план октября 2026 — доход 750 000 (5 пятниц), «Капитал»/«Месяц» строка «✓ 0 из 5», «Пришла» →
   отметка `period` 2026-10-02, строка «1 из 5», доход плана = 150 000 факт + 600 000 ожидание; (б) аванс: два
   события, «до зарплаты» показывает ближайшее; (в) плавающий: «Пришла» без суммы невозможна, после трёх отметок
   (300/320/340) ожидание = 320; (г) выписка с четырьмя пятничными приходами → четыре вопроса, «да» → четыре
   отметки; (д) старый документ без ритма — прежние числа; (е) второй телефон видит события и отметки.
3. Снимки обе темы («Изменить оклад» три ритма, строка и лист недельной, плавающая, первый запуск) → артефакт.
4. Доки: `DESIGN.md`; §6 «После Блока 7» (поля `Person`, `payEvents`, `period` ISO-дня, `expectedSalaryTenge`,
   `PayRhythmFields`); `STATE.md` — приёмка.
