# Бриф «Паритет React → Vue и план погашения»

## Контекст

Прод `family-finance-ff.vercel.app` с 2026-09-24 на Go + Vue. Пользователей двое — владелец и
партнёр. Сверка паритета (`../развитие-приложения/parity-react-vue.md`) нашла ~30 потерь переноса
React → Vue: действия, которые стали невозможны, неверные расчёты, урезанные тексты. Расчётные
функции `finance.ts` перенесены построчно, потери — в интерфейсе и сторе. Эталон — React `src/`
(не трогать до «Уборки старого»). Нумерация пунктов ниже — по сверке: А-1…А-11, Б-12…Б-22.

## Что хочется получить и зачем

Вернуть потерянное — прежде всего расширенный калькулятор «копить или гасить» — и сделать
его лучше: выбранный план не остаётся картинкой, а ведёт семью каждый месяц. Цели,
поставленные ради него на паузу, объясняют, почему стоят. По каждому платежу по кредиту
видно, сколько ушло в долг, а сколько банку. Источник — решение владельца в сверке
(2026-09-24) и ответы в интервью.

## Эпики / крупные куски

1. Калькулятор «копить или гасить» как в React (А-1) и точные расчёты (А-4, А-6…А-8, А-11).
2. Правка денег: кредит (А-2), форма платежа с разделом и оценкой (А-3), обязательство (А-9),
   валютный счёт (Б-16), калькулятор досрочки (Б-17), удаление (Б-21); разбивка «в долг /
   проценты» и график платежей.
3. Выбранный план «Сначала долги» — новое, сверх React.
4. Покупки и цели (А-5, А-6).
5. Оболочка, тексты, мелочи (Б-12…Б-15, Б-18…Б-20, Б-22).

## Явно НЕ делаем

- А-10 (партнёр по коду без шага дохода) и вход по коду без сессии — хвост «новые семьи».
- Слияние версий обязательства (`mergeObligation`, хвост §4 RP) — остаётся хвостом.
- Отбасы в плане — это RP-23 (Блок 5 `развитие-приложения`).

## Резюме бриф-интервью

- **Цель одной строкой:** вернуть во Vue всё, что было в React (кроме нового входа партнёра), и
  превратить «копить или гасить» в выбранный план, который ведёт месяц за месяцем, с честной
  разбивкой каждого платежа на долг и проценты.
- **Скоуп:** все пункты А сверки, кроме А-10; все пункты Б (Б-12…Б-22); три хвоста §4
  `развитие-приложения` — закрытый кредит в плане, кит окон (Н-9, Н-10, подпись `Field`), тема на
  старте; новое — выбранный план и разбивка «в долг / проценты» с графиком.
  · **Не-скоуп:** А-10 и «по коду без сессии»; `mergeObligation`; Отбасы в плане (RP-23); бэкенд.
  · **После MVP:** —.
- **Решения (кандидаты в Р-*):**
  - Р-1. **Скоуп** — как выше. *(ответ владельца, раунды 1–2)*
  - Р-2. **Эталон — React `src/`** (файл:строка — в сверке): поведение, поля, тексты и выводы как в
    React; вид — паттерны Vue и кит (Р-29 RP), цвет только из токенов. *(дефолт)*
  - Р-3. **Калькулятор возвращается целиком:** горизонт «год/два/три», «Что не останавливать»,
    «Сначала подушка», «Вложить уже накопленное», «без процентных долгов через N мес.», вывод в обе
    стороны («копить выгоднее на…»), заметка о беспроцентных. Расчёт — `simulateStrategy`
    (`finance.ts`), остатки — из записей Блока 1, закрытые кредиты не участвуют.
    *(ответ владельца, раунд 1)*
  - Р-4. **«Выбрать этот план» — план ведёт каждый месяц.** План хранится в общем документе, его
    видят оба. Отмеченные цели показывают «На паузе ради плана» с переходом к плану и объяснением.
    Их взносы в Бюджете и «Свободно» становятся строкой «Досрочно по плану». Каждый месяц план
    называет одну сумму досрочки в самый дорогой процентный долг, её вносят одним нажатием через
    досрочку Блока 1 (счёт — по Р-5 RP). Пропущенный месяц не упрекает: план пересчитывается от
    факта, дата закрытия сдвигается. *(ответ владельца, раунд 2)*
  - Р-5. **Конец плана.** Закрыт самый дорогой долг — его платёж идёт в следующий по ставке.
    Закрыт последний долг с процентами — цели снимаются с паузы сами, план уходит в историю с итогом
    «сэкономили N ₸ процентов». Отменить план можно в любой момент: цели возобновятся, история
    останется. *(ответ владельца, раунд 2)*
  - Р-6. **Экран плана:**
    - план и факт по месяцам;
    - что не ушло в цели: по каждой цели на паузе — сумма и сдвиг даты;
    - выигрыш против «копим как сейчас»: прогноз на момент выбора и факт по досрочкам;
    - шаг плана в «Ритуале» и в строке кредита вместо `credits[0]`.

    *(ответ владельца, раунд 2)*
  - Р-7. **Подушка в плане — цель, отмеченная при выборе.** Взносы в неё не останавливаются. Пока в
    ней меньше месяца обязательных списаний, шаг плана — пополнить её. Цели нет — план предложит её
    завести. «Ритуал» больше не угадывает подушку по слову «подушка» в названии.
    *(ответ владельца, раунд 3)*
  - Р-8. **Разбивка «в долг / проценты»** (`creditSplit`, снимок `Payment.principal`):
    - строка кредита — следующий платёж;
    - отметки «Оплатил» и досрочки — с итогом за всё время;
    - Бюджет — «из них проценты банку N ₸ в месяц»;
    - график платежей по кредиту, при активном плане — с досрочками.

    *(ответ владельца, раунд 2)*
  - Р-9. **Пауза цели выводится из активного плана и не хранится в цели.** `Goal.monthly` не
    переписывается, отмена плана не правит цели. План — запись с id в новом списке верхнего уровня
    (`SyncDoc`, `defaultSyncDoc`, явно в `mergeDocs`, Р-14 RP). Активный план один, завершённые
    остаются историей. Если двое выбрали разные планы офлайн, побеждает поздний. *(дефолт)*
  - Р-10. **Досрочка по плану — по умолчанию «сократить срок»**, как считает `simulateStrategy`:
    платёж не меняется, и хвост «снизить платёж по LWW» не разрастается. Режим можно сменить в окне
    досрочки, план пересчитается от факта. *(дефолт)*
  - Р-11. **Хвост §4 «досрочка при платеже меньше процентов» (`lumpPlan` → null) — в блок плана.**
    Иначе план назначит шаг в долг (например, кредитку с минимальным платежом), который нельзя
    применить. *(дефолт)*
  - Р-12. **viewer не выбирает и не отменяет план**, форм правки не видит (как Р-13 RP). *(дефолт)*
  - Р-13. **Кит окон:** `Sheet`, `Select`, `Row` со слотом действия, токен затемнения, подпись
    `Field` без обёртки групп кнопок. Все новые и возвращённые окна строятся на ките. Старые копии
    переводятся на кит только на экранах, которые блок и так трогает. *(ответ владельца, раунд 1)*
  - Р-14. **Испорченные данные правим руками в вернувшихся формах**, скрипта нет. Приёмка L-блока
    правки (с «да» владельца, прод только на чтение) выписывает подозрительные записи:
    обязательства `d4` без оценки, кредиты под 0%, цели с минусом. *(ответ владельца, раунд 3)*
  - Р-15. **Контракт Go не меняется.** Ошибки входа (Б-13) переводятся на фронте по текстам Go.
    *(дефолт)*
  - Р-16. **Календарные границы плана** (месяц шага, пропуск) — по Asia/Almaty, хелпер RP-06
    (Р-30 RP). *(дефолт)*
  - Р-17. **Порядок и деплой.** Старт — после 🏁 Блока 1 `развитие-приложения` (клинап с деплоем).
    Блок 2 RP ждёт 🏁 последнего блока паритета. Деплой — после каждого блока. Ветки —
    `pv-block-N-<тема>` от `main`, ID задач — `PV-NN`. *(решение владельца в сверке 2026-09-24;
    порядок — раунд 3; ветки и ID — дефолт)*
  - Р-18. **Судьбы хвостов §4 `развитие-приложения`** (проставляет шаг `/backlog`):
    - «потери переноса», Н-9/Н-10, «тема на старте», «закрытый кредит в плане» → этот бэклог
      (RP-12 закрытый кредит больше не делает);
    - «по коду…» + А-10 → хвост «новые семьи» в `STATE.md`;
    - «досрочка при платеже меньше процентов» → этот бэклог (Р-11);
    - «Что уже есть» в ТЗ RP-23 переписывается в конце блока плана: калькулятор и план — факт,
      Отбасы встраивается в план.

    *(раунд 1 + дефолт)*
