## Задача

1. `lib/finance.ts`: `scheduleMismatch(principal, payment, months): { paid, gap, suggest } |
   null` по формулам React (`null`, когда `rateFromSchedule` находит решение или входы ≤ 0).
2. Капитал: подписи и тексты как React — переключатель «Без них» / «Знаю ставку» / «Знаю срок»
   (на `Segmented` внутри `Field`), текст «Без них», поле «Сколько платежей осталось», плашка
   «Ставка получается / N% годовых», предупреждение с числами и вторым абзацем. Сохранение
   остаётся возможным (0% + note «рассрочка»).
3. Мастер: «Сколько платежей осталось» (placeholder «17»), «Ставка (ГЭСВ из договора), %
   годовых», подсказка про ГЭСВ, предупреждение при `null` (текст React `:382-385`).
4. Всё, что с цифрами, — `finance.ts`; компоненты только показывают.

## Тесты

- `lib/finance.test.ts`: `scheduleMismatch` — `null` при решаемом графике; при 1 000 000 / 10 000
  / 12 → `{ paid: 120_000, gap: 880_000, suggest: 100 }`; входы ≤ 0 → `null`;
  `rateFromSchedule` при слишком коротком сроке → `2` (документирует потолок 200%).
- SSR `views/Capital.test.ts`: Капитал по маршруту `/capital?add=debt` (открывает форму через
  watch `:145-156`) — есть «Сколько платежей осталось», «Знаю срок», «Без них».
- Мастер: шаг кредита за внутренним состоянием — проверка в браузере (критерии); если
  удобно — SSR через `initial`-состояние шага, не обязательно.

## Критерии приёмки

- Браузер, Капитал: «Знаю срок», 1 000 000 / 10 000 / 12 → предупреждение «12 платежей по
  10 000 — это 120 000 ₸, а остаток вы указали 1 000 000 ₸. Не хватает 880 000 ₸: похоже,
  платежей 100, а не 12.» + «Записать всё равно можно…»; «Добавить» сохраняет 0% «рассрочка».
  1 000 000 / 91 680 / 12 → «Ставка получается 18,0% годовых», сохраняется с этой ставкой.
- Браузер, мастер: те же входы → плашка ставки / предупреждение; сохранение не блокируется.
- `cd frontend && npm run build && npm test` зелёные.
