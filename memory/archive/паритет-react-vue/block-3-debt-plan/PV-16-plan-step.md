## Задача

1. **Ритуал:** при активном плане корзина «Досрочно по плану» (сумма шага, эффект через
   `lumpPlan` в режиме `term`) вместо «Досрочно по кредиту»; подушка — только
   `plan.cushionGoalId` (угадывание по названию убрать; без плана подушки в Ритуале нет);
   при шаге `cushion` — текст «Сначала подушка: до месяца обязательных списаний не хватает N ₸»
   и корзина подушки первой. `confirm()` по-прежнему пишет только цели — досрочка вносится
   кнопкой ниже, не Ритуалом (Ритуал распределяет «освободившееся», план — свою сумму).
2. **Строка кредита-цели плана в Капитале:** подпись «шаг плана: N ₸ в {monthIn(key)}» и
   действие `Row` «Внести по плану» (member); внесено в этом месяце (`applied`) — «внесено по
   плану · N ₸ · {atLabel}», без кнопки. Одно нажатие: счёт по умолчанию — прошлый для этого
   кредита (`lastAccountFor`); истории нет — `Sheet` с выбором счёта и «Не списывать» (как первая
   оплата в `PaidRow`), затем `applyPlanStep`. Ссылка «Изменить режим» открывает окно досрочки с
   подставленной суммой (там можно выбрать «снизить платёж» — Р-10; план пересчитается от факта).
3. **Экран плана (`DebtPlan.vue`, минимум PV-15):** блок «Шаг этого месяца» с той же кнопкой;
   при `cushion` — «Пополнить подушку» → `/goals/:id`; при `done` — ничего (PV-14 закроет план).
   Пропущенный месяц: строка «В {monthIn(прошлый)} досрочки не было — план пересчитан от факта»
   (без упрёка; только если прошлый месяц после старта и без `applied`).
4. Viewer: кнопок нет, тексты видны.

## Критерии приёмки

- Браузер, два профиля: Ритуал показывает «Досрочно по плану»; в Капитале у кредита-цели
  кнопка «Внести по плану» — одно нажатие (счёт прошлой оплаты) → остаток и карта у обоих, в
  окне досрочки запись с «по плану»; «Изменить режим» → «снизить платёж» → план пересчитан;
  перевести время на следующий месяц (DevTools/фикстура) → новый шаг, старый — факт.
- `cd frontend && npm run build && npm test` зелёные.
