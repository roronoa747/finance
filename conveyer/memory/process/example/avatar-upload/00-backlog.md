## 1. Цель

Пользователь загружает аватар в профиле; аватар виден в шапке и профиле вместо
инициалов, переживает перезагрузку. Режим процесса: M, один блок.

## 2. Зафиксированные решения

- **Р-1. Хранение**: диск `var/avatars/<user_id>.jpg`, раздача `GET /avatars/{user_id}`
  (public, immutable-кэш с версией `?v=`). S3 — после MVP. *(интервью р.1)*
- **Р-2. Валидация**: вход JPEG/PNG ≤ 2 МБ; бэкенд ресайзит до 256×256 и хранит
  всегда JPEG. Ошибки — plain-text `http.Error`, как во всём API. *(дефолт)*
- **Р-3. Признак наличия**: поле `avatar_version int` в `users` (0 = нет аватара);
  фронт строит URL сам: `/avatars/{id}?v={version}`. *(составитель, из разведки кода)*
