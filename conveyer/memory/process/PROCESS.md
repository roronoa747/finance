# Процесс: чистая логика

Дистилляция механики ведения проекта через бэклоги. Это ядро — инварианты, которые
не зависят от проекта, стека и моделей. Как применять — `BRIEF-GUIDE.md` (этап брифа)
и `BACKLOG-GUIDE.md` (ведение бэклога); проектные отличия — `PROJECT.md` (если заведён).
Почему именно так — `RATIONALE.md`.

## Зачем это нужно

Крупная работа (несколько сессий, зависимые задачи) с LLM-исполнителем разваливается
в трёх местах: решения пересматриваются каждой новой сессией; контекст сессии либо
раздут (дорого, шумно), либо неполон (галлюцинации); прогресс и отклонения теряются
между сессиями. Процесс закрывает все три дыры письменными артефактами.

## Конвейер

```
Бриф владельца
  → Бриф-интервью (вопросы до полной ясности — BRIEF-GUIDE)
  → Бэклог (решения зафиксированы, задачи разложены по блокам)
  → Блоки по очереди: рабочая сессия → критик → приёмка [→ пост-приёмка]
  → Архив (закрытое уезжает целиком)
```

## Инварианты (ядро — не нарушать ни в одном проекте)

1. **Решения фиксируются один раз.** Бэклог открывается списком пронумерованных
   решений (`Р-1, Р-2, …`) — «конституция» инициативы. Рабочие сессии их НЕ
   пересматривают. Изменить решение может только владелец; изменение записывается
   (дата, старое → новое, причина), а не молча правится.
2. **Контекст сессии минимален и точен** (контекст-диета). Сессия читает: индекс
   бэклога → файлы своего блока → файлы кода, названные в ТЗ. Живые доки целиком не
   читаются — нужные факты заранее перенесены в ТЗ; при пробеле — точечный grep.
3. **Одна сессия — одна роль.** Исполнитель, критик и приёмщик — разные сессии со
   свежим контекстом. Исполнитель не принимает сам себя. Критика без свежих глаз —
   не критика.
4. **Всё письменно.** Статусы — в индексе бэклога. Факты выполнения, отклонения от ТЗ
   с причинами, грабли среды — в Handoff блока. Ничто важное не живёт только в голове
   (контексте) сессии: следующая сессия стартует с нуля и должна собрать картину из
   файлов.
5. **ТЗ самодостаточно.** Файл задачи содержит контекст (факты кода), шаги, критерии
   приёмки с командами верификации и явное «вне скоупа». Цель: задача выполнима без
   чтения живых доков целиком.
6. **Верификация реальностью.** «Зелёный билд ≠ работает». Каждая задача проверяется
   исполняемыми командами (build + тесты) И в реальной среде (браузер для UI,
   живой стенд для API) до отметки «готово».
7. **Промпт следующей сессии — артефакт текущей.** Сессия завершается тем, что
   актуализирует блок-специфику следующей роли в SESSION.md и называет её команду
   (`/critic <слаг> N` и т.д.; общая часть роли — в `.claude/commands/`). Конвейер
   самоподдерживается: владелец только копирует команду в новую сессию.
8. **Скоуп-гигиена.** «Вне скоупа» — в каждом ТЗ. «После MVP» — в индексе. Находки
   крупнее текущей задачи не делаются походя — записываются в хвосты с явной судьбой
   (см. BACKLOG-GUIDE «Хвосты»). Абстракции «на будущее» не заводятся.
9. **Атомарность.** Задача = отдельный коммит. Блок = единица приёмки и деплоя.
   Инициатива = единица архивирования.
10. **Архивная дисциплина.** Активный каталог держит только живое; закрытый бэклог
    уезжает в архив целиком. Доки и бэклоги — в git, вместе с историей.
11. **Секреты никогда не попадают в git.** Любые значения — пароли (включая
    тестовые), токены, DSN с кредами, ключи — живут ТОЛЬКО в `memory/secrets/`
    (в `.gitignore`) или в env; в доках/Handoff-ах — имя переменной или ссылка на
    файл в `secrets/`, никогда значение. Гвард — pre-commit-хук
    `memory/process/hooks/pre-commit` (включается `git config core.hooksPath memory/process/hooks`);
    обходить его (`--no-verify`) для секретов запрещено.

## Роли

| Роль | Что делает | Чего НЕ делает |
|---|---|---|
| **Владелец** (человек) | Бриф, ответы на вопросы, изменение решений, вердикт по хвостам | Не пишет ТЗ и не гоняет верификацию |
| **Составитель** (сессия) | Бриф-интервью → бэклог: блоки, решения, ТЗ, промпты | Не пишет код |
| **Исполнитель** (сессия) | Задачи строго по порядку, по одной; Handoff | Не меняет решения, не принимает сам себя, не переходит к следующему блоку |
| **Критик** (сессия) | Ревью диффа блока: корректность, упрощение, тесты, доки; актуализирует промпт следующего блока | Не добавляет фич |
| **Приёмщик** (сессия) | Сверка с критериями, верификация в реальной среде, вердикт | Не чинит код сам (возврат исполнителю) |

Роли — это сессии, не модели. Какую модель на какую роль — `MODELS.md`
(один сменный листок, промпты ссылаются на роли).

## Режимы: масштаб процесса под масштаб работы

Тяжесть процесса выбирается на этапе брифа и пишется в индекс бэклога. Дефолт — M.

- **S — мелочь.** ≤ 1 сессии работы, один репо, легко откатить. Бэклог не заводится:
  одна сессия делает и верифицирует; при неуверенности — файл задачи по шаблону, без
  каталога. Признак S: описание задачи короче, чем был бы её бэклог.
- **M — стандарт.** Несколько сессий/блоков. Полный бэклог; конвейер блока —
  **три сессии: исполнитель → критик → приёмка**. Деплой — в приёмке после вердикта.
- **L — высокий риск.** Публичные контракты, безопасность, деньги, миграции данных,
  критичный прод. Конвейер M **плюс пост-приёмка**: независимое код-ревью диффа блока
  по каждому затронутому каталогу → клинап-сессия, выполняющая рекомендации; деплой
  переезжает в клинап (на прод уходит только код, прошедший все ревью).

Эскалация точечная: инициатива может идти в M, а отдельный блок (например, «auth»)
помечается L прямо в таблице блоков.

## Артефакты (карта)

```
memory/
├── STATE.md                       # статус проекта: активные бэклоги, хвосты, история
├── backlog/<инициатива>/          # активный бэклог
│   ├── 00-backlog.md              # индекс: цель, решения Р-*, таблица блоков/задач, техконтекст
│   ├── <инициатива>-brief.md      # бриф владельца + резюме бриф-интервью
│   └── block-N-<тема>/
│       ├── SESSION.md             # цель блока, трекер, промпты сессий, Handoff, итоги
│       ├── <ID>-NN-<слаг>.md      # ТЗ одной задачи
│       └── REVIEW-<каталог>.md    # только L: находки каталожного ревью
├── secrets/                       # локальные секреты — в .gitignore, в git только README (инвариант 11)
├── decisions/                     # журнал изменённых решений (только изменения Р-*)
└── archive/                       # закрытые бэклоги целиком
```

Шаблоны каждого артефакта — `memory/process/templates/`. Заполненный пример —
`memory/process/example/`.

## Жизненный цикл блока (M)

```
⬜ → 🔄 исполнитель (задачи по ID, Handoff)
   → 🔄 критик     (дифф + Handoff → упрощение, тесты, доки; промпт след. блока)
   → ✅ приёмка    (критерии + реальная среда → вердикт; деплой)
   → 🏁 закрыт     (в L — после клинапа пост-приёмки)
```

Блок N+1 не открывается, пока блок N не закрыт. После последнего блока — архив
и запись в STATE.md.
