# Family Finance

**Сайт:** https://family-finance-ff.vercel.app — деплоится автоматически при каждом пуше в main.

Семейный финансовый учёт на двоих: цели, обязательства, накопления и покупки в дом.
Мобильный интерфейс в первую очередь, десктоп — вторым.

## Запуск

```bash
npm install
npm run dev      # откроется на http://localhost:5173, в консоли будет и адрес для телефона
npm run build    # продакшен-сборка в dist/
npm run preview  # посмотреть собранную версию
npm run smoke    # прогнать приложение в браузере: экраны, консоль, миграция данных
```

`npm run smoke` открывает приложение в настоящем Chrome и проверяет, что экраны
отрисовались, в консоли пусто и данные старого формата переживают обновление. Это дешевле,
чем ловить такое руками: именно он поймал и падежи в датах, и потерю поля при миграции.

Чтобы открыть на телефоне, возьмите из вывода `npm run dev` строку **Network** — телефон
должен быть в той же сети. Дальше «Поделиться → На экран Домой»: приложение ставится как
обычное, работает офлайн и открывается без адресной строки.

## Что уже работает

- **Обзор** — свободные деньги месяца, доход с разбивкой по участникам, распределение по разделам,
  ближайшие платежи, прогресс целей.
- **Событие «освободится N ₸»** — рождается автоматически из версий обязательства, а не заводится руками.
- **Бюджет** — три вида одного месяца: план по долям, календарь по дням, плоский список.
  Суммы и оклады редактируются, проценты пересчитываются на лету.
- **Цели** — создание, взносы с историей, два режима расчёта (от даты и от суммы), индексация на инфляцию.
- **Покупки в дом** — список с ценой, автором и ссылкой; отметка «куплено» переносит вещь в историю.
- **Капитал** — счета, обязательства, чистый капитал.
- **Вклад** — условия редактируются, проценты, эффективная ставка и реальная доходность считаются сами.
- **Распределение освободившихся денег** — эффект каждого варианта в датах и тенге.
- **Оформление** — тема, основной цвет, цвета разделов.

## Облако и синхронизация

Приложение работает без облака — тогда это локальный кошелёк на одном устройстве.
Чтобы включить общий доступ на двоих, нужен проект Supabase:

```bash
cp .env.example .env.local     # вписать URL и публичный ключ проекта
npm run dev
```

Схема лежит в [`supabase/migrations`](supabase/migrations). После подключения появляется
вход по почте, создание общего бюджета и приглашение второго участника коротким кодом.

**Как устроена синхронизация.** Состояние семьи хранится одним JSON-документом. Клиент
забирает его, сливает со своим и отправляет обратно вместе с номером версии, которую видел.
Если сервер уже новее — запись не применяется, возвращается актуальный документ, клиент
сливает ещё раз и повторяет.

Слияние держится на двух правилах:

1. **Списки, куда только добавляют** (взносы в цели, версии обязательств), объединяются по
   идентификатору. Внесли оба офлайн — будут оба взноса. Накопленное по цели пересчитывается
   из объединённого списка, поэтому платёж не может исчезнуть.
2. **Описательные поля** (название, срок, сумма) берут последнюю правку по времени, отдельно
   по каждой сущности — чтобы переименование цели на одном телефоне не затёрло новую цель
   на другом.

Удаление — это метка `deletedAt`, а не вырезание из массива: иначе удалённая запись вернулась бы
с устройства партнёра.

Оформление (тема, цвета) в облако не уходит: это настройка устройства, партнёр не должен
перекрашивать чужое приложение.

**Личный кошелёк** — отдельная таблица, которую база не отдаёт партнёру. Приватность на уровне
прав доступа, а не фильтра в интерфейсе.

## Чего ещё нет

- Импорта банковских выписок.
- ИИ-советника.
- Уведомлений о платежах.
- Экрана личного кошелька (таблица и права готовы, интерфейса нет).

## Как это устроено

```
src/
  lib/finance.ts   формулы: аннуитет, досрочка, вклад, цели, подушка
  lib/money.ts     деньги — целые тенге, форматирование
  lib/dates.ts     месяцы, падежи, календарная сетка
  lib/palette.ts   палитры; все цвета заданы парами light/dark
  store/           состояние + localStorage
  screens/         экраны
  components/      примитивы и оболочка приложения
```

Три правила, которые стоит держать:

1. **Деньги — целые числа.** Никаких дробей в состоянии. Когда появятся валютные счета,
   переводим хранение в минорные единицы одной миграцией.
2. **Все числа считает `lib/finance.ts`.** Когда появится ИИ-советник, он получит готовый
   результат и будет только объяснять его словами. Считать деньги модели не доверяем.
3. **Цвет берётся только из токена** в `index.css`, и у каждого токена есть пара для тёмной темы.
   Литеральный цвет в компоненте — это будущий невидимый элемент.
