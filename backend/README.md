# Бэкенд Family Finance (Go)

REST API приложения: вход, домохозяйство, синхронизация `household_docs` / `private_docs`,
курс Нацбанка. Все таблицы — в схеме **`app`** (в той же базе Supabase в `public` лежат
таблицы старого React-приложения).

## Как устроено

- `server/` — сборка роутера (`NewHandler`, `FromEnv`); единая точка для двух запусков:
  - `cmd/server` — долгоживущий сервер для локальной разработки, миграции на старте;
  - `../api/index.go` — функция Vercel (корневой модуль `finance-vercel`, `replace` на
    `./backend`); миграций **не** запускает, пул — `db.ServerlessPool`.
- `cmd/migrate` — миграции отдельной командой (прод).
- `cmd/fxbackfill` — история курсов Нацбанка за `-days` дней назад (прод, вручную после
  `cmd/migrate`); спрошенные дни пропускает, сбой банка по дню считает `failed` — повтор добирает.
- `migrations/` — SQL, встроены в бинарник.
- Вход (`handlers/auth.go`, `internal/googleauth`, миграция `000005`, Р-13, Р-25):
  `POST /api/auth/google {id_token}` — ID-токен Google проверяется по JWKS Google (подпись RS256
  по `kid`, ключи кэшируются по `max-age`, незнакомый `kid` — перезагрузка не чаще раза в минуту;
  `iss` — Google, `aud` ∈ `GOOGLE_CLIENT_IDS`, `exp`, `email_verified`). Пользователь ищется по
  `google_sub`, иначе по почте (старый пользователь привязывается: `google_sub`, `display_name`),
  иначе создаётся без пароля и **без семьи** — 201, иначе 200; ответ — `AuthResponse`, у
  пользователя без семьи `household`/`member` — `null`, JWT без семьи. Почта, привязанная к
  другому аккаунту Google, — 409. Без `GOOGLE_CLIENT_IDS` — 503; JWKS недоступен — 503; плохой
  токен — 401; после неудачной загрузки JWKS минуту отвечает 503 без новых запросов к Google.
  Из токена ничего не логируется. `register`/`login` остаются для стенда и e2e; **в проде
  (`APP_ENV=production` и функция Vercel) `register` нет** — почту никто не подтверждает, а
  Google привязывается по почте: занятый заранее чужой адрес увёл бы вход его владельца;
  пользователь без пароля по `login` получает 401; без семьи `login`, как и Google, отдаёт
  токен без семьи (`household`/`member` — `null`).
  **Семья по факту базы:** защищённые ручки берут семью, роль и слот не из JWT, а из базы на
  каждом запросе (`auth.Middleware` + `membershipResolver`): удалённый пользователь — 401,
  смена роли действует сразу. Без семьи (`auth.RequireHousehold`) — 409 `no household` на
  `/sync/*`, `/statements`, `/operations*`, `/photos*`, `/household/invites`, `/household/members`, `/fx-rates`;
  работают `/auth/me`, `/household` и `/household/join`.
- «С кем» (`handlers/household.go`, B2C-23, Р-7): пользователь состоит максимум в одной семье.
  `POST /api/household {name?, display_name}` — пользователь без семьи создаёт семью (слот `a`,
  документы; имя по умолчанию — «Наша казна»; пустое `display_name` — 400), ответ 201 —
  `AuthResponse` с новым токеном; уже в семье — 409 `already in household`.
  `POST /api/household/join {code, display_name}` — только без своей семьи (из семьи — 409, переход
  между семьями не поддерживается). Проверка «уже в семье» — и в репозитории под `FOR UPDATE`
  строки пользователя (два нажатия не создадут двух семей). Слот — первый из `a`/`b`/`c`, который не
  занят ни участником, ни записью в `people` общего документа — и надгробием с `deletedAt`: оно
  сильнее правки при слиянии (`usedSlotsSQL`, возврат приёмки Б4 В-1): ушедший оставляет свою запись, и новый по коду её не наследует — свой слот и свой первый
  запуск. Полноправных участников (`member`) не больше двух — третий по старому коду, как и при
  занятых слотах, получает 400 `household has maximum members`; новый после ухода — на свободное
  место (viewer по коду не создаётся). Имя (`display_name`, и из Google) — без пробелов по краям,
  ≤ 60 символов (`cleanName`). `GET /api/household/members` (member
  и viewer) — `{members: [{slot, display_name, role, joined_at}]}` своей семьи, без почты и id.
- Удаление аккаунта (`handlers/account.go`, `repository/account_repo.go`, B2C-24, Р-14):
  `DELETE /api/account` — любому вошедшему (member, viewer, без семьи), 204; токен сразу перестаёт
  работать (пользователя нет — 401). Одна транзакция, блокировки по порядку «строка пользователя
  (`FOR NO KEY UPDATE`) → его приглашения (создал или использовал) → семьи (`FOR UPDATE`)»: «Создать
  семью» в соседней вкладке ждёт удаления, вход по коду и удаление партнёра цикла не образуют;
  **последний участник** уносит семью целиком (документы, приглашения, фото, загрузки и операции
  семьи — каскадом); иначе семья остаётся, `households.created_by` переходит к самому раннему
  оставшемуся участнику (FK `ON DELETE RESTRICT` не ослабляется — миграции нет). Затем удаляются
  фото, операции, загрузки и личные документы пользователя, его приглашения, членство и сам
  пользователь. **У семьи остаётся** общий документ с записями ушедшего (`people[slot]`, взносы,
  отметки `by`) — сервер документ не правит; `updated_by` обнуляется. Подписки на пуш (Блок 5) —
  каскадом по `user_id`.
- События и цифры владельца (`handlers/events.go`, `repository/events_repo.go`, миграция `000006`,
  B2C-28, Р-16, Р-27): `app.events` — `kind` (`app_open`, `week_done`, `first_run_goal`,
  `first_run_done`, `push_open`), время, пользователь (SET NULL при удалении), семья (CASCADE),
  день Алматы; свободного текста нет. `POST /api/events {kind, at?}` — любой вошедший, и без семьи;
  тело ≤ 1 КБ, лишние поля и незнакомый `kind` — 400; `at` старше 30 дней или из будущего — «сейчас»;
  `app_open` — раз в день Алматы на пользователя (повтор молча отбрасывается уникальным индексом);
  204. `GET /api/admin/metrics` — только почте из `ADMIN_EMAILS`, остальным и без переменной — 404:
  пользователи и семьи, семьи с выпиской, «вторая выписка за 14 дней» (знаменатель — семьи с первой
  выпиской старше 14 дней; считаются записи загрузок), активные за 7 и 28 дней (`app_open`),
  воронка семей за 28 дней (создали → выписка → цель → первый запуск), 8 недель Алматы (новые
  семьи, загрузки, `week_done`). `/auth/me` отдаёт `admin: true|false`.
- Apple Pay (`handlers/applepay.go`, `internal/applepay`, `repository/phonekey_repo.go`, миграция `000008`, бэклог
  «Apple Pay»): `GET /api/wallet` (member) — `{connected, phones, last_used_at?, shortcut_url, shortcut_url_legacy,
  push_shortcut_url}`;
  `POST /api/wallet/connect` — 201 `{key}` с `Cache-Control: no-store`, **единственный раз**, когда ключ `ffk_…`
  уходит с сервера: в базе только SHA-256 (`app.phone_keys`), свой ключ на каждый телефон, не больше 5 (шестой
  вытесняет тот, что дольше всех не работал: сначала ни разу не использованный — каждое открытие листа подключения
  делает ключ); `DELETE /api/wallet` — отзыв всех, 204. viewer — 403. `POST /api/wallet/tap` — вне JWT:
  `Authorization: Bearer ffk_…`, роль и семья из базы на каждый запрос (нет / отозван — 401, viewer или без семьи —
  403); тело ≤ 4 КБ `{merchant?, amount?, card?, name?, at?, raw?}`, лишние поля игнорируются; без `amount` сумма
  ищется в тексте (команда шлёт всю транзакцию в `merchant`). Тенге — `amount` (тиыны отбрасываются), USD/EUR/RUB/CNY —
  `amount 0` + `fx_*` (курс считает телефон), без валюты и меньше тенге — не пишется; ответ 200
  `{ok, status: saved|duplicate|skipped, reason?}` без операции; та же сумма в пределах 2 мин — `duplicate` (проверка
  и запись — одна транзакция под блокировкой человека: два срабатывания разом дают одну трату); 200 операций с
  телефона за сутки Алматы — 429 `{"error":"limit"}`. Операция — в `app.operations` (`source: tap`, `occurred_at`,
  `category_id` null, банк по названию карты: kaspi/freedom/halyk/card). Батч `/operations/batch` поля сервера не
  меняет; `deleted: true` — надгробие (выписка заменила трату), необратимо, лента его отдаёт. Ключ и тело не пишутся
  в лог; тело, которое пришлось разбирать из текста, хранится **только у почт `ADMIN_EMAILS`** — одна строка, ≤ 2 КБ,
  сутки (`app.wallet_debug`, `GET /api/admin/wallet-debug`, остальным 404).
- Пуши банков (`Push` в `handlers/applepay.go`, `internal/applepay/push.go`, миграция `000009`, бэклог «Apple Pay»
  Блок 2): `POST /api/wallet/push` — тот же ключ и те же ответы, что у касания; тело ≤ 4 КБ `{app, title, body,
  at?}` (строки триггера «Уведомление» iOS 27; уведомление целиком — объектом или одной строкой — тоже читается).
  `ParsePush` по таблице форм Kaspi / Freedom / Halyk: вид (покупка, перевод человеку — продавец «Перевод Имя Ф.»,
  пополнение, зарплата, снятие), сумма — первая после выреза «Доступно / Остаток / Баланс …» вместе с подписью
  (остаток не хранится), сумма после «от / до» — диапазон рекламы, не операция; маски карт и 6+ цифр через пробелы
  вырезаются; отказ, код, возврат или отмена (в любой строке), курсовая разница, реклама — `skipped/format`,
  незнакомый текст — тоже (у админа тело — в `wallet-debug`). Каждый пуш +1 в счётчик дня и банка `app.push_stats` (`parsed` / `ignored` / `unknown`,
  без человека и текста) → `push_stats` в `/api/admin/metrics` (7 и 30 дней). Запись — `InsertPhoneOperation`, одна
  для касания и пуша, под блокировкой человека: повтор того же источника (у пуша — и банка, вида) за 2 мин —
  `duplicate`; касание и пуш одной покупки (та же сумма и валюта, ≤ 10 мин, любой порядок; два известных разных
  банка — две покупки) — одна операция: банк
  пуша, продавец касания, если он не «Apple Pay» (сменился продавец — раздел сбрасывается), ответ `duplicate`;
  перевод из одного своего банка и пополнение той же суммы в другом за ≤ 10 мин, **оба без получателя** (продавец —
  слово вида «Перевод» / «Пополнение»; «Перевод Имя Ф.» — трата, как у выписок) — обе `internal` (не трата); банк
  пишет «между своими» — `internal` сразу. Приход — `amount > 0` (`transfer-in`, «зарплата» — `income`); приход в
  валюте — `skipped/currency`.
- Синк (`handlers/sync.go`, `repository/doc_repo.go`): push с верной ревизией сохраняет ключи
  верхнего уровня, которых нет в присланном документе (`data || pushed` в том же `UPDATE`, что
  и проверка ревизии), — старый PWA не стирает списки нового кода; присланные `[]` и `null`
  побеждают. Вложенное сервер не сливает — это клиент (`frontend/src/lib/merge.ts`).
  `data`, который jsonb не примет, — 400, а не 500 из базы (B2C-26, `docDataProblem`):
  невалидный UTF-8 или JSON, `\u0000` и одиночные суррогаты (`\ud83d` без пары) в строках и ключах.
- Выписки (`handlers/statements.go`, `repository/statement_repo.go`, миграция `000002`): файл
  выписки на сервер не приходит — только JSON операций, разобранных на телефоне.
  `POST /api/statements` (member) — запись загрузки `{bank, period_from, period_to, ops_count}`;
  `GET /api/statements` (member и viewer) — загрузки семьи со слотом загрузившего.
  `POST /api/operations/batch` (member, ≤ 2000 строк / 2 МБ) — upsert **своих** операций по
  отпечатку `id`; `GET /api/operations?since=<RFC3339>&limit=<≤2000>` (member) — свои операции
  после курсора `updated_at`, `next` — метка последней; страница не рвётся внутри одного батча.
  В текстовых полях 6+ цифр подряд — 400 (и CHECK в базе); тела операций не логируются.
- Фото целей и желаний (`handlers/photos.go`, `repository/photo_repo.go`, миграция `000003`, Р-9):
  картинка сжимается на телефоне (~100 КБ webp), байты лежат в `app.photos` (`bytea`).
  `POST /api/photos?hidden=0|1` (member; тело — байты, `Content-Type` `image/webp` или
  `image/jpeg`, ≤ 512 КБ → иначе 413; сигнатура формата проверяется → 400) — `201 {id}`.
  `GET /api/photos/{id}` (member и viewer) — своя семья; скрытое (`hidden`, подарок-сюрприз) —
  только автору, всем остальным **404**, как и чужой семье и неизвестному id (существование
  не раскрывается); заголовки `Cache-Control: private, max-age=31536000, immutable` и
  `X-Content-Type-Options: nosniff`. `DELETE /api/photos/{id}` — автор всегда; **не-скрытое —
  любой member семьи** (цель общая, её картинка тоже — решение B2C-16); viewer — 403; чужое
  скрытое — 404. `<img src>` токен не несёт — клиент забирает `fetch`-ом с `Authorization` и
  показывает через object URL. Байты идут параметром `[]byte`: `bytea` принимает и бинарную
  форму (пулер с `binary_parameters=yes`), в отличие от `jsonb`.
- История курсов (`handlers/fx.go`, `repository/fx_repo.go`, миграция `000004`, Р-71):
  `app.fx_rates` — курс дня по коду (`fx.Supported`: USD, EUR, RUB, CNY), `app.fx_days` — «день
  спрошен у банка». `GET /api/fx-rates?code=EUR&from=YYYY-MM-DD&to=YYYY-MM-DD` (member и viewer;
  другая роль — 403, токен без семьи — 409): `from ≤ to ≤ сегодня (Алматы)`, ≤ 400 дней — иначе
  400. Дни без отметки догружаются из банка: новые первыми, ≤ 20 за запрос, по 4 параллельно,
  общий таймаут 6 с; остаток или сбой банка — `partial: true` с тем, что есть (клиент спросит
  снова). Правила `fx_days` (`MissingDays`/`SaveAsked` — одни для ручки и `cmd/fxbackfill`):
  пустой прошлый день — «не опубликован», пустое «сегодня» не пишется (курс может выйти позже),
  опубликованный день назад не откатывается. Ответ банка без закрывающего `</rates>` (страница
  работ, обрезанная лента) — ошибка, а не пустой день. Публичная `GET /api/fx-rate` пишет свой
  опубликованный день раз на экземпляр (таймаут записи 2 с, ошибка — только лог).
  **Новый код в `fx.Supported`** сам в историю не догрузится (отметка дня общая на все коды):
  `DELETE FROM app.fx_days`, затем `cmd/fxbackfill`.

## ИИ (бэклог «ИИ»)

Клиент Claude — `internal/ai` (Go SDK): без `ANTHROPIC_API_KEY` клиента нет, ИИ выключен
везде (`/auth/me` → `ai: false`). Флаг семьи — `app.households.ai_enabled` (по умолчанию
выключен), счётчики — `app.ai_usage` (семья × месяц `YYYY-MM` по Алматы: запросы, токены,
`cost_micros` — целые микродоллары; удаляются с семьёй), миграция `000007_ai.sql`. Лимит
`AI_MONTHLY_LIMIT` — одно значение на все семьи; списывается только успешный ответ. Два
одновременных запроса на последнем месте могут пройти оба — перерасход в 1–2 запроса допустим.

- **Клиент** — `ai.New(key, baseURL)` (без ключа `nil`), `Call(ctx, Request, &out)` → `Usage`; ответ —
  структурный JSON по схеме (`output_config.format`). Один дедлайн 45 с на весь вызов (ретрай SDK ≤ 1
  внутри — на 5xx и сеть; 429 не повторяется, сразу `ErrRateLimited`), функция Vercel — `maxDuration: 60`
  (`vercel.json`), `cmd/server` — `WriteTimeout` 60 с: оба выше дедлайна. Без стриминга `max_tokens` ≤ ~21 000
  (больше SDK отказывает до отправки → `ErrFailed`). Ошибки — `ErrRateLimited`, `ErrRefused`, `ErrFailed`,
  только со статусом. Цены — `price.go` (центы за MTok), `CostMicros`; неизвестная модель — 0 (в админке «≈ —»).
- **Админка** (только `ADMIN_EMAILS`, остальным и без переменной — 404, хелпер `adminOnly`):
  `GET /api/admin/families` → `{families: [{id, created_at, emails, ai, month, requests, cost_micros}],
  limit, key}` за текущий месяц (ИИ сверху, затем новые); `PUT /api/admin/families/{id}/ai` `{on}` →
  строка (неизвестная семья — 404, лишнее поле — 400, > 64 Б — 413); `POST /api/admin/ai-check` —
  короткий вызов лёгкой модели (`AI_MODEL_SELLERS`) → `{ok, model, ms}` или `{ok: false, reason:
  no_key|failed|rate_limited|refused}`, в расход семей не пишется.
- **Ничего лишнего (Р-15):** ни ключ, ни тело запроса, ни ответ модели, ни картинка не пишутся в логи
  и в базу; логгер chi пишет только метод, путь и статус. Сервер ничего не добавляет к присланному
  (тест `ai_test.go` фиксирует состав исходящего тела).
- **Откат миграции** (только вместе с кодом): `DROP TABLE app.ai_usage; ALTER TABLE app.households
  DROP COLUMN ai_enabled; DELETE FROM app.schema_migrations WHERE version = '000007_ai.sql';` —
  без последней команды раннер при повторном выкате пропустит файл по имени, и ручки ИИ в админке
  ответят 500.

## Переменные окружения

| Переменная | Где | Значение |
|---|---|---|
| `APP_ENV` | прод | `production` (регистр и пробелы не важны) — включает fail-fast: без `DATABASE_URL` или с дефолтным/коротким (< 32) `JWT_SECRET` сервер не стартует. Функция Vercel (`FromEnv`) проверяет это **всегда**, даже без `APP_ENV` |
| `DATABASE_URL` | прод, опционально локально | без неё локально — in-memory моки |
| `JWT_SECRET` | прод | 32+ символа, свой для Preview и Production |
| `PORT`, `CORS_ORIGIN` | только `cmd/server` | дефолты `8080` и `localhost:5173` |
| `ADMIN_EMAILS` | прод, опционально | почты владельца через запятую — страница цифр `/admin`; без неё `/api/admin/metrics` — 404 всем. Значение — `memory/secrets/` |
| `GOOGLE_CLIENT_IDS` | прод, опционально | id клиентов OAuth Google через запятую (веб, Android, iOS) — допустимые `aud`; без неё вход через Google отвечает 503. Значения — `memory/secrets/google-oauth.md` |
| `ANTHROPIC_API_KEY` | прод, опционально | ключ Claude (Anthropic API) — ИИ-помощник; без него ИИ выключен везде, прод валиден. Значение — `memory/secrets/anthropic.md` |
| `AI_MODEL_REVIEW`, `AI_MODEL_SELLERS`, `AI_MODEL_WISH` | опционально | модель по функции: разбор месяца, продавцы, скриншот; дефолты `claude-opus-5-5`, `claude-haiku-5-5`, `claude-opus-5-5` |
| `AI_MONTHLY_LIMIT` | опционально | запросов ИИ на семью в месяц (Алматы), одно значение на все семьи; дефолт `30`, `0`/минус/не число → `30` |
| `APPLEPAY_SHORTCUT_URL` | прод, опционально | ссылка iCloud на команду «Траты сами» для iOS 27 (триггер внутри); принимается только `https://www.icloud.com/shortcuts/…`, иное — как не задано (предупреждение в логе без значения). Без неё у iPhone с iOS 27 нет карточки «Apple Pay» |
| `APPLEPAY_SHORTCUT_URL_LEGACY` | прод, опционально | то же для iOS 17–26 (команда без триггера, автоматизация руками). Ссылки — не секрет, но в git не кладутся: живут в env Vercel. На стенде — заглушки `https://www.icloud.com/shortcuts/stub-ios27` и `…/stub-legacy` (карточка видна, «Открыть команду» ведёт в никуда); как собрать команды — `memory/backlog/apple-pay/block-1-tap/OWNER-SHORTCUT.md` |
| `APPLEPAY_PUSH_SHORTCUT_URL` | прод, опционально | ссылка iCloud на вторую команду «Пуши банков» (iOS 27, триггер «Уведомление»), та же проверка `https://www.icloud.com/shortcuts/…`. Без неё в листе подключения нет шага «Ещё — пуши банков»; ручка `/api/wallet/push` работает и без неё. Стенд — `…/stub-push`; как собрать — `memory/backlog/apple-pay/block-2-push/OWNER-PUSH-SHORTCUT.md` |
| `VITE_GOOGLE_CLIENT_ID` | прод (сборка фронта) | id веб-клиента OAuth (тот же, что в `GOOGLE_CLIENT_IDS`). **Константа сборки**: Vite вшивает её в JS, без неё сборщик выбрасывает код Google — в проде нет входа (формы пароля в проде нет). Заводить в Vercel для **Production** до сборки; после деплоя — `gsi/client` в главном JS прода или кнопка Google на `/access` |

Строки подключения к Supabase — только в `memory/secrets/` и env Vercel, в доки не пишутся.

- **Функция Vercel** — транзакционный пулер Supavisor, порт `6543`, с `binary_parameters=yes`
  в строке (иначе `lib/pq` делает prepare и bind в разных обращениях, а пулер между ними
  может сменить соединение).
- **`cmd/migrate` и `cmd/fxbackfill`** — сессионное/прямое подключение, порт `5432`
  (advisory lock миграций и перенос в одной транзакции требуют одной сессии).

## Команды

```sh
go run ./cmd/server                                   # локально, моки
DATABASE_URL=<5432> go run ./cmd/migrate              # миграции схемы app (идемпотентно)
DATABASE_URL=<5432> go run ./cmd/fxbackfill -days 730   # история курсов (идемпотентно; повтор добирает failed)
go test ./...                                         # юнит-тесты на моках
TEST_DATABASE_URL=<одноразовая БД> go test -p 1 -run Postgres ./...   # БД стирается
```

`testdb` отказывается работать, если в `TEST_DATABASE_URL` есть `supabase`: тесты делают
`DROP SCHEMA public CASCADE`, а на живом проекте там прод-данные React.
